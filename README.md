# V1 —— 一个**可测量**的 agent 内核

> 先把最要紧的话说清楚，因为它是这个项目存在的理由：
>
> **V1 不是 AGI，也不"无限接近 AGI"。** 我做不到，也没有人能在一个晚上用几千行
> Python 做到。任何把 V1 描述成 AGI 的说法都是谎话，包括如果我自己这么写。
>
> V1 只声称一件事：**它是一个能被完整验证的 agent 内核。**
> 七段认知循环全部可跑、预算可对账、守卫可数、记忆去重由数据库保证、
> 测量带噪声下限、**"变好了"这句话有外部依据**。
> 这件事我能做到，而且已经做到了（`tests/contract_test.py` 97/0、
> `tests/bench_test.py` 83/0，含五把假尺子的反证组）。

---

## 一、它为什么存在

V5 跑了 136 轮、215K 行生产代码、329 次提交、16 天。对抗性审查的判决是：

| V5 的实测读数 | 含义 |
|---|---|
| `bench_gain.jsonl` 54 条记录 **gain 全部 = 0.0** | 适应度函数恒等于 0 |
| `pairs=95 evaluated=0 ... domain=0/94` | 主测量通道**从未测到过任何东西** |
| 同配置重复 3 次：`0.7241 / 0.6724 / 0.7586`，**极差 0.0862** | 尺子噪声 > 任何可能的改进 |
| 唯一的目标数字 `0.7184` **五天没动过一格** | 而每轮都在交付"全绿" |

结论不是"某个 bug 没修"，是：**系统不具备声称"我变好了"的分辨力。**

V1 由此定下第 0 条设计约束 —— 来自 V5 的**唯一**一条真正有价值的遗产：

> **先有测量基座，再有能力。**
> 在写第一行"能力"代码之前，先定义清楚"什么算变好"、
> 以及"多小的变化会被噪声淹没以至于不该被当真"。

所以 `mw/measure.py` 不是附属工具，它是 V1 的第一块砖。

## 二、内核做什么 / 不做什么

用户的要求是"核心做 MW，其它功能通过调用外部 agent、skill 和工具完成"。V1 严格执行：

| 内核**做**（这是它的全部） | 内核**不做**（一律外部） |
|---|---|
| 预算分配与对账（`budget.py`） | 写代码、改仓库 |
| 三层记忆读写与去重（`memory.py`） | 查资料、爬网页 |
| 动作预演与失配沉淀（`worldmodel.py`） | 调用别的 agent / skill / MCP |
| 规划、重规划、候选生成（`planner.py`） | 任何领域知识 |
| 四道运行时守卫（`guard.py`） | 任何具体业务逻辑 |
| 能力注册与分派（`tools.py`） | —— |
| **测量与判定**（`measure.py`） | —— |

外部能力通过 `agents.json` 接入（范例见 `agents.example.json`）。
**文件不存在时内核照常运行**（外部能力数 = 0）—— 这是刻意的：
内核的可验证性不依赖任何外部系统、网络或密钥。

⚠️ 测量与判定**分两层**，这条分界是刻意的：
内核里的 `measure.py` 只做**统计**（重复、噪声下限、配对判定），
外部锚层的 `mw/bench.py` 才做**判定**（因为它拿得到外部真值）。
**内核不许给自己发分数** —— 这一条就是 V5 栽掉的地方。

## 三、七段认知循环

```
perceive  组装状态：目标 + 工作记忆 + 检索到的语义记忆 + 上一步观测
think     ACT 判复杂度 → 快通道(1 候选) / 深通道(≤N 候选)
plan      planner.propose / replan（失败必带错误原文，绝不原地重试）
gate      guard 四道检查点：目标劫持 / 工具滥用 / 记忆投毒 / 级联熔断
foresee   worldmodel 预演 + 选择性前瞻（低置信预测不进决策链）
act       tools.dispatch（**永不抛异常**，失败变成可记账的 ToolResult）
observe   worldmodel.observe → 失配沉淀为 episodic 案例 + semantic 启发式
persist   working / episodic / semantic 三层记忆各自落位
```

## 四、2026 理论 → 代码的对应（每条都有出处）

| 理论（2026 实查，非凭记忆） | 出处 | 落在哪 |
|---|---|---|
| **能力 = 预算的函数**；固定预算评测给的是**下界不是上界** | Noam Brown 2026-06《Implications of Large-Scale Test-Time Compute》；UK AISI 2026-07；arXiv:2606.17930 | `budget.py` 全模块 + `measure.py` 强制**同预算档才能比** |
| **自适应计算量（ACT）**：难题深想，易题快答 | WAIC 2026「复杂度第一约束」 | `planner.looks_complex()` → 决定候选宽度 N 与是否付预演成本 |
| **三层记忆 + 上下文内世界模型**（不动参数、改上下文） | WorldEvolver, NUS 2026-06；RedLineSoft 2026 技术报告 | `memory.py` / `worldmodel.py` |
| **Agentic Top-10 运行时治理** | OWASP Agentic Top-10 / AGT 2026 | `guard.py`（四道在内核可控范围内的检查点） |

**关键推论**（这是 V1 与 V5 最大的分歧点）：
既然"能力是预算上的曲线"，那"候选 A 比候选 B 好"这句话**不完整** ——
必须说"在预算档 X 上 A 比 B 好"。`measure.paired_compare()` 在预算档不一致时
**直接拒绝判定**，而不是给出一个混着预算差异的假差值。
V5 当年拿 4x 预算的新方案去比 1x 的旧基线，差值里混着预算，无从归因。

## 五、外部锚层 —— V1 与 V5 的分界线

V5 的判决不是"某个 bug 没修"，是 **反馈不可信**：它的尺子自己写、自己读，
所以 54/54 条 gain 恒等于 0 也没人发现，而每轮都在交付"全绿"。

V1 因此立下唯一不变量：

> **尺子可以被内核读取，但不可以被内核改写。**
> 内核只拿到一个 float。它拿不到尺子，也改不了尺子。

```bash
# 校准尺子 → 跑任务集 → 过口径闸
python3 run.py --bench --compare
# 先把读数存成基线，之后的改动才有东西可比
python3 run.py --bench --save-baseline
```

四道物理保证：打分器跑在**独立子进程**里（内核无法 import 或改它）、
尺子身份 = **文件内容哈希**（不是路径）、内核的 10 个模块**没有一个** import bench、
任务集是只读 frozen 结构。

| 实测读数 | 值 |
|---|---|
| 尺子校准 | 6/6 条逐条可分辨，**6 条中段有序**（0.25 / 0.6 / 0.8333 三档），margin **+1.0000** |
| **确认改进** | 旧版（部分解）`mean=0.6194` → 新版（参考解）`mean=1.0000`，**判定"改进成立"，增益 +0.3806**；两次口径签名一致 |
| 拒绝跨口径 | 改预算档后比较被拒；基线 md5 **一个字节没变** |
| 五把假尺子 | 恒定 / 反相关 / **二值** / 单条失分辨 / 崩溃 —— **全部被判红** |
| R13 撤回态 | 撤四处实现：RC=1、**Traceback=0**、汇总行在、变红清单与预期**一一对应**、md5 三态一致 |
| 真模型噪声下限（见 5.2） | T=0 **极差 0.0000**（逐题逐次完全一致）／ T=0.8 **极差 0.1111**（6 题中 2 题抖） |
| 契约断言 | `tests/bench_test.py` **86 条，全绿** |

⚠️ 校准不是"跑个分"。它要求**逐条** `空答案 < 部分解 < 参考解` 严格成立，否则
fail-closed 拒用 —— 一把"要么 0 要么 1"的二值尺子照样会让所有"改进"纹丝不动，
那正是 V5 那把五天不动的尺子的同构体。设计细节见 `DESIGN.md` 第 9 节。

### 5.2 真模型上实测：噪声下限（2026-10-17 首次）

校准只证明"尺子有刻度"。要真用它，还必须知道**读数本身抖多少**。
本轮第一次把它接到真模型上（本地 ollama `qwen2.5:7b`，6 题 × 5 轮 = 30 次判分）：

| 采样温度 | 各次总分 | 极差 | 逐题不稳定 |
|---|---|---|---|
| **T=0（贪心）** | 5 次全为 `0.9445`，纹丝不动 | **0.0000** | 0/6 |
| **T=0.8（采样）** | mean `0.8722`，落在 `[0.8055, 0.9167]` | **0.1111** | **2/6** |

三个结论：

1. **V5 的死亡数字被复现了。** T=0.8 下的极差 **0.1111 比 V5 的 0.0862 还大**。
   V5 从没测过 T=0 —— 它一直在采样温度下比较候选，所以**任何小于噪声的改动
   都不可能被检测出来**。这就是"54/54 条 gain 恒等于 0、目标数字五天不动一格"
   的机制解释：不是适应度函数写错了，是**噪声把信号淹了**。
2. **噪声集中在 2 道题上，不是均匀分布。** t01 在 `0.1667 ~ 0.8333` 之间跳，
   而 t02/t03/t05/t06 五次全同。只报总分极差 `0.1111`，你看不出该盯哪里；
   看逐题明细，立刻知道该对 t01、t04 做重复测量。
   ⇒ 因此 `BenchReport.as_dict()` 把**逐题明细不截断地落盘**（契约⑤：证据可追溯）。
3. **"稳定地错"与"随机地抖"是两件事。** T=0 下 t04 稳定地拿 `0.6667`
   （6 条断言里稳定挂 2 条）—— 那是**系统误差**，改候选就能修；
   t01 的抖动是**随机误差**，改候选毫无意义。
   水平与极差两个维度各承载信息，压成一个数字就都看不见了。
   契约断言 E13/E14 把这条钉住了。

⚠️ 这个读数只覆盖**一台本地 7B 模型 + 6 道纯函数题**，不是通用结论；
换模型、换任务集都要重测。而且它已被写进**口径签名**：`Caliber` 现在含
`temperature` —— 温度变了就是换了尺子，两次读数**拒绝比较**（实测见下）。

```bash
# 真模型直连（不经内核，测最短链路）—— 噪声实验的核心旋钮是温度
V1_LLM_BASE_URL=http://127.0.0.1:11434/v1 V1_LLM_API_KEY=ollama \
V1_LLM_MODEL=qwen2.5:7b python3 run.py --bench --solver llm-direct \
    --repeat 5 --temperature 0 --max-tokens 512
```

⚠️ **思考型模型要留够 token**：实测 `Qwen3.5-4B` 在 `--max-tokens 512` 时
`reasoning` 会吃光额度、`content` 变空 —— 系统把它记为 `skipped_no_answer`
（"没量到"）而不是 0 分，并把整轮判为 `可信=❌`。**这正是契约③在起作用**：
"这题得 0 分"与"这题没量到"必须可区分。

### 5.3 内核路径（`--solver llm`）在真模型上：看起来像，但**不是**

上一条测的是 `llm-direct`（**绕过了内核**的最短链路）。内核路径在真模型上
**从未跑过** —— 第一次跑就抓到静默降级（见 `DESIGN.md` 第 12 节）：读数
`mean=0.0000` 却标着 `可信=✅`，真模型一次都没被调用。

修完并钉住"同口径必须可复现"之后，才有资格比较。同一把尺子、同一温度（真 T=0）、
同一任务集、记忆逐题隔离：

| 路径 | 预算档 | mean | 逐题 | 交付 |
|---|---|---|---|---|
| 真模型直连（不经内核） | 1x | `0.9445` | — | 6/6 |
| **内核路径**（七段循环） | **1x** | **`0.8333`** | `0.667/1.0/1.0/0.333/1.0/1.0` | 6/6 `done` |
| **内核路径** | **4x** | **`0.8333`** | **逐题完全相同** | 6/6 `done` |

三个结论，一个比一个重要：

1. **内核不是免费的。** 0.9445 → 0.8333：七段循环（规划 + 闸 + 预演 + 观测 + 沉淀）
   在这组窄任务上**净损失约 0.11**。这是第一次把"内核开销"量出来 ——
   而不是靠"内核设计得好"这类话。
2. **同口径可复现了。** 修口径之前，同一题"同口径"两轮给 `0.5000` / `0.6667`；
   修之后三轮**逐位相同**。**不可复现的读数不是读数** —— V5 就是在一个
   不可复现的读数上跑了 136 轮。
3. ⛔ **"能力 = 预算的函数"在这组任务上没有被证实 —— 函数是平的。**
   4x 的预算是 `steps=0/32`，实际只用了 **1~2 步**，逐题分数与 1x 一字不差。
   ⇒ 诚实的结论是：**V1 目前把预算当作"上限"，而不是"可以花掉的资源"**。
   计划器在第 1 步就给出 `finish`，多余预算没有任何机制去消费它。
   这不是"实现有 bug"，而是**能力上的缺失**，必须写在明面上：
   现在能给"预算不会让系统变坏"提供证据，**不能**给"预算让系统变强"提供证据。

## 六、怎么跑

零第三方依赖。只用 Python 3.11+ 标准库（本机实测 3.13.12 / SQLite 3.50.4 / FTS5 可用）。

```bash
cd /Users/linshaojie/V1

# 1) 离线端到端自检（无需网络、无需密钥，几秒跑完）
python3 run.py --selftest

# 2) 契约测试（164 条断言，零依赖，可独立运行）
python3 tests/contract_test.py

# 3) 真跑一个任务
V1_LLM_API_KEY=sk-... V1_LLM_MODEL=gpt-4o-mini python3 run.py --goal "你的目标"

# 4) 测量模式（V1 存在的理由：不要用一个数字描述一个候选）
python3 run.py --selftest --repeat 5 --sweep 1,2,4

# 5) 外部锚层（第五节的命令，先校准尺子再跑任务集）
python3 run.py --bench --compare

# 6) 走一次完整判定：旧版本存基线 → 新版本比较
python3 run.py --bench --solver partial --repeat 5 --save-baseline
python3 run.py --bench --solver oracle  --repeat 5 --compare

# 7) 真模型直连（需要 V1_LLM_BASE_URL / V1_LLM_API_KEY / V1_LLM_MODEL）
#    温度是噪声实验的核心旋钮；--max-tokens 要给够（思考型模型会先花在 reasoning 上）
python3 run.py --bench --solver llm-direct --repeat 5 --temperature 0 --max-tokens 512
```

`--selftest` 会**故意让规划器提一个破坏性动作**（`rm -rf ~`），
用来证明守卫真的在拦 —— 而不是一个永远不会触发的摆设。
自检的通过条件是：`status=done` **且** 守卫拦截数 ≥1 **且** 记忆重复行 =0。

### 环境变量（唯一登记处见 `mw/config.py` 的 `ENV_KEYS`）

| 变量 | 默认 | 用途 |
|---|---|---|
| `V1_STATE_DIR` / `V1_LOG_DIR` / `V1_WORKSPACE` | 项目下同名目录 | **测试必须覆盖它们**（不许碰生产目录） |
| `V1_BENCH_DIR` | 项目下 `bench_out/` | 基线与读数落盘目录（**刻意不进 `ensure()`**：不写基线就不创建，否则测试会顺手创建生产目录） |
| `V1_LLM_BASE_URL` / `V1_LLM_API_KEY` / `V1_LLM_MODEL` | OpenAI 兼容 | 真模型接入 |
| `V1_LLM_OFFLINE` | 空 | 置 1 强制走确定性桩 |
| `V1_MAX_STEPS` / `V1_MAX_LLM_CALLS` / `V1_MAX_WALL_S` / `V1_MAX_CANDIDATES` | 12 / 24 / 120 / 3 | 预算上限（刻意小 —— 一次跑十分钟的内核最后一定没人跑） |

## 七、V1 明确**没有**做到的事（边界声明）

写在这里，是为了让"没做到"变成记录在案的事实，而不是被含糊过去。

1. **没有持续学习。** 参数是冻结的。所谓"学习"全部发生在记忆层（改上下文，不改权重）
   —— 这正是 WorldEvolver 的路子，但它的天花板也很明确：**它不能产生新能力**，
   只能把已有能力用得更准。
2. **没有真正的世界模型。** `worldmodel.py` 做的是**文本层面的**动作后果预演，
   不是物理或因果模型。它降低"假设错一步后面全错"的概率，不消除它。
3. **外部打分器接上了，但它只覆盖 6 道纯函数题。** `bench.py` 让"变好了"这句话
   第一次有了外部依据，但那依据的**适用范围很窄**：纯函数、机器可判、零依赖。
   真实的、开放的、没有 ground truth 的任务，V1 仍然不能判定自己有没有变好 ——
   而那恰恰是 V5 假装测到了的那类任务。**别把 6 道题的成绩当成通用能力。**
   另外，校验证明的只是"好/中/坏三档有序"，**未证明**两个相近分数（0.6 与 0.65）可分；
   这一条已经写进 `Calibration.evidence.unknowns`，不是靠这里的声明兜着。
4. **内核不做任何实际能力。** 没有外部 agent 接入时，它只是把"检索记忆、写记忆、
   收尾"这条最小链路走通。这是刻意的设计选择，不是缺陷。
5. **网络与基础设施层的治理不在内核内。** OWASP Agentic Top-10 里的
   零信任网络隔离、审计基础设施等，V1 只做了内核可控的四道检查点，
   其余写在 `guard.py` 的注释里，不假装做了。
6. **预算不可"转化"为能力（2026-10-17 实测）。** 4x 预算下内核只用了 1~2 步
   （分母是 32），逐题分数与 1x **一字不差**。也就是说 V1 当前把预算当**上限**
   而不是**资源**：计划器第 1 步就 `finish`，没有任何机制把多余预算
   换成更深的思考或验证。所以"能力 = 预算的函数"这条 2026 理论，
   V1 目前**只证明了前半句（预算不会让系统变坏），没证明后半句**。
   这是能力缺口，不是 bug —— 修法是设计问题（例如"复杂任务的答案要不要
   花预算去自检"），而任何新动作都必须先证明它**能被看见**。

## 八、如果要判断"V1 有没有意义"

不要看它有多少行代码，不要看契约测试多少绿。只看一个实验：

> 同一候选 × 同一把尺子 × **同一预算档** × **N≥5 次重复**。
> 若候选的**最差一次**仍然高于 (基线均值 + 噪声下限) ⇒ 这才是"改进"。

`run.py --repeat 5` 就是干这个的。在离线桩上它的极差是 `0.0000`
（证明**测量管线本身不引入噪声**）。真实候选的噪声必须在真模型上测出来，**不许假设**。
