## 产品摘要（30 秒读完）

**是什么**：一个能被**完整验证**的 agent 内核。七段认知循环可跑、预算可对账、
记忆去重由数据库保证，而且「它变好了没有」这句话有**外部依据**（外部打分器 +
口径闸 + 撤回态）。零第三方运行依赖（`dependencies = []`，由 AST 审计与契约钉死）。

**不是什么**：**不是 AGI**，也不声称「无限接近 AGI」。见文末「边界」。

**30 秒验证**（零模型、零网络、零密钥，全部本机实测）：

```bash
./quickstart.sh                      # 契约 + 锚层 + 端到端自检，四步
bash demo/run_demo.sh                # 三臂参照点：1.0000 / 0.0000 / 0.6194（逐位可复现）
./run_tests.sh                       # 七步全量门（含依赖审计：白名单外一个 import 都不许有）
python3 run.py --goals               # L5 入口：它从**自己的账本**里决定该做什么
python3 -m mw.loop --rounds 3 --noise-floor 0 --out /tmp/curve.jsonl   # 常驻循环 + 能力曲线
```

**别人 clone 之后能不能自证** —— 这是「交付物」与「我机器上绿了」的分界线：

且每个绿灯都能被撤回证明不是恒真。

## 一、能力阶梯（实测位次，不是路线图）

| 级 | 能力 | 位次 | 硬读数 |
|---|---|---|---|
| **L0** 执行 | 写代码、跑、读输出 | ✅ 完成 | `coding_small` **0.9722** |
| **L1** 判决 | 判产物对不对，且判据不是恒真 | ✅ 完成 | 契约 **781/0**、撤回态 **339**、噪声地板 0 |
| **L2** 测量 | 知道自己「变没变好」，带外部依据 | ✅ 完成 | 三臂 + 安慰剂 + 跨套件 `suite_sha` 闸 |
| **L3** 自省 | 发现自己错在哪，并改 | ⚠️ 半 | 定位 **28/28**、召回 0.578、真盲区 9.0%；判停 **29~30/33**；改不动（**92.5%** 判了没改进） |
| **L4** 自改 | 自己写出有用的知识，跨跑累积 | ✅ 两半都成立 | 区域 **21/25（84%）**；写→读→用 −**57.4%** 判分；`B=120` 时 COLD 17/25 → WARM 20/25 |
| **L5** 自主目标 | 自己决定要做什么 | ⚠️ **最小形态成立** | 会排产（`SELF` 14/25 vs 人类序 9、随机 6.45）；**V170 起能从自己的账本产生目标、自判、记账、换下一个**（判据 4/5，见第三节）；**V171 起能把自己做不到的写进账本并停止重复**（判据 6/6）；**V172 起「停下来」分清是哪种停**（`IDLE`/`DONE`/`EMPTY`/`STALE`，判据 8/8）；**V180 起诊断能说「哪一层的尺子坏了」**（行为级 COARSE 才给 `RULER`） |

**L4 的「成立」必须带三条限定**（少一条就是吹）：
1. 区域是 **84%**，不是 100% —— 缺口 4 个全在 `g7d3`，共同点是多站点重构 / 重写表达式。
2. 累积只在**资源紧张**时有牙：`B ≥ 400` 时 COLD 自己也能做完，边际收益归零。
3. 知识的形式是**人定的**：`(落点类, 链)` 这个抽象、删除算子、判据本身，全是人写的。

**L5 的边界**：`RAISE` 类目标（把分数提上去）系统**提得出、做不到** ——
那需要改能力，而「该改成什么」正是 V79 那堵墙（系统自造判据判别力 **0/8**）。
系统今天能自主闭环的，只有**测量类**目标。

V171 之后这条边界多了一半：它**知道自己做不到**。
`RAISE` 的判据是测量的不动点（再测只让均值更稳），所以连判 3 次均分不变 ⇒ 转 `ESCALATE`、
不再重复提、但**留在输出里**（⛔ 不静默丢弃）。
⛔ 这**不是**「做到了」：不改任何分数，只是停止假装自己还有事可做。

## 二、怎么跑

```bash
git clone <repo> && cd PyautoL-V1
./run_tests.sh          # 不需要装任何东西；本机 Python ≥3.11
```

| 入口 | 用途 | 需要模型 |
|---|---|---|
| `./quickstart.sh` | 四步上手：契约 → 锚层 → 自检 → 读数 | 否 |

| `python3 run.py --selftest` | 离线端到端（七段循环全跑一遍） | 否 |
| `python3 run.py --goals` | **自主目标**：从账本提议该做什么 | 否 |
| `python3 run.py --goals --goals-act 1 --offline` | 真执行一条目标并判定 | 否 |

## 三、L5 的「自主目标」（V170 提出，V171 补「做不到」，V172 分清「哪一种停」）

### 3.1 它做什么

```
python3 run.py --goals
```

读两样东西：**自己的分数账本**（`state/score_ledger.jsonl`，一条题一次观测）
与**环境里有哪些题**（`bench/tasks/*.jsonl` 的 `id` 字段）。
⛔ 不读题面、不读 `--goal`、不调模型。

| 类 | 触发（全部来自账本） | 判据 | 能否自己闭环 |
|---|---|---|---|
| `COVER` | 题在套件里，账本里 **0** 行 | `n_obs ≥ 1` | ✅ |
| `PROBE` | `0 < n_obs < 3` | `n_obs ≥ 3` | ✅ |
| `RAISE` | `mean_score < 1.0` | `mean_score ≥ 1.0` | ⛔ 不能（要改能力） |

排序用**词典序**（COVER > PROBE > RAISE，同类按缺口升序）。
⛔ 不做「收益/成本」加权 —— 那是一个需要被单独验证的预测模型，
拿它决定先做哪件事、再拿结果当它的证据，是循环论证。

判定后写 `state/goal_ledger.jsonl`：**MET 的下次不再提，NOT_MET 的必须重新提**。
目标观测写 `state/goal_obs.jsonl`，⛔ 不写分数账本（后者带口径闸，混进去等于伪造履历）。

### 3.2 实测（`bench/evidence/l5_s258/`，预注册 `PREREG_v170.md`）

| 判据 | 结果 | 读数 |
|---|---|---|
| P1 无证据不许编 | ✅ | 空账本 + 空套件 ⇒ 0 条；有题没测 ⇒ 只出 COVER |
| P2 可追溯、不是人给的 | ✅ | 溯源 40/40 自洽；**把 40 条题面全换成占位符 ⇒ 目标逐条不变** |
| P3 自己判得了 | ✅ | 40 条判定无 UNKNOWN；三类各有一个能翻转的见证 |
| P4 目标随读数变（top-1） | ❌ | 4 个扰动里 top-1 改变 **0/4**（1 个扰动哑火，见下） |
| P5 判完就换下一个 | ✅ | COVER→MET 后同 `gid` 不再出现，同格换类为 PROBE |

**P4 为什么 FAIL（如实登记，不解释掉）**：今天的账本里 40 格有 **34 格零覆盖**，
而「零覆盖」意味着**没有任何读数**。34 条目标在判据上完全并列，
所以「先做哪一条」只能靠题 id 的字典序 —— **那是一段人写的常量**。
唯一能让这条判据变绿的办法是给它加一个与数据无关的种子，那是把判据刷绿，不是把系统做对。
（逐目标的读数依赖是 **40/40**：改掉某条目标引用的读数，那条目标必然消失或换类。）

**补充读数**（不参与五条判据）：

- **目标链**（单题套件，连续执行 4 次）：`COVER→MET` → `PROBE→NOT_MET` →
  `PROBE→MET` → `RAISE→NOT_MET`。**下一个目标由上一个结果派生**，不是重新掷骰子。
- **覆盖跑**：一次把 34 条 `COVER` 全执行掉，墙钟 **8.5 s**（离线桩），
  目标集从 `COVER 34 / PROBE 6` 变成 `PROBE 40` ——
  **34 件没人要求的事，它自己列出来并做完了**。
  ⚠️ 离线桩的分数是**装置读数**，不是能力读数；覆盖跑证明的是「找活干」这条链通，不是「会做题」。

### 3.3 V171：把自己做不到写进账本

`RAISE` 是唯一一类「提得出、闭不了」的目标，原因不是题难，是**判据的形状**：

| 类型 | 判据 | 测量会不会改变它 |
|---|---|---|
| `COVER` / `PROBE` | `n_obs >= 1 / 3` | **会** —— 测一次就满足 |
| `RAISE` | `mean_score >= 1.0` | **不会** —— 同分布再测只让均值更稳 |

⇒ 同一个 `gid` 每轮都会被重新提出。实测（`t06_rle` 8 轮）：**提了 6 次，每次同一条 gid，均分逐位 0.0**。

**做法**：同一 `gid` **连判 3 次** `NOT_MET`、且这 3 次的均分**逐位相同** ⇒ 转 `ESCALATE`：
不再提 `RAISE`，但**在输出里单列一节「已转运维」**（⛔ 不静默丢弃）。
阈值复用 `MIN_OBS`，不新增可调参数。

| 判据 | 结果 | 读数 |
|---|---|---|
| Q1 触发 | ✅ | 连判 3 次 + 均分逐位相同 ⇒ 触发（分母 1 格） |
| Q2 触发后不再提 | ✅ | 8 轮里 B 臂提 **3** 次 vs A 臂（未启用）**6** 次；分界恰在 fail#3 之后 |
| Q3 读数在动不触发 | ✅ | `0.2→0.4→0.6` 在收敛 ⇒ 不转（否则会把「快到了」判成「到不了」） |
| Q4 可撤销 | ✅ | 删掉 1 行账本 ⇒ 判定消失（纯函数，不是持久化状态位） |
| Q5 留痕不丢 | ✅ | 输出有该节、json 有该格、该格不在提议里 |
| Q6 无新阈值 | ✅ | 模块级常量仍 = `{KINDS, MIN_OBS, TARGET}` |

**全部饱和时它会说什么**：40 题各测 4 次、均分全 0.0 ⇒ **提议 0 条、转运维 40 格**。
输出是「测量路径已用尽，40 格需换能力」—— **不是「做完了」**。
⭐ 「没有目标」有两种，账本必须分得清：全做完了 / 全做不动。
分不清的后果是第二种被当成第一种报上去。

⛔ **判别力在部署侧接近 0**：确定性 solver 下「再测均分不动」对每一格都成立 ⇒ 全饱和时全转运维。
它真正有牙的是**行为**（提议数 6→3），不是「挑出哪一格」。

### 3.4 V172：停下来时，说得清**是哪一种停**

V171 之后还有一个洞：提议 0 条时，输出那句话是

```
（没有可提的目标：账本与套件都对不上，或该做的都做完了）
```

**一句带「或」的话**。四种成因挤在一起，读者只能猜 —— 而最顺的猜法是最后那半句：**做完了**。
于是「无事可做」永远会被读成「做完了」。

做法：一个纯函数 `state(goals, esc, suite_ids, obs)`，只把**已经算出来的三个量**
（提议条数、转运维格数、逐格 `satisfied()`）变成一句不再带「或」的话：

| 名字 | 条件 | 它说的是 |
|---|---|---|
| `WORK` | 提议 > 0 | 有活可干 |
| `EMPTY` | 提议 0、**套件 0 题** | 无从提议（装置/口径问题） |
| `IDLE` | 提议 0、**转运维 > 0** | 测量已用尽，提不出目标了 |
| `DONE` | 提议 0、转运维 0、**每格读数都达标** | 真的做完了 |
| `STALE` | 提议 0、转运维 0、**有格没达标** | 目标被已 MET 的 `gid` 挡住了 |

⛔ `DONE` 由**读数**逐格算，不由「提议 0 条」算：`done_gids()` 是单调的，
某格判过 `MET` 之后若均分回落，`propose()` 就不再提它 —— 拿提议数当判据，正好在这一格上谎报。

| 判据 | 结果 | 读数 |
|---|---|---|
| P1 五态可达 | ✅ | 5 个构造输入 ⇒ 5 个互不相同的名字 |
| P2 **IDLE ≠ DONE** | ✅ | 40 格全饱和 ⇒ `IDLE`（转运维 40）；40 格全达标 ⇒ `DONE` |
| P3 DONE 由读数算 | ✅ | 一格 0.5 且那条 `RAISE` 判过 `MET` ⇒ `STALE`，并**点名**该格（blocked = 1） |
| P4 EMPTY 优先于 IDLE | ✅ | 同一份转运维证据：套件非空 ⇒ `IDLE`、套件 0 题 ⇒ `EMPTY` |
| P5 可撤销 | ✅ | 删掉 1 行 `NOT_MET` ⇒ 转运维 40→39 ⇒ 变 `WORK` |
| P6 输出换了话 | ✅ | 4 份 CLI 输出里旧文案出现 **0** 次；`IDLE`/`DONE`/`EMPTY` 各就各位 |
| P7 无新阈值 | ✅ | 模块级常量仍 = `{KINDS, MIN_OBS, TARGET}` |
| P8 判据有牙 | ✅ | 恒返回 `WORK` 的变异体上 P1~P4 **4/4 FAIL** |

**补充读数**（不入判据）：「旧语义」变异体（提议 0 ⇒ 一律 `DONE`）在 5 个臂上说错 **3 个**，
其中全饱和那 40 格被报成 **`DONE`** —— 这正是本轮要消掉的那句话。

⛔ 它**不提高任何分数**，也不新增目标类型：它只让「没有目标」这句话可分辨。

### 3.5 修复轴：诊断说「该动哪一层」（V180）

转运维那一节每格会印一条「修复轴」，值域恰三个名字：
`CRITERION`（改判据）/ `MODEL`（改模型）/ `RULER`（改尺子）。

V180 之前，`RULER` 只在两种 claim 下出现，而其中「行为级用尽」那条**走不到** ——
调用点只有一个，实参来自分数级读数。V180 把行为级读数接进 overlay，并补一条：

> 行为级 `COARSE`（**存在异行为同分**）且行为类 ≥3 ⇒ 给 `RULER`。

**为什么不用分数级 `COARSE`**：真实池 6/6 都是分数级 `COARSE`，但其中 5 格行为级是单射
（多个实现行为完全相同、只是写法不同）⇒ 拿分数级判，假正例 **5/6**。
分辨力是相对于**行为**说的，不是相对于实现。这条取舍由 `AZ141e` 钉死。

⛔ 它仍然**只被印出来**：没有任何代码路径拿轴决定动作。
V181 把 30 行带 `impl_sha`+`vec` 的观测喂进账本后，部署上**恰 1 格**（`t01_parse_duration`）
第一次拿到 `RULER`（`['CRITERION']` → `['CRITERION','RULER']`）。

### 3.6 一格的观测来自几把尺子（V182）

账本里的 `caliber_sig` 一行一个。同一个格子上如果落了两把尺子的行，`stats()` 仍会把它们
一起平均 —— 而那个均分**不对应任何一个口径**：

```
sg02   混池=0.5000   487a78e8 n=1 mean=1.0000｜8974b37b n=1 mean=0.0000
```

会话 4 全对、会话 5 全错，混池报 0.5。`--goals` 现在多印三行（`sig_report`）：

```
口径      24 格有观测：单口径 14 格，混口径 10 格，其中**平票 4 格**
平票      两把尺子都有行且并列 ⇒ 混池均分**不对应任何口径**：…
```

- **平票不猜**：并列时 `major=None`、`mean_major=None`。用「最新/字典序」挑一个是把冲突藏起来。
- **无签名不是一把尺子**：没有 `caliber_sig` 的行单独计 `n_unknown`（与 `ScoreLedger`
  的 `no_caliber_sig` 同义），不并入任何口径。
- **它只是报警**：`propose()` / `stats()` 一个字没改（`AZ143c` 钉住「调它前后 `propose` 逐字相同」）。

⚠️ 为什么不直接「按主口径过滤」：平票格会因此**归零**，`propose()` 就把它报成
`COVER`（「补齐从未测过的题」）—— 而它测过两次。实测 4 格 `PROBE→COVER`。
⇒ **「不猜口径」与「不许谎报未测过」在现有三分类下冲突**，平票格没有正确的表达位置。
这是结构性的（与下一节 `RAISE` 可达性为 0 同类），不是实现没写好。

### 3.7 判据能不能自己造（V183，动的是 V79 那堵墙）

V79 压了 24 轮的判决是「**自写自检在原理上不构成独立判据**」。V183 把它拆成两半：

| | 问题 | 读数 |
|---|---|---|
| **W2** | 判据**形态**上能不能独立 | **能**：`decode(f(x)) == x` 这种人写关系判据在 V79 同一批 8 题上过正确 **8/8**、判别力 **6/8**（V79 断言是 1/8） |
| **W3** | 系统能不能**自己造出来** | **不能**：模型自由写 0/8、选算子+填槽 0/8、再加槽校验与一次修复仍 0/8 |

⇒ 不独立的成因是**期望值的来源**（模型把读错的格式写成字面量），不是"自检"这件事。
把判定交给 stdlib 之后，**误伤从 7/8 降到 0/8**。墙因此从「原理」移到「能力」。

产品侧只加一道**准入闸**（`mw/metacrit.py`），纯 AST、不执行判据源码：

```
literal_expectations(src)   找出「非空字面量当期望值」的位置
admit(src) -> (通过?, 理由)
run(code, crit)             转交 mw.verify.run_example（内核同一把尺）
```

- V79 那 8 题断言：**8/8 全拒**；人写关系库：**14/15 放行**（1 例误拒是规格映射，可改写）。
- ⛔ 内核**没有「判据输入」这条路**，所以闸目前**没通电**（存在、被契约钉住、不决定动作）。

⚠️ 天花板是**人写且事后调过**的 ⇒ 6/8 只能当上界。另有一道裂缝：`g7j_n4` 四题的惯例
**不在题面里**（只在种子库），V79 把它们混进 0/8 的分母 —— 那 4 题任何只看题面的判据
都不可能过正确，与独立性无关。

### 3.8 判据生成器：把「结构」从模型手里拿走（V184）

V183 的 W3 是 0/8：模型选对了算子，却死在**槽形状**（`inputs` 被平铺、单参数函数给两个实参）。
V184 把结构交给装置，模型只填**值**：

```
mw/critgen.py
  arity(code)           从 def 读「必填位置参数个数」（纯 ast）
  POOL / inputs_for()   按参数**类型**从固定池生成输入 —— 模型碰不到 inputs
  DECODERS / KEEPS      槽只能是枚举 id，⛔ 不许写任意表达式
  legal_indexes()       在目标实现上圈域：只问「函数吃得下吗」，⛔ 不问返回值对不对
  build() / validate()  判定逻辑全由装置渲染
```

读数（同 8 题、同尺、同进程）：

| 臂 | 可跑 | 过正确 | 咬错 | **判别力** |
|---|---|---|---|---|
| V183 装置（`base`） | 4/8 | 0/8 | 4/8 | 0/8 |
| **类型化装置（`typed`）** | **7/8** | **2/8** | 6/8 | **1/8** |
| 类型化 + 记忆（`typed_mem`） | 6/8 | 2/8 | 5/8 | 1/8 |

⇒ **失败从「装置不会用」变成「关系选不对」**（`base` 4 条全是形状错，`typed` 5 条全是语义错）。
判别力第一次非零，但只有一格，且严格口径下（槽值必须与惯例一致）`typed` 仍是 0/8 ——
那一格是「判据松了也能咬到 `partial`」，不是判据好。

接记忆确实**改对了槽值**（`keep`：`tail_n` → `ellipsis_tail_n`），但**没有改变任何一格的
pass/bite**：记忆的效应只到「判据源码」这一层。另有两题（`g7e1`/`g7d3`）在 6 个算子下
**结构不可达**（一个返回 `bool/None`、一个要金额 decode），报告同时给 8 题与 6 题分母。

### 3.9 把「为什么不过」说清楚，仍然不构成约束（V185）

V184 的失败分类里藏着一个错：`g7d2` 是一元函数，模型选了二元算子 `TAIL`，而
`validate()` 先判 `len(types)==n_args`（1==1 通过），再撞上「第二个类型必须是 int」的特判
⇒ 回错说的是**类型**，不是**参数个数**。V185 把诊断分层：

```
diagnose()   → {ok, code, need, got}，code ∈ KIND / ARITY / TYPES / SLOT
             （优先级：先比参数个数，再说类型，最后说槽）
retry_hint() → 结构事实 + 全量目录（⛔ 不点名该换哪个算子）
```

`validate()` 逐字不动；`AZ148c` 钉住「两者对过/不过必须逐例一致」——
分层是加解释，不是放宽门槛。

读数很干净，也很不好看：两臂**完全相同**（可跑 7/8、过正确 2/8、判别 1/8）。
唯一差别那一格是 `g7d2` —— 收到「本题函数只有 1 个位置参数」之后，它把 `TAIL`
换成了 **`BOUND`**，两者**都是二元**，`types` 还只给了一个元素。两次独立跑逐字相同。

> ⇒ **把结构事实说给它听，不构成结构约束。** 下一刀不是把话说得更重，
> 而是把候选集按参数个数**过滤掉**（V186）。

### 3.10 「选不到」才算约束（V186）

V185 证明了相反的事：回错里明写「本题函数只有 1 个位置参数」，模型仍然换成另一个**二元**算子。
于是 V186 不问模型要，**装置不给**：

```
ops_for(n_args)       只返回 arity 相符的算子（n_args < 0 ⇒ 全量，不假装有约束）
catalogue(n_args)     只列这些算子；无参调用仍是全量（retry_hint 用）
```

| 臂 | 过正确 | 判别力 | ARITY 失败 |
|---|---|---|---|
| 全量候选 | 2/8 | 1/8 | 1 |
| **按 arity 过滤** | **3/8** | **2/8** | **0** |

⭐ `g7d2` 一旦选不到二元算子，就选了 `SUBSEQ` —— 正好是 `dedupe_keep` 的语义。
**它此前不是想不出关系，是被结构挡在门外。**

⚠️ 也有反向的一格：`g7d3` 写了 `types: ["int", "float"]`（两个类型 + 编了个 `float`）。
过滤管得住「选哪个算子」，管不住「types 写几个」—— 那是 V187 的事。

### 3.11 补上缺的算子之后（V187）

V184~V186 之后还有两道题「一格都过不了」：`g7e1`（输出域）与 `g7d3`（数值类型 + 金额规格）。
本轮补上，同一个装置的其余部分不动：

```
POOL["num"]        (0, 7, 1234.5, -1234.5, 1234567.891, -0.5)   ← 必须跨过三位边界
POOL["flag"]       ("y"," YES ","0","on","  ","xyz","1","OFF")  ← 池里没有「哪个算真」
NUMFMT             arity 1，槽 sep/dec/neg（规格型）
INVARIANT          arity 1，无槽（大小写/空白不变 + 非退化）
skeleton(n_args)   types 占位重复 n 次 —— 骨架的**长度**就是模型看到的约束
```

| 臂 | 可跑 | 过正确 | 判别 |
|---|---|---|---|
| V186 重放（A） | 7/8 | 3/8 | 2/8 |
| +新算子（B） | **8/8** | 3/8 | 1/8 |
| +新算子+记忆（C） | **8/8** | 3/8 | 2/8 |

⭐ 三臂的「过正确」都是 3/8，但**是三道不同的题**：
A={`k01`,`g7d2`,`g7e2`}、B={`k01`,`g7e1`,`g7e2`}、C={`k01`,`g7d3`,`g7e2`}。
`g7d2` 从 A 的 `SUBSEQ`（对）掉到 B 的 `CONSERVE`（错）——
V186 是「过滤掉不可达的 ⇒ 选对」，本轮是「加进两个新的 ⇒ 选错」。

⭐⭐ **记忆第一次穿到四格**：`g7d3` 无记忆时段落分隔符选 `comma`，有记忆时选 `space`
（`sep`/`dec`/`neg` 三槽在 24 种组合里是唯一正确的那一个）⇒ 从「能跑但判据在正确实现上失败」
变成「过正确 + 咬错」。

⚠️ 还有一条 STAGE0 的硬读数：**判别力是 `(判据, 输入域)` 的函数**。同一份判据、同一个槽值，
只把输入池从小值换成跨三位边界，对「逗号千分位」这个错误实现的判定就从**通过**变**失败**。
小值池上看不见错，不是判据弱。

### 3.12 这条链**没有**解决什么

- 目标类型表（COVER/PROBE/RAISE）是人写的。系统选的是「挑哪一格」，不是「发明哪一类」。
- `RAISE` 类目标可达性为 0 —— 提得出，做不到。V171 起它会**被判成做不到并停止重复**，
  但那只是不再重复，不是解决了。
- 同类并列时按 id 排序，是人写的常量（P4 的 FAIL 就是它）。
- **判据仍然不是系统自己造的**：V183 证明「独立判据存在」（人写 6/8），
  但系统自己造的三条路全 0/8 ⇒ 造不出来的那一半还在。
- **算子库、类型表、惯例全部人写**（V184~V187）。V187 只证明「把结构拿走之后模型能选对算子」
  与「槽值对了判别力就上来」，⛔ 不证明「它会自己造算子」或「它会自己去找惯例」。
- **判别力对输入域敏感**：同一份判据、同一个槽值，换个池就能从「咬得住」变「咬不住」，
  也能从「过正确」变「误伤」（V187 C 臂在 `g7e1` 上实证）。⇒ 这套装置的读数
  **不能脱离池单独引用**。

### 3.13 收口三条坏信号：装置改的是「算不算证据」（V188）

V187 登记的三条不是判据写错，是**读数的可信度**问题。本轮只动外围，判据源码一字未改：

```
EMPTY_IFF_EQUAL 的两个输入必须同类型           ← 异类型时 (a==b) 恒假 ⇒ 判据恒真
critgen.constant_on(code, fn, inputs)          ← 实现在这个池上「输出是否全同」
critgen.verdict(...)                           ← 三值：UNDECIDED 优先于 PASS/FAIL
metacrit.admit(src, params=())                 ← 规格参数不算「写死的期望值」
```

**验证方式本身是本轮的重点**：不跑模型，拿 V186/V187 冻结的 24 格输出，在**老装置**
（`git show d56230b:`）与**新装置**上各判一次。判分走同一个 `mw.verify.run_example`，
且新旧 `build()` 的判据源码 `sha256` 逐格相同 ⇒ 差分只能来自装置。

| 臂 | 过正确 | 判别 | 准入 | 不可判 |
|---|---|---|---|---|
| A | 3/8 → 3/8 | 2/8 → 2/8 | 7 → 7 | **1** |
| B | 3/8 → 3/8 | 1/8 → 1/8 | 7 → **8** | 0 |
| C | 3/8 → 3/8 | 2/8 → 2/8 | 7 → **8** | **1** |

⭐ 三臂的分数**一格没动**。⇒ 这三条决定的不是「谁过谁不过」，而是「哪些格算证据」；
它们修完也不让系统离「会自己变强」近一步。

⭐⭐ 两格从 `FAIL` 变 `UNDECIDED`，**第一格不是 `INVARIANT`**（A 臂用的是 `ROUNDTRIP`）：

| 臂 | 算子 | `types` | 池为什么没行使到实现 |
|---|---|---|---|
| A | `ROUNDTRIP` | `["str"]` | `parse_flag` 对 str 池全部返回 `None` |
| C | `INVARIANT` | `["str"]` | 同上 |

⇒ 「池没有行使到实现」是 **(实现 × 池)** 的性质，**与算子无关**；按算子写修法会漏一半。

⚠️ 装置空间 264 格里还有 6 格在新装置下**仍然**恒真（`truncate_tail` × `TAIL` × `dict`/`list`）：
门槛 `len(s) > n` 在存活域上从未为真，而**输出并不恒定** ⇒ `constant_on()` 看不见它。
⇒ **三值不是「是不是证据」的万能判据**，它只覆盖「输出恒定」这一族（登记为 S4，下一轮）。

### 3.14 让诊断改变下一轮：通了「走哪条路」，没通「走得准不准」（V189）

诊断（`critgen.diagnose()`）在产品里**曾经零调用点** —— 它只被契约测试调用。
把它的结果做成一句人话塞回 prompt，V185 已证明**不产生任何变化**（模型把 `TAIL` 换成另一个
二元算子）。⇒ 本轮把诊断的输出接进**候选集**，不是接进措辞：

```
read_signal(...)        → 五类信号（结构两类 + CONST + SEMANTIC + OK）
narrow(signal, ...)     → 按信号删候选；`scope` 区分「删一个」与「按类删」
catalogue(allow=)       → 目录只列剩下的；空集合就是空（不回退全量）
```

| 臂 | 过正确 | 判别 | pass 集合 |
|---|---|---|---|
| A（单轮） | 3/8 | 1/8 | `{k01, g7e1, g7e2}` |
| B（≤3 轮，删一个） | **4/8** | **2/8** | `{k03, g7d2, g7d3, g7e2}` |
| C（≤3 轮，按类删） | 4/8 | 2/8 | 同 B（逐题相同） |
| D（3 轮，**不收窄**） | 3/8 | 1/8 | 同 A，三轮 `raw` **逐字相同** |

**D 臂是归因的关键**：同一个 prompt 重跑三轮零变化 ⇒ A 与 B 的差异只能来自收窄。

⭐ `A ∩ B = {g7e2}` —— 只交 1 个，**5 格翻转**。⇒ 「3→4」这个净数掩盖了
「换了一批题的对错」：收窄不是让模型更准，是**把它从本来会选的算子上推开**。

⭐ C 等于 B 的成因很具体：C 的「按类删」分支需要**合法签名**才能测「这个签名下谁能吃」，
而模型出错时写下的 `types` 常连长度都不对 ⇒ 退化成单删 ⇒ 该分支**一次都没走到**。

> 诊断的分类能力，与「诊断能派上用场」的时机，在结构上互斥。

**覆盖率**（216 格装置空间，不跑模型）：可达 91 格里 `SEMANTIC` 占 **78%**。
这七成的失败只有一种不泄漏的动作 —— **删掉这个已被否证的算子**。
说不出「该换成谁」，因为那要读判分结果 = 拿尺子挑尺子。

### 3.15 对弱点自己出题：变异器再强也没用（V190）

系统能自己发现「这一格没有证据」（`critgen.constant_on()` 报 `CONST`），本轮让它自己**造输入**去补：

```python
probe.tokens(text)          # 从一段文本取词元（引号内 / 斜杠组 / 裸 ASCII 词）
probe.structural(types)     # 按类型变异：大小写、空白、分隔符、截断、取负、嵌套
probe.literals(src)         # ⚠️ 从实现源码取字符串字面量 —— 泄漏，产物一律标 LEAK
probe.expand(...)           # 拼池 + 逐条记来源
probe.constants(rows)       # 从读数里挑出弱点格（= 发现问题）
```

⭐ 铁律：**`expand()` 的参数表里没有 `oracle`、没有 `fn`**。只要生成器能跑一遍实现，
就能「先挑出会让输出变化的输入，再宣布池退化已修复」—— 那是重言式，读数一文不值。

| 源 | `str` 池 | 17 个盲区里转可判 |
|---|---|---|
| 原池 | 4 | — |
| 结构变异 | **36** | **0** |
| 同尺寸随机噪声 | 32 | **0** |
| 记忆条目词元 | 10 | **5** |
| 题面词元 | 13 | **5**（与记忆**逐格相同**） |
| 实现字面量（泄漏） | 14 | **5**（仍与记忆**逐格相同**） |

三条否证：

1. **「变异器要更聪明」**：结构变异与随机噪声在 74 个可判格上翻的是**同一格、同一个原因（负数）**
   ⇒ 结构变异 ≡ 随机噪声。
2. **「词表源有等级」**：记忆 / 题面 / 直接抄实现，逐格、逐裁定、逐 bite **全同** ⇒ 泄漏没占到便宜。
3. **「转可判 = 改善」**：5 格里 1 格是 `PASS` 但 `bite_partial=0` ⇒ **翻开的是假绿**。
   ⇒ 主读数必须分两列：`转可判 5` / `其中有信息 4`。

17 个盲区的真实构成：**5** 词表缺口 + **10** 签名错（拿 `dict` 喂只吃 `str` 的函数）+ **2** 空容器骗可达
（`('','')` 让循环体一次不进，于是 `AttributeError` 也不发生）。⇒ **12/17 出题救不了，只能改签名。**

那 5 格能翻开，靠的是**题面里恰好写着 `True / False / None`**（正是 `parse_flag` 的输出字母表）——
一次性巧合，⛔ 不是能力。

⛔ **`probe` 目前只被证据脚本调用**，产品里没有调用点 —— 与 V189 之前的 `diagnose()` 同一种状态。
本轮证明的是「这套装置能做到什么」，⛔ 不是「系统已经会自己出题」。

## 五、证据怎么复核

每条结论都落在 `bench/evidence/<轮名>/`，最小集合：

```
PREREG_*.md     跑之前押什么、判据是什么、分母是多少
*.py            装置（能重跑，不是截图）
READINGS_*.txt  原始读数（未经整理的输出）
RESULTS_*.md    结论 + 自踩 + 边界
```

复核顺序：先读 `PREREG` 看它当时押了什么 → 跑装置拿读数 → 对比 `RESULTS`。
⛔ 三类东西**不算证据**：同一份数据的二次整理、没有预注册的事后解释、
以及「读数更干净」但不改变任何判断的改动。

## 六、边界（先读再评估）

1. **不是 AGI**，不声称「无限接近」。这是一个几千行的内核，不是通用智能。
2. **CI 只覆盖离线部分**。所有分数证据都需要本机模型，CI 不跑。
3. **L3 只完成一半**：能看、能量、判不过、改不动。

### 3.18 给量具造一条真入口：`--verify-impl`（V193）

V192 的结论是「判据三模块在部署面 0 引用」。本轮造了第一条真入口：

```bash

```

它只付**免费**信息，⛔ 不出 PASS/FAIL：

| 信号 | 含义 |
|---|---|

| `FAULT` | 探测失败 |

### 3.21 多 agent 的第一格：管道是通的，断在策略（V195）

用户定的顺序走到第三步「多 agent」。第一步照老规矩：**先量插座位，不先造**。

问题只有一个：**一个外部 agent 的输出，能走到另一个外部 agent 的输入吗？**
断在物理 / 策略 / 契约哪一层？四臂全零模型（0.43s）：

| 层 | 形态 | 证据 |
|---|---|---|
| 物理 | **通** | 两个 shell agent 真 dispatch，B 的 stdout 里出现 `A[…]`；负例 `[]` |
| 策略 | **无条件断** | `task` 的值构造点全库只有 1 处（`answer_task`），执行点只按 `produces_answer` 覆写成题面原文 |
| 契约 | **不硬** | 题面+上游仍 `PROCEED`，且上游一路进到 prompt；只有「丢了函数名」才拒答 |

历史 171 个 run：用过外部能力的只有 **17 个（9.9%）**，55 次调用里
**`ok − used_as_answer = 0`** —— 每一次成功调用都被当成答案，**一次也没被当成中间步骤**。

⭐ 结论：这套装置把「**拿到上游**」与「**交付答案**」设计成**互斥**两类
（交付型必被切断上游；非交付型拿得到上游但交不了货）。
⇒ 缺的不是管道、不是能力，是**允许中继的策略**。

⭐ 顺带改判一桩旧案：那次「中继让同一道题从 1.0000 掉到 0.0000」的病因
**不是中继**，是**中继时把函数名弄丢了**。⇒ 可救，但还没救。

### 3.23 失败诊断是「答案」不是「噪音」（V197）

V195 说 ③ 的唯一断点是策略、唯一入口是「打回」。V196 判死「自己交自己」。
剩下唯一没验的中继物是**失败诊断**。先问一句：**这个诊断本身是什么？**

答案不客气：23 格里 22 格的 `why` 含 `assert <fn>(` 调用、**共 52 条隐藏测试原文**。

```

```

对归类器它是**噪音**（前 60 字是测试源码），对做题的模型它是**答案**（输入→期望输出全在）。

所以量两件事：

| 臂 | 输入 | 均分 |
|---|---|---|
| N | 题面原文 | 0.3232 |
| M | 题面 + 只有「通过 4/6」 | 0.3435 |
| **L** | 题面 + `why` 全文 | **0.5174** |

**涨 60%**（+0.194），而答案里 `assert` 串出现 **0/46** —— 不是照抄，是**读懂测试后照做**。
⇒ 这比照抄更危险：照抄能一眼检出，这个从答案表面**完全看不出来**。

好消息是**现在一个通道都没有**：5 条可能的路径里 0 条带原文，207 次真打回里隐藏测试串命中 **0**
（正例对照 1 ⇒ 检测器不瞎）。

⚠️ 但原文**已经落盘**：`run.py:2599` 把 `why` 前 160 字写进 `episodes` 表。
它没泄，只因为 `recall()` 查的是 `facts` 表。**脏在库里、干净在路上** —— 谁把 `episodes` 接进 `recall()`，立刻泄题。

⭐ 顺带撞出一格：**函数名写对、`return None` 的空实现，23 题全部通过交付闸**（三档都过）。
默认 5 条判据全是格式判据，一条不看行为。⇒ 交付闸对功能错 **0 判别力**。

### 3.24 交付闸是「格式闸」，不是「质量闸」（V198）

V197 顺带撞出「`return None` 的空实现 23/23 过闸」，但那是副产物。这轮量**部署路径上真正在跑的那个闸**
（`_gate_finish`，默认 `verify_static=2 / verify_exec=0`，5 条判据全是格式）在**真实作答**上的判别力。

| 臂 | 读数 |
|---|---|
| 真实答案 33 条 | **33/33 全过闸**，而其中 **23 条（69.7%）没有满分**，17 条不到 0.5 |
| 满分答案故意破坏 10 条 | **10/10 拦下**，且 10/10 真的语法错 ⇒ 闸不瞎 |
| 空实现（`return None`）33 条 | **33/33 也全过闸** |
| 空实现 vs 真实答案 的均分 | **0.0343 vs 0.5283** —— **闸的判决完全一样** |

⇒ 这个闸的判断**只取决于格式**：答案行不行它不知道，答案**成不成形**它知道。
所以它不能当筛选器（会把 `return None` 和做得不错的答案一样放过去），但它能当**灾难闸**
（空答案、语法错、丢函数名一律拦住）。

两条必须一起说的口径：真实池 pass 100% **不是闸的功劳**（这 33 条本来就是格式合格的最终交付物）；
池里 `score==0` 的格是 **0** ⇒ 「能不能拦 0 分」这一问在这里问不出来。

⭐ 顺带一条：4 个套件里的同一道 `parse_flag`，**空实现和真实答案同分 0.2** —— 那格的测试集里
只有 1 条能把「做对了」与「什么都没做」分开。这不是闸的锅，是**打分器分辨率**的锅。

⭐ 四轮连起来是一条线：自己出题（V190/V191）→ 自造判据闸（V194）→ 失败诊断（V197）→ 交付闸（V198），
**免费信息全在「结构」这一维上，没有一条能判「质量」**。
「让系统自己判断自己好不好」在免费信息上已经走完，剩下只能付费跑打分器。

### 3.28 累积的生产端：产出 67 条经验，一条也进不了 prompt（V202）

—— 一条专用通道，永远读到空。

给它通电（500 条原料 × 真模型）：

| 环节 | 数 |
|---|---|
| 全库 episodes | 3059 |
| distill 可见（`limit=500`） | **500（16.4%）** |

| 语义簇 | 43（最大一簇 16 条同义变体） |

两件必须分开说的事：

部署默认确实 0，但把 V84 那个默认关着的字级第二级打开，同一批题立刻收到 **25 个 `[经验]` 块**。
代价是载荷——26 条里只有 2 条与题意相关。

⇒ **关则断，开则通而噪**。字面匹配要么 0、要么噪音，中间那一档（按意思匹配）系统里没有。
这才是累积要补的那一块，不是签名、不是渲染、不是接线。

### 3.29 换了匹配器，能取到的知识反而少了一条（V203）

上一轮把累积的生产端通了电：产出 67 条经验，进 prompt 0 条。我给的三条路里，
「换匹配方式（加向量检索）」是第一条。这轮先量它的上限，没接。

同一个池子、同一批 6 题、同一个 k=6，三种取法：

| 取法 | 命中 | 真相关的条数 |
|---|---|---|
| 部署默认（字面） | 0 | 0 |
| 字面二级（开关打开） | 26 | **2** |
| 向量（`nomic-embed-text`） | 36 格 | **1** |

向量路不但没多，还**丢了一条**：它把 `[46]`「保留原文的出现顺序」排到第一，
却把讲同一件事的 `[53]`「明确保留哪次出现的原文」挤出前六 —— 更靠前的那条是
「模型输出不可解析」，两条分数只差 **0.0010**。

三个数说清为什么：

- 这 67 条**彼此**平均相似度 0.71，而与**题目**只 0.57 —— 题目根本不在这一团里；
- 每题第一名和第六名只差 **0.032**（有一题只差 0.015），排序落在噪声带内；
- **一条话越空，越容易被选中**（相关系数 +0.674）。最泛的四句各被选进 4/6 题，
  比如「数据格式可能不一致时先统一格式」「递归调用先检查基线条件」。

这是相似度的结构性质，不是模型不行：什么具体内容都不说的句子，与任何题目都有基础重叠。
所以拿它做质量筛选，**方向是反的** —— 不是分不开，是**主动挑空话**。

36 格里真正有信息的是 **1 格**。六道题里五道（千分位、合并重叠区间、前 k、游程编码）
在 67 条里一个结构词都没有。⇒ 瓶颈已经指名：**池子里没有「题目结构型经验」，65/67 是流程泛句。**
再好的检索器也取不出不存在的东西。

### 3.30 换了蒸馏指令，噪音掉九成，知识还是一条没多（V204）

上一轮把「换检索器」判死，说问题在池子。这轮直接解剖池子的生产线 —— 那个把执行记录
变成「下次注意什么」的蒸馏器。四条臂，2×2：原料（全部 / 门控后）× 指令（原 / 新）。

| 臂 | 条目 | 真知识 | 浓度 | 讲自己流程的占比 |
|---|---|---|---|---|
| 原指令 × 全部 | 67 | **1** | 3.0% | 55.2% |
| 新指令 × 全部 | 19 | 2 | 10.5% | **5.3%** |
| 原指令 × 门控 | 31 | 2 | 6.5% | 41.9% |
| 新指令 × 门控 | 11 | 2 | **18.2%** | 9.1% |

新指令确实好用：像「遇见到交付前检查时，先确保所有函数定义完整」这种废话掉了九成，
换成「空 dict 返回空串而非 None」。浓度从 3% 涨到 18%。

**但真知识还是 2 条。** 而且原来那 2 条都在同一道题上，新的 2 条在另外两道题上 ——
**是换了一批，不是多了一批。**

原因很干净：让新指令去看六道题的题面，它只对一道出活 ——
`parse_duration`，因为那题的题面**明确写了**「空串返回 None」。
其余五题（千分位、游程编码、前 k、合并区间、去重）全部回答 NONE。
因为那些题面写的是**算法怎么做**，而「算法怎么做」等于答案，蒸馏器不许说。

⇒ 对题面这类原料，**蒸出来的就是题面本身，对下次零新增**。

再往上看一层：全库 738 条题面，逐字相异只有 63 条，**真正的不同题只有 46 道**，
其中 418 条是同一道测试占位题 `solve(x)`。每道题最多蒸出一条题级知识 ⇒ 上限就是 46。

**这不是 prompt 能解决的。同一道题重复 418 次，信息熵是 0。**

而 `merge_ranges` 在全库里只有 11 条记录：9 条题面、1 条失败、1 条预演不符。
也就是说 —— **每道题只被做过一次。库里重复的是「题面」，不是「尝试」。**

指令我改了（一行字符串，旧版留作常量和复现用），门禁全绿。
但门控没接：它会把契约 `AN8` 弄红，因为那条测试用的两条记录都短于 40 字。

### 3.31 累积不工作的四个断点（V205/V206）

上一轮换了蒸馏指令，噪音掉九成，知识还是一条没多。这一轮去问「为什么原料本身就没有料」。

先看原料的构成，一个数就够：

| 类别 | 题面条数 | 被真正尝试的次数 |
|---|---|---|
| 代码题 | **669** | **4** |
| 系统自己的运维任务（清临时文件、总结根因…） | 69 | **1510** |

代码题平均 250 条题面才有 1 次尝试；运维任务每条被尝试 22 次。
所以蒸馏器看到的 99.4% 是「系统怎么运维自己」—— 那 48% 的自指，不是模型爱说空话，
是原料里本来只有空话。

再往下挖，断成四截：

1. **失败不落盘。** 让 `merge_ranges` 跑 6 次、温度调到 1.0，确实失败两次（0.333），
   但库里一条 `failure` 都没有。因为打分器在 `Core.run` 外面判分，而内核心只在
   「自检打回」时写失败记录。
2. **加上 `--use-reward` 才有东西。** 落下来的原文很好：
   `assert merge_ranges([(1,3),(2,6),(8,10)]) == [(1,6),(8,10)] ⇒ TypeError: 'tuple' object does not support item assignment`。
3. **蒸出来了，又被当成「空」丢掉。** 蒸这条时模型的输出是「元组不可修改」——
   六个字，而「空」的判据是「少于八个字」。
4. **就算留下，也是这一道题的知识**，换一道题就没用。

四条断点串成一条链，每一环都有读数，**每一环单独修都不解决问题**。

顺带把第 3 条试着修了一下：把长度闸从 8 放到 4。收益是真的（「元组不可修改」进来了），
代价也真的（另外新增 7 条里 3 条空话，43%）。收益一条、噪音三条 —— **没改**。
长度只是「空」的代理，换刻度并不改变「用长度判空」这件事。

### 3.32 换归纳单元也救不了：**原料里没有同一个坑**（V207）

上一个断点链说「提取出来也是这一道题的知识」。自然的下一步：把蒸馏的输入单元
从「一条记录」换成「一类记录」——同一个坑在多道题上重复出现，就有东西可归纳了。

三臂对照，判据是「跨题知识」：

| 臂 | 输入单元 | 调用 | 跨题（严格判） |
|---|---|---|---|
| A | 一条 episode | 11 | 0 |
| B | 一个错误类别 | 3 | 0 |
| C | 一道题 | 6 | 0 |

先把原料造出来：29 道题 × 2 次 × 温度 1.0 × `--use-reward`，58 次真跑。
结果 **11 条失败，只来自 6 道题**（其余 23 题两次全对）。错误类别：

```
AssertionError 8   TypeError 1   SyntaxError 1   ValueError 1
```

**能成簇的那一簇（AssertionError，8 条 / 4 题）恰好不含结构信息** ——
它只有「输入是什么、期望是什么」，没有「为什么错」。
有结构信息的那三条，各只有一条，**成不了簇**。

所以跨题知识 0 条不是「换单元没用」，是**没有可归纳的东西**。

更意外的是另一件事：这些输出和题面几乎不重合（最长共同子串 2~3 字）。
它们不是「复述题面」，是**凭空建议**——「时间单位顺序要固定」「URL 解码要正确处理编码字符」。
机制很清楚：原料里只有输入和期望，而指令要求「不许写代码、不许出现变量名、必须点名具体结构」，
**三条要求在 AssertionError 上互相矛盾** —— 具体输入就在手里，却被禁止引用。
模型于是把「需要具体知识的判断」降级成「流程建议」。

这也解释了上一节那个 72% 的 NONE 率：模型常常**知道自己不知道**，所以说 NONE；
少数不 NONE 的，是编的。

（自踩：装置只实现了判定规则的前两条，机械判定报出「跨题 8/2/3」，人工按第三条判是「0/0/0」——
差 3~8 倍，而且排序反了。字段名叫 `跨题`，装的只是「没有函数名」。）
