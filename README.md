## 一、它为什么存在

一个跑了 136 轮、215K 行生产代码、329 次提交、16 天的自演化系统，对抗性审查的判决是：

| 那场的实测读数 | 含义 |
|---|---|
| `bench_gain.jsonl` 54 条记录 **gain 全部 = 0.0** | 适应度函数恒等于 0 |
| `pairs=95 evaluated=0 ... domain=0/94` | 主测量通道**从未测到过任何东西** |
| 同配置重复 3 次：`0.7241 / 0.6724 / 0.7586`，**极差 0.0862** | 尺子噪声 > 任何可能的改进 |
| 唯一的目标数字 `0.7184` **五天没动过一格** | 而每轮都在交付"全绿" |

结论不是"某个 bug 没修"，是：**系统不具备声称"我变好了"的分辨力。**

V1 由此定下第 0 条设计约束 —— 那场教训留下的**唯一**一条真正有价值的遗产：

> **先有测量基座，再有能力。**
> 在写第一行"能力"代码之前，先定义清楚"什么算变好"、
> 以及"多小的变化会被噪声淹没以至于不该被当真"。

所以 `mw/measure.py` 不是附属工具，它是 V1 的第一块砖。

## 二、内核做什么 / 不做什么

用户的要求是"核心做 MW，其它功能通过调用外部 agent、skill 和工具完成"。V1 严格执行：

| 内核**做**（这是它的全部） | 内核**不做**（一律外部） |
|---|---|
| 预算分配与对账（`budget.py`） | 写代码、改仓库 |
| 三层记忆读写与去重（`memory.py`） | 查资料、爬网页 |
| 动作预演与失配沉淀（`worldmodel.py`） | 调用别的 agent / skill / MCP |
| 规划、重规划、候选生成（`planner.py`） | 任何领域知识 |
| 四道运行时守卫（`guard.py`） | 任何具体业务逻辑 |
| 能力注册与分派（`tools.py`） | —— |
| 交付前自检（`verify.py`，判据只从题面派生） | —— |
| **测量与判定**（`measure.py`） | —— |

外部能力通过 `agents.json` 接入（范例见 `agents.example.json`）。
**文件不存在时内核照常运行**（外部能力数 = 0）—— 这是刻意的：
内核的可验证性不依赖任何外部系统、网络或密钥。

⚠️ 测量与判定**分两层**，这条分界是刻意的：
内核里的 `measure.py` 只做**统计**（重复、噪声下限、配对判定），
外部锚层的 `mw/bench.py` 才做**判定**（因为它拿得到外部真值）。
**内核不许给自己发分数** —— 这一条就是整个问题的关键所在。

#### 2.1c 两层判据（2026-10-17 第三轮）

`coherence.py`（拆了环还转吗）只能回答**承重墙在哪**，
它答不了"这个能力对 AGI 是否必要" —— 因为**拆一个不存在的模块，读数当然不变**，
于是 Δ=0 被读成"不必要"，而真相是"未实现"。

所以有第二层 `bench/capability.py`：不问"拆了会怎样"，问
**缺了这个能力会看到什么现象，现在看到了吗**。三态判定，不是两态：

| 判定 | 含义 |
|---|---|
| 成立 | 现象出现 ⇒ 这个能力必要，**且当前缺** |
| 反证 | 现象未出现 ⇒ 证明这张表不是恒真（反证组为空就说明它什么都没证明） |
| 不可判 | 读数缺失 ⇒ **不许当作"不必要"**（"没量到" ≠ "不需要"） |

实测（补上 critique 之后）：成立 2 ／ 反证 8 ／ 不可判 0。成立的是
**记忆写入截断（5000→300，6%）／ 自我模型未通电（咨询 3 次、影响 0 次）**。
（自我模型这一条已于第四轮由 §2.1d 的跨会话账本通电。）
（第三格「社会与情感」已于同日补上判据并通电 —— 详见边界第 14 条；
「语言与沟通」同日**换了判据**：从答案字数换成任务自带 `assertions`
的可复核性 —— 详见边界第 15 条。）

#### 2.1d 自我模型：跨会话、带口径签名的分数账本（2026-10-17 第四轮）

`metacog.py` 此前**空着起跑**（`Core()` 里写的是 `SelfModel()`，没有任何历史），
于是它的判据只能退到代理量 —— 而代理量（被咨询过几次）**永远绿**。
第四轮给它造证据来源 `mw/ledger.py`，并把判据换成**行为锚**：

| | 判据 | 能证明什么 |
|---|---|---|
| 旧（代理量） | `selfmodel.consulted × influenced` | 只能证明"它说过话" —— 而它总会说话 |
| 新（行为锚） | 用历史会话预测未来会话，误差必须**优于**不区分族的对照基线 | 证明"它说的话对未来有信息" |

三条硬纪律（每条都对应一个已发生过的失败）：

| 纪律 | 实现 | 违反它的后果 |
|---|---|---|
| **跨会话，不是轮内** | 起跑冻结 `ScoreLedger.snapshot()`，之后本轮不再更新 | 第 N 题拿到第 N-1 题的分数 ⇒ `repeat` 从"同条件重复"变成"顺次影响" |
| **带口径签名** | 缺 `caliber_sig` 的行一律拒，**分项计数**；不放行、不默认 | 把两种东西当一种 ⇒ 跨口径比较（口径混用的同一类） |
| **内核轮内没有写通道** | 写入只在 `run.py --bench` 拿到外部分数**之后** | 内核给自己记分 ⇒ 测量体系失效 |

⚠️ 账本签名与基线签名**不是同一把**：账本签名**故意不含** `suite_sha`。
因为 `family = suite.name`，若把题目集钉死，"同口径"就必然"同族"，
跨族预测在物理上**永远不可测** —— 判据会退化成又一条恒真断言。
题目集在基线比较里是**尺子**（不许换），在自我模型里是**被泛化的对象**（必须换）。
其余字段（scorer / temperature / limits / llm_cond / memory\_\*）**一个都不许放**。
实现见 `mw/ledger.py:LEDGER_SIG_EXCLUDE`。

---

⚠️ **反证不等于永久结论**：每条签名带一个 `note` 写明翻转条件。
例如"学习与泛化"在离线剧本下是反证，换成真模型（实测 `检验=5 命中=5`）会转成成立；

## 三、七段认知循环

```
perceive  组装状态：目标 + 工作记忆 + 检索到的语义记忆 + 上一步观测
think     ACT 判复杂度 → 快通道(1 候选) / 深通道(≤N 候选)
plan      planner.propose / replan（失败必带错误原文，绝不原地重试）
gate      guard 四道检查点：目标劫持 / 工具滥用 / 记忆投毒 / 级联熔断
foresee   worldmodel 预演 + 选择性前瞻（低置信预测不进决策链）
act       tools.dispatch（**永不抛异常**，失败变成可记账的 ToolResult）
observe   worldmodel.observe → 失配沉淀为 episodic 案例 + semantic 启发式
persist   working / episodic / semantic 三层记忆各自落位
```

## 四、2026 理论 → 代码的对应（每条都有出处）

| 理论（2026 实查，非凭记忆） | 出处 | 落在哪 |
|---|---|---|
| **能力 = 预算的函数**；固定预算评测给的是**下界不是上界** | Noam Brown 2026-06《Implications of Large-Scale Test-Time Compute》；UK AISI 2026-07；arXiv:2606.17930 | `budget.py` 全模块 + `measure.py` 强制**同预算档才能比** |
| **自适应计算量（ACT）**：难题深想，易题快答 | WAIC 2026「复杂度第一约束」 | `planner.looks_complex()` → 决定候选宽度 N 与是否付预演成本 |
| **三层记忆 + 上下文内世界模型**（不动参数、改上下文） | WorldEvolver, NUS 2026-06；RedLineSoft 2026 技术报告 | `memory.py` / `worldmodel.py` |
| **Agentic Top-10 运行时治理** | OWASP Agentic Top-10 / AGT 2026 | `guard.py`（四道在内核可控范围内的检查点） |

**关键推论**（这是 V1 与"分数自娱自乐"最大的分歧点）：
既然"能力是预算上的曲线"，那"候选 A 比候选 B 好"这句话**不完整** ——
必须说"在预算档 X 上 A 比 B 好"。`measure.paired_compare()` 在预算档不一致时
**直接拒绝判定**，而不是给出一个混着预算差异的假差值。
拿 4x 预算的新方案去比 1x 的旧基线，差值里混着预算，无从归因。

## 五、外部锚层 —— 系统与"分数自娱自乐"的分界线

那场审查的判决不是"某个 bug 没修"，是 **反馈不可信**：尺子自己写、自己读，
所以 54/54 条 gain 恒等于 0 也没人发现，而每轮都在交付"全绿"。

V1 因此立下唯一不变量：

> **尺子可以被内核读取，但不可以被内核改写。**
> 内核只拿到一个 float。它拿不到尺子，也改不了尺子。

```bash
# 校准尺子 → 跑任务集 → 过口径闸
python3 run.py --bench --compare
# 先把读数存成基线，之后的改动才有东西可比
python3 run.py --bench --save-baseline
```

四道物理保证：打分器跑在**独立子进程**里（内核无法 import 或改它）、
尺子身份 = **文件内容哈希**（不是路径）、内核的 10 个模块**没有一个** import bench、
任务集是只读 frozen 结构。

| 实测读数 | 值 |
|---|---|
| 尺子校准 | 6/6 条逐条可分辨，**6 条中段有序**（0.25 / 0.6 / 0.8333 三档），margin **+1.0000** |
| **确认改进** | 旧版（部分解）`mean=0.6194` → 新版（参考解）`mean=1.0000`，**判定"改进成立"，增益 +0.3806**；两次口径签名一致 |
| 拒绝跨口径 | 改预算档后比较被拒；基线 md5 **一个字节没变** |
| 五把假尺子 | 恒定 / 反相关 / **二值** / 单条失分辨 / 崩溃 —— **全部被判红** |
| R13 撤回态 | 撤四处实现：RC=1、**Traceback=0**、汇总行在、变红清单与预期**一一对应**、md5 三态一致 |
| 真模型噪声下限（见 5.2） | T=0 **极差 0.0000**（逐题逐次完全一致）／ T=0.8 **极差 0.1111**（6 题中 2 题抖） |
| 契约断言 | `tests/bench_test.py` **97 条，全绿** |

⚠️ 校准不是"跑个分"。它要求**逐条** `空答案 < 部分解 < 参考解` 严格成立，否则
fail-closed 拒用 —— 一把"要么 0 要么 1"的二值尺子照样会让所有"改进"纹丝不动，
那正是一把五天不动的尺子的同构体。设计细节见 `DESIGN.md` 第 9 节。

### 5.2 真模型上实测：噪声下限（2026-10-17 首次）

校准只证明"尺子有刻度"。要真用它，还必须知道**读数本身抖多少**。
本轮第一次把它接到真模型上（本地 ollama `qwen2.5:7b`，6 题 × 5 轮 = 30 次判分）：

| 采样温度 | 各次总分 | 极差 | 逐题不稳定 |
|---|---|---|---|
| **T=0（贪心）** | 5 次全为 `0.9445`，纹丝不动 | **0.0000** | 0/6 |
| **T=0.8（采样）** | mean `0.8722`，落在 `[0.8055, 0.9167]` | **0.1111** | **2/6** |

三个结论：

1. **噪声下限第一次被量出来了。** T=0.8 下的极差 **0.1111 已超过本项目登记的噪声上限**。
   此前从没测过 T=0 —— 一直在采样温度下比较候选，所以**任何小于噪声的改动
   都不可能被检测出来**。这就是"适应度函数恒等于 0、目标数字五天不动一格"
   的机制解释：不是适应度函数写错了，是**噪声把信号淹了**。
2. **噪声集中在 2 道题上，不是均匀分布。** t01 在 `0.1667 ~ 0.8333` 之间跳，
   而 t02/t03/t05/t06 五次全同。只报总分极差 `0.1111`，你看不出该盯哪里；
   看逐题明细，立刻知道该对 t01、t04 做重复测量。
   ⇒ 因此 `BenchReport.as_dict()` 把**逐题明细不截断地落盘**（契约⑤：证据可追溯）。
3. **"稳定地错"与"随机地抖"是两件事。** T=0 下 t04 稳定地拿 `0.6667`
   （6 条断言里稳定挂 2 条）—— 那是**系统误差**，改候选就能修；
   t01 的抖动是**随机误差**，改候选毫无意义。
   水平与极差两个维度各承载信息，压成一个数字就都看不见了。
   契约断言 E13/E14 把这条钉住了。

⚠️ 这个读数只覆盖**一台本地 7B 模型 + 6 道纯函数题**，不是通用结论；
换模型、换任务集都要重测。而且它已被写进**口径签名**：`Caliber` 现在含
`temperature` —— 温度变了就是换了尺子，两次读数**拒绝比较**（实测见下）。

```bash
# 真模型直连（不经内核，测最短链路）—— 噪声实验的核心旋钮是温度
V1_LLM_BASE_URL=http://127.0.0.1:11434/v1 V1_LLM_API_KEY=ollama \
V1_LLM_MODEL=qwen2.5:7b python3 run.py --bench --solver llm-direct \
    --repeat 5 --temperature 0 --max-tokens 512
```

⚠️ **思考型模型要留够 token**：实测 `Qwen3.5-4B` 在 `--max-tokens 512` 时
`reasoning` 会吃光额度、`content` 变空 —— 系统把它记为 `skipped_no_answer`
（"没量到"）而不是 0 分，并把整轮判为 `可信=❌`。**这正是契约③在起作用**：
"这题得 0 分"与"这题没量到"必须可区分。

### 5.3 内核路径（`--solver llm`）在真模型上：看起来像，但**不是**

上一条测的是 `llm-direct`（**绕过了内核**的最短链路）。内核路径在真模型上
**从未跑过** —— 第一次跑就抓到静默降级（见 `DESIGN.md` 第 12 节）：读数
`mean=0.0000` 却标着 `可信=✅`，真模型一次都没被调用。

修完并钉住"同口径必须可复现"之后，才有资格比较。同一把尺子、同一温度（真 T=0）、
同一任务集、记忆逐题隔离：

| 路径 | 预算档 | mean | 逐题 | 交付 |
|---|---|---|---|---|
| 真模型直连（不经内核） | 1x | `0.9445` | — | 6/6 |
| **内核路径**（七段循环） | **1x** | **`0.8333`** | `0.667/1.0/1.0/0.333/1.0/1.0` | 6/6 `done` |
| **内核路径** | **4x** | **`0.8333`** | **逐题完全相同** | 6/6 `done` |

三个结论，一个比一个重要：

1. **内核不是免费的。** 0.9445 → 0.8333：七段循环（规划 + 闸 + 预演 + 观测 + 沉淀）
   在这组窄任务上**净损失约 0.11**。这是第一次把"内核开销"量出来 ——
   而不是靠"内核设计得好"这类话。
2. **同口径可复现了。** 修口径之前，同一题"同口径"两轮给 `0.5000` / `0.6667`；
   修之后三轮**逐位相同**。**不可复现的读数不是读数** —— 曾经的教训就是在一个
   不可复现的读数上跑了很久。
3. ⛔ **"能力 = 预算的函数"在这组任务上没有被证实 —— 函数是平的。**
   4x 的预算是 `steps=0/32`，实际只用了 **1~2 步**，逐题分数与 1x 一字不差。
   ⇒ 诚实的结论是：**V1 目前把预算当作"上限"，而不是"可以花掉的资源"**。
   计划器在第 1 步就给出 `finish`，多余预算没有任何机制去消费它。
   这不是"实现有 bug"，而是**能力上的缺失**，必须写在明面上：
   现在能给"预算不会让系统变坏"提供证据，**不能**给"预算让系统变强"提供证据。

## 七、V1 明确**没有**做到的事（边界声明）

写在这里，是为了让"没做到"变成记录在案的事实，而不是被含糊过去。

1. **没有持续学习。** 参数是冻结的。所谓"学习"全部发生在记忆层（改上下文，不改权重）
   —— 这正是 WorldEvolver 的路子，但它的天花板也很明确：**它不能产生新能力**，
   只能把已有能力用得更准。
2. **没有真正的世界模型。** `worldmodel.py` 做的是**文本层面的**动作后果预演，
   不是物理或因果模型。它降低"假设错一步后面全错"的概率，不消除它。
3. **外部打分器接上了，但它只覆盖 4 个领域、共 21 道纯函数题。** `bench.py` 让
   "变好了"这句话第一次有了外部依据，但那依据的**适用范围仍然很窄**：纯函数、
   机器可判、零依赖。真实的、开放的、没有 ground truth 的任务，V1 仍然不能判定
   自己有没有变好 —— 而那恰恰是最容易被"假装测到"的那类任务。
   ⚠️ 而这 4 个领域**全都是"写一个 Python 函数"** —— 所以 V1 现在的"通用"是
   **"在『结果可被确定性 assert 判定』这个边界之内"的通用**。边界之外的部分
   （多轮交互、有状态环境、需要人类判断、开放式任务）**一个都没测**。
   说"V1 是通用 Agent"就是越界。**别把 21 道题的成绩当成通用能力。**
   另外，校验证明的只是"好/中/坏三档有序"，**未证明**两个相近分数（0.6 与 0.65）可分；
   这一条已经写进 `Calibration.evidence.unknowns`，不是靠这里的声明兜着。
4. **内核不做任何实际能力。** 没有外部 agent 接入时，它只是把"检索记忆、写记忆、
   收尾"这条最小链路走通。这是刻意的设计选择，不是缺陷。
5. **网络与基础设施层的治理不在内核内。** OWASP Agentic Top-10 里的
   零信任网络隔离、审计基础设施等，V1 只做了内核可控的四道检查点，
   其余写在 `guard.py` 的注释里，不假装做了。
6. **预算不可"转化"为能力（2026-10-17 实测）。** 4x 预算下内核只用了 1~2 步
   （分母是 32），逐题分数与 1x **一字不差**。也就是说 V1 当前把预算当**上限**
   而不是**资源**：计划器第 1 步就 `finish`，没有任何机制把多余预算
   换成更深的思考或验证。所以"能力 = 预算的函数"这条 2026 理论，
   V1 目前**只证明了前半句（预算不会让系统变坏），没证明后半句**。
   ⚠️ **第二十一轮给了它一个"花预算去验证"的位置**（`mw/verify.py` 的
   `verify_retries`，打回一次就多一次 `llm` 调用 + 一次 replan），代价实测
   `struct 244.9s → 284.5s`（+16%）/ `heldout 400.1s → 441.3s`（+10%）。
   但**这仍然不是"预算变成能力"的证据**：同一组题上收益属于"打回重写这个动作"，
   内容无关的安慰剂拿到**逐字相同**的读数（§16.20 Q3），而且 `heldout` 上 Δ=0。
   ⇒ 本条**维持原文**：位置有了，后半句还是没证明。详见 §16.20 与边界第 26 条。
   这是能力缺口，不是 bug —— 修法是设计问题（例如"复杂任务的答案要不要
   花预算去自检"），而任何新动作都必须先证明它**能被看见**。
7. **没有概念层：抽象读数 = 0.0（2026-10-17 实测）。** `memory.fingerprint()`
   是**规范化后字面文本**的 sha256 ⇒ 两条表达同一个意思、字面不同的话会被算成
   **两条**记忆。所以 V1 现在**只有字面，没有概念** —— 这是"能力为 0"，
   不是"接近但还差一点"。读数由 `mw/measure.py:abstraction_collapse` 给出，
   并被契约 W4 钉住（那是一枚**读数锚**，不是不变量）。详见 DESIGN §15.4。
8. **记忆还不能让它在同族新题上变好：泛化读数 Δ = 0（2026-10-17 首次实测）。**
   学一个领域 → 考 held-out 同族新题，带记忆 vs 空记忆**逐题配对**：
   三题 Δ 全为 0（`h01 0→0`、`h02 1→1`、`h03 1→1`）。而且已经查明**为什么** ——
   不是"记忆没生效"，是 ①学到的 facts 是现象描述、**不可执行**；
   ②检索是**词法**的（给 `int_to_roman` 检索出的第一条是自指噪音）；
   ③**失配信号本身没有分辨力**（见下条）。⚠️ 但**不许**说"泛化 = 0"：
   这个实验**功效不足**（3 题里 2 题两侧已满分，剩下 1 题的失败模式是
   "用 C 回答 Python 题" —— 模型行为，记忆救不了）。详见 DESIGN §15.2。
   ⚠️ 修完第 9 条之后原样重跑，**还是 Δ = 0，但性质变了**：这次记忆里
   **一条 facts 都没有**（世界模型没有可学的失败）⇒ 它测的是"空记忆 vs 空记忆"，
   这个实验**已经空转**。两个 Δ=0 不能混为一谈。详见 DESIGN §15.2b。
9. ~~**世界模型的"失配"信号没有分辨力。**~~ **已修（2026-10-17）。**
   旧实现让 `predict` 预演**一句话**、`observe` 拿去和**整段答案**比 Jaccard
   ⇒ 跨种类比较 ⇒ 结构上每次必判失配（9/9 次一致度 ≤ 0.09），而且**反相关**
   （正确解 0.0714 / 错误解 0.1429）。这是同一种失效形态：一个永远不可能"好"的信号。
   修法**不是调门槛**，是把预测对象降到内核真能观测的层面：
   改成"这一步**会不会成功**"（`expect_ok`），由 `result.ok` 检验；
   文本类失配降级为"只记情景、不进语义"（不许从测量噪声里造知识）。
   实测：失配 9/9 → **0**，检验次数 0 → **5**，命中率 不可算 → **1.0**，
   噪音 facts 10 条 → **0**，而任务集 mean 未变（0.7667）。详见 DESIGN §15.3b。
   ⚠️ 代价是**能力自称变小了**：它现在只能说"这一步执行成功了吗"，
   说不了"答案对不对"——后者属于外部打分器，内核不得冒充。

10. **因果闭环在代码任务上**没有学习面**（2026-10-17 实测，比第 9 条更根本）。**
   修完第 9 条之后，读数变成 `检验=5 命中=5` —— 分母说明：这一轮内核
   **一次都没失败过**（每题都是 1 步 `finish` 成功）。而 `finish` **永不失败**，
   失败的是**答案对不对**。所以世界模型即使有了分辨力，这一轮也**没有东西可学**。
   ⇒ 要让它真学到东西，唯一合法的路是把**外部奖励当成只读输入**
   （"尺子可被内核读取、不可被内核改写"本来就允许这件事）。
   在那之前，V1 的"因果闭环"只能声称：**机制存在、信号有效、学习面是平的。**
   ⚠️ **第二十一轮把"平"撬开了一道缝**：`finish` 现在**可以失败**（被自检打回），
   而那次打回是**真失败** ⇒ 真模型实测世界模型第一次记到失配：
   `mismatches 0 → 1`（`confusion.ok_fail=1`，`struct_convert` 5 题）。
   ⛔ 但 n=1，而且安慰剂臂给出**完全一样**的 `mis=1` ⇒ 只能说"有了一个失败面"，
   **不能说"它学到了东西"**。详见 DESIGN §16.20 与边界第 26 条。

11. **情景记忆不进入推理路径（2026-10-17 接线审计，已知边界，未修）。**
   `record("outcome", …)` 写 `episodes` 表，而 `recall()` **只查 `facts` 表**
   ⇒ 情景记忆在推理路径上一次都读不到，只在收尾兜底读最后 1 条。
   真模型实测：`numeric_logic` 5 题写了 **16 条** outcome，进入提示词的 **0 条**。
   ⚠️ **没有"顺手修"**：让 `recall` 多查一张表会把"情景"与"语义"混成一层
   —— 那正是知识层失控的起点。正确做法是先定义**"情景 → 语义"的提炼规则**

25. **★ 第二十轮：修掉感知 → 记忆那个**不可逆的漏斗**（2026-10-18）。**


    工具返回 5000 字，进下一步上下文的只有前 300 字，**其余 4700 字当场消失

### 第三十七轮：那条"全部 facts"的根，拔掉了（§17-7i）

上一轮记在明面上的那一条，本轮选了 **(a) 改 `recall` 的返回口径**，理由只有一条但很硬：

删掉之后，三组读数：

### 第三十八轮：§17-7j 造一个能控制"命中几条"的 suite

7i 把兜底拔掉之后，§17-7 手上**没有可用的 suite** 了：四题的真命中是 **0/0/1/1**
—— 两题零命中、两题靠 ASCII 偶然命中。没有可控的 suite，任何"邻域效应"的读数
都无处安放。本轮只做一件事：**造出它，并证明它可控**。没跑任何臂。

**先看清机制**（这是本轮唯一的新知识）：

```python
_TOKEN = re.compile(r"[A-Za-z0-9_\u4e00-\u9fff]+")   # ← CJK 被并进同一个字符类
```

⇒ **整段连续中文被当成一个 token**，而 FTS5 找的是**完全相同的串**。所以中文的
命中条件是"整段逐字相同"，不是"包含某个词"：

| 题 | 与惯例的真交集 | 说明 |
|---|---|---|
| `g7d2` | 空 | 「对字符串列表去重」≠「去重惯例」 |
| `g7d3` | 空 | 「千分位用什么符号」≠「千分位用空格分隔」 |
| `g7e1` | `None` | ASCII 命中 |
| `g7e2` | `n` / `个字符` / `不超长时原样返回` | 后两个是**7 个字恰好一字不差** |

⇒ **7d 想测的「题面不完备」，在中文上从来没被真正测过**：前两题零命中，
后两题命中的是 ASCII，不是判别条件。

**做法**：给每条惯例加一把 **ASCII 钥匙**（`（ZK1）`…`（ZK4）`），题面提几把就命中几条。
必须是 ASCII —— 骨架安慰剂只打散汉字、**原位保留 ASCII**；钥匙若是汉字，
P 臂的钥匙会被打散，两臂检索行为就不再等价。

| 配置 | H | P | 注入字符 | R1 预检 |
|---|---|---|---|---|
| `7j` + n0 题面 | **1/1/1/1**（本条✅） | 1/1/1/1 | 43/40/63/56（H=P） | **通过** |
| `7j` + n4 题面 | **4/4/4/4**（本条✅） | 4/4/4/4 | **202 = 202** | **通过** |
| `7d` + 原题面 | 0/0/1/1 | 0/0/1/1 | — | **失败**（反向对照） |

**一条必须写死的硬约束**：`_state()` 里是 `f.text[:120]` ⇒ 单条封顶 120 字。
所以"1 条 vs 4 条"**必然同时改总长**（≤120 vs ≤480）——**条数与长度在这套装置里
不可分离**。下一轮只能声称"一组惯例 vs 一条惯例"的组合效应，**不许**声称"条数效应"。

**验收**：契约 515 → 520（AZ26–AZ30），撤回态 90 → **95 条全部精确转红**。
其中 AZ30 钉的是"预检**有分辨力**"：同一条代码路径上 `7j` 通过、`7d` 仍失败 ——
只证明"7j 通过"等于只说"现在是绿的"。

（它已经能证明的是另一件事：**它有 537 条契约 + 97 条外部锚层断言，
且每条都经得起逐个撤回** —— 即"可被完整验证"，不是"已经变强"。）
