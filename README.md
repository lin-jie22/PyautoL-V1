## 产品摘要（30 秒读完）

**是什么**：一个能被**完整验证**的 agent 内核。七段认知循环可跑、预算可对账、
记忆去重由数据库保证，而且「它变好了没有」这句话有**外部依据**（外部打分器 +
口径闸 + 撤回态）。零第三方运行依赖（`dependencies = []`，由 AST 审计与契约钉死）。

**不是什么**：**不是 AGI**，也不声称「无限接近 AGI」。见文末「边界」。

**30 秒验证**（零模型、零网络、零密钥，全部本机实测）：

```bash
./quickstart.sh                      # 契约 + 锚层 + 端到端自检，四步
bash demo/run_demo.sh                # 三臂参照点：1.0000 / 0.0000 / 0.6194（逐位可复现）
./run_tests.sh                       # 七步全量门（含依赖审计：白名单外一个 import 都不许有）
python3 run.py --goals               # L5 入口：它从**自己的账本**里决定该做什么
python3 -m mw.loop --rounds 3 --noise-floor 0 --out /tmp/curve.jsonl   # 常驻循环 + 能力曲线
```

**别人 clone 之后能不能自证** —— 这是「交付物」与「我机器上绿了」的分界线：

| 要件 | 状态 | 说明 |
|---|---|---|
| `LICENSE` | ✅ MIT | 与 `pyproject.toml` 的 `license` 同一份 |
| `.github/workflows/ci.yml` | ✅ **当前全绿** | py3.11 / 3.12 / 3.13 三档、无失败步。⚠️ **V144~V168 曾连续 32 次红**（只有 py3.11 档）：`AZ130a` 拿「3.12+ 的 `sum()` 补偿求和」当差异见证，3.11 上该子句恒假，且它的撤回态在同版本恒不红 —— 双向失效。修复与两版本验证见 `bench/evidence/ci_s257/`、DESIGN §237。⛔ 绿勾不算读数，当前状态以 run 号为准 |
| 发布 tag | ✅ `v1.0.0` | 打在 CI 首次全绿的提交，与 `pyproject.toml` 的 `version` 对应 |
| CI 覆盖到哪 | ⚠️ **只到离线部分** | 七步全离线、零密钥；**bench 不跑**（需要本机 Ollama + `qwen2.5:7b`）。分数证据以 `bench/evidence/*/` 入库，带 PREREG、读数与自踩 |

**与 Inspect AI（评测 harness）的差异** —— 不比能力规模，比的是**测量有效性**：

| 维度 | Inspect AI（公开定位） | V1 |
|---|---|---|
| 角色 | 跑评测、算分数 | agent 内核 + **测量有效性层** |
| 判据来源 | 用户提供 scorer | 判据只从题面派生（`mw/verify.py`）+ 外部真值锚层 |
| 「绿灯可信吗」 | 不内置回答 | **255 条撤回态**：每条断言都被证明「撤掉实现就红」，不是恒真；8 条待修（3 条锚点腐烂、5 条断言耦合，登记在 DESIGN §89.12，不当作全绿） |
| 噪声处理 | 不内置 | 噪声下限 + 安慰剂臂（等长、非空、非原文）+ T=0 跨请求不确定性实测 |
| 三臂对照 | 无内置 | oracle / null / partial 参照点 + 等长中性扰动（AO 系契约） |
| 依赖 | pip 生态 | 零第三方运行依赖 |

**边界**：V1 **不是 AGI**，不声称任何「无限接近」。它声称的只有「可被完整验证」这一件事，
且每个绿灯都能被撤回证明不是恒真。

## 一、能力阶梯（实测位次，不是路线图）

| 级 | 能力 | 位次 | 硬读数 |
|---|---|---|---|
| **L0** 执行 | 写代码、跑、读输出 | ✅ 完成 | `coding_small` **0.9722** |
| **L1** 判决 | 判产物对不对，且判据不是恒真 | ✅ 完成 | 契约 **682/0**、撤回态 **255**、噪声地板 0 |
| **L2** 测量 | 知道自己「变没变好」，带外部依据 | ✅ 完成 | 三臂 + 安慰剂 + 跨套件 `suite_sha` 闸 |
| **L3** 自省 | 发现自己错在哪，并改 | ⚠️ 半 | 定位 **28/28**、召回 0.578、真盲区 9.0%；判停 **29~30/33**；改不动（**92.5%** 判了没改进） |
| **L4** 自改 | 自己写出有用的知识，跨跑累积 | ✅ 两半都成立 | 区域 **21/25（84%）**；写→读→用 −**57.4%** 判分；`B=120` 时 COLD 17/25 → WARM 20/25 |
| **L5** 自主目标 | 自己决定要做什么 | ⚠️ **最小形态成立** | 会排产（`SELF` 14/25 vs 人类序 9、随机 6.45）；**V170 起能从自己的账本产生目标、自判、记账、换下一个**（判据 4/5，见第三节）；**V171 起能把自己做不到的写进账本并停止重复**（判据 6/6） |

**L4 的「成立」必须带三条限定**（少一条就是吹）：
1. 区域是 **84%**，不是 100% —— 缺口 4 个全在 `g7d3`，共同点是多站点重构 / 重写表达式。
2. 累积只在**资源紧张**时有牙：`B ≥ 400` 时 COLD 自己也能做完，边际收益归零。
3. 知识的形式是**人定的**：`(落点类, 链)` 这个抽象、删除算子、判据本身，全是人写的。

**L5 的边界**：`RAISE` 类目标（把分数提上去）系统**提得出、做不到** ——
那需要改能力，而「该改成什么」正是 V79 那堵墙（系统自造判据判别力 **0/8**）。
系统今天能自主闭环的，只有**测量类**目标。

V171 之后这条边界多了一半：它**知道自己做不到**。
`RAISE` 的判据是测量的不动点（再测只让均值更稳），所以连判 3 次均分不变 ⇒ 转 `ESCALATE`、
不再重复提、但**留在输出里**（⛔ 不静默丢弃）。
⛔ 这**不是**「做到了」：不改任何分数，只是停止假装自己还有事可做。

## 二、怎么跑

```bash
git clone <repo> && cd PyautoL-V1
./run_tests.sh          # 不需要装任何东西；本机 Python ≥3.11
```

| 入口 | 用途 | 需要模型 |
|---|---|---|
| `./quickstart.sh` | 四步上手：契约 → 锚层 → 自检 → 读数 | 否 |
| `bash demo/run_demo.sh` | 三臂参照点，验证尺子有分辨力 | 否 |
| `python3 run.py --selftest` | 离线端到端（七段循环全跑一遍） | 否 |
| `python3 run.py --goals` | **自主目标**：从账本提议该做什么 | 否 |
| `python3 run.py --goals --goals-act 1 --offline` | 真执行一条目标并判定 | 否 |
| `python3 run.py --bench --suite bench/tasks/coding_small.jsonl` | 外部锚层模式：校准 → 跑 → 过口径闸 | **是** |
| `python3 -m mw.loop --rounds N --noise-floor X` | 常驻循环 + 能力曲线 | 是 |

真模型只需三个环境变量：`V1_LLM_API_KEY`、`V1_LLM_MODEL`、`V1_LLM_BASE_URL`
（本机 Ollama 见 `agents.example.json`）。⚠️ 少一个 key 会**静默退化**成 oracle 桩 ——
跑完先看血缘行，别信分数。

## 三、L5 的「自主目标」（V170 提出，V171 补上「做不到」）

### 3.1 它做什么

```
python3 run.py --goals
```

读两样东西：**自己的分数账本**（`state/score_ledger.jsonl`，一条题一次观测）
与**环境里有哪些题**（`bench/tasks/*.jsonl` 的 `id` 字段）。
⛔ 不读题面、不读 `--goal`、不调模型。

| 类 | 触发（全部来自账本） | 判据 | 能否自己闭环 |
|---|---|---|---|
| `COVER` | 题在套件里，账本里 **0** 行 | `n_obs ≥ 1` | ✅ |
| `PROBE` | `0 < n_obs < 3` | `n_obs ≥ 3` | ✅ |
| `RAISE` | `mean_score < 1.0` | `mean_score ≥ 1.0` | ⛔ 不能（要改能力） |

排序用**词典序**（COVER > PROBE > RAISE，同类按缺口升序）。
⛔ 不做「收益/成本」加权 —— 那是一个需要被单独验证的预测模型，
拿它决定先做哪件事、再拿结果当它的证据，是循环论证。

判定后写 `state/goal_ledger.jsonl`：**MET 的下次不再提，NOT_MET 的必须重新提**。
目标观测写 `state/goal_obs.jsonl`，⛔ 不写分数账本（后者带口径闸，混进去等于伪造履历）。

### 3.2 实测（`bench/evidence/l5_s258/`，预注册 `PREREG_v170.md`）

| 判据 | 结果 | 读数 |
|---|---|---|
| P1 无证据不许编 | ✅ | 空账本 + 空套件 ⇒ 0 条；有题没测 ⇒ 只出 COVER |
| P2 可追溯、不是人给的 | ✅ | 溯源 40/40 自洽；**把 40 条题面全换成占位符 ⇒ 目标逐条不变** |
| P3 自己判得了 | ✅ | 40 条判定无 UNKNOWN；三类各有一个能翻转的见证 |
| P4 目标随读数变（top-1） | ❌ | 4 个扰动里 top-1 改变 **0/4**（1 个扰动哑火，见下） |
| P5 判完就换下一个 | ✅ | COVER→MET 后同 `gid` 不再出现，同格换类为 PROBE |

**P4 为什么 FAIL（如实登记，不解释掉）**：今天的账本里 40 格有 **34 格零覆盖**，
而「零覆盖」意味着**没有任何读数**。34 条目标在判据上完全并列，
所以「先做哪一条」只能靠题 id 的字典序 —— **那是一段人写的常量**。
唯一能让这条判据变绿的办法是给它加一个与数据无关的种子，那是把判据刷绿，不是把系统做对。
（逐目标的读数依赖是 **40/40**：改掉某条目标引用的读数，那条目标必然消失或换类。）

**补充读数**（不参与五条判据）：

- **目标链**（单题套件，连续执行 4 次）：`COVER→MET` → `PROBE→NOT_MET` →
  `PROBE→MET` → `RAISE→NOT_MET`。**下一个目标由上一个结果派生**，不是重新掷骰子。
- **覆盖跑**：一次把 34 条 `COVER` 全执行掉，墙钟 **8.5 s**（离线桩），
  目标集从 `COVER 34 / PROBE 6` 变成 `PROBE 40` ——
  **34 件没人要求的事，它自己列出来并做完了**。
  ⚠️ 离线桩的分数是**装置读数**，不是能力读数；覆盖跑证明的是「找活干」这条链通，不是「会做题」。

### 3.3 V171：把自己做不到写进账本

`RAISE` 是唯一一类「提得出、闭不了」的目标，原因不是题难，是**判据的形状**：

| 类型 | 判据 | 测量会不会改变它 |
|---|---|---|
| `COVER` / `PROBE` | `n_obs >= 1 / 3` | **会** —— 测一次就满足 |
| `RAISE` | `mean_score >= 1.0` | **不会** —— 同分布再测只让均值更稳 |

⇒ 同一个 `gid` 每轮都会被重新提出。实测（`t06_rle` 8 轮）：**提了 6 次，每次同一条 gid，均分逐位 0.0**。

**做法**：同一 `gid` **连判 3 次** `NOT_MET`、且这 3 次的均分**逐位相同** ⇒ 转 `ESCALATE`：
不再提 `RAISE`，但**在输出里单列一节「已转运维」**（⛔ 不静默丢弃）。
阈值复用 `MIN_OBS`，不新增可调参数。

| 判据 | 结果 | 读数 |
|---|---|---|
| Q1 触发 | ✅ | 连判 3 次 + 均分逐位相同 ⇒ 触发（分母 1 格） |
| Q2 触发后不再提 | ✅ | 8 轮里 B 臂提 **3** 次 vs A 臂（未启用）**6** 次；分界恰在 fail#3 之后 |
| Q3 读数在动不触发 | ✅ | `0.2→0.4→0.6` 在收敛 ⇒ 不转（否则会把「快到了」判成「到不了」） |
| Q4 可撤销 | ✅ | 删掉 1 行账本 ⇒ 判定消失（纯函数，不是持久化状态位） |
| Q5 留痕不丢 | ✅ | 输出有该节、json 有该格、该格不在提议里 |
| Q6 无新阈值 | ✅ | 模块级常量仍 = `{KINDS, MIN_OBS, TARGET}` |

**全部饱和时它会说什么**：40 题各测 4 次、均分全 0.0 ⇒ **提议 0 条、转运维 40 格**。
输出是「测量路径已用尽，40 格需换能力」—— **不是「做完了」**。
⭐ 「没有目标」有两种，账本必须分得清：全做完了 / 全做不动。
分不清的后果是第二种被当成第一种报上去。

⛔ **判别力在部署侧接近 0**：确定性 solver 下「再测均分不动」对每一格都成立 ⇒ 全饱和时全转运维。
它真正有牙的是**行为**（提议数 6→3），不是「挑出哪一格」。

### 3.4 这条链**没有**解决什么

- 目标类型表（COVER/PROBE/RAISE）是人写的。系统选的是「挑哪一格」，不是「发明哪一类」。
- `RAISE` 类目标可达性为 0 —— 提得出，做不到。V171 起它会**被判成做不到并停止重复**，
  但那只是不再重复，不是解决了。
- 同类并列时按 id 排序，是人写的常量（P4 的 FAIL 就是它）。
- **V79 那堵墙一字未碰**：系统仍然不能自己造判据。

## 四、目录结构

```

tests/              契约 682 条 + 锚层 97 条，每条配撤回态
bench/              量具与实验装置（tasks / evidence / withdraw_check.py）
site/index.html     单页版（零外部请求，由 AZ49 断言）
```

## 五、证据怎么复核

每条结论都落在 `bench/evidence/<轮名>/`，最小集合：

```
PREREG_*.md     跑之前押什么、判据是什么、分母是多少
*.py            装置（能重跑，不是截图）
READINGS_*.txt  原始读数（未经整理的输出）
RESULTS_*.md    结论 + 自踩 + 边界
```

复核顺序：先读 `PREREG` 看它当时押了什么 → 跑装置拿读数 → 对比 `RESULTS`。
⛔ 三类东西**不算证据**：同一份数据的二次整理、没有预注册的事后解释、
以及「读数更干净」但不改变任何判断的改动。

## 六、边界（先读再评估）

1. **不是 AGI**，不声称「无限接近」。这是一个几千行的内核，不是通用智能。
2. **CI 只覆盖离线部分**。所有分数证据都需要本机模型，CI 不跑。
3. **L3 只完成一半**：能看、能量、判不过、改不动。
4. **L4 的 84% 只在 26 个实现 / 4 道题上量过**，且累积只在资源紧张时有牙。
5. **L5 的自主是「测量自主」**：它自己决定去测什么、判自己测成没有；
   它不是自己决定「要变成什么」。
6. **撤回态里有 8 条待修**（3 条锚点腐烂、5 条断言耦合），已登记在 DESIGN §89.12，
   不藏在「全绿」里。
