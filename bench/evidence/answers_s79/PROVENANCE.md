## 三、两个 bug 的原文与位置

```
sg01  516 字符   `re.sub(...)` 用了但**没有 import re**
      出错点在第 **298** 字符   ⇒ 200 字符截断之后
      实际执行：NameError: name 're' is not defined

sg05  444 字符   `OrderedDict(...).values()` 之后调 `.sort()`
      出错点在第 **318** 字符   ⇒ 200 字符截断之后
      实际执行：AttributeError: 'odict_values' object has no attribute 'sort'
```

**两个 bug 都落在 200 字符之后** —— 也就是说，旧通道切在**出错行之前**。
这不是巧合能解释的：这两题的错误都在函数体后半段（用到某个东西时才发现没导入 /
类型不对），而 200 字符大约只够看到函数签名与前两个预处理步骤
（`sg05` 的前 200 字符停在 `processed = [` 中间）。

⇒ 「加长 `why`」并不能解决这件事（`why` 里根本没有答案原文，只有断言窗口）。
必须有一条**独立**的答案通道，本目录就是它的第一份证据。

## 四、内核自检对这两份答案说了什么

对 `sg01` / `sg05` 的**原文**跑 `mw/verify.py::derive(题面) + run(答案)`：

```
sg01： 4 条判据（非空 / 函数名 / 围栏标签 / 能 compile）全部通过 ⇒ ok = True「通过」
sg05： 同上                                         ⇒ ok = True「通过」
```

而 `exec` 一跑就炸。⇒ §41.3 的「自检看不见运行时错误」现在有**原文证据**，
不再是合成样本。
