# §71 预注册：`tasks_v4` 的第一个真实读数（T1）

> 写于跑真模型**之前**。落盘理由与 §66/§70 相同：事后补判据等于自带选择偏差。

## 一、本轮只问一个问题

`tasks_v4` 在**当前内核**上的分数是多少 —— 这是新尺子的**第一个读数**，不是「改进」。
⛔ 本轮**不做**任何 A/B、**不改**内核、**不比较**任何旧分数（`suite_sha` 不同）。

## 二、两个分母（§66 自踩的修法，必填）

| 分母 | 值 | 说明 |
|---|---|---|
| 机会数（attempts） | `8 题 × 3 rep = 24` | 每一次「一题一 rep」是一次机会 |
| 格数（grids） | `128 格 × 3 rep = 384` | 每一格是一条独立断言 |
| 咬合数 | 见下表的「可归因失败次数」 | 每个失败必须落到 5 类之一 |

## 三、判负条件（满足任一条 ⇒ 读数作废，不许写进结论）

| # | 判负 | 为什么 |
|---|---|---|
| N1 | `attempted != recorded` 或 `failed_scorer > 0` | 口径没接通（§70.8 T1 的判负条件） |
| N2 | `oracle` 在**同一 env** 下不是 1.0000 | 尺子自身不可解；离线已验过一次，跑真模型时要再验一次 |
| N3 | 24 次全 0 且**未**做三因归因 | 「全 0 是最易被误读的假读数」（§70.4 ① 自踩） |
| N4 | 任何题出现 `skipped_no_answer` 却不记账 | 「没交」≠「交错」，必须单列（§67.2） |

## 四、⛔ 全 0 时的三因归因（跑之前就定好，不许事后补）

若 24 次全 0，必须先把下面三种**可区分**的原因量出来，才能说「模型不会写文件」：

| 因 | 量法 | 判据 |
|---|---|---|
| a 交付层 | 答案里有没有 `def write_<name>` | 若**有** ⇒ 不是没交代码，是**交的代码不写文件** |
| b 内容层 | 答案里有没有 `open(`, `write_bytes`, `makedirs`, `os.replace` | 若**有**写调用却仍 0 分 ⇒ 语义错（不是形态错） |
| c 接线层 | `failed_scorer`、`skipped_no_answer`、逐题分是否**全 0 且 oracle 也 0** | 若 oracle 也 0 ⇒ 装置错，读数作废 |

⭐ 「a 有 / b 无」是**最可能的真因**：模型会把 `write_lines` 写成「返回拼接好的字符串」——
那正是 `pure` 变体的形态（v1~v3 的满分答案），也正是这把尺子存在的理由。
⇒ 若真是这个，本轮就**定量地**证明了 §70 的判据：**同一份实现换了尺子就从满分变 0 分。**
