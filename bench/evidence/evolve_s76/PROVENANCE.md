# 进化闭环的**第一圈**（s76）—— 它判了 `NO_EVIDENCE`，这是对的

**日期**：2026-10-24 20:20–21:09（GMT+8）
**模型**：本地 ollama `qwen2.5:7b`（零成本、无网络）
**题集**：`bench/specgen/tasks_v1.jsonl`，**14 条用例**（第七十四轮加密后的新尺子）
**打分器**：`bench/scorers/code_exec.py`
**温度**：T=0 · `--fresh`（每题新建内核）· `--no-external` · `--repeat 1`（每次一个独立进程）

本目录存在的原因：第七十五轮体检的结论是「**不能进化**」——三块拼图（变异器 /
裁决器 / 台账）都在，但**没有一条线把它们连起来**，而且一次都没真跑过。
这一轮写了 `bench/mutate_driver.py` 把线接上，并**真跑了一圈**。

## 一、这一圈跑了什么

```
变异意图 → apply_mutation（内核的界 + 记账）→ 注入环境变量 → 启动 run.py
        → 从台账读回**实际生效的** caliber.limits → 断言「生效」与「单变量」
        → 每臂 5 次独立运行 → 按 (臂, 口径, solver, limits) 分池
        → 噪声下限 → mutation_verdict → 保留 / 回退
```

| 臂 | 改了什么 | 口径 sig | 5 次读数 | 轮间极差（噪声） |
|---|---|---|---|---|
| `base` | 无（默认） | `73ff79361402ac6b` | 0.5238, 0.5595×4 | **0.0357** |
| `cand` | `max_stall` 2 → 3 | `a5ff8c337d1c89c3` | 0.5595×5 | 0.0000 |
| `placebo` | `working_memory_items` 24 → 32 | `1b6aa50fdc975607` | 0.5595×5 | 0.0000 |

**裁决**：

```
Δ(cand)     = +0.0071
Δ(安慰剂)   = +0.0071      ← 逐位相同
净变化      = +0.0000
噪声下限    = 0.0357
⇒ NO_EVIDENCE  「没证据说更好（那就别改）」
```

**保留？否。** 这一圈**没有**改变内核的任何默认值 —— 这是设计意图，不是失败。

## 二、三个必须记住的读数

### ① 安慰剂把「收益」全部吃掉了

如果只跑 base 与 cand，+0.0071 会被读成「改进」。
加上安慰剂臂（改一个**用不到**的旋钮），同一个 +0.0071 也出现了
⇒ 它不属于 `max_stall`，它属于这一跑的运气。

这就是 `mutation_verdict` 存在的理由，也是 AO11「裁决权不许在内核里」的实然后果：
内核不知道安慰剂的存在，所以它没法"配合"安慰剂。

### ② `base` 的 0.0357 全部来自**整个实验的第一次运行**

`base` 五条：`0.5238`（冒烟，第 1 次，写盘 20:23:51）然后 `0.5595 × 4`
（20:36:07 / 20:39:29 / 20:42:17 / 20:45:39）。`cand` / `placebo` 各五条全同
—— 它们的"第一次"已经不是冷启动了（20:26:44 / 20:29:48）。

逐题看，这 3 格差**全部落在 `sg02`**（7/14 ↔ 10/14），其余 5 题逐位相同。
3/84 = 0.0357 就是这么来的。

⛔ **原因没有定。** 「冷启动」/「T=0 下的残余抖动」/「旧尺子测不到」
三条被这份数据同时容得下。

**这条原先写的是「第七十三轮那个 0.0000 是尺子太粗把差异掩盖了」—— 已撤回。**
撤回理由是实测的：第七十四轮只是把 `sg02` 的断言从 7 条加到 14 条，
且旧 7 条恰好是新 14 条的**前 7 条**（`new[:7] == old` 实测成立）
⇒ 只要知道那 3 格多出来的失败落在第几位，就能判「旧尺子本可看见 / 根本看不见」。
但 `report.per_task[].why` **硬截断在 200 字符**
（实测两条都正好 200、竖线只 2 个）：「通过 7/14」却说不出 7 条是哪 7 条；
`51973` 那次没有 run.py 日志（见第四节），`bench_out/runs.jsonl` 里也只存
`report`（无答案本体，已查）⇒ **失败位置不可恢复，判定做不出来**。

能说的只有：**14 条尺子照出了 1 次 3 格差**。
⛔ 不能外推成「噪声就是 0.0357」，也不能说「旧尺子一定看不见」。

### ③ 结论不靠噪声口径撑着

把噪声下限强行写成 `0.0` 再判一次，结论**仍是 `NO_EVIDENCE`** ——
因为净变化恰好是 `0.0000`，`0 > 0 + tol` 为假。
（这条已写进契约 AZ85。）

## 三、自踩三处（都是本轮自己的 bug，都被守门员当场抓住）

**① 守门员把期望值当参数传。** `check_record(rec, arm, base, knob)` 的 `knob`
在主流程里恒传处理臂的 `max_stall`，于是安慰剂臂（改的是 `working_memory_items`）
被自己的守门员判红。而 `base` 臂因为期望为空，这个参数**恒不被读** ——
正是这个"恒不被读的参数"让 bug 藏到安慰剂才露头。
修法：期望只能从 `arm.expect` 推，不许当参数传。

**② 池子漏了 solver 过滤。** `Caliber` 里**没有** solver 字段，所以
裸模型直连与内核可以是同一个 `sig`。第一版只按 `(口径, limits)` 挑，
实测在台账 `sig=39e815e18165b03b` 上会挑到 **10 条、两套 solver** ——
那正是第七十三轮那个 0.3095 假噪声的实形。修法：四重过滤
`(口径, solver, limits, run_id)`，并写进契约 AZ84（带反证）。

**③ 安慰剂的"惰性"判据第一版是错的。** 原来要求「逐题分与 base 逐个相同」，
那等于要求噪声为 0 —— 而这一轮实测噪声就不是 0，于是它会**必然误报**。
改成与 `mutation_verdict` 同口径的判据：`|Δ(安慰剂)| ≤ 噪声` ⇒ 惰性前提成立。

## 四、边界（不许读成别的）

- 它只说「**这一次、这套题、这个模型**下，`max_stall 2→3` 没有证据更好」。
  ⛔ 不许读成「这个旋钮永远没用」，更不许读成「内核不会进化」。
- 14 条用例改了 `suite_sha` ⇒ **口径是新的**。第七十二/七十三轮的
  0.2857 / 0.5952 是 7 条尺子下的读数，**不能与这里的 0.5524 并列比较**。
- 三臂的 `sig` 互不相同（`limits` 进 `Caliber`）⇒ 这里用的"可比"是
  `mutation_verdict` 的**弱闸**（两臂 Limits 只差声明的那一个旋钮），
  不是"同一个 sig"。这道弱闸**第一次**在真实数据上被使用。
- `n=1` 的冒烟那次是**旧版驱动器**跑出来的（`check_record` 有上面那个 bug），
  但 `base` / `cand` / `placebo` 三臂的配置与新版**逐字相同**，记录合格，已计入池子。
  它**没有 run.py 日志** —— 三份冒烟运行（`51973` / `52426` / `52847`）
  都在 `smoke.log` 里只留下一行汇总（`placebo` 那行还断在崩溃前），
  读数只能从池子里的 `report.per_task` 读。

| 撤回点 | 改了什么 | 结果 |
|---|---|---|
| ㊳ | 守门员的期望退回「猜」：`sorted(arm.expect) or ["max_stall"]` | 只有 **AZ83** 红 |

**㊵ 第一次没红。** 因为 AZ85 的判据第一版写的是 `noise(base) > 0`，
而抹平之后残差还有 **1.67e-05**（另四条是 `0.559516666…`，不是 `0.5595`

**这是本轮唯一一处「撤回态自己发现的问题」** —— 没有它，AZ85 会一直以
「看起来很严（`> 0`）」的样子摆在那里，而它其实什么都没在测。

## 七、这一步**没有**证明什么

- `NO_EVIDENCE` 不是「这个旋钮没用」，是「这一次没有证据说它更好」。
- 它**不**证明「内核会自己变强」—— 那需要一次 `KEEP`，而 `KEEP` 要求
  「净增益 > 噪声」，这一轮净增益恰好是 `0.0000`。
- 它**不**改变内核的任何默认值：`max_stall` 仍然是 2。
  这一圈的全部产出是「一个能被复核的否定结论」。

## 八、这份证据是**旧裁决器**产出的（第七十七轮补注）

`verdict.json` 与 `driver_full.log` 都由第七十六轮的驱动器生成，那时裁决器
只有「净增益 > 噪声」一道闸。之后补了**交叠闸**与**量级闸**（DESIGN §39）。

用新闸重判这三份池子（纯函数，`bench.mutate_driver.judge`，零模型调用）：

```
means  base 0.5524  cand 0.5595  安慰剂 0.5595
runs   base [0.5238, 0.5595×4]  cand [0.5595×5]
对照(base ∪ 安慰剂) 最好 = 0.5595 ；cand 最差 = 0.5595
⇒ NO_EVIDENCE  「交叠：cand 最差 0.5595 没有严格好过对照组最好 0.5595」
```

**结论没变，理由变了** —— 从「净变化恰好 0.0000」升级成「两个分布分不开」。
后者**不依赖噪声下限是多少**：即使把第一次运行丢掉（噪声 → 0），
`cand` 的最小值仍然没有超过对照的最大值。

⛔ 本目录的池子与日志**没有重跑**，也没有改写 —— 它们是历史读数。
上面这一段是**重判**，不是重跑；两者不许混着说。

## 九、容差改过之后（第七十八轮再判一次）

第七十八轮把裁决器的容差 `_TOL` 从 `1e-9` 改成 `1e-3`（依据见 DESIGN §40：
台账里的 `mean` 由**四舍五入到 4 位小数**的逐题分数再平均而来，量化到 `1e-4` 级，
`1e-9` 比它小四个数量级 ⇒ 边界由舍入决定）。

用新容差再判这三份池子（仍是纯函数、零模型调用）：

```
NO_EVIDENCE  「交叠：cand 最差 0.5595 没有严格好过对照组最好 0.5595
              （cand 0.5595~0.5595 ｜ 对照 0.5238~0.5595）」
```

**结论第三次没变，理由还是「交叠」** —— 三次（旧单闸 / 两道闸 / 新容差）
都落在结构性理由上：`cand` 的最小值没有超过对照的最大值。

⛔ 同样：**这是重判，不是重跑**。池子、日志、`verdict.json` 一个字节都没改。

## 十二、文件指纹

```bash
cd bench/evidence/evolve_s76 && shasum -a 256 -c FILES.sha256
```

`FILES.sha256` 覆盖本目录除自身以外的全部 **23** 个文件（含本文件）。
它是在**所有内容定稿之后**生成的 —— 任何后续改动都会让核验失败，这是刻意的：
证据目录只增不改，要改就新开一个目录。
