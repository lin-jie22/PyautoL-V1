## 一、要回答的问题

§58 的结账是：91 轮所有读数都是**我出题、我判分**，而 `tasks_v1/v2` 的题面与 oracle
**同源**（都由 `gen_spec_tasks.py` 里同一份 `spec` 渲染）。所以那个分数回答的其实是
「模型写的代码符不符合我脑子里的 spec」，不是一个可外推的能力读数。

这一轮换掉其中的**两个外部层**：

| 层 | v1 / v2 | v3（本轮） |
|---|---|---|
| 输入 | 我手挑 | **固定种子随机器**（我不挑） |
| 期望值 | `specgen` 渲染 | **CPython 自己的实现现算** |
| 规格文字 | `spec` 渲染 | 我写（❌ 这一层仍自证，下一轮再解） |

⛔ 因此本轮**不能**声称「换成了完全外部的尺子」。能声称的是：
**我一行期望值都没写，一个输入都没挑。**

## 二、设计：只换尺子，别的逐位不动

| 项 | 值 | 与 §56 臂 A 是否相同 |

交什么」。⛔ 与 v2 的 `0.7024` **不许并列**（`suite_sha` 不同、格数不同、题族不同）。

## 三、六条预测（跑前写死，含方向）

| # | 预测 | 依据 | 证伪条件 |
|---|---|---|---|
| **P1** | 非空交付 ≥ **27/30**（90%） | §56 臂 A 是 30/30 非空 | 任意 4 题次交空 |
| **P2** | 均分落在 **0.25 ~ 0.55** | 这些题要精确复现 stdlib 语义（列号、base32 补位、URL 编码细节），比 v2 的「按编号规则处理列表」难 | 落在区间外 |
| **P3** | 假绿-崩池 ≥ **10%** 的失分 | v2 是 21.3%；这类题更容易写出「能编译、一跑就炸」（下标/类型/属性错） | <10% |
| **P4** | 逻辑错池 ≥ **50%** 的失分 | v2 是 62.9%；预测分池**结构**跨题族复现 | <50% |
| **P5** | 离线复算与落盘**逐格相同**（0 处不一致） | §58 的审计器在 v2 上是 60/60 一致 | 有 1 处不一致 |
| **P6** | 区分度：**≥3 题** <0.5 且 **≥2 题** ≥0.75 | 太全崩 = 尺子超纲；太全对 = 尺子太浅 | 两侧任一不成立 |

⭐ **P3 与 P4 是本轮真正想量的东西**：如果 v2 上那个「62.9% 是逻辑错」的结构
在新题族上复现，那它就是**关于这台机器**的读数，而不是关于 v2 那 10 道题的。
如果不复现，§58.2 的分池表就只是「关于那批样本」的，不许外推。
