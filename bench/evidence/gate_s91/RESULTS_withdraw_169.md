## 为什么多红 —— 重复覆盖，不是结构耦合

`AZ92`（第九十一轮§57）的夹具走 `c._reset_verify(goal)`，判据来自
`vfy.derive(goal, int(self.s.limits.verify_static)) if verify_retries > 0 else ()` 这条接线。
而 `AS11` 撤的正是 `else ()` 那半句、`AZ90` 撤的正是 `int(...verify_static)` 这个参数
⇒ 两条变异都会让 `AZ92` 拿到的判据变空/没有静态检查 ⇒ **连带打红**。

「判据从哪来」是 `AS11`/`AZ90` 的被测物，**不是** `_close_out` 的被测物。
按纪律「断言之间不许共享读数」，这是断言侧的毛病。

## 修法与复验

`tests/contract_test.py` 的 `_az92_close()` 改成**显式给判据**：

```python
c._checks = (tuple(_AZ89_V.derive(_AZ92_GOAL, 2)) if retries > 0 else ())
c.verify_stats["checks"] = [x.name for x in c._checks]
```

（`AZ92` 的三个方向 ①置标 ②清标 ③关掉零跑 语义不变，交付物逐字不变那条不变。）

复验 `bench/withdraw_check.py AS11 AZ90 AZ92`（`withdraw_fix_az92.log`）：

| 变异 | 结果 |
|---|---|
| 基线 | `('586','0')` 红=无 ✅ |
| `AS11` | 红=`['AS11']` 多红=无 ✅ |
| `AZ90` | 红=`['AZ90']` 多红=无 ✅ |
| `AZ92` ×3 | 红=`['AZ92']` 多红=无 ✅（三条各一次） |
| 还原后基线 | `('586','0')` 红=无 ✅ |
| 驱动器裁决 | **R13 通过** |
