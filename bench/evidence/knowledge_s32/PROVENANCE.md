## 4. 机制：H 臂交付的到底是什么代码

从跑后库里取 `kind=finish` 的原文：

- `dedupe_keep` → `if not (x in seen or seen_add(x))`（**精确匹配**去重）
  ⇒ 与记忆里的"strip + 小写 + 保留首次原文"无关。
- `fmt_amount` → `"{:,.2f}"`（**逗号**千分位、负数带负号）
  ⇒ 与记忆里的"空格千分位 + 圆括号负数"无关。

⇒ **同一条内容、同一条拼装路径、已证进入 state，模型仍然用默认写法。**

把**同一条惯例写进题面**、空库、单次（`d1_suite.jsonl` / `d1_runs.jsonl` / `d1_out.log`）：

| 题 | E（记忆位） | D1′（指令位） |
|---|---|---|
| `g7e2_truncate_tail` | 0.20 | **1.00** |
| `g7e1_parse_flag` | 0.20 | 0.60 |
| `g7d2_dedupe_keep` | 0.20 | **0.00** |
| `g7d3_fmt_amount` | 0.20 | **0.00** |

掉到 0.00 的两题**不是没照做，而是写崩了**（代码见 `d1_memory.db` 的 `finish` episode）：
- `dedupe_keep`：确实按惯例实现了 strip + lower + 保留首次，但用了 `yield`
  ⇒ 函数变成**生成器**，所有列表比较失败；
- `fmt_amount`：确实写了圆括号与空格千分位，但格式串写成 `f"{abs(x):,,.2f}"`
  ⇒ `ValueError: Invalid format specifier`。

⇒ ①**题可解**（`g7e2` 满分），这个 0 不是"题面/判据坏了"；
②知识进"指令位"后模型会照做，但**把约定落成能跑的代码这一层本身不稳**；
③"记忆位"连"照做"都触发不了。**两个断点是串联的，不是一个。**

⛔ D1′ 改了题面 ⇒ 不是同一把尺子，其均值（+0.20）**不许**当作通道效应的估计。

## 7. 本轮踩到的坑（全部已登记进 DESIGN）

1. **⑨a**：H 只送 1 条（FTS 精确命中函数名 `dedupe_keep`），P 送 4 条（无词可中 ⇒ 兜底）
   ⇒ 注入 50 字 vs 231 字 ⇒ **R7 的"等长"在注入层就破了**。修法：惯例文本去掉函数名。
2. **⑨a′**：`g7e1` / `g7e2` 的惯例含 `true` / `None` / `n`，与题面同名 ⇒ 又被精确命中（H=1）。
3. **⑨c**：改用**骨架安慰剂**（ASCII 与标点原位保留、只替换汉字）⇒ 两臂检索行为按构造相同。
4. **⑨d**：R1 原判据写成"H 必须取回全部 facts"，把**送达充分**与**对照等价**混成一句话。
   正确判据 = own-fact + `len(H)==len(P)` + 注入字符数相等 + `E==0`。
5. **⑨b**：构建器在**已存在**的种子目录上追加，旧 facts 与新 facts 混库（H=1 旧 + 1 新）
   ⇒ 加闸：目录里已有种子库就拒绝启动。
6. **⑧**：池 v1 有 2/4 题的惯例能被常识默认值猜中（E=1.00）⇒ 按登记作废；
   在**任何 Δ 读数产生之前**扩池重校准（换的是题面设计，不是判据/阈值）。
