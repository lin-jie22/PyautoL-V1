# ★7v-a PROVENANCE —— 墙钟耦合假设的定向检验（第五十轮，2026-10-21 03:1x–03:4x）

## 设计（DESIGN §19quinquies 跑之前写死）
- 假设 H7v-a：7u 观察到的窗内不稳由"墙钟预算 × LLM 延迟 ⇒ 通道分叉"造成；
  放大墙钟（120s ⇒ 600s）后同一题在多 rep 上走同一通道 ⇒ 窗内极差归零。
- 自变量**只有** `V1_MAX_WALL_S`；不动 steps / llm_calls / reserve / prompt / 记忆。
- 两配置同窗串行（qwen2.5:7b / T=0 / n4 × 3 rep），内核 = 7u 收口后的 HEAD
  （基线行为，无消歧指令）⇒ 与 7u 的 B 臂同源。

## 零模型前置（两条，先验 false 才开跑）
1. **`V1_MAX_WALL_S` 生效吗** —— config.py 注释明写"契约 T5 实测 5 个键里
   4 个不生效"，`V1_CLOSE_RESERVE_S` 就在其中 ⇒ 先验默认 false。
   实测（probe_w600.log，单题探针）：`wall=0.02s/600s` ⇒ **生效**，前置通过。
2. **读数里有没有按题通道标记** —— 7u 已见 `kernel_closeout` 是**整轮汇总**
   （4 题合计，字段 by_reason/origin）⇒ 无法按题分层 ⇒ 本轮通道只能从
   run log 按题段落人工判读（此限如实登记，见下"下一步"）。

## 判读：**H7v-a 不成立**，并**修正 7u 的第 1 条结论**
1. **墙钟不是本套题的瓶颈**：n4 每题 ~20–35s（4 题 ~2 min），远不到 120s/题；
   W600 与 W120 读数逐位相同 ⇒ 放大墙钟零效应。
2. **"墙钟耦合是量具缺陷"是过度概括，撤回该措辞**：7u 的 A 臂确实出现了
   "⏳ 预算耗尽 [wall_s] 已用 70.7/120 ⇒ 收尾"，但那是**消歧指令让单题变慢**
   （补救调用 21 次 > 基线 18）之后才撞上收尾余量（70+45 reserve ≈ 115 < 120）。
   ⇒ **wall 只是中介，根因是干预本身**：干预让题变慢 ⇒ 触发收尾 ⇒ 通道变 ⇒ 分数变。
   因果链：指令 → 更多补救调用 → 撞收尾余量 → 走收尾通道 → 分数不同。
3. **正面读数（本轮最有价值的副产品）**：基线在 n4 上 **3 rep × 4 题零极差、
   通道单一（finish ×12）**，且与 7u 的 B 臂（0.5500，g7e2=0.2）一致
   ⇒ **量具本身是干净的**：噪声底 ≈ 0。7t 的 D 臂不稳、7u 的 A 臂不稳，
   都来自**被改动的那条臂**，不是尺子抖。⇒ 这反过来把 7u 的"撤回"钉死：
   该指令既无效应又自造不稳。

## 自踩（如实）
- 通道解析首版把**文件头部日志**算成第 0 题、并在末尾多留一段残余 ⇒
  通道序列整体偏移一位、多出两个 `?` 假通道 ⇒ 判据 1 输出 **True 的假象**
  （差点据此宣称"对照成立"）。修法：段落实从第一个「▶ 任务开始」起，并
  `assert 段数 == 题数`。教训（解析器版）：**中间结果必须打印 + 用题数断言**。
- 本轮"判据 2 True 但无意义"暴露登记一处含糊：主判据**没有要求 W120 必须
  先不稳**。若 W120 本就稳定，W600 一致就成了空胜利 ⇒ 判据应写成
  "对照臂必须先表现出待解释的现象，否则本轮作废"。
