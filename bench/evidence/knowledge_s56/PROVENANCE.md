# ★7v-d 证据包（knowledge_s56）—— 字面 vs 语义

第五十二轮（§19septies）。问题：7v-c 判"承载是『逐条』"，但**所有复现的串都字面含那两个字**。
若承载是**字面词法**，换说法就失效 ⇒ 那是脆的提示效应，不许进产品叙事；若承载是
**逐项枚举语义**，同义替换也该复现 ⇒ 才配叫机制。本轮就是拆这个。

## 判读（按跑前写死的判据）

**★7v-d：未定位 —— S1/S2/S3 三条 34 字串全部 0.2，只有原句 1.0。**

⇒ 7v-c 的"承载是『逐条』"**被推翻**：
- **字面单独不够**：S2（含"逐条"但明说"不构成要求"）0.2、S3（"逐条"×16）0.2；
- **语义单独也不够**：S1（"每一条/一条一条分别生效"同义替换）0.2。

⇒ 只能说：**在已测的字符串里，只有 A 这一整句复现**。⛔ 不许写成"机制已解释"，
也不许把"逐条"或"指令性"当承载者写进任何对外文档。

## 过程证据（`shapes_7vd.txt`，零模型）

补救答案的**末次**形态决定得分（前缀链条无效，看最后一次）：

| 臂 | n4 三次 rep 的补救答案序列 | 末次 |
|---|---|---|
| A | `BAD(n-3,去重渗漏) → OK → OK` / `BAD(n-3,去重渗漏) → OK` / `BAD(n-3,去重渗漏) → OK` | **全部收敛到 `s[-n:]`** |
| S1 | `OK → BAD(n-3)` / `OK → OK → BAD(n-3)` / `OK → BAD(n-3)` | 全部**漂回 `s[-(n-3):]`** |
| S2 | `BAD ×2` / `BAD ×3` / `BAD ×2`（全部带 ZK1 去重渗漏） | 从头错 |
| S3 | `OK → BAD(n-3,去重渗漏)` ×3 | 先对后错 |
| B | `BAD(n-3,去重渗漏) → BAD(n-3)` ×3 | 从头错 |

**新现象（登记为下一轮假设，本轮不认领）**：S1/S3 是"**先对后错**"——第一次补救答对了，
后面几次反而漂回错的；A 是"先错后对"，末次稳定收敛。⇒ A 那句的作用更像**收敛闸门**
（让链条末态落到 `s[-n:]`），而不是"让第一次就答对"。
⛔ 这是事后读出来的，本轮判据没有预先登记这一项 ⇒ 只作现象登记。

## 自踩（如实）

- 首版 `run_arms.sh` 用 `declare -A` 做关联数组 ⇒ 本机 `/bin/bash` 是 **3.2**（不支持关联数组），
  在 `set -u` 下直接 `A: unbound variable` 退出，**连 progress.log 都没建**。改成 `case` 分支。
  教训：macOS 上的 bash 是 3.2，写脚本前先 `bash --version`。
- 首版 `shapes_7vd.py` 判据写成 `tail == ["n"]`，而实际捕获是 `['n:']`（切片文本含冒号）
  ⇒ 全部判成 BAD。第五次同类"静态串未核对"⇒ 已改为打印实际捕获值再比对。
- 测量耗时 83 分钟（20 次 run），跑前未预估 ⇒ 登记为"五臂 × (1 n0 + 3 rep) ≈ 85 分钟"。
