## 0. 问题为什么必须有一个定义

`_resolve_start` 现在的规矩是「**同分取先出现**」。这条规矩是在**没有证据**的时候写下的
（注释里给的理由是「append-only，先出现的更老、更可能已进缓存」——那是**缓存命中率**的
理由，不是「哪份更容易改进」的理由）。

V239c 把这两件事分开了：同一格 0.8333 的两份实现，

| 实现 | `vec` | 单点可修 |
|---|---|---|
| `90579ece` | `111011` | **1 / 9913** |
| `09d0e23d` | `011111` | **0 / 4839** |

⇒ 「同分」不等于「同样好」。**选错起点，整个闭环的读数就不再是关于模型的**
（它在修一份结构上修不好的代码，然后被记成「没变强」）。

## 1. 四个候选与它们的理由

| 候选 | 理由 | 反例 / 风险 |
|---|---|---|
| A **先出现**（现状） | 账本 append-only，最早那条最稳定 | 与「更容易改」无关；V239c 里恰好选了**修不动**的那份 |
| B **失败位序最靠后** | 前面断言都过了 ⇒ 结构对、洞在末尾 | n=1 对证据（V239c），**不许**当普适规律 |
| C **最新** | 代表当前代码状态下的产出 | 与改进难度无关；会把「最近一次退化」当 best |
| D **最短代码** | 假设短 = 精炼 | 与分数无关；会把「省掉功能的短码」选上来 |

**决定：B**，理由只有一条可复核的：**它是四个候选里唯一有观测支持的**
（V239c：位序最靠后的那份是唯一单点可修的，位序最靠前的那份 0/4839）。
⛔ 同时如实登记：**n=1 对**，这只说明「B 不比 A 差」，**不说明 B 普遍更好**。

## 2. 排序键（写死，不许事后改）

```
rank(o) = ( score,                        # 主键：分高者胜（不变）
            last_fail_pos(vec),           # 同分：末位失败断言的下标，**大者胜**
            -index_in_ledger )            # 再同：先出现的胜（保持 A 的稳定性）
```
- `last_fail_pos(vec)`：`max(i for i,b in enumerate(vec) if not b)`；`vec` 全 True ⇒ `-1`。
- **没有 `vec` 的行排在有 `vec` 的行之后**（`None` 不可比 ⇒ 降级，不许当成 `-1`）。
  ⚠️ 这一条是纪律 137 的孪生：`vec` 缺失时若当 0 处理，「缺记录」会冒充「洞在最前」。
- 全部相等 ⇒ 先出现（append-only 稳定）。
