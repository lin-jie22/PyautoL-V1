## 1. 类一：锚点腐烂（22 条）

**共同病**：`old_string` 已经不在了。驱动器报「变异锚点出现 0 次」——
这条**不是红的**，是**静默通过**：规则失效了，而基线照绿（纪律 205 的同型：
「旧数字会被当成现值一直引」）。

修法**不是**改判据，是把锚点重新对准**当前代码里承担同一职责**的那几行。
`fix_anchors_v242.py` 的三条硬规矩：

1. 按**名字**定位元组块，不按行号（行号会漂）；
2. 块边界用 `ast.parse` 取 `(lineno, end_lineno)` —— ⛔ 任何引号计数启发式都会提前命中
   （`CASES` 有三种字面写法：三引号 / 双引号+转义 / 多行拼接）；
3. 替换后**强制校验**每条 `old` 在目标文件里**恰好出现 1 次**。

### 1.1 三类「改法」在写的时候就要分开

| 写错的方式 | 后果 | 正确写法 |
|---|---|---|
| 把 `if` 整段换掉 | 源码锚要求那行逐字存在 ⇒ **连带打红**（`TH1` 打红 `AZ162e`） | 只把条件恒真（`if True:`），源行不动 |
| 撤「那句 `if`」 | 下游 `f"{e['best']:.6f}"` 格式化 `None` ⇒ `TypeError`（`AZ135b`） | 撤**它数的那个数**（`len(tail)` → `len(tail)+1`） |
| 撤「单参数包 1-tuple」 | 下游 `for x, in` 解包抛错（`AZ145d`） | 撤**形状不变、取值变**的那处（`LEN_POOL[2]`→`[1]`） |
| 撤错对象 | 目标是 A、红的是 B（`AZ22` 红了 `AZ147`；`AZ62` 红了 `AZ63`/`AZ95`） | 先看**真的走哪条分支**（`AZ62` 实际走 `replan` 而非 `propose`） |

### 1.2 定向结果

| 项 | 读数 |
|---|---|
| 22 条锚点重写后「恰好出现 1 次」 | **22 / 22** |
| 定向跑：**精确**转红（红集 == {自己}） | 19 / 22 |
| 改声明后 `R13 通过` | 4 / 22（`AS7` / `AZ22` / `AZ62` / `AZ137c`，其中 `AZ137c` 与 19 条不互斥） |
| 目标**没红**（红的是别人） | 0 |

## 2. 类二：连带未声明（35 条）

撤回真的波及下游断言（同一个判决被好几条断言读），但 `COUPLED` 里没写
⇒ 驱动器读成「多红 = 锚定跑偏」。

修法：跑出**真实红集**，逐条按**机理**判断这是「同一根线的下游」还是「锚定跑偏」，
是前者才登记。登记进 `_V242_EXTRA`（34 个键），并且**合并而非覆盖**
（`COUPLED.update(...| v)`：`update` 会把原有声明整个盖掉 —— 这是预埋的自踩点）。

两条要单独说：

- **`AZ140f`**：撤「`pool_from_rows` 见 `vec` 键即拒」⇒ 可动性读数一起变，
  红集 `[AZ140f, AZ141c, AZ141d, AZ141e, AZ142c]` —— 与 `AZ137c` 同一组下游。
- **`AE9`**：多红 `AZ110` ⇒ 补进 `COUPLED["AE9"]`。

## 3. 类三：撤回后崩溃（3 条）

「崩溃」与「判红」必须分开：崩溃时**没有汇总行**，那一次读数作废（R13 的硬坑）。

| 案例 | 崩法 | 修法 |
|---|---|---|
| `AZ136e` | 撤 `min_pool` 闸 ⇒ 空池进分类 ⇒ `ZeroDivisionError` | 门槛降到 `if n < 1:` |
| `AZ140f` | 撤「见 `vec` 即拒」⇒ 连带 4 条 | 改成「见 `vec` 键即 `n_no += 1; continue`」 |
| **`AU6`** | 撤哨兵 ⇒ **换掉控制流** | 见 §3.1 |

### 3.1 `AU6`：一个「兼作控制流的哨兵」必须撤**两处**

`AU6` 判的是：离线桩（没有 `timeout_s` 属性）⇒ `_attempt_timeout()` 返回 `inf` ⇒ 不裁剪。

那行同时是**断言值**和**分支条件**：

```python
if base is None:            # 桩/无网络：不裁剪
    return float("inf")     # ← AU6 断言这个值
...
if _to == float("inf"):     # ← 同一个 inf 又当分支条件
    return self.inner.complete(messages, **kw)   # 不带 timeout_s
```

只把值换成有限数（`1e9` / `1e308`，两版都试过）⇒ 走 else 分支 ⇒
`inner.complete(..., timeout_s=1e9)` 打到 `_AZ105LLM.complete(messages, max_tokens=None)`
（**不接受** `timeout_s`）⇒ `TypeError` ⇒ 整条离线计划链零轮次 ⇒
**AZ107 红 + AZ108 `IndexError`（无汇总行）**。

⇒ 撤回的正确形状 = 「哨兵值」+「认哨兵的分支」**一起撤**（同 `AZ135b`：
撤它数的那个数，不撤那句 `if`）。为此给驱动器加了「一次撤回可撤多处」的能力：
`old`/`new` 允许是**元组**，每一处仍要求**恰好出现一次**，任一处不唯一即整条失败。

```python
("AU6", "mw/core.py",
 ('''...return float("inf")''', '''                if _to == float("inf"):...'''),
 ('''...return float(1e308)''', '''                if float(_to) >= 1e300:...'''))
```

定向读数：`红=['AU6'] 目标=✔ 多红=无 汇总行=('838','1') 崩溃=无`。

## 4. 全量动态复跑：**没跑完**（如实登记）

### 4.1 三次尝试与各自的失败点

| # | 形式 | 结果 |
|---|---|---|
| 1 | 单进程 375 条 | 起跑 12 分钟只到 ~20 条 ⇒ **我主动停**：发现顺序错了（新锚点还没加，跑完也会作废） |
| 2 | **4 分区并行**（仓库复制 4 份 + `V1_WITHDRAW_BAK` 隔离） | 跑 **6.5 小时**、约 320/382 条，但**一行结果都没留下** —— 驱动器只在末尾打印汇总表；随后被沙箱 `_BrokerProtocolError: execution capability 已过期` 杀掉 |
| 3 | 单进程**分块**（先给驱动器加逐条即时打印 + `flush`） | 能留下读数了，但实测单条 **1~4 分钟**（有些变异会让预算/墙钟路径真的去等）⇒ 全量 **6~10 小时**，超出单次工具 10 分钟上限与沙箱执行能力期限 |

⛔ 第 2 次的教训写进纪律 216：**长跑装置必须在跑的过程中落读数**，

### 4.3 为什么这 306 条「没跑」不等于「可以不管」

它们的锚点都过了静态检查（唯一），而动态部分要验的是「目标会不会转红」——
那只会在**判据与变异有共同代码路径**时被本轮改动影响。本轮只改了
`run.py`（`_resolve_start`/`_start_rank`/一个新 CLI 参数）、`bench/withdraw_check.py`、
`tests/contract_test.py` 与四份文档（数字）。受影响文件里的 51 条，其锚点落在改动同区的
已全部跑过（16 条）；其余 35 条锚在 `run.py` 的其它函数或文档段落上，与本轮改动无共同路径。

⛔ 但这只是**推理**，不是读数。下一轮若要把这件事做实，唯一办法是分块跑（每次 ≤ 8 条），
或者先把「每条案例的实测耗时」量出来、按耗时排程。

## 5. 新增纪律（213~216）

213. ⛔⛔ **撤回一个「兼作控制流的哨兵」必须撤两处**：只换值会换分支 —— 实测
   `TypeError` 打在不接受 `timeout_s` 的桩上 ⇒ 整条离线链零轮次。形状 = 哨兵值
   \+ 认哨兵的分支一起撤（与 141 的「撤它数的那个数」同宗）。
214. ⭐⭐ **「多点撤回」每一处都必须恰好一次**：允许「两半一起撤」不等于放宽唯一性 ——
   放宽唯一性就等于回到「锚点漂了没人知道」。
215. ⭐⭐ **并行跑撤回态必须按副本隔离备份目录**：`MANIFEST` 与备份同路径时，四份进程会
   互相拿别人的变异去还原自己的工作树（第二十二轮事故的并行版）。`V1_WITHDRAW_BAK`
   只做「可传」，默认不变 ⇒ 单进程行为逐字节同旧。
216. ⛔⛔ **长跑装置必须在跑的过程中落读数**：只在末尾打印汇总，等于「跑多久都可能一行不剩」。
   本轮 4 分区跑了 6.5 小时、约 320 条，末尾前被沙箱杀掉 ⇒ **零读数**。
   修法是逐条 `print(..., flush=True)`，不是「下次跑快点」。
217. ⭐⭐ **「全量跑不完」要先报耗时分布再谈替代**：本轮实测单条 1~4 分钟 ⇒ 全量 6~10 小时；
   替代口径（静态唯一性 + 受影响同区动态）必须先证明「未测的那部分为什么不会被本轮改动影响」，
   并把未测条数写成**未测**，⛔ 不许写成绿。
