# PREREG v246 —— 自省的第二层：自验回路（VERIFY-LOOP）

> 写这份文件时，v246 还没跑过一次。v245 的读数已落盘，本文件不修改它。

## 0. v245 给出的、决定这一刀的事实

v245（3 臂 × 16，0 失败）主判据**不成立**：给执行轨迹 B 臂 6/6 = **0/16**，
强制自问 C 臂 **0/16**。但机制探针（`mech_v245.jsonl`，18 条）把病因指到更窄的一处：

| 现象 | 读数 |
|---|---|
| A 臂逐字节照抄起点 | **16/16**，唯一产出 sha **1/16** ⇒ 确定性，根本没动手 |
| B 臂开始动手 | 5/16 非照抄 |
| C 臂开始动手 | 10/16 非照抄 |
| **动手且定位正确**（改第 16 行 `int(parts[1]…)`） | **4 条**（C#0/C#2/C#4/C#5） |
| **定位正确的补丁里语义对** | **0 / 4** |
| 实际产出 | `int(parts[0]) * 3600`（=36000）、`minutes = 0`（=0）、`else: return 0` |

⇒ **信息不够不是瓶颈，定位也不是瓶颈。**
`'10m'.split('m')` = `['10', '']`，此处 `parts[0]` 是**分钟**；
模型把它当成小时（从上方 `h` 分支串了语义），于是补丁「不崩了但算错」。

⛔ 这正是 2026 综述说的「用弱信号替代强信号」的反例：信号已经够强，
   缺的是**对自己补丁的效果做一次核验**。

## 1. 自变量

**唯一变量 = 改完之后有没有「自己跑一遍断言、把新失败喂回去」的回路。**

| 臂 | 定义 |
|---|---|
| **B1** | v245 的 B 臂：单轮，带轨迹（已有读数 0/16，本轮**同条件复跑** 16 条作为对照） |
| **D** | 同 B1 起手，但**最多 3 轮**：每轮用自己的产出重算失败断言与轨迹，喂回自己；一旦 6/6 立即停 |

⛔ D 不换模型、不换温度、不换起点、不加新提示模板 —— 首轮提示与 B1 **逐字节相同**。
⛔ 不自造断言：判分与「哪些断言失败」都来自那 6 条原断言。

## 3. 判据（三值）

**主判据（唯一一行）**：

> **D 臂最终 6/6 命中数 ≥ 3（n=16） ⇒ 自验回路有牙。**

把「实得 0（期望 600）」喂回去，是把**语义核验**从模型手里拿走 —— 与轨迹那次同理。

## 4. 机制读数（必报，不当判据）

- 每条：`rounds`（实际用了几轮）、逐轮 score、最终 sha
- 「第 2 轮把 `* 3600` 改成 `* 60`」出现几次 ⇒ 是否真的靠**数值反馈**纠正语义

## 5. UNKNOWN 条件

1. 任一条调用失败 > 3 次且未补足 ⇒ 该臂 UNKNOWN。
2. B1 复跑的 6/6 命中 ≥ 3（现状本身有牙）⇒ D 的增量不可归因，只报「有无」。
3. 若 D 臂**首轮**就有 ≥3 条 6/6 ⇒ P2 不成立 ⇒ 说明 v245 的 0/16 是窗口漂移，
   本轮**只报漂移**，不谈回路。
