## 2. 自变量与三臂

**唯一变量 = 在给出代码之前，是否先产出一个可判的「语义承诺」，并把它逐字节回喂。**

| 臂 | 做什么 | n | 参与判据 |
|---|---|---|---|
| **A** 对照 | 就是 v245 B 臂（2307 bytes / `1bdea4fc92d67817`），一次生成直接给码 | 16 | 是（复现闸） |
| **Q** 语义问答 | 只问两个问题，**不写码**：`parts` 的值是什么、`parts[0]/parts[1]` 谁是分钟数 | 16 | 否（只判 P2） |
| **S** 自述回喂 | 把该条 Q 的回答**原文**贴进改码提示的【你上一轮的自述】段，再给码 | 16 | 是（主判据） |

- **Q 与 S 共用同一批 Q 产出**：Q 只跑 16 次，S 用这 16 条逐条回喂，不重跑。
- Q 的无效条（空 / 整段代码）**仍照常回喂并跑 S**（保 S 的 n=16 可比），只在 P2 分母里剔除。
- ⛔ 不加「人工正确自述」臂：那等于把答案递过去，量出来的不是自省。

## 4. 判据（三值，跑之前写死）

**主判据（唯一一行）**：

> **S 臂 6/6 命中数 ≥ 3（n=16） ⇒ 「先自述语义再改」这个动作有牙。**

押：**不成立**（即押 `S_6of6_over_16 ≤ 1`）。

理由（机制，不是感觉）：
1. 若 Q 答对（`parts[0]` 是分钟），S 的回喂等于把「语义」摆到它面前 —— 但 v245 的 trace 已经把
   `parts=['10','']` 摆到它面前，4/4 定位对、0/4 语义对 ⇒ **看见不等于用上**。
2. 若 Q 答错（`parts[1]` 是分钟），回喂的是它自己的错，S 只会更差。
3. ⇒ 两种情况下 S 都不该高于 A。

三值映射（不留模糊）：

| `S_6of6_over_16` | 判定 |
|---|---|
| ≤ 1 | **不成立**（押中） |
| **2** | **UNKNOWN**（压线，不许选边） |
| ≥ 3 | 成立（**=3 或 4 必须自报压线**，纪律 91） |

次判据：

| 编号 | 判据 | 分母 | 押 |
|---|---|---|---|
| P1 | A 臂 `6/6 == 0` 且 `same_as_start == 16` | /16 | **成立**（复现 v245） |
| P2 | Q 里「明确指认 `parts[0]` 是分钟」 | /16 | **UNKNOWN**（不知道，这是本轮最想知道的数） |
| P3 | 在 **P2 判对的那些条**里，S 仍 `< 6/6` 的比例 **≥ 0.75** | /`P2 对的条数`（**不是 16**） | 成立（若 P2 成立） |

⛔ P3 的分母必须写成「P2 对的条数」——两个分母一起报（纪律 64）。
⛔ 若 `P2 对的条数 < 8`，P3 直接记 **UNKNOWN**（样本不足，不许拿 3/4 报 75%）。
⛔ 不许把主判据改成「S 比 A 好」来凑 PASS（§315.6-3）。

**P2 的判定标准（判定前写死，人工逐条读）**：

- **对**：明确写出「分钟数是 `parts[0]`」（或等价：`parts[0]` 的值 10 就是分钟数）
- **错**：写「`parts[1]` 是分钟」/「`parts[1]` 是单位，空串表示缺单位」/「无法确定」
- **只答值未答语义**：只写 `parts=['10','']`，不说谁是分钟 ⇒ 记为**错**（不算对）
- ⛔ 判定前不看分数，先读完 16 条原文再判（防事后对齐）。

## 5. 机制读数（不参与判据，但必须一起报）

对每条 S 产出算四件事：

- `same_as_start` / `sim` / 唯一 sha 数 → **照抄还是改**
- 出现 `int(parts[0])` 且其乘数为 `60` → **语义落到码**（`sem_in_code`）
- 出现 `int(parts[1]` → **原样保留缺陷**（`kept_bug`）
- `sem_in_code == (P2 判对)` → **自述与行为一致**（`self_consistent`，「承诺-履行」的直接读数）
  ⚠️ 这个量测的是**一致性**，不是对错：它答错且码也错，`self_consistent` 仍是 True。
  只有「答对却写错」和「答错却写对」两种才是 False。

⚠️ `sem_in_code` 检测器必须先在**原码**上自检：原码是 `int(parts[1].split('m')[0])`，
它应判 `kept_bug=True`、`sem_in_code=False`。若在原码上判 `sem_in_code=True`，检测器作废（纪律 221）。

1. 任一臂调用失败（空产出 / 超时）> 3/16 且未补足 ⇒ 该臂 UNKNOWN，不参与比较。
2. 起点复算 `verify != 5` ⇒ 全局 UNKNOWN。
3. 速度 < 15 tok/s ⇒ 不启动（纪律 116）。
4. Q 的有效回答（非空、且不是整段代码）< 12/16 ⇒ **P2 UNKNOWN**，S 照跑但不解释 P2。
5. A 臂 `6/6 ≥ 3` ⇒ 对照失效（起点本身就有牙），只报「有无」，不报动作增量。
6. `S.replace(实填后的 INS, "") != A`（§3 的构造校验失败）⇒ 装置坏了，UNKNOWN，不许跑。
