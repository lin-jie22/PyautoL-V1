## 5. 机制：为什么加了信息还是 0

### 5.1 A 臂是**确定性**的（这一条先要报）

A 臂 16 次产出**唯一 sha = 1**，全部逐字节等于起点。
⇒ A 臂的「n=16」在统计上其实是 **n=1**（纪律 94：确定性装置上读数不动是全局属性）。
⇒ P1 的「成立」因此**没有判别力**，只说明「原样再跑一遍还是原样」。

### 5.2 加信息改变的不是命中，是**多样性**

A → B → C，唯一 sha 数 1 → 6 → 8，照抄率 16/16 → 11/16 → 6/16。
**反馈保真度把「复制」变成了「探索」，但探索没有命中。**

### 5.3 探针：改在哪（18 次，每臂 6 次，不参与判据）

非照抄的 6 条，改动位置与结果：

| 产出 | 动的是哪 | 对 `'10m'` 的结果 | 分数 |
|---|---|---|---|
| B#0 / B#1 | 第 20 行（**小时**分支的判空） | 没碰到故障行 | 5/6 |
| C#0 | 第 16 行（**正确**） | `if len(parts[1]) == 0: return 0` → **0** | 5/6 |
| C#2 | 第 16 行（**正确**） | `return int(parts[0]) * 3600` → **36000** | 5/6 |
| C#4 | 第 16 行（**正确**） | `minutes = … if parts[1] else 0` → **0** | 5/6 |
| C#5 | 第 16 行（**正确**） | `else: return 0` → **0** | 5/6 |

⇒ **定位正确 4 条，语义正确 0 条。**

关键：`'10m'.split('m')` = `['10', '']`，此处 `parts[0]` **就是分钟数**，正确补丁是
`return int(parts[0]) * 60`。四条补丁全都在处理「空串这个异常」，把 `parts[1]` 为空
当成非法输入，于是返回 `0` / `None` / 小时。
**它不是不知道 `10 分钟 = 600 秒`，而是把 `parts` 在这个分支里的含义搞错了**
（从上方 `h` 分支串了语义：那里 `parts[0]` 是小时）。

`len\(parts\[1\]\)` 把原代码自带的 `if len(parts[1]) == 0:` 也匹配了

## 6. 押注为什么错（这一条比读数重要）

我在 PREREG 里押「B 臂有牙」，理由是「轨迹把『`parts[1]` 是空串』这一步从模型手里拿走」。
**这个前提成立了**：4 条补丁确实改到了第 16 行，说明它们看见了 `parts=['10','']`。
**但从「看见了」到「改对了」之间还有一步我没算进去**：
> 看见 `parts[1]` 是空串 ≠ 知道 `parts[0]` 在此处是分钟。

⇒ 自省不是一步（「给信息 → 就会改」），是**三步**：
**① 看见（+轨迹即达成）→ ② 定位（4/4 达成）→ ③ 语义（0/4）**。
v245 把 ① 和 ② 补上了，第 ③ 步没动。
