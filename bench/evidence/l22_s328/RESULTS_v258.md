## §4 两个收益，**两个不同机制**（逐行日志）

### 4-1 `g7t4`：0.0 → 1.0，**直接**由早分支拿到

```
03:31:33  🧪 自检未过（第 1/2 次打回）⇒ 编译失败 line 4: unexpected character after line continuation character
          ⇒ return ', '.join(f'"{item.replace(\"\", "\
03:31:33  ⇢ 无候选可让位 ⇒ 早分支（REJECT_CARRY=6）        ← V257 之前这里走的是 replan(error=…)
03:31:37  ↻ 打回重写：走**交付协议**（REJECT_CARRY=6，answer(clean) 产出 271 字符）
03:31:40  ✎ 重写的答案与被打回那版**不同**（模型改了）
03:31:40  ✅ 打回之后的重写**过了闸**
03:31:40  ■ done    → 外部打分 1.0（vec 5/5）
```

`steps=2`：第 1 步交原答案被打回，第 2 步交重写。**没有第三轮、没有让位、没有停滞。**
⇒ 这条路以前走的是 `replan(error=…)`，而 `g7t4` 在 V257 里正是死在这条路上
（planner 又交回同一份带 `\"` 的代码 → 重复闸 → 停滞 2/2）。

### 4-2 `z02`：0.0 → 0.6，**间接**——早分支买的不是「换协议」，是**多一轮**

```
03:33:35  🧪 自检未过（第 1/2 次打回）⇒ 同一类错：f'"{cell.replace(\"\", "\"\"")}"'
03:33:35  ↪ 交付被打回 ⇒ 让位给候选 2/2（不重规划）           ← 有候选，走 elif（=5 也有这条路）
03:33:44  ↻ 走**交付协议**（REJECT_CARRY=6，445 字符）        ← 等于 5 档那条路
03:33:48  🧪 自检未过（第 2/2 次打回）⇒ 仍是 f-string 反斜杠  ← 换协议**没修好**
03:33:48  ⇢ 无候选可让位 ⇒ 早分支（REJECT_CARRY=6）           ← 只有 6 档有：第二次重问
03:33:56  ⏭ 重提的答案**逐字相同** ⇒ 重复闸跳过 ⇒ 停滞 1/2
03:33:56  ↻ 带错误原文重规划（连续失败 1 次）…（22 秒）
03:34:22  ✅ 打回之后的重写**过了闸**                        ← 真正修好的是**这一轮**
03:34:22  ■ done    → 外部打分 0.6
```

⭐ **归因必须写清（纪律 137 / 261）**：`z02` 的 0.6 **不是**「换交付协议修好了」——
两次 `answer(clean)` 都产出 445 字符、第二次**逐字相同**（重复闸当场抓到）。
真正落地的是之后那一轮 **`replan(error=…)`**。早分支的作用是把这一轮**买出来**
（多一次打回配额 + 一次重复闸命中 ⇒ 停滞计数变化 ⇒ 才轮到带报错重规划）。

⛔ 若只看分数写「6 档让 z02 也换了协议就修好了」，就正好写反了。

## §6 更正与登记

1. **V257 ④「病在模型不在接线」泛化错了。** 原话根据 `z02` 的「`=5` 生效 1 次仍写 f-string
   反斜杠」推出。本轮的 `g7t4` 证明：**同一个病类**（同为 f-string `\"`），在**有早分支**
   时一次 clean 重问就 1.0。⇒ 正确表述：**`z02` 的病在模型（换协议也复现），`g7t4` 的病在接线
   （给到那一次就修好）**——这正是纪律 271 要求分开报的两种情形，V257 把它们合并了。
2. **V257 的「`g7t4` 打回 2 次」是口径串了。** 那个 2 来自 `verify` 第三格（`verify=[2,0,2,0]`），
   而日志里 `🧪 自检未过` 只有 **1** 行（本轮 `readings_v258.json` 用日志行数，同样是 1）。
   两个口径都指向同一结论（5 档零次生效），但「打回几次」应当统一按日志行数说。
3. **`harness_sha` 断段**：`a05e15df…` → `8ae95f03…`。本轮所有读数只在**本轮内部**可比；
   跨到 V257 只能比「=5 的 13 格分数」（已比，13/13 同分）。
4. **新增契约 `AZ171`**（6 条子判据，位置值优先于分数：`via_answer_early=1`、5 档 `=0`、
   答案请求早于任何 `replan`、交付逐字等于 `answer()`、交空后不再进早分支、5 档不用 clean 协议）。
5. **两条撤回态改动**：
   - `AZ171` 新增（`== 6` → `== 99`，只它转红，实测通过）；
   - `AZ146` 的撤回**换了撤点**：`clean=True` 那一行被抽进共用方法后，改它会把 `AZ171`
     一起打红（实测 `红=['AZ146','AZ171']`，违反「只它一条转红」）⇒ 改撤
     `if _rc in (5, 6):` → `if _rc == 6:`（5 档独有的一格）。代价如实登记：
     这样撤，「协议」与「分支存在」这次绑在一起撤。
   - 撤回态总数 **382 → 383**；受本轮改动影响并**逐条动态复跑**的从 16 条变 **17 条**
     （`AZ146` / `AZ171` 两条已跑：`R13 通过：逐条撤回都精确转红`）。
