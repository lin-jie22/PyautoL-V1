### 2.2 L2 闸层：派了什么判据（真调生产 `derive()`，`static=1, exec_=1`）

| 格 | 派出的判据 | `n_example_asserts` |

### 2.3 L3 分歧层：首个分歧长什么样

| 格 | 探针 | 实际 | 期望 |
|---|---|---|---|
| `g7t2` | `parse_pairs('a=1;b=2')` | **`{}`** | `{'a': '1', 'b': '2'}` |
| `g7t2` | `parse_pairs("a=1;b='x;y'")` | **`{}`** | `{'a': '1', 'b': 'x;y'}` |
| `g7t2` | `parse_pairs('a=')` | **`{}`** | `{'a': ''}` |
| `s02` | `[hit('a',0..3)]` on `Limiter(3,10)` | **`[T,T,T,T]`** | `[T,T,T,F]` |
| `s02` | `count('a',3)` | **`0`** | `3` |
| `m02` | `mkdir('a/b')` | **`AttributeError: no attribute 'root'`** | 正常建目录 |
| `m03` | `from lru import LRU` | **`ModuleNotFoundError: lru`**（交付里无 `FILES`） | 两文件就位 |

四个根因，逐个看到行：

- **`g7t2`：变量角色互换。** `key` 只在 `=` / `;` 分支被 `key = key.strip()` 赋值，
  而字符累积进的是 `value` ⇒ `if key:` **恒假** ⇒ 函数**永远返回 `{}`**。
  这不是「边界没写对」，是「整个函数不产出任何条目」。
- **`s02`：数据结构完全错。** `records[key]` 存的是 `{now-window: count}`，
  只在 `now-window` 这一个时刻上记数 ⇒ 每次 `hit` 都把计数重置成 1 ⇒ **永不限流**，
  `count` 恒 0。题面写的「半开区间 `(now-window, now]` 内已记录的命中数」被实现成
  「一个时刻的计数器」。
- **`m02`：类根本没有 `__init__`。** `class VFS:` 下面直接是 `def mkdir`，
  所有方法第一行 `current = self.root` ⇒ **任何调用都 AttributeError**。
  （V254 的那份实现错在别处：`ls('')` 把空路径当「找不到」抛 KeyError，双空格来自
  `f'File or directory {path} not found'` 且 `path=''`。）
- **`m03`：交付格式没遵守 + 命名冲突。** 把两个文件用 `# lru.py` / `# tiered.py`
  注释拼在**一个代码块**里，**没有 `FILES` 字典**（题面明写「用 `FILES` 字典交付」）；
  且 `self.keys = []` 与 `def keys(self)` 同名 ⇒ 方法被实例属性覆盖。

## §5 两处措辞盲区（本轮新登记，可修但收益 0）

`derive()` 只认字面措辞，这两处是**真实存在的**、此前没登记的：

1. **`_CODE_ONLY` 认不出「只输出定义 `FILES` 的代码」。**
   正则只匹配 `只输出代码|只要代码|只给代码|仅输出代码|只返回代码` 连续四字，
   `m02`/`m03` 的「只输出**定义 `FILES` 的**代码」不匹配 ⇒ **整个 `_CODE_ONLY` 分支被跳过**
   ⇒ `compiles` / `fence_lang` / `undefined` 三条判据**全部缺席**，只剩「非空」。
2. **`example_asserts` 认不出「`'a//b' == 'a/b'`」。**
   `m02` 的题面里**确实有 `==`**（`path_has_eq=True`），但抽取要求左边是**函数调用**
   （`_cut_call`），左边是字符串字面量就跳过 ⇒ `n_ex=0`。
   ⇒ 「题面有 `==`」**不等于**「有可派生的期望值」。

两处都值得记，但**都不能指望它们救分**：补上之后 `m02`/`m03` 会多派 `compiles`，
而它们的代码本来就编译通过；`example_asserts` 那条即使抽到，也只是一条与目录语义无关的字符串比较。

### 5.1 影响面普查（39 题，真调 `derive()` 的三个正则）

⇒ **35/39 题（89.7%）的闸没有任何一条判据能看返回值对不对**；
13 格里只有 **`t04`** 有 1 条示例 —— 而 `t04` 正是 V257/V258 唯一修好的那格。
（这次独立复算的「4 题有示例」与 V255 普查的「`exec=1` ⇒ 4/39 可判」**数目完全对上**，

## §6 局限（必须写清楚）

1. **本轮的「9 份实现」不是同条件 k 次采样。** 三份来自三种不同 prompt 条件
   （有实现 / 有实现+断言 / 只有题面），只能说「已观测到的 9 份不同实现全 0 分」，
   **不能**外推成「同条件 k=8 采样也全 0」（纪律 243：换分母就重判外推）。
2. **T=0 下同 prompt 不可产生多样性**（纪律 244），所以「采样」若要做，必须换温度 ⇒ **换口径**，
   与 V253/V258 的 0.3436 / 0.3949 / 0.5179 **不可直接比**。
3. **本轮没有预注册。** 它是纯审计（0 生成、0 改动），输出是事实清单而不是「A 让 B 发生」的判据，
   所以不适用四项前提。但「没有押注」这件事本身要登记，不许事后包装成「我早就押了」（纪律 275 同族）。
4. **4 格里 3 格的「一次调用即暴露」是结构性的**（`{}`、`[T,T,T,T]`、`AttributeError`），
   但装置想要「调用」就必须知道**调什么、传什么、期望什么** —— 前两项题面能抽，第三项不能
   （抽期望值的三条来源：题面示例 0 条、打分器开卷 V254 已量 1/13、模型自造 V255 已否）。

## §9.2 追因：不是温度坏了，是分布太尖

先排装置：`caliber_sig` 从 `4a497ee8de982e4c` 变成 `13e9dad09c54112f` ⇒ 温度**进了签名**，
config 确实读到 0.8；`mw/llm.py:177` 把 `temperature` 放进 `options`，请求体没问题。

再用原生 API 直接验（绕开本仓客户端）：

| 探针 | 结果 |
|---|---|
| `Output only six random lowercase letters`，T=1.5 × 3 | **三次全不同**（`gfdjkz` / `gjdhfr` / `gjdhfb`） |
| 同 prompt，T=0 × 2 | **两次相同**（`gjdhfl`） |
| `Write one short sentence about autumn`，T=1.5 × 3 | **三次全不同** |

⇒ **温度有效、装置无罪。** 之前用「写个 sum-of-squares 函数」测不出差异，是因为那类模板代码的
分布本来就是尖的（80 字符、约 30 token 全部近 1.0 概率）。

⇒ 那么 8 次全同只能有一个解释：**这 4 格的处理，模型输出分布在 T=0.8 下几乎是点质量。**
它不是「碰巧写错」，是**对这一份错误实现有近乎确定性的偏好**。

## §9.3 这条追因把 V254 的现象升级成机制

V254 量到：给了断言原文，`g7t2`/`m02` **逐字节未动**、`s02` **重置成「从零」那份**。
上一轮只能把它写成「动作没发生」（纪律 260）。本轮给出了机制：

**模型对「修正」这个动作的响应是「重新生成」，而重新生成的结果就是它的高概率点；
那个点窄到 T=0.8 采 8 次也不动一个字节。**

⇒ 所以「把失败信息喂回去」在这 4 格上不是「信息不够」，是**信息无法移动一个已经是点质量的分布**。
这与「差一个能力」是同一件事的两种说法，但机制版更硬：它预测**任何 prompt 级改动都无效**，
并且这个预测已被三种改动（加断言 / 有当前实现 / 只有题面）分别验证过。

## §12 方法论修正（要写进纪律）

**T=0 的读数有两个用途，只有一个成立：**

- ✅ **用于同口径前后比较**（装置 A vs 装置 B、`=5` vs `=6`）：成立，因为两边都取最坏点，
  `Δ` 仍然指向装置的真实差异。
- ❌ **用于陈述「模型能力 / 题集是否饱和 / 可修性上界」**：不成立 —— 它测的是分布的**最低点**。

⇒ 今后凡是要说「模型做不到 X」，必须给 **k≥3 的 T>0 采样**，
否则只能说「**在 T=0 这个点上做不到**」。
