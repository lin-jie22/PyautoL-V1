## §1 定义（判据只从这里派生）

输入池 `pool` = `(impl_id, score)` 行的序列，**一格**（同一题）内。分数要求实数。

先过三道**弃权闸**（fail-open，⛔ 任何一道都不许崩、不许静默降级成 CONSTANT）：

1. `TOO_FEW`：去重后实现数 `< MIN_POOL`（默认 2）⇒ `UNKNOWN`
2. `RULER_BROKEN`：出现 `score > TARGET(1.0)` 或 `score < 0` 或非数值 ⇒ `UNKNOWN`
   （尺子坏了/口径混了 ⇒ 弃权，与 V173 `unreachable()` 的同名闸同语义）
3. `IMPL_SCORE_CONFLICT`：同一 `impl_id` 出现两个不同分数 ⇒ `UNKNOWN`
   （确定性判分下这只能是口径混了或判分器不稳；T=0 噪声地板 0 是既有读数）

过闸后，按**去重实现**的分数集合分类（`n` = 实现数，`k` = 不同分数数）：

| kind | 条件 | bits | resolution |
|---|---|---|---|
| `CONSTANT` | `k == 1` | `0.0` | `k/n` |
| `INJECTIVE` | `k == n` | `log2(n)` | `1.0` |
| `COARSE` | `1 < k < n` | `log2(k)`（上界）；`H(桶分布)`（实得） | `k/n` ∈ (0,1) |
| `UNKNOWN` | 弃权闸任一触发 | `None` | `None` |

- **桶** = 同一分数的实现集合；`buckets` 字段逐桶点名（分数 → 实现列表），⛔ 不许只报个数。
- `bits_max = log2(k)`：知道分数后**最多**能区分几类的上界；`bits = H(buckets)`：
  桶分布的香农熵（均匀时取到上界）。两个数都报，⛔ 不许只留好看的那一个。
- 判定顺序 CONSTANT → INJECTIVE → COARSE（穷尽且互斥）；UNKNOWN 由闸决定，优先于分类。

**为什么 bits 用 `log2(k)` 而不是 `log2(n)`**：分数只能告诉你在哪个桶里，桶数 `k` 是
它能表达的信息量上界；`k == n` 时两者相等（单射），`k == 1` 时归零（常数）——
三个 kind 在同一把尺上，不许各说各话。

## §2 判据（7 条，⛔ 主实验前一字不改）

| # | 命题 | 押的读数 |
|---|---|---|
| P1 | 常数臂 | 全等池（如 2 实现全 1.0）⇒ `CONSTANT`，`bits == 0.0` |

| P4 | 弃权三条 | `n=1` ⇒ `TOO_FEW`；有 1.2 ⇒ `RULER_BROKEN`；同 impl 两个分 ⇒ `IMPL_SCORE_CONFLICT`；三条输出都在值域内、都带 reason |
| P5 | 变异体有牙（撤回态） | 恒 `CONSTANT` ⇒ P2/P3 转红；恒 `INJECTIVE` ⇒ P1 转红；拆掉 `RULER_BROKEN` 闸 ⇒ P4 的 1.2 臂转红 |
| P6 | 部署态（真池） | `v6_s208` 25 实现逐题 4 格分类 == STAGE0 手数（4×COARSE，桶逐一对上）；同池两次调用输出**逐字相同**（纯函数） |
| P7 | 值域与自洽 | kind 值域恰 4 名字；`CONSTANT ⇒ bits=0`；`INJECTIVE ⇒ bits=log2(n)`；`COARSE ⇒ 0 < bits ≤ log2(k)`；`resolution ∈ (0,1]`；`bits ≤ bits_max` 恒成立 |

**P5 的两个变异体是撤回态的全部内容**：判据若恒真，撤掉实现也应该绿 —— 那就白做。

## §3 边界（⛔ 不许放大）

1. **不提高任何分数**：本模块只做二次读数。⛔ 不改打分器、不改任何一格分数。
2. `UNKNOWN` 是**弃权**不是失败：宁可不判，不许拿坏读数断言「常数」（fail-open，
   与 V173 三条闸同构）。
3. 标签是 **(题 × 池)** 的属性：换池可以换标签（§0.3 的真池上 4 格全是 COARSE，
   而 §169.5 的小池上有单射/常数）。⛔ 不许把某池的标签写成题的属性。
4. ⛔ **不是异源判据**：它读的还是同一批分数（§169.7 的排除项仍有效 ——
   「换一套题面就能当异源判据」已被否决）。它是**给分数称重**，不是新秤。
5. 本轮**不做消费接线**（L5 提议器/L3 跳过决策怎么用它是下一刀）；
   ⛔ 不借接线的名义改 `propose()`/`escalations()` 的判据。
