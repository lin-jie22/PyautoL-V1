### 0.4 最刺眼的一条：混池把「全对」和「全错」平均成「中等」

`sg01~sg04` 每格两个口径各 1 行：

| 格 | `487a78e8`（会话 4） | `8974b37b`（会话 5） | 混池 mean |
|---|---|---|---|
| `sg02` | 1.0 | **0.0** | **0.5** |
| `sg03` | 1.0 | 0.2857 | 0.6429 |
| `sg04` | 1.0 | 0.4286 | 0.7143 |

⇒ 这是纪律 67 的教科书形态：**分母里混进另一把尺子的成员，比率先被平均成「中等」**，
而真相是「一把尺子全对、另一把全错」。混池给出的 0.5 是**两把尺子的算术平均，
不是任何一个口径下的读数**。

### 0.5 危害是不是「只是虚的比率」—— 两格实验说不是

```
口径 A：x 五行 0.4 / 口径 B：x 五行 1.0 / y 只有口径 A 五行 0.65
混池   → propose = [y, x]      x:0.700  y:0.650
单口径 → propose = [x, y]      x:0.400  y:0.650
```

⇒ **顺序翻转**。`propose` 的 `RAISE` 内部按均分升序（缺口大的在前），
混池把 x 的均分从 0.40 抬到 0.70 ⇒ 越过 y ⇒ **动作顺序被改写**。
这不是「读数更干净」，是**做事的次序变了**。

## §1 本轮命题

> **观测次数可以跨口径累加（次数是事实），均分不可以（读数是尺子的属性）。**

推论：`caliber_sig` 不同的行放进同一个池算 `mean`，得到的是**没有对应尺子的数**。
但它要不要现在改，得看「池里实际有没有两把尺子各占到能改变判据的行数」。

## §2 判据（三值：成立 / 不成立 / UNKNOWN）

### A 组 —— 真账本的结构事实

| # | 押 | 判据 | 若 UNKNOWN |

## §3 本轮做什么（可判定的自我约束）

1. **`mw/goals.py` 只加一个纯函数** `sig_report(rows, cells)`：
   逐格返回 `{cell, n_sigs, sigs, major, tie, mean_all, mean_major, n_obs}`。
   - `major` = 行数最多的口径（**并列 ⇒ `None`**，⛔ 不许用「最新/字典序」猜）
   - `mean_major` = 只在 `major` 非 None 时给，否则 `None`
   - `mean_all` = 现状（混池）的均分，**原样保留**，用于对照
2. **`run.py --goals` 多印 3 行**：混口径格数 / 其中平票格 / 逐个平票格的「两把尺子各是多少」。
3. ⛔ **不动 `propose` / `evaluate` / `stats` / `KINDS` / 任何判据常量。**
4. ⛔ **不动 `coerce()`**（V181 刚改过；`sig_report` 吃**裸行**，走 `G.load()` 的原样输出）。
5. ⛔ 不动 `ScoreLedger` 的闸（那道闸是对的，本轮只是让 `goals` 也看见）。

### 3.1 改判据的触发条件（写在这里，下一轮据此开题）

**当且仅当**下面任一条成立，`propose` 必须改成「按主口径算 `mean`」：

- `sig_report` 里出现「`n_sigs>=2` 且 `major` 非 None 且 `n_obs(major) >= MIN_OBS`」的格（本轮 A3 押 0）；
- 或 `tie=True` 且两口径各 ≥ `MIN_OBS` 行（平票 + 行数够 ⇒ 两个读数都成立，必须报冲突而不是选一个）。

⇒ 本轮只把**触发条件本身**做成可读的读数，不实现「满足后怎么办」。
