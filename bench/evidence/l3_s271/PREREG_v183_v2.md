B 臂（自由写关系）实测：过正确 **1/8**、咬错 **7/8**、判别力 **0/8** ⇒ P1/P2/P3 全部否。

⇒ **独立性（W2）与自造（W3）是两件事**：人写的关系库在同一批题上 6/8、过正确 8/8，
说明「判定交外部」这条路**在原理上走得通**；模型走不通是因为它**造不出装置**。

于是追加一问：**把算子库给它，只让它选算子 + 填槽（探针输入 / decode），能不能走通？**

## 1. C 臂的提示词（逐字）

给 6 个算子，每个一行语义，**不许它写判定逻辑**，只许输出一个 JSON：

```json
{"kind": "<算子名>", "inputs": [<python 字面量>...],
 "decode": "<可选：def decode(out): ...>",
 "leaves": "<可选：def leaves(x): ...>",
 "norm": "<可选：def norm(x): ...>",
 "keep": "<可选：表达式，用 s 和 n>",
 "bound": "<可选：表达式，用 n>"}
```

## 2. 算子（模板由**我方**写死，模型只填槽）

| 算子 | 模板（判定一律由模板算，模型不参与） |
|---|---|
| `ROUNDTRIP` | `decode(f(x)) == x` |
| `CONSERVE` | `Counter(leaves_out(f(x))) == Counter(leaves_in(x))` |
| `EMPTY_IFF_EQUAL` | `(f(a,b) == {}) == (a == b)`（inputs 是二元组列表） |
| `SUBSEQ` | `f(xs)` 是 `xs` 的子序列，且 `norm` 后两两不等 |
| `BOUND` | `len(f(s,n)) <= bound` 且短输入原样返回 |
| `TAIL` | `f(s,n).endswith(keep)` |

⛔ 模板里**没有任何任务名**（不是 per-task 硬编码），模型的选择与填槽才是不确定量。
⛔ 同一 8 题、同一 `partial`、同一 `oracle`、同一空实现、同一 `run_example`。
