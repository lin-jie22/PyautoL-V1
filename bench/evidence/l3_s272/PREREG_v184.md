## 二、装置改动（事前写死，跑后不许调）

### 2.1 产品侧新增 `mw/critgen.py`（⚠️ 不是探针私货）

V183 §251.5 的判词是「闸存在但**没有任何循环路径调用**」。本轮把算子库也搬进产品，
理由：**「系统自己造判据」的能力如果只活在 bench 脚本里，就永远是探针**。

| 接口 | 作用 |
|---|---|
| `arity(code)` | 纯 `ast` 读 `def` 的**必填位置参数个数**（有默认值的不算）⛔ 不执行 |
| `TYPES` | 4 个类型池（`str`/`int`/`dict`/`list`），逐字见 §2.2 |
| `OPS` | 算子签名表：每个算子声明 arity 要求、允许的槽、槽的**枚举值** |
| `build(kind, types, slots, fn)` | **装置**生成输入 + 渲染判据源码；⛔ 模型不写 inputs |
| `validate(kind, types, slots, n_args)` | 纯结构校验，返回一句可行动的错误 |
| `reachable(kind, n_args)` | 该算子在 arity=`n_args` 的函数上是否**结构可达** |

⭐ 关键差别（与 V183 `templates.py` 逐条对照）：

| 项 | V183 | V184 |
|---|---|---|
| `inputs` | 模型写 Python 字面量（**形状可错**） | **装置生成**（模型碰不到） |
| 参数个数 | 模型猜（实测 `dedupe_keep() takes 1 but 2 given`） | 装置从 `oracle` 的 `def` 读 |
| `decode` | 模型写任意代码 | 从**枚举**里选（`""` / `json.loads` / `parse_qsl` / `int` / `str` / `list`） |
| `keep` | 模型写表达式 | 从枚举里选（`""` / `tail_n` / `ellipsis_tail_n` / `head_n`） |
| `leaves_*`/`norm` | 模型写 | 装置固定实现（模型不再填） |

模型**只填值**：`kind`（枚举）+ `types`（4 个类型名组成的 list，长度必须等于 arity）+ 三个槽的枚举 id。

### 2.2 类型池（逐字写死；跑后不许改）

```
str  : "abcdef" | "" | "  a b  " | "A;B=1,2"
int  : 0 | 3 | 5
dict : {"b": 1, "a": 2} | {} | {"x": {"y": 1}}
list : ["b", "a", "b"] | [] | ["A", "a"]
LEN  : 1 | 3 | 9            # nat⁺，只用于 TAIL / BOUND 的第二个参数
```

输入生成规则（写死）：

- arity == 1：`[(v,) for v in POOL[types[0]]]`（该池全取，≤4 组）
- arity == 2 且 `types == [str, len]`（TAIL/BOUND）：
  `[("abcdef", 1), ("abcdef", 9), ("  a b  ", 3), ("", 1)]`
- arity == 2 其它：
  `[(A[0], A[0]), (A[0], A[1]), (A[1], A[1])]`（同型；第 1、3 组是**相等**对）／
  `[(A[0], B[0]), (A[0], B[1]), (A[1], B[0])]`（异型）

⚠️ `LEN` 从 1 起：`s[-0:]` 是整串，`n=0` 会让 TAIL 判据自相矛盾 ⇒ 池里排除 0（V183 没这层，属装置缺陷）。

### 2.3 可达性（**免费**的那一半，纪律 66）

`reachable(kind, n_args)`：`EMPTY_IFF_EQUAL` 要求 arity==2；`TAIL`/`BOUND` 要求第二个参数是长度；
其余要求 arity==1。

⛔ 可达性判断**不看 oracle 是否通过**（那是「有效性」，要付费）。
本轮的 `pass_oracle` 仍是**生成之后跑一次**的读数，不是模型可见的输入。
