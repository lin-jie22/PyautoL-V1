# V184 预注册 · v2 补充（**跑臂之前**落盘）

## 一、为什么有这份补充

`PREREG_v184.md` 落盘后跑 STAGE0，量出**装置自身**的三处缺陷。按纪律 88（先怀疑装置）
与纪律 67（分母不许混进不可达成员），这三处必须在跑臂前改掉并登记，⛔ 不许留到读结果时再解释。

## 二、改了什么（逐条）

### 2.1 通用池会造出**越界输入** ⇒ 加「圈域」一步

STAGE0 实测：`to_ini` 要求顶层值是 dict，池里 `{"b": 1, "a": 2}` 越界（`'int' object has no attribute 'items'`）；
`fmt_amount` 要数值，`str` 池整池越界。这类失败**不是判据弱**，是装置喂错了。

改法（写死，对所有题同规则）：

```
legal_indexes(code, fn, inputs) -> list[int] | None
```

- 在**目标实现**上逐组试 `fn(*a)`，抛异常的组剔除；
- ⛔ 只问「能不能吃」，⛔ 不问「返回值对不对」（后者是判别力 = 收费那一半，纪律 66）；
- 全组越界 ⇒ 记 `OUT_OF_DOMAIN`，不算判据失败；
- 探测故障 ⇒ `None` ⇒ 记 `PROBE_FAULT`，不算判据失败。

⭐ 逐格登记「圈域前/后组数」（`stage0_v184.json` 的 `domain` 字段），**报告里两个分母都写**（纪律 64）。

### 2.2 单参数输入曾包成 1-tuple 且 `fn(x)` 直传 ⇒ 8 题一起报 `'tuple' object has no attribute ...`

改为：`INPUTS` 统一是**实参元组**列表（单参 = 1-tuple），判据里 `for x, in INPUTS:`。
这是装置焊错，不是能力读数（纪律 88 同型：先怀疑装置）。

### 2.3 `TAIL`/`BOUND` 的类型约束放宽

原：`types == ["str","int"]`。改：`types[1] == "int"`（第一个参数可以是 str/dict/list，
`len()` 对三者都成立）。⛔ 不为任何一道题定制。

### 2.4 prompt 里明确给出**必填参数个数**

`arity` 由装置从 `def` 读（PREREG §2.1）。既然读到了却不告诉模型，就是**故意制造的形状失败**——
本轮要测的是「选算子 + 判类型」，不是「数 def 的参数」。⇒ 提问里写「必填参数 N 个」。
⛔ 这不泄漏任何判分信息（`def` 是题面交给做题人的东西）。
