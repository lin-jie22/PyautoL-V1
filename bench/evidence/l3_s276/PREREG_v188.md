## 一、问题：V187 登记的三条坏信号

| # | 形态 | V187 出处 |
|---|---|---|
| **S1** | `INVARIANT` 的「非退化」**对池敏感**：池里没有能触发不同输出的值 ⇒ **正确实现被判红** | §1.4-2、§3.3（C 臂 `g7e1`） |
| **S2** | `EMPTY_IFF_EQUAL` 在 `types[0] != types[1]` 时**恒真**（`a == b` 恒假 ∧ `got == {}` 恒假） | §1.4-1（STAGE0 `g7e2` 矩阵） |

**本轮的命题不是「修好它们会让分数涨」，而是：这三条是读数的可信度问题，还是分数问题？**
两者都能修，但修法完全不同 —— 前者改的是「这一格算不算证据」，后者要改判据本体。
⛔ 本轮**不许**为了让分数好看而改判据；判据源码必须逐字不变（见 §二.2 的机械自检）。

## 二、装置改动三条（逐字规则）

### 2.1 S2：`EMPTY_IFF_EQUAL` 要求两输入**同类型**（结构约束）

- `validate()` / `diagnose()` 各加一条：`kind == "EMPTY_IFF_EQUAL" and types[0] != types[1]` ⇒ 不过，
  `code="TYPES"`（⛔ 不新增 code —— `AZ148b` 钉着「四种 code 与 `CODES` 集合相等」）。
- 依据是**算子自身的语义**，不是便利：断言是 `(got == {}) != (a == b)`，左侧的 `⟸` 支
  （`a == b` 真）要求两输入可比；异类型时 `_inputs_for()` 永远造不出相等对 ⇒ 右支恒假 ⇒ 判据恒真。
- ⛔ 不改 `_inputs_for()`（同类型时它已经给出 `(a0,a0)/(a1,a1)` 两对相等 + 一对不等，`AZ145d` 钉着）。

### 2.2 S1：**判据源码不动**，改的是「判定算不算证据」

- 新增 `critgen.constant_on(code, fn, inputs) -> bool | None`：在**目标实现**上跑一遍池，
  回答「输出（`repr`）是不是全同」。`None` = 探测失败。
  ⛔ 只回答「恒定吗」，⛔ 不问「对不对」—— 与 `legal_indexes()` 同一条边界（纪律 66）。
- 读数层三值：

  | `oracle_const` | `pass_oracle` | 判定 |
  |---|---|---|
  | `True` | 任意 | **`UNDECIDED`** —— 池没有行使到正确实现，失败不可归因 |
  | `False` | `True` | `PASS` |
  | `False` | `False` | `FAIL`（可归因） |

- ⭐ **机械自检**：本轮前后 `build()` 对同一 `(kind, types, slots, inputs)` 的输出串必须**逐字相同**
  （`src_sha` 逐格比对）。这是「没有为了读数好看而放宽判据」的唯一证据 —— 只改分类，不改断言。
- ⚠️ 已知的不可分辨：常量实现（stub）与「正确实现落在池外」在装置眼里**同一个现象**（输出全同）。
  ⇒ `UNDECIDED` 只声明「不可归因」，⛔ 不声明「判据对」。这是本轮登记的口径代价，不是缺陷。

### 2.3 S3：`admit(src, params=())` —— 区分「写死答案」与「写死规格」

- 新签名 `admit(src: str, params: Sequence[str] = ())`。`params` = **设备渲染的规格参数名**
  （`critgen.spec_params(kind)`：`NUMFMT` ⇒ `("sep","dec","neg")`，其余 ⇒ `()`）。
- 规则：字面量与非字面量比较时，若非字面量侧是 `Name` 且 **该名字 ∈ `params` 且它是源码里
  某个 `FunctionDef` 的形参** ⇒ 不计为「字面量期望值」。
- 为什么这不是拆门：`NUMFMT` 的字面量**不是模型写的**，是装置从枚举表（3×4×2）渲染的；
  模型只能选枚举 id，正确答案由**同一把尺**在 oracle 上判（`AZ150a` 钉着 24 组合里恰好 1 个能过）。
  `admit` 要挡的是「模型自己写下的期望值」，那在此处不存在。
- ⛔ 后门防护：只认「形参」不认「模块级同名变量」，且 `params` 由装置给定，模型无权声明。
