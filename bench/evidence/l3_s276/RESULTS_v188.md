## 三、三条坏信号各自的收口

### 3.1 S2（`EMPTY_IFF_EQUAL` 异类型恒真）：**0 格命中** ⇒ 对模型读数零影响

- 结构约束：两输入必须同类型（`validate`/`diagnose` 都加，`code="TYPES"`）。
- 24 格里撞上「`EMPTY_IFF_EQUAL` 且 `types[0] != types[1]`」的：**0 格**（模型一致写 `["dict","dict"]`）。
- 装置空间里它确实有害：异类型 60 组里只有 8 组可建，其中 **INFORMATIVE 0 / VACUOUS 6 / HARMFUL 2**
  ⇒ **没有一格承载信息**（§四）。
- ⇒ 这是一条**装置卫生**：修它不会让任何人的分数变好，只是让装置不再生产恒真判据。

### 3.2 S1（池退化误伤）：修法**不能挂在算子上**

V187 把这一条记成「`INVARIANT` 的非退化对池敏感」。实测**第一格不是 `INVARIANT`**：
A 臂用的是 `ROUNDTRIP`，同样掉进去。⇒ 缺陷是 **(实现 × 池)** 的性质，与算子无关。

所以修法也没挂在算子上：`critgen.constant_on()` 问「这个实现在这组输入上输出是否全同」，
`critgen.verdict()` 把 `oracle_const=True` 判成 `UNDECIDED`。
⛔ 判据源码不动（I2 已证），改的是**这次判定算不算关于判据的证据**。

⚠️ 口径代价（写死在这里，⛔ 不许事后淡忘）：常量实现（stub）与「正确实现落在池外」在装置眼里
**同一个现象**。⇒ `UNDECIDED` 只声明「不可归因」，⛔ 不声明「判据没问题」。

### 3.3 S3（`admit` 与规格型判据）：翻 2 格，门没被拆

| 对象 | 旧 | 新 |
|---|---|---|
| B/C 的 `g7d3`（`NUMFMT`） | `False` | **`True`** |
| 其余 22 格 | 不变 | 不变 |
| V79 手写 22 条断言 | 判 False 19 条 | **判 False 19 条（零翻转）** |

口径：`admit(src, params=)`，`params` 由 `critgen.spec_params(kind)` 给（只有 `NUMFMT` 非空）。
跳过条件有两半：名字 ∈ `params` **且** 它是源码里某个 `FunctionDef` 的形参 ⇒
模块级 `sep = " "` 这种冒充被 `AZ151d-③` 挡住。

V79 那 3 条被放行的（`diff_tree(..) == {}`、`to_ini({}) == ''`、`parse_flag(" ") == None`）
全部是**空容器/空串/None** —— 模块文档里本来就写着「不算期望值」。
⇒ 它们的放行不是新口径的漏洞，是**旧口径的既定豁免**（见 §六 P3 的判错）。

|---|---|---|---|---|---|

⭐⭐ **异类型 8 个可建格里，承载信息的是 0 格**（6 恒真 + 2 连正确实现都跑不动）。

## 五、⭐⭐ 新装置**没有**清掉的那一族（本轮新发现，登记为 S4）

`space_v188.json` 里 6 格在新装置下**仍然 VACUOUS**，与旧装置逐格相同：

```
g7e2_truncate_tail  TAIL  ['dict','int'] / ['list','int'] × keep ∈ {tail_n, ellipsis_tail_n, head_n}
```

成因与 S1 **不同**：`constant_on()` 看不见它 —— 判据里 `if len(s) > n and ...` 这个**门槛**
在存活域上从未为真（`legal_indexes()` 剔掉越界组后，留下的组全都 `len(s) <= n`），
于是判据恒真而**输出并不恒定**。

⇒ **三值不是「是不是证据」的万能判据**：它只覆盖「输出恒定」这一族。
「谓词从未被行使」是另一族，需要另一把尺（`TAIL`/`BOUND` 该不该收非序列类型、
或该量「哪一支从未进入」）。⛔ 本轮不修 —— 那是一个新问题，不是本轮的第四处补丁。

### 11.1 撤回态的作用域，与三处**先于本轮**的缺陷

**取证方式**：`git worktree add /tmp/v1_v187 d56230b` 建 V187 干净树，在同一处跑同样三条。
读数**逐字相同**：

```
V187 树：AZ145c 红=['AZ145c','AZ148c'] 多红=['AZ148c']
        AZ145d 红=['AZ145d','AZ150c'] 多红=['AZ150c']
        AZ148b 变异锚点出现 0 次
```

⇒ 三处**都不是本轮引入**。

1. **`AZ148b` 的撤点从 V187 起就已失效**：它的 `old` 串里还写着
   `table = DECODERS if key == "decode" else KEEPS`，而 V187 已换成 `SLOT_TABLES[key]`
   ⇒ 报「变异锚点出现 0 次」。本轮改成 `diagnose()` 独有的四行
   （顺带避开 `validate()` 里同形的循环 —— 同一段文本出现两次也会被驱动器拦下）。
   ⚠️ 这一条意味着 V187 §255.8 的「撤回态 318」里**有一条从来没生效过**。

   而 `AZ150c` 正是拿一元 `INVARIANT` 跑正确实现的那条。⇒ 已按实测登记进 `COUPLED`。
3. ⭐ **`AZ148c` 曾对 `AZ151a` 是瞎的**：它原来 10 组枚举里没有一组异类型 `EMPTY_IFF`。
