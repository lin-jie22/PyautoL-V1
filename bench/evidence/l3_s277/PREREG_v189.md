## 0 为什么这一轮排第一

用户给的顺序是：**① 诊断结果改变下一轮判断（L2→L5 通电）→ ② 系统对弱点自己出题（L3）→ ③ 多 agent / 运行时自扩展**。

排第一的理由不是「它简单」，是**②依赖它**：系统要能「对弱点自己出题」，先得有一个能指出弱点、
且其输出**真的改变后续行为**的诊断。现在没有：

```
$ grep -rn "diagnose(" --include=*.py mw/
（零命中 —— 产品里没有调用点，只有契约测试和 bench 调它）
```

V185 已经量过一次「诊断 → prompt → 模型重选」：**两臂读数逐字相同**（模型把 `TAIL` 换成另一个
二元算子 `BOUND`）。⇒ 把诊断结果**说给模型听**不构成约束。

**本轮的命题**因此不是「加一个诊断」，是：**诊断的输出能不能改变下一轮的「可选空间」**，
即从「文本建议」变成「结构性收窄」。这是 L2（对失败成因的判断）→ L5（目标推进的可选域）唯一
可判定的通电形态。

## 1 已确认的前提（运行前离线取证，⛔ 不是读数）

### 1.1 信号种类来自判分三元组，不是来自我的分类

V187 冻结的 24 格，按 `(pass_oracle, bite_stub, bite_partial)` 分组：

| 三元组 | 格数 | 含义 |
|---|---|---|
| `(0,1,1)` | **14** | 咬住空实现与部分实现，却**误伤正确实现** |
| `(1,1,1)` | 5 | 完全判别 |
| `(1,1,0)` | 4 | 过正确、咬空实现，但**咬不住部分实现** |
| `NOBUILD/TYPES` | 1 | 结构不可达 |

### 1.2 ⛔ 一条硬边界：判分结果不许用来挑下一个算子

上表 14 格是「误伤正确实现」，看上去该「放宽」。但**任何用 `pass_oracle`/`bite_stub` 去挑下一个
算子的做法都是拿尺子挑尺子** —— 装置手里有 oracle，用它反推就是答案泄漏。

⇒ 本轮可用的结构信号**只有两个**：

| 信号 | 来源 | ⛔ 不能做什么 |
|---|---|---|
| `TYPES`（结构） | `diagnose()` 四码 | ⛔ 不能替换成「哪个算子更容易过」 |
| `CONST`（语义） | `constant_on()`：输出是否全同 | ⛔ 只问恒定，不问对错（与 V188 同一条边界） |

其余语义失败一律归 `SEMANTIC`，**动作只能是「删掉这个已被否证的算子」**。
这不是偷懒，是边界：对 `SEMANTIC` 我们**没有**任何不泄漏的信息说该换成谁。

## 2 装置设计

### 2.1 产品侧新增（`mw/critgen.py`）

```python
SIGNALS = ("OK", "STRUCT:TYPES", "STRUCT:OTHER", "CONST", "SEMANTIC")
read_signal(*, built, fail, pass_oracle, bite_stub, oracle_const) -> str
reachable(kind, types, oracle, fn) -> bool          # 该签名下这个实现吃不吃得下至少一组
narrow(signal, n_args, chosen, types, oracle, fn, *, scope) -> (dict, dict)
    scope="one"    # 只删 chosen —— B 臂
    scope="class"  # 按 signal 决定范围 —— C 臂
```

`narrow` 的 `scope="class"` 范围表（**写死**）：

| signal | 删除范围（`scope="class"`） |
|---|---|
| `OK` | 不删（`no_action`） |
| `STRUCT:TYPES` | 删该签名下 `reachable()==False` 的**全部**算子；⚠️ 若全删光 ⇒ 签名本身不可达 ⇒ 退回「只删 `chosen`」，标 `ALL_UNREACHABLE_SIGNATURE` |
| `STRUCT:OTHER` | 只删 `chosen` |
| `CONST` | 只删 `chosen` —— ⚠️ **运行前降级**：原设计是「删 chosen + 同签名下恒定者」，但后者要为每个候选枚举槽组合才能 `build()`（`NUMFMT` 36 组 × 候选数），成本与「拿槽值当先验」两样都不成立 ⇒ 撤掉，如实登记（许撤不许藏） |
| `SEMANTIC` | 只删 `chosen`（无信息说该换谁） |

⭐ **B 与 C 的唯一差别就是这个参数**，不是两套代码（纪律 65：装置要自报「我导入了谁」）。

### 2.2 三臂（同模型、同温度 0、同 8 题）

| 臂 | 轮次 | round k 的候选集 |
|---|---|---|
| `A` | 1 | `ops_for(n)`（= V186 `typed_filtered` 逐字重放） |
| `B` | 3 | `narrow(..., scope="one")` |
| `C` | 3 | `narrow(..., scope="class")` |

- round 1 的 prompt 三臂**逐字相同** ⇒ 装置自检：A 的读数必须与 V186 `typed_filtered` 逐格相同。
- round k≥2 的 prompt 只把目录段换成收窄后的 `catalogue(n, allow=...)`；骨架、说明、user 消息逐字不动。
- **硬拒**：模型写了不在候选集里的算子 ⇒ 记 `OUT_OF_CANDIDATE`，⛔ 不算 pass。
- 候选集空 ⇒ 记 `EXHAUSTED`，**从 pass 分母里剔除并单独报**（纪律 67：分母不许混进结构不可达成员）。

### 2.4 信号定义（**运行前补充**，⛔ 不是改押注；§3 一条未动）

| signal | 判定 |
|---|---|
| `STRUCT:TYPES` | `built=False` 且 `fail ∈ ("TYPES", "OUT_OF_DOMAIN")` —— ⚠️ **运行前补充**：`OUT_OF_DOMAIN`（结构过、实现吃不下）与 `TYPES` 是同一件事「该签名没有域」，归到 `OTHER` 会让 `narrow` 的签名分支对最常见的那种不可达视而不见 |
| `STRUCT:OTHER` | `built=False`，其他 |
| `CONST` | `built` 且 `constant_on() is True` |
| `OK` | `built`、非恒定、`pass_oracle ∧ bite_stub ∧ bite_partial` |
| `SEMANTIC` | 其余（含 `(1,1,0)`「过正确、咬空实现、但咬不住部分实现」） |

⭐ 把 `(1,1,0)` 归 `SEMANTIC` 而不是 `OK`：`disc` 的定义就是 `pass_oracle ∧ bite_partial`，
算成 `OK` 会让该题「第 2 轮不动作」，把收窄机会白扔（纪律 63：判「相同」时原语也是判据）。

### 2.3 三层读数，前两层不跑模型

| 层 | 内容 | 为什么单列 |
|---|---|---|
| L1 | **诊断覆盖率**：枚举全部可达 (算子 × 签名) 组合，量五类信号各占多少 | 这是「诊断能对多少格说话」的**上限**，与模型无关 |
| L2 | **收窄函数**：每格 `scope=one` vs `scope=class` 的删除集合 | 若两者恒等 ⇒ 诊断码无信息量（V168 同型） |
| L3 | **行为**：三臂 × 8 题 × ≤3 轮 | 唯一跑模型的一层 |

## 3 押注（三值；⛔ 不押幅度，只押结构）

| # | 押注 | 依据 |
|---|---|---|
| **P1** | L1 上 `SEMANTIC` 是最大类，占比 **>50%** | V187 24 格里 14/24=58%，但那是**被模型选过的**子集，可能偏高 ⇒ 押「趋同但不更高」 |
| **P2** | `scope="class"` 至少有一个信号导致删除数 **>1** | `STRUCT:TYPES` 的设计意图；若连这个都不成立，整个 C 臂是空操作 |
| **P3** | `scope="one"` 与 `scope="class"` 在 `SEMANTIC`/`STRUCT:OTHER`/`OK` 上删除集合**逐格相同** | 设计如此，这是**自检**不是发现 |
| **P4** | C 臂末轮 `pass` **不高于** B 臂末轮 | 「否证外推到类」可能删掉正确解 ⇒ 保守押「不更好」 |
| **P5** | 至少 1/8 题在 3 轮内 `EXHAUSTED` | 二元题候选只有 3 个（`EMPTY_IFF_EQUAL`/`BOUND`/`TAIL`） |
| **P6** | ⚠️ **运行前修正**（`CONST` 降级使原押注的差异面消失，原押「≥2/8」与新设计不符）：B 与 C 的选择序列在 **≥1/8** 题上不同，**且不同只允许出现在 round1 信号为 `STRUCT:TYPES` 的题上** —— 其余信号上 B≡C 是设计保证，⛔ 不是发现 | 差异面 = 「删一个」vs「删一类」；`SEMANTIC` 一格不动 |

⛔ 不押：pass 提升几个（纪律 40）。
⛔ 不押：C 一定更好（P4 就是反向押）。
⛔ 不押：`WEAK`/`(1,1,0)` 那一类 —— 它在 V187 的 24 格里 4 格，但在**本轮 round1**是否出现未知；
出现才报，不出现就写「未出现，未验证」（纪律 72 原型）。

## 3b 运行后补的对照臂 D（⚠️ 预注册之外，只用于分离归因）

跑完 A/B/C 后发现 §4 的 `F4` **无法被现读数据检验**：B 的 pass 3/8→4/8，但 B 与 A 同时差了
「多跑两轮」与「候选集在收窄」两件事，没有对照就分不开。⇒ 补 D 臂：**三轮、system 每轮逐字
重放 round 1、不删任何算子**。

- `D ≡ A` ⇒ 同 prompt 重跑不产生变化 ⇒ B 的差异只能来自收窄；
- `D ≠ A` ⇒ 「多轮」本身就有变化 ⇒ A→B 的归因必须打折。

⛔ 这一臂不改变 §3 的任何押注，也⛔不许拿它当新读数来「凑判别力」。

## 4 预注册的失败模式（出现即如实记，⛔ 不许当噪声）

| 代号 | 形态 | 含义 |
|---|---|---|
| `F1` | C 的 `class` 删除删掉唯一正确解 ⇒ pass 下降 | 「否证从实例外推到类」**不安全**，与 V183 W2 同型 |
| `F2` | 候选集 3 轮内耗尽 | 该题无解，剔出分母；同时说明「收窄」有下界问题 |
| `F3` | 模型写不在候选集里的算子 | 装置硬拒；计数即可，说明文本目录挡不住、只有硬拒挡得住 |
| `F4` | B 的读数与 A 相同（单轮=多轮） | 「多跑几轮」本身不产生变化 ⇒ 变化只能来自收窄 |

## 6 口径代价（写死在前面）

1. **8 题 / 单模型 / 温度 0**：一次读数是「这个模型在这 8 题上」，⛔ 不是「诊断有效」。
2. `narrow` 的 `CONST` 分支要跑 `constant_on()`（每个候选一次子进程），**成本记进读数**。
3. L1 的枚举是「装置空间」，⛔ 不等于模型会走到的路径（纪律 74）。
4. 若 P6 不成立 ⇒ 正确结论是「**诊断码的分类没有行为后果**」，而**不是**「诊断无用」：
   它仍可能改变「算不算证据」（V188 那一层）。两者别混。
