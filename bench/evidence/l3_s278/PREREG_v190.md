# V190 预注册：系统对弱点自己出题（L3）

> 用户定的顺序：① 诊断改变下一轮判断（V189 已做）→ ② **系统对弱点自己出题（本轮）** → ③ 多 agent / 运行时自扩展。
> 本轮只做 ②。**不跑模型**：弱点是 `(判据, 池)` 的性质，与模型无关（V187 §255 已量「判别力是
> `(判据, 输入域)` 的函数」）。⛔ 因此本轮**不许**出现「分数变好」这类措辞。

## 1 命题

> 系统能不能**自己发现**「这一格没有证据」（池退化），并**自己造出输入**把它翻开？

「翻开」的可判定形态只有一条：`constant_on()` 从 `True` 变 `False` —— 这一格从 `UNDECIDED`
变成有判定的格。⛔ 不要求变 `PASS`：**翻开坏消息也是翻开**。

## 2 弱点集（运行前冻结）

来源：`bench/evidence/l3_s277/space_v189.json` 的 216 格装置空间（8 题 × 可行算子 × 可行签名），
`sig == "CONST"` 的格 = 弱点集。

| 项 | 数 | 说明 |
|---|---|---|
| 总格数 | 216 | 含结构不可达 |
| 可达格 | 91 | `legal_indexes()` 至少放行一组 |
| **弱点格（`CONST`）** | **17** | 15 在 `g7e1_parse_flag`、2 在 `k01_diff_tree` |
| 其中 `reach=True` | 17 | 全部「看起来可达」 |

两种成因（运行前已复现，见 §2.1），本轮必须**分开报**，⛔ 不许合成一个「池退化」比例。

### 2.1 成因 A：词表缺口（15 格）

`parse_flag` 对 `POOL["str"]` 的四个值（`abcdef` / `''` / `  a b  ` / `A;B=1,2`）一律返回 `None`
⇒ 输出恒定。它的定义域是一个**词表**（`y/yes/1/n/no/0/off/false/true/on`），
⛔ 不是「结构上可枚举」的东西。

### 2.2 成因 B：签名错误被「空容器短路」误判为可达（2 格）

`k01_diff_tree` × `EMPTY_IFF_EQUAL` × `["str","str"]` / `["list","list"]`：
`legal_indexes()` 只放行 `('','')` / `([],[])` —— 因为空容器让 `for k in set(a)|set(b)` 的循环体
**一次都不进**，于是 `a.get` 那个 `AttributeError` 也不发生。

⇒ ⭐ **`reachable_on()` 会因退化输入而误报可达**。这是本轮运行前就量到的事实，
登记为独立结论，⛔ 不许当「生成器没本事」的解释。

## 3 装置（`mw/probe.py`，新增）

### 3.1 铁律：生成器**看不见实现**

```python
def expand(kind, types, *, sources=("mutate",), texts=()) -> dict
def structural(types) -> dict[str, tuple]     # 按类型做变异
def tokens(text) -> list[str]                 # 从一段文本取词元
def literals(src) -> list[str]                # ⚠️ 唯一读实现的入口，标 LEAK
```

`expand()` 与 `structural()` / `tokens()` 的签名里**没有** `oracle` / `fn` —— 结构上不可能
「跑一遍看输出变不变再决定留哪条」。⛔ 否则「池退化已修复」就是重言式（先挑出会变的输入，
再宣布它变了）。

唯一读实现的 `literals(src)` 只做 AST 取**字符串字面量**，⛔ 不跑实现；且它的产物
必须在 `prov` 里标 `LEAK`，⛔ 不许混进可部署臂。

### 3.2 五条臂

| 臂 | 输入来源 | 可部署？ | 作用 |
|---|---|---|---|
| `A` | 原池 | — | 基线 |
| `B` | `structural()`：大小写/空白/首尾/分隔符/截断/数值边界/嵌套 | ✅ | 「变异器够不够强」 |
| `C` | 同尺寸随机噪声（**同数量**、同类型、种子固定） | ✅ | 对照：排除「只是加了更多输入」 |
| `E` | `tokens(记忆条目正文)` | ⚠️ 假设条目**已取到** | 记忆通道的上限 |
| `D` | `literals(实现源码)` | ❌ **泄漏** | 只用来量「盲区里有多少是词表」 |

⭐ `C` 是本轮最重要的对照：若 `C ≈ B`，说明「转可判」与**内容**无关，只与**数量**有关。

### 3.3 `E` 的口径（必须先说清）

种子惯例（`bench/build_g7d_seed.py` 的 `FACTS`）对 `g7e1` 的正文是：

> 开关惯例：只把 y/yes/1 当成真，'true'、'on' 这类历史脏值一律算假，其余无法识别的返回 None。

`tokens()` 从中取到 `y / yes / 1 / true / on`（**不含** `n/no/0/off/false`）。
⚠️ 已知 `recall()` 按题面检索**取不到**本题条目（`build_g7d_seed.py` 的 R1 预检从第三十七轮起必然失败）。
⇒ `E` 量的是**记忆取到之后**的上限，⛔ 不是部署能力。这条必须写进结论。

## 4 判据

每格每臂记：

```
n_legal      legal_indexes(expanded_pool) 放行几组
const        constant_on(oracle, fn, legal)   ← True/False/None
verdict      UNDECIDED（const 为真或 None）/ PASS / FAIL
```

主读数：`UNDECIDED → decidable` 的格数（**分母 17**）。
次读数：在 199 个本来可判的格上，判定翻转数（`PASS→FAIL` / `FAIL→PASS`），
用来看「扩池是揭开真相还是制造噪声」。

**判据源码校验（对应 V188 的 I2）**：同一格跨臂的判据必须**只差 `INPUTS` 一行**。
把 `^INPUTS = .*$` 归一成 `INPUTS = <POOL>` 后取 sha256，跨臂必须全等。
⛔ 不等 ⇒ 说明不是「换池」而是「换了判据」，读数作废。

## 5 押注（跑前锁定）

| # | 押注 | 理由 |
|---|---|---|
| **P1** | `B`（结构变异）在 17 格上转可判 **0 格** | 15 格要词表、2 格要换签名；变异器两样都给不了 |
| **P2** | `C`（随机噪声）转可判 **0 格** | 同上，且随机串更不可能落在 `parse_flag` 的词表里 |
| **P3** | `E`（记忆词表）在 `g7e1` 的 15 格里转可判 **≥12 格** | 取到 5 个词元，其中 3 个输出不同（`True/False/None`）⇒ 必不恒定 |
| **P4** | `D`（泄漏）转可判 **≥ E**，且 `k01` 的 2 格在**任何臂**下都转不了 | 字面量覆盖全套词表；`k01` 缺的是 dict 签名，任何输入都救不了 |
| **P5** | 转可判的格里，**多数变 `FAIL` 而非 `PASS`**（≥ 8/15） | 这些格子原来的 `CONST` 掩盖的多半是「判据根本不适用」（`ROUNDTRIP` 用在返回布尔值的函数上） |
| **P6** | 199 个可判格上，`B` 的判定翻转 **≤ 10%** | 变异器只加边界值，不该大范围改判 |

⛔ 六条都按「押方向 + 押幅度」写死。跑完照实报，押错不打折。

## 6 本轮的失败模式

| # | 形态 | 处理 |
|---|---|---|
| F1 | `expand()` 造出的池让 `legal_indexes()` 全放行，但 `build()` 失败 | 记 `SHAPE_BUILD`，⛔ 不算「转可判」 |
| F2 | 某臂的「转可判」全靠 1 个格撑起 | 报格清单，不报百分比 |
| F3 | `E` 的 `tokens()` 把整句中文当一个词元 | 这是装置缺陷，先修再跑（`tokens` 必须有长度上限） |
| F4 | 跨臂 sha 校验不过 | 读数作废，查是不是 `slots` 也动了 |
| F5 | 转可判但 `pass_oracle is None`（判分崩了） | 单独记 `CRASH`，⛔ 不算 `FAIL` |

## 7 边界（写进结论）

- 8 题 / 26 实现 / 单次；⛔ 不跑模型 ⇒ 不能声称「模型会因新池选得更好」。
- 弱点集来自 L1 的**抽样槽值**（每个槽表取第一个非空值），不是全枚举。
- `E` 假设记忆条目已取到 —— 而实际 `recall()` 取不到（已记）。**这是本轮最大的缺口，不是可以忽略的细节。**
- ⛔ 不说「系统会自己变强」「L3 完成」。准确说法只能是：**弱点被翻开了多少格、翻开后是多少坏消息**。

## 8 运行后更正（⛔ 不许静默改预注册，只许追加）

### 8.1 §4 的分母错了：**74**，不是 199

§4 写「199 个本来可判的格」= 216 − 17。这是错的：216 格里 **125 格结构不可达**（`legal_indexes()` 一组都不放行），
它们本来就没有「判据好不好」这回事。可测的只有 **91** 格（`reach∈True ∧ const≠None`），
其中弱点 **17**、本来可判 **74**。

⇒ 全部读数改用 **74**。这条正是纪律 67 的原型，我在自己的预注册里犯了一次。

### 8.2 §5 P5 降级为 UNKNOWN

P5 写「转可判的格里 ≥8/15 变 FAIL」。实测只翻开 **5** 格 ⇒ 分母 15 没成立。
按 5 格看是 4 `FAIL` + 1 假绿，方向与押注一致，但**幅度押注没被检验**。
⛔ 不许把分母从 15 改成 5 再判 ✅（那是事后调分母）。

### 8.3 §4 自检 I3 的措辞太强

§4 I3 写「`D` 臂的 `leak` 旗标必须为真」。实际只有 **20/91** 为真，另 71 格是**对的**：
`dict`/`list` 格加不进字符串；`g7d2` 的实现里**一个字符串字面量都没有**（连作弊都没料）。
判定改为：`leak=True` 的集合 ⊆ 含 `str`/`flag` 的格，且 `literal` 源为空时**必须**为假。
