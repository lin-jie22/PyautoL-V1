# V191 预注册：把「池退化」拆成病名，先量诊断会不会误诊

> 承 V190（§258）。V190 的下一刀写的是「签名级重选，直接吃掉 12/17」。
> **本轮先检验这句话本身**，⛔ 不默认它成立。
> ⛔ 不跑模型；弱点是 `(判据, 池)` 的性质。

## 1 命题

> V190 把 17 个盲区格说成「5 格缺词表 + 12 格签名错」。这是**两个病**吗？

如果不是 —— 如果「缺词表」只是「类型错」的一个外观 —— 那么 V190 的下一刀 #2
（签名重选吃掉 12/17）与 #1（拆两种病）就是**同一件事的两种说法**，
而真正的可判收益也不是 12，是别的数。本轮把这个数算出来。

## 2 弱点集（沿用 V190 冻结口径，⛔ 不改）

来源 `bench/evidence/l3_s277/space_v189.json`：216 格中 `reach=True ∧ const≠None` 的 **91** 格，
其中 `sig == "CONST"` 的 **17** 格。构成（V190 已量）：

| 组 | 格数 | 签名 |
|---|---|---|
| `g7e1_parse_flag` × 5 算子 × `["str"]` | 5 | 词表缺口（V190 的 `E` 臂翻开这 5 格） |
| `g7e1_parse_flag` × 5 算子 × `["dict"]` / `["list"]` | 10 | 签名错 |
| `k01_diff_tree` × `EMPTY_IFF_EQUAL` × `["str","str"]` / `["list","list"]` | 2 | 空容器骗可达 |

## 3 装置（`mw/probe.py` 追加）

### 3.1 只用**免费信息**

`route()` 判病只看两样，都不吃判分（纪律 66）：

1. 结构事实：`legal_indexes()` 放行几组（吃得下吗）；
2. 输出是否恒定：`constant_on()`（有没有产出差异）。

⛔ 不读 `pass_oracle`。⛔ 不按「哪个签名更容易过」排序 —— 签名枚举用 `TYPES` 的**声明序**，
取第一个「有域且输出不恒定」的。拿判分排序就是拿尺子挑尺子。
（可被这条烧到的后果：重选出来的签名一定是**已经存在**的那个格。见 §5 P3 —— 那不是 bug，是定理。）

### 3.2 五个函数

```python
sig_space(kind, n)                      # 该 arity 的可行签名（声明序）
varies(kind, types, oracle, fn, *,
       pool=None) -> bool | None        # 有域且输出不恒定？None = 无域/探测失败
degenerate_free(pool, types)            # 剔掉 "" / {} / [] / () / 0 / 0.0
false_reach(kind, types, oracle, fn)    # 可达，但剔掉退化输入后不可达
route(kind, types, n, oracle, fn) -> {
    "disease": "RESIGN_FREE" | "RESIGN_VOCAB" | "NEEDS_VOCAB" | "DEAD",
    "target": [types] | None, "cost": "free"|"vocab"|None, "probes": int }
```

`disease` 的定义（顺序即优先级）：

| 值 | 判据 | 后果 |
|---|---|---|
| `RESIGN_FREE` | ∃ 另一签名在**基池**上 `varies` | 换签名，免费 |
| `RESIGN_VOCAB` | 无免费目标，但 ∃ 签名在**扩池**上 `varies` | 换签名 + 换池 |
| `NEEDS_VOCAB` | 只有当前签名在扩池上 `varies` | 只换池 |
| `DEAD` | 全都 `varies=False` | 无动作，如实记 |

另有三个**守卫值**（不是病名，只在调用方给错了格时出现）：
`HEALTHY`（当前签名本来就 `varies`，不需要路由）、`NO_DOMAIN`（当前签名连域都没有）、
`FAULT`（探测失败）。⛔ 三者都**不许**算进 `DEAD`（F1）。

⛔ `route()` 的参数表里不许出现 `pass_oracle` / `correct` / `expected`。

## 4 主读数（2×2，分母 17）

|  | 原签名 | 重选后签名 |
|---|---|---|
| **原池** | `0/17`（V190 `A` 臂，已有） | 本轮新测 |
| **扩池** | `5/17`（V190 `E1` 臂，已有） | 本轮新测 |

外加 **collapse 账**：17 格重选后落在几个**不同的** `(算子, 签名)` 配置上；
这 7 个（若 P2 成立）配置里，有几个在 216 格空间里**本来就有判定**。

## 5 押注（跑前锁定）

| # | 押注 | 依据（读源码推的，⛔ 没跑） |
|---|---|---|
| **P1** | `route()` 在 17 格上**全部** `RESIGN_FREE`；`NEEDS_VOCAB = 0`、`DEAD = 0` | `parse_flag` 第一句是 `str(s).strip().lower()` ⇒ **任何类型都收**；基池 `int = (0,3,5)` 里 `0` 的字符串正是词表里的假值 ⇒ `["int"]` 在基池上就不恒定 |
| **P2** | 目标只有 **2 个**：`["int"]`（`g7e1` 15 格）、`["dict","dict"]`（`k01` 2 格） | `TYPES` 声明序 `str→int→dict→list→num→flag`；`g7e1` 的第一个非退化是 `int`，`k01` 的 `EMPTY_IFF` 签名是 `[t,t]`，第一个有域的是 `dict` |
| **P3** | 17 格重选后的判定与 `space_v189.json` 里**目标格**的判定**逐格相同**，⇒ 新增可判配置 **0** | 签名一换，判据源码（除 `INPUTS`）逐字相同 ⇒ 同配置必须同判。这是恒等式，不是发现 |
| **P4** | `false_reach` 在 91 个可达格里**恰好 2 格**，且**全在**弱点集里 | V190 §2.2 已量过同一件事（剔空容器后仅 `k01` 两格变不可达）；本轮是把它从脚注做成产品函数，并扩到全 91 格 |
| **P5** | V190 `E1` 臂翻开的 5 格，`route()` 全判 `RESIGN_FREE`（**5/5**） | 同 P1：词表轴被签名轴包含 |
| **P6** | `g7e1` 那 15 格重选后的判定 **FAIL ≥ 12/15** | `ROUNDTRIP` 拿 `json.loads` 解 `True/False/None` 必崩；`CONSERVE`/`SUBSEQ` 在布尔输出上也不成立 |

⛔ 押错不打折。P1 若错（出现 `NEEDS_VOCAB`），说明词表轴**独立**于签名轴，V190 的 5 格是独立一类
—— 那也是有信息的结论，照实报。

## 6 失败模式

| # | 形态 | 处理 |
|---|---|---|
| F1 | `route()` 把「无域」读成「恒定」 | 分开记 `NO_DOMAIN`；⛔ 不许算进 `DEAD` |
| F2 | 重选目标**自身**仍恒定 | 记 `RESIGN_LOOP`，⛔ 不算转可判 |
| F3 | 「17 格 → 2 配置」被写成「17 格都修好了」 | 报告必须同时给**格数**与**配置数**两个分母（纪律 64） |
| F4 | 拿 `pass_oracle` 参与选目标 | 读数作废 |
| F5 | 签名枚举顺序随探测结果变 | 断言 `sig_space()` 两次调用逐字相同 |

## 7 边界（写进结论）

- 8 题 / 26 实现 / 单次；⛔ 不跑模型 ⇒ 不能声称「模型会选得更好」。
- 弱点集是**抽样槽值**（每槽取第一个非空值）的子集，不是全枚举。
- `RESIGN_FREE` 的「免费」是**口径上的免费**（不吃判分），⛔ 不是「零成本」：每次 `varies()` 是一次子进程。
