# V193 预注册（第 293 轮）：给量具造一条真入口 —— `run.py --verify-impl`

写于开跑前。⛔ 跑后不许改判据；判据变更走「追加 §N+1 + 标注失效范围」。

---

## §0 为什么

V192 量出：V184~V191 的 33 个函数在部署面引用 **0** 次，因为链路里没有「挑判据」这一步。
用户在三个方案里选了 **C：最小真入口**。

本轮做两件事：

1. **造入口**：`run.py --verify-impl <file>` —— 把 `critgen` / `probe` 接进一条真链路；
2. **量它的牙齿**：这条入口到底能分开什么、不能分开什么。

---

## §1 入口的设计边界（写死，⛔ 不许边说边改）

部署端**没有 oracle**。所以这条入口只能付三种**免费**信息：

| 能答 | 用什么 |
|---|---|
| 这个算子在这签名上结构可达吗 | `critgen.ops_for(n)` + `probe.sig_space(kind, n)` |
| 这组输入落不落进候选的定义域 | `critgen.legal_indexes(code, fn, inputs)`（返回**索引**） |
| 候选在这组输入上有没有产出差异 | `critgen.constant_on(code, fn, legal)` |

⛔ **输出里不许出现 PASS / FAIL。** 一旦出现，这条入口就变成「不发工资的尺子」——
它对错判不了，只能说「这个候选能不能被区分出来」。

四个信号名（写死）：`VARIES`（有产出差异，可区分）／`CONST`（输出全同，与桩不可分）／
`STRUCT:TYPES`（候选在这组输入上没有合法域）／`FAULT`（探测失败）。

### §1.1 一个必须显式处理的退化

`arity()` 不数 `*args` / `**kwargs`。桩若写成 `def f(*a, **k): return None`，
读出的必填参数个数是 **0**，`ops_for(0)` 空 ⇒ **一格都没跑**。
⛔ 不许打一张 0/0/0 的表 —— 那是「没跑」冒充「都不行」。必须返回码 2 并说明原因。

## §2 实验（离线，无 LLM）

对象：`bench/heldout/` 两个套件共 **8 题** × 4 种实现：

| 实现 | 来源 |
|---|---|
| `oracle` | 题集自带正确实现 |
| `partial` | 题集自带半对实现（不是本轮写的） |
| `stub_none` | 本轮写：签名照抄题面，`return None` |
| `stub_star` | 本轮写：`def f(*a, **k): return None`（检验 §1.1） |

每题每实现跑一次入口（`--json`），记录 `tally` 与返回码。

## §3 预注册判据

| # | 判据 | 押 |
|---|---|---|
| **P1** | `oracle` 的 `VARIES` > 0 | **8/8**（否则入口连正确实现都认不出可区分） |
| **P2** | `stub_none` 的 `VARIES` == 0 | **8/8**（否则这道闸漏桩） |
| **P3** | `oracle` 与 `partial` 的 `tally` **逐题相同** | **8/8** ⇒ 入口对「半对」判别力 **0**（这是本轮的负结果，押它会中） |
| **P4** | `stub_star` 返回码 == 2 且输出含「一格也没跑」 | **8/8** |
| **P5** | 32 次调用总耗时 ≤ 180 秒 | 是 |
| **P6** | 接入后 `AZ155a`（原钉「部署面不碰三模块」）转红 | 是 ⇒ 这是接线自证 |

### §3.1 反证（纪律 60）

- **R1**：`AZ155a` 改成钉「部署闭包**含** `critgen` 与 `probe` 且引用数 > 0」之后，
  撤回态（删掉 `cmd_verify_impl` 里那两行 import）必须让它**精确转红**。
