预注册 `PREREG_v193.md`（跑前写死）。读数 `readings_v193.json`，脚本 `arms_v193.py`（**36.5 秒**）。
⛔ 不跑模型。**5/5 命中 + P6 自证**。

## 一、做了什么

V192 量出：V184~V191 的 33 个函数在部署面引用 **0** 次，链路里没有「挑判据」这一步。
用户选 C（最小真入口）。于是新增：

```bash
python3 run.py --verify-impl <候选实现.py> [--fn 函数名] [--json]
```

它只付三种**免费**信息，⛔ 输出里没有 PASS / FAIL：

| 信号 | 判据 |
|---|---|
| `VARIES` | 候选在这组输入上**有产出差异**（可被区分） |
| `CONST` | 输出全同 ⇒ **与桩不可分** |
| `STRUCT:TYPES` | 候选在这组输入上没有合法域 |
| `FAULT` | 探测失败（超时 / 没吐标记） |

实现只用 `critgen.ops_for` / `probe.sig_space` / `critgen.inputs_for` / `critgen.legal_indexes`
/ `critgen.constant_on`。**没有一个参数是 oracle**，因为它不存在。

## 三、判词：这是一道**桩检测器**，不是一把尺子

⭐ **P3 是本轮最重要的一条**：oracle 与 partial 的 tally **8/8 逐格相同**。
也就是说这条入口对「半对实现」的判别力是 **0** —— 它看得出「输出恒定」，看不出「差一条惯例」。

| 它能分开 | 分不开 |
|---|---|
| 恒输出候选 ↔ 有产出差异的候选（8/8） | 正确 ↔ 半对（0/8） |
| arity 不匹配（rc=2 显式报错） | 「输出有差异」里的对与错（那要 oracle，收费） |

⇒ 这正是 V191 那条定律的又一次落地：**免费信息只能修「问得出问题」，不能加「答案」**。
入口能替你省掉「明显是桩的候选」的判分，省不掉判分本身。

⭐ 但它完成了 V192 缺的那颗钉子：**部署面引用从 0 变成非 0**。
`AZ155a` 从「钉 0 引用」翻成「钉接上了 critgen + probe + 属性访问 ≥3 次」，
撤回态（删两行 import）精确转红、无多红 —— 这条接线是**有证据的**，不是「我改了代码」。

⚠️ `metacrit` **仍然没接**（0 引用）。锚点只钉已接的两个，不假装全家都通。

## 四、自踩 3 条

1. ⛔ **API 用错**：`legal_indexes()` 返回的是**索引**不是实参，初版直接喂给 `constant_on()` ⇒
   `TypeError: 'int' object is not iterable`。读它的 docstring 才看见 `return [i for i, v in ...]`。
2. ⛔⛔ **判据代码自己把正确读数判成 ❌**：初版写 `(tall(...) or -1) != 0`，而 `0 or -1` 得 **-1**
   （0 是假值）⇒ 「桩一格 VARIES 都没有」这个**正确**读数被判失败。
   ⇒ 判「等于零」时不许用 `or` 兜底（纪律 63 同型：判数值的原语也是判据）。
3. ⛔ **0 格冒充「都不行」**：桩写成 `def f(*a, **k)` 时 `arity()` 数出 0 个必填参数，
   `ops_for(0)` 空 ⇒ 一格没跑，而表打成 `0/0/0`，读起来像「什么也没发现」。
   已改成显式 rc=2 + 说明（这是**产品行为**，不只是本轮装置）。

## 五、这轮让累积离可测更近了吗

**近了一步，而且是形式不同的一步**：

- 前八轮（V184~V191）加的是**读数**；V192 把读数判成**量具**；V193 第一次把量具**插进链路**。
- 可验证的形式：部署闭包对 `critgen`/`probe` 的引用从 **0** 变成非 0，且由锚点守着。
- ⛔ 不说「L3 打通了」：接上的只有「免费那一半」。判对错仍然没有入口，
  因为部署端没有 oracle —— 这条限制**没有因为接线而消失**。
