# V194 预注册：免费闸接进 bench 之前，先量「筛掉的有多少真该筛」

日期：2026-11-18　⛔ 本文件写于**任何真实答案产生之前**。写完才开始跑模型。

## 0. 上一轮留下的岔口（必须原样接上）

V193（§261）造了 `run.py --verify-impl`，部署面对 `critgen`/`probe` 的引用从 0 变非 0。
但那个入口**没有调用方** —— 它是一条「造好了、没人用的路」。当时登记的下一刀：

> 把入口接进 `--bench` 的候选筛选，**先量「筛掉的有多少真该筛」**。

⛔ 先量再接，不许反过来。若先接再量，量到的就是「我接的对象」的精密度，而不是「这道闸值不值得接」。

## 1. 一个问题

> 把 `--verify-impl` 的判据放在 bench 的「答案 → 判分」之间（即**花掉一次判分之前**），
> **它筛掉的候选里有多少真该筛？真该筛的它筛掉几个？**

拆成三个可数的量：**触发率**（它到底动不动手）、**精密度**（筛掉的对不对）、**召回**（该筛的漏没漏）。
⛔ 三者缺一，结论都会被读成「闸好用」或「闸没用」——都不成立。

## 2. 池（跑前固定，⛔ 不许事后增删）

`bench/heldout/` 下全部 9 个 jsonl（27 题）+ `bench/tasks/coding_small.jsonl`（6 题）= **33 题**，
每题 **1 次**真实作答（`qwen2.5:7b`，T=0，`--no-ledger`）。

选它的理由：
- 三把已登记的尺子都在里面（`g7j_n4` / `struct_convert` / `numeric_logic`），
  `coding_small`（0.9722）也在 —— 高分池正好用来测**误伤**；
- 全是**现有**题集，本轮不造任何新题、新尺子。

⚠️ 为什么每题只 1 次：T=0 下重复作答近乎逐字相同（V36：多数轮次不是扰动小，是输入相同），
`--repeat 3` 只会把同一个格数三遍，制造虚假分母。分母口径写在这里，后面报数一律写 `分母=33`。

## 3. 闸的定义（跑前锁定，⛔ 读数出来后不许调阈值）

对每个答案：

1. 用**打分器自己那份**抽取器 `bench/scorers/code_exec.py:extract_code()` 从答案里取代码
   —— ⛔ 不另写一套抽取，否则闸看的代码和判分跑的代码不是同一段（纪律 61）。
2. `fn` 从**题面**取：`tests` 里第一次出现的被调函数名（正则），取不到时退到 `oracle` 的第一个 `def`。
   记录每个答案用了哪个来源（`from_tests` / `from_oracle` / `none`）。
3. 调**真入口**：`python3 -u run.py --verify-impl <tmp> --fn <fn> --json`（纪律 95：走真入口，不调副本）。
4. 判定：

| 判决 | 条件 |
|---|---|
| `DROP` | 退出码 0，且 `tally["VARIES"] == 0`（每格都是 CONST / FAULT / STRUCT） |
| `ABSTAIN` | 退出码 2（arity 读不出 / 语法错 / 没 def）⇒ **放行**（fail-open） |
| `KEEP` | 其余（退出码 0 且 `VARIES > 0`） |

⭐ `DROP` 的语义严格限定为「**候选对输入完全不敏感**」。⛔ 不含「可能错」「看起来简略」这类判断
—— 那需要 oracle，是收费那一半（V191 定律）。

## 4. 真值

`report.per_task` 里的 `score`（打分器真跑出来的）。
**「真该筛」= `score == 0.0`** —— 这次判分一分也拿不到，等于白花。

⚠️ 分母口径（写进字段名）：`zero=score==0` 与 `imperfect=score<1` 两个都报，⛔ 只在事后挑一个好看的。
主判据用 `zero`；`imperfect` 只作参考，因为「半对」本来就已知筛不掉（V193 P3）。

## 5. 押（三值：成立 / 不成立 / UNKNOWN；⛔ 不许事后改措辞）

| # | 押 | 判定 |
|---|---|---|
| P1 | **触发率低**：`n_drop ≤ 2`（33 题里至多 2 个答案输出完全不敏感） | 成立 / 不成立 |
| P2 | **精密度满**：`DROP` 的答案 `score==0` 占 100% | 成立 / 不成立 |
| P3 | **召回低**：`recall ≤ 0.5`（真该筛的漏一半以上） | 成立 / 不成立 |
| P4 | **盲区为零**：`n_abstain == 0`（33 个答案都能读出 arity） | 成立 / 不成立 |
| P5 | **分母够用**：`zero ≥ 2`；不成立则 P3 判 `UNKNOWN`（⛔ 不许拿 1 个格算比率） | 成立 / 不成立 |
| P6 | **装置有牙（自证）**：把闸改成恒 `KEEP` ⇒ `n_drop` 必须变 0；改成恒 `DROP` ⇒ P2 的精密度必须下降（因为池里必有 `score>0` 的答案） | 两个方向都动才算成立 |
| P7 | **省的判分不到一成**：`n_drop / 33 < 0.10` | 成立 / 不成立 |

⭐ P7 与 P1 不是同一条：P1 数个数，P7 数占比。若 P1 成立而 P5 不成立，只报 P1、把 P7 降级为弱证据。

## 6. 装置自检（跑前定义，⛔ 不许事后补）

- **I1** 抽取一致性：闸看到的代码字符串 == 打分器抽取的代码字符串（逐字节，33/33）。
- **I2** 血缘：`report.provenance.llm_kind == "http"` 且 `model` 含 `qwen2.5:7b`。
  不成立 ⇒ 本轮全部读数作废（静默退化成 oracle 时答案会是满分，看起来像「闸全放行」）。
- **I3** 分母闭合：`len(答案) == 33` 且 `len(score 表) == 33`，每个答案都能 join 到分数。
- **I4** 幂等抽查：随机 3 个答案跑两次 `--verify-impl`，`tally` 逐字节相同。

## 7. 这轮**不**做的事

- ⛔ 不改内核：不动 `mw/core.py` 的候选分叉（那是方案 A，要碰主循环）。
- ⛔ 不因为读数好看就把闸接进去；接不接是**下一轮**的事，且要另立预注册。
- ⛔ 不说「L3 打通了」。闸即使精密，也只省判分次数，不加判别力（V193 P3 已证）。
- ⛔ 不造新题、新尺子、新探针：池全是现有题集，闸是现有入口。

## 8. 成本上限

33 题 × 1 次 ≈ 每轮 45s ⇒ **≤ 30 分钟**；闸侧 33 次子进程 ≈ 1.2s each ⇒ **≤ 1 分钟**。
超时或任一 suite 崩掉 ⇒ 如实报「分母不足」，⛔ 不补跑凑数。
