## 1. A1 静态普查：`task` 到底有几个来源

| 位置 | 类别 | 内容 |
|---|---|---|
| `mw/core.py:457` | **值** | `{"task": str(goal)}` ← 唯一的代码构造器（`answer_task`） |
| `mw/tools.py:378/394` | schema | `{"task": "交给该 agent 的任务"}`（参数说明，不是值） |
| `mw/tools.py:387` | 读取 | http 分支 `args.get("task")` |
| `mw/bench.py:315` | 无关 | 打分器子进程载荷 `{"task":…, "answer":…}` |
| `run.py:286` | 无关 | 轨迹行 `{"task": task_id, …}` |

`cand.args` 赋值 3 处，**只有 1 处能改 agent 的入参**：

| 位置 | 右值 | 守卫 |
|---|---|---|
| `core.py:1469` | `answer_task(goal, _dl2)` | `if spec is not None and spec.produces_answer` ⇒ **无条件** |
| `planner.py:677` | `dict(st.args)` + `["answer"]` | 外层 `if st.tool == "finish"` ⇒ 碰不到 agent |
| `planner.py:708` | 同上（补救路径） | `blank` 已按 `tool == "finish"` 过滤 ⇒ 碰不到 agent |

`answer_task()` 调用 2 处：`core.py:1380`（门 B 注入）与 `core.py:1469`（门 A 覆写）——**两处实参都是 `goal`**。

**⇒ 结论（结构）**：答案型 agent 的入参有且只有一个来源 = 题面原文；上游在**执行点**被丢弃，
不是"想不起来传"，是**写死覆写**。

## 3. A3 契约：不是"只认原文"，是"只认函数名"

真入口 `external/code_agent.py`（sha 自报 `2978ffabe0f37b5e`），把 `_chat` 换成记录器：

| payload | 判决 | 进模型次数 | prompt 含上游 |
|---|---|---|---|
| V1 题面原文 | `PROCEED` | 3 | — |
| V2 题面 + 上游 | `PROCEED` | 3 | **True** |
| V3 上游 + 题面 | `PROCEED` | 3 | **True** |
| V4 只有上游（无「函数名必须是 X」） | `REFUSE` | 0 | — |
| V5 空 | `REFUSE` | 0 | — |

⭐ **这是本轮唯一一条新信息**：`code_agent` 自述「输入只有题面原文，多一个字都没有」，
但实测**上游文本能一路进到 prompt**。它的墙不是"原文 purity"，而是
`_FUNC_NAME` 那一条正则（`函数名(?:必须|应)(?:是|为)`）——**缺函数名才拒答，带上游不拒答**。

⇒ 由此把 V66/V67 那次判决（门 B `1.0000` vs 门 A `0.0000`）的病因**改判**：
不是"中继有毒"，是"那次中继把函数名弄丢了"。当时修的是**入参**（改成只喂原文），
而真正的病灶是**保真度**。这两者的修法完全不同：前者关掉中继，后者只需保证上游不覆盖原文。

| 读数 | 值 |

| 单 run 最大调用次数 | 10（`used=10`） |

**⇒ 结论（采样）**：这套装置上线至今，**每一次成功的外部 agent 调用都被当成了答案**，
没有一次被当成中间步骤。中继不是"用得少"，是**一次都没发生过**。

⭐ 但这里有一条**结构上的第二条出口**，别漏（先查代码再报读数）：
答案型结果先经过 `_gate_finish`（`core.py:1701`）；若自检闸把它打回，
`result.ok` 变 `False`，交付分支（`core.py:1840`）不成立 ⇒ 它会走成一条**观测**
进工作记忆（`core.py:1750` 附近），下一步模型就能看见它。
⇒ **中继的唯一现成入口是"打回"**：不是成功路径，是失败路径。
采样上 `ok − used = 0` 说明这条路 17 个 run 里一次没走过（⛔ 不是"路不存在"）。

⚠️ 口径：`tasks` 是**题数**累加（`run.py:649`），不是调用数；`samples=72/48 成功调用 ≈ 1.5 份/次`
是 agent 自述的内部采样数（配置 K=2），⛔ 不是"内核试了几次"。

## 6. 判决：三个断点的实际形态

| 断点 | 形态 | 证据 |
|---|---|---|
| ① 物理 | **通** | A2 正例 `[0]`；`tools.py:340` `input=str(args["task"])` |
| ② 策略 | **断，且是无条件断** | A1：唯一构造器只吃 `goal`；覆写只看 `produces_answer` |
| ③ 契约 | **不硬**（只卡函数名） | A3：V2/V3 进模型且 prompt 含上游 |

**⇒ ③ 多 agent 缺的不是管道，也不是能力契约，是"允许中继"的策略**：
内核把「拿到上游」和「交付答案」设计成**互斥**两类 ——
`produces_answer=True` ⇒ 入参被覆写（切断上游）；`produces_answer=False` ⇒ 能拿上游，但输出只进 observation，不能交付。

**唯一现成的中继入口 = 打回**（§4 那条）：答案先被交付前自检闸拒掉 ⇒ 降级成观测 ⇒ 模型下一步能拿它当上下文。
这是**失败路径**上的中继：能走，但要走它必须先让答案不合格 —— 与"拿别人的答案当输入"是两件事。

而且策略这一刀**当初是有代价换来的**（V66/V67：`1.0000` vs `0.0000`），
本轮 A3 把它的病因从"中继"收窄到"中继时丢了函数名" —— **这一层是可以救的**，但⛔ 不是本轮救。

## 7. 登记（自踩 / 口径）

1. **P1 的边界**：字面量层面唯一，但**非答案型 agent 的 `args` 由模型 JSON 直供**
   （`planner._extract` → `Step(tool, args)`），代码既不构造也不检查。
   ⇒ 中继对"非答案型"其实**有入口，只是入口在模型自觉里**，且历史上没有任何一个这样注册的 agent。
   ⛔ 把 P1 读成"全库只有一个入口"就是越界。
2. **`run_id=None`**：166 行里有 2 行缺 `run_id`（早期格式），仍计入 calls 汇总；
   逐 run 校验把这两行也算进去了（它们同样 `calls==ok+err`）。
3. **A3 是被改造过的装置**：`_chat` 换记录器 ⇒ 只测「拒答 / prompt 组装」，
   ⛔ 不测生成质量、不测分数。这一点写进了预注册 §2，不算事后降级。
