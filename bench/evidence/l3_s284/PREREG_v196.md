# V196 预注册：中继值不值 —— 先把「上游草稿」的反事实量出来

日期：2026-11-18　⛔ 本文件写于**任何新答案产生之前**。

## 0. 接上什么

V195（§263）判：③ 多 agent 的断点不在管道、不在契约，在**策略** ——
`produces_answer=True` 的入参被无条件覆写成题面原文，上游在执行点被丢弃。

⇒ 要接中继，得改策略。**但改策略之前先回答一个更基本的问题：中继有收益吗？**
这正是 V194 的价（先量再接）：如果中继本身不涨分，策略就不该改。

⛔ 本轮**不改内核、不改 `agents.json`、不造题、不造新尺子**。只量反事实。

## 1. 一个问题

> 把**内核自己上一次的答案**当草稿一起交给外部能力，它交回来的东西**比原来好吗**？

三臂（同一批题、同一条打分路径）：

| 臂 | 送进 `external/code_agent.py` stdin 的东西 | 来源 |
|---|---|---|
| **N**（基线） | 只有题面原文 | V194 冻结的分数，**零成本** |
| **R**（中继） | 题面原文 + **本题**旧答案 | 本轮真跑 |
| **P**（安慰剂） | 题面原文 + **别题**旧答案（长度最近） | 本轮真跑 |

⭐ P 是必须的：没有它，"涨了"分不清是"草稿有用"还是"多一段代码样例有用"。
⭐ N 是必须的：没有它，读的是"这一版绝对分"，而不是"比原来好多少"。

## 2. 池（跑前固定，⛔ 不许事后增删）

V194 的 **33 格**里，**score < 1 的 23 格**。

| 口径 | 数 |
|---|---|
| 全池 | 33 格（10 套件） |
| **本轮分母** | **23 格**（`denom=23`） |
| 剔除 | 10 格 `score==1.0` |
| 剔除理由（**结构性**，⛔ 不是挑好看的） | 满分格在"比原来好"这个判据下**必然变化 0**（纪律 53：不许含必然变化量）。它们在 R 臂上的价值只可能是"退步"，而退步由 §4 的逐格翻转表单独看得见 —— 见 §7 的限制 |

基线（N，23 格）：**均分 0.3232**、中位数 0.2；分布 `0.2×14 / 0.4×2 / 0.5×1 / 0.6×5 / 0.3333×1`。

⚠️ 分母口径写进字段名：报数一律写 `mean@denom=23`。⛔ 不许把 33 格的数混进 23 格的表。

## 3. 装置（跑前锁定）

1. **上游/安慰剂的取法**（零随机）：
   - R：该格在 `answers_v194.jsonl` 里的答案，join 键 = **(`run_id`, `task_id`)**。
     ⚠️ `run_id` 是套件级（10 个 header），**不许只用 `task_id`** —— 同一题在 6 个套件里（V194 自踩 1）。
   - P：从**别的题**的答案里选 `|chars 差|` 最小的一条；平票按 `task_id` 字典序取第一个。
2. **拼接格式**（跑前定死）：`题面原文 + "\n\n【上游草稿】\n" + 草稿`。
   ⛔ 不截断、不改写、不在草稿后加任何指令（加了就成了另一个自变量）。
3. **调用**：`python3 external/code_agent.py`，`AGENT_DEADLINE_S=90`、进程超时 150s。
4. **打分**：走**真打分器** CLI `bench/scorers/code_exec.py`（stdin `{"task": ..., "answer": ...}`），
   与 `mw/bench.py:315` 同一个载荷形状 —— ⛔ 不另写判分。

## 4. 押（三值；⛔ 不许事后改措辞）

| # | 押 | 判定 |
|---|---|---|
| P1 | **处理接上了**：R 与 P 的答案**逐字节不同**的格 ≥ 80%（≥19/23） | 成立 / 不成立 |
| P2 | **中继有收益**：`mean(R) − mean(N) ≥ +0.10`（`denom=23`） | 成立 / 不成立 |
| P3 | **安慰剂无收益**：`|mean(P) − mean(N)| ≤ 0.10` | 成立 / 不成立 |
| P4 | **中继优于安慰剂**：`mean(R) ≥ mean(P)` | 成立 / 不成立 |
| P5 | **装置合格**：R/P 两臂「不适用拒答」= 0 次；两臂 `answer` 非空 ≥ 90%；血缘 `meta.model` 含 `qwen2.5:7b` | 成立 / 不成立 |
| P6 | **噪声地板低**：抽 2 格把 R 重跑一次，逐格 Δ ≤ 0.05 且两格都得同一个分 | 成立 / 不成立 |

⭐⭐ P2 与 P3 是**一对**：只报 P2 不报 P3，"涨了"就分不清是草稿还是文本长度。
⭐⭐ P6 决定 P2 能不能读：T=0 是承诺不是保证，噪声 > 0.10 ⇒ P2 降级为不可读。

## 5. 判据作用域（⛔ 越界即作废）

- 只覆盖「**同模型**（`qwen2.5:7b`）自己出草稿、自己改」这一种中继。
  ⛔ 不外推到「异模型多 agent」「多轮协作」「投票」。
- 只覆盖「**一格一次**」：不做重复、不做多种拼接格式。
- ⛔ 结论不许写成「多 agent 有没有用」—— 只写「这一次中继比基线好/差多少」。

## 6. 成本上限

23 格 × 2 臂 = 46 次调用 + 2 次噪声复跑 = **48 次**；实测单次 ≈ 3~4 次 `_chat`、40~70s ⇒ **≤ 60 分钟**。
超时/任一臂崩 ⇒ 如实报「分母不足」，⛔ 不补跑凑数。

## 7. 本轮**不**做的

- ⛔ 不改内核：`answer_task` 的覆写原样留着（改了就是另一轮，且要先有本轮的读数）。
- ⛔ 不在 `agents.json` 里加任何东西（本轮直接从 stdin 调 agent，绕开内核注入）。
- ⛔ 不把 R 的结果说成「接线后的分数」—— 那是**手工模拟**中继，不是部署面。
- ⛔ 不碰满分 10 格（见 §2 的结构性理由）。⇒ 本轮对「中继会不会**弄坏**已解对的题」**没有读数**，如实登记。
