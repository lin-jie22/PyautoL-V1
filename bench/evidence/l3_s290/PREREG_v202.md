## 0. 为什么是这一刀（不接 §269 的 A/B）

§269 留了两条：A 签名下沉、B 改 `as_line()` 载荷。两条都是**传输侧**。
但 §268 已经量出：到 prompt 的那 3 行里 **0 行是可迁移知识**（72.2% 是「通过 N/N」）。
⇒ 运输侧再怎么修，运的都是空的。所以本轮转向**生产端**。

生产端 = `mw/abstractor.py:148 distill()`：

```
episodes 原文 ──LLM 提炼──> 一句话经验 ──四道闸──> commit_fact(source="abstract")
                                                      │
                                    读侧 core.py:2239 `[经验]` 块（--memory-mode=abstract）
```

已知（V82 判决 + 本轮 grep）：

- `distill()` 在 `run.py` 的调用点 = **0**；全部调用方只有 `bench/`、`tests/`。
- `state/memory.db` 里 `source="abstract"` 的 fact = **0 条**（facts 共 4 条：worldmodel×3、selftest×1）。
- 读侧**是接好的**：`core.py:2239` 有专用分支 + `run.py:3245` 有 `--memory-mode` 参数。

⇒ **读侧有一条专用通道，但它永远读到空，因为写侧一次都没跑过。**

## 2. 押注（全部针对未见过的量）

| 号 | 押 | 依据 |
|---|---|---|
| **P1** | 四道闸是加在 **LLM 输出**上，不是输入上 ⇒ 输入侧的「含标识符」不预测 kept | 读码 |
| **P2** | `dropped_empty ≥ 100`，且其中 `outcome` 那 75 条**全部**落入（12 字「(语义记忆中无相关条目)」） | 空原料 |
| **P3** | kept **≤ 5**（分母 = 实际调用次数） | V82 注释「13 进 1 出」 |
| **P4** | 最大拒收类 = `dropped_identifier`：原料全是函数名，模型倾向复述点名 | 原料形态 |
| **P5** | kept 的句子里，含具体约束词（数字或 排序/去重/边界/空/重叠/进制/符号/前缀）的比例 **≤ 1/3** | system prompt 强制去点名 |
| **P6** | 写侧机械正例：蒸馏后 `source="abstract"` 的条数 == `DistillStats.kept`，且 `abstract_only()` 能逐条取回 | 读码 |
| **P7** | ⭐ **主押**：6 题 `_state()` 里 `[经验]` 块出现 **0 次**（即便库里已有 abstract 条） | 见下 |

**P7 为什么押 0**（不是猜，是读了三处口径）：

1. `facts_fts` 用 fts5 **默认 unicode61** ⇒ 连续中文是**一个** token。题面「写一个函数 commas(n)，把非负整数转成…」
   切出的是整段中文 token；抽象经验「遇到输入不确定时先核对边界」是**另一个**整段 token。MATCH 要求 token 全等 ⇒ 零命中。
2. 第二级 `LIKE` 要求**题面前 64 字的整串**出现在事实文本里 ⇒ 抽象经验永不包含题面原文。
3. 第三级 `_recall_char()`（字级 2 字链）**默认关**（V84）。

⇒ 若成立，判决是：**写侧去字面化是为了「可迁移」，读侧只认字面才能「检索得到」⇒ 两端语言正交**。
这不是接线缺损，是**表示层冲突**。

> ⚠️ 预注册修正 ①（在任何付费读数之前）：P6 原写作「`[经验]` 块能出现 ≥1 次」，
> 与 P7「≤2 次」在 0 次时互相矛盾（0 同时满足 P7、违反 P6）。
> 两条判据不独立 ⇒ 改 P6 为**写侧机械正例**（只查库与 `abstract_only()`），
> 检索那条只由 P7 承担。改动时间早于第一次真 LLM 调用，登记在此。
