# V204 预注册：原料门控 vs 指令改造 —— 哪个能救蒸馏

**写于任何 LLM 判据读数之前。** 已完成的只有两项**免费结构普查**（不是判据）：
① 可见 500 条的 kind 构成与长度分布；② 门控规则的筛除量。两者都用确定性代码算，不调模型。

## 0. 为什么问这个

V203 把「换匹配器」这条支路关死，判决落在池子：67 条 abstract 里 65 条是流程泛句。
池子由 `abstractor.distill()` 生产，而它的原料池普查给出两个**结构性**事实：

| 事实 | 数 |
|---|---|
| `failure` 120 条里，**「收尾交付未过自检 — 缺少 def xxx(...)」** | **108 条（90%）**，长度中位 97，内容 = 「我没写某个函数」 |
| `outcome` 75 条里，**`(语义记忆中无相关条目)`** | **75 条（100%）**，12 字符占位符 |
| 而 `_source_episodes` 的排序是 **`failure` 优先** | ⇒ **把最没信息的 108 条喂在注意力最高的位置** |

⇒ 两个可疑病因，必须分开量：**原料（A）** 与 **指令（B）**。

## 1. 四臂（2×2）

| 臂 | 原料 | 指令 | 调用数 |
|---|---|---|---|
| **A** | 全部 500（`episodes(limit=500)`，`failure` 优先） | 原 `_DISTILL_SYSTEM` | **复用 V202 的 67 条**（不重跑） |
| **B** | 全部 500 | 新「结构型」指令 | 500 |
| **C** | 门控后 **108** | 原 `_DISTILL_SYSTEM` | 108 |
| **D** | 门控后 **108** | 新「结构型」指令 | 108 |

A 臂复用理由（纪律 64：省掉的工作也要说清）：V202 在同一台机、同一 `qwen2.5:7b`、
同一份库副本上跑过「原指令 × 全部 500」，产出 67 条在案。
⚠️ **分母不同名**：A/B 的分母是 500，C/D 是 108 ⇒ 报「绝对条数」+「每条原料产出率」两个数。

### 门控规则（确定性，冻结）

```
剔除 placeholder : ^\(语义记忆中无相关条目\)$ | ^stalled: \{\}$
剔除 miss_def    : ^收尾交付未过自检 — \d+/\d+ 项未过：缺少 def \w+\(\.\.\.\)$
剔除纯答案      : ^(closed|done):\s*```
剔除短且无证据  : len<40 且不含 ⇒/assert/编译失败/Traceback/Error/Exception
去重            : content 前 100 字相同者只留第一条
```

筛除量：`placeholder 100 / miss_def 56 / short_noevid 36`，保留 308，去重后 **108**
（`goal 61 / failure 25 / mismatch 9 / finish 6 / outcome 7`）。

### 新指令（结构型）

```
你是「题目结构提炼器」。给你一段执行记录（可能含题面、失败信息、预演差异）。
任务：写出**这道题/这类题的结构性陷阱** —— 下次遇到同类题，具体该防什么。

要求：
1. 一句话，但必须点名**具体的结构**（例：「空串要返回 None 而不是 ''」
   「端点相接 (1,3)+(3,6) 不算重叠」「千分位从右往左每三位插逗号」）。
2. ⛔ 不许出现函数名、变量名、代码块。
3. ⛔ 不许写「先检查」「注意细节」「确保完整」「统一格式」这类**没有可执行内容**的空话
   —— 那不算经验，算复述脚手架。
4. 若这段记录确实不含结构性信息，只输出一个词：NONE
```

与原指令的差异只有三处：**去掉「遇见到 X 时，先 Y」句式模板**、
**去掉「不要复述任务的答案」**（改为「必须点名具体结构」）、**显式拉黑空话**。

## 2. 「可迁移」的判据（β，人工逐条，全列不抽样）

> 一条产出算**可迁移**，当且仅当：它点名了一个**具体的输入形态/约束**，
> 使模型能做出一处**具体的代码决定**。

- ✅「空串要返回 None 而不是 `''`」——可执行
- ✅「端点相接 `(1,3)` 与 `(3,6)` 不算重叠」——可执行
- ❌「交付前检查时先确保所有函数定义完整」——不可执行（任何题都能贴）
- ❌「注意数据格式统一」——不可执行

⛔ 判读时**只看产出文本**，不看它来自哪个臂（先打乱顺序再判，避免臂标签污染判断）。

## 3. 押注

| 号 | 押 | 理由 |
|---|---|---|
| **P1（主押）** | D（门控+新指令）可迁移条数 **≥ 8**（A 是 2，即 ≥4 倍） | 108 条原料里有 61 条题面，含千分位/重叠区间/游程等具体约束 |
| **P2** | B（只换指令，不门控）**≥ 4** | 押「指令是主要矛盾」：原指令的句式模板强制泛化 |
| **P3** | C（只门控，不换指令）**≤ 3** | 押「原料不是主要矛盾」：原指令会把好原料也压成流程句 |
| **P4** | 门控后条数 = **108**（可预测量） | 上面已算 |
| **P5** | 新指令（B/D）的 **NONE 率 ≥ 30%** | 押「新指令会诚实拒答」，而原指令几乎不拒（205 条 dropped_empty 里绝大多数是空串原文，不是 NONE） |
| **P6** | 新指令产出的**自指率 ≤ 20%**（V202 是 48%） | 空话被显式拉黑 |

**P2 与 P3 不互斥**，是两个独立方向的押注，用来归因「主要矛盾在哪」。

## 5. 自踩预案

1. **A 臂是复用的，不是同轮跑的** ⇒ 若 A 与 B 的原料排序有差异（同库同代码，应当无差异），
   必须在读数里注明「跨轮比较」。
2. **β 判读由我一人做** ⇒ 先打乱顺序、全部列出，容许你复核推翻。
3. **108 条是「去重后」的，若某条原料重复度高，可能少算** ⇒ 同时报「未去重 276 条」版本的次数。
4. **模型可能把题面直接复述成「经验」**（如「千分位要对非负整数处理」）⇒ 这类算 **弱**，不算强。
