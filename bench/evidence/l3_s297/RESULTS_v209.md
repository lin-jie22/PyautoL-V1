## 4. 机制：同一条通道，两种用法

### 4.1 t04 —— 异常信息点的是**根因**，照做就修好了

评审原文：`assert merge_ranges([(1,3),(2,6),(8,10)]) == [(1,6),(8,10)] ⇒ TypeError: 'tuple' object does not support item assignment`

| 臂 | 答案里出现「对 tuple 下标赋值」（`merged[-1][1] = …`） | idx0 通过 |
|---|---|---|
| A | **18/20** | 2/20 |
| C | 17/20 | 2/20 |
| **B** | **13/20** | **7/20** |

**少掉 5 次赋值，正好多出 5 次通过。** 通过的答案改成重建元组：
`merged[-1] = (merged[-1][0], max(last_end, current_end))` —— 完全照评审原文的说法改。

⇒ 当异常名点的是**根因**（元组不可变），自评是**可执行的知识**。

### 4.2 t01 —— 异常信息点的是**症状**，照做就更糟

评审原文：`assert parse_duration('1h30m') == 5400 ⇒ ValueError: not enough values to unpack (expected 2, got 1)`

| 臂 | 用**单位表**（`units={'s':1,'m':60,'h':3600}`） | 写死 `按h切/按m切`、不含秒 |
|---|---|---|
| A | **10/20** | 0/20 |
| **B** | **3/20** | **6/20** |

B 臂典型答案（原文）：

```python
parts = s.split('h')
if len(parts) == 2:
    hours, minutes = int(parts[0]), int(parts[1].split('m')[0])
else:
    minutes = int(s.split('m')[0])        # ← '45s' 走这里 ⇒ int('45s') ⇒ ValueError ⇒ None
```

⇒ `expected 2, got 1` 被当成**设计线索**：模型据此把输入切成两段（按 `h`），
于是**单单位（`45s`/`2h`/`10m`）全部掉出**。而这三条在 A 臂本来是过的（14/15/14）。

⭐⭐ **判据**：同一条 `[外部评审]` 通道，用得好不好取决于**异常信息里哪一半被当成指令**——
「异常名 / 根因」可迁移；「异常文的元数（expected 2, got 1）」是有害的具体化。

## 5. ⭐ 这解释了 V208 的 UNKNOWN

V208 用 6 题全量测得 Δ = +0.074 < 噪声，判 UNKNOWN。现在知道那不是「没效应」：

| 效应 | 幅度 | 显著性 |
|---|---|---|
| t04 修好（照根因改） | +0.117（题分）/ +25pp（目标格） | p=0.127 |
| t01 弄坏（照症状改） | −0.200（题分）/ −45~−60pp（3 格） | p≤0.01 |

⇒ **V208 的「测不出」是聚合方式造成的，不是机制不存在。**（纪律 94 的同型：总额不动 ≠ 每格不动。）
