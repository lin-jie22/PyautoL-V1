C3  calls 是不是装置常量（同配置逐次重复）
==========================================================================
    读代码（mw/core.py:1482）：`for ci, cand in enumerate(cands)`
    ⇒ 内核按 planner 给出的**顺序**逐个执行，不重排、不比较（§107 静态扫描：比较/选择 0 处）。
    ⇒ calls 由「planner 把 produces_answer 候选排在第几位」决定。

    2 题子集内，calls 与 run_id 的先后（看是否成段）：

==========================================================================
C4  追加：门 B 默认关闭 ⇒ 159 行的 calls 全部来自门 A
==========================================================================
读码（mw/core.py:1386）：
    _ext = self.s.limits.external_answer_tool
    if _ext and it == 1 and self.tools.get(_ext) is not None:
        ... cands = [Step("整题交给外部能力", _ext, ...)] + list(cands)
而 mw/config.py:424：default_factory = os.environ.get("V1_EXTERNAL_ANSWER_TOOL", "").strip()
⇒ 默认空串 ⇒ 门 B **从未触发**（那些 skipped_not_applicable=0 是"根本没进这个 if"，
   不是"进了但被拒"—— 两者在读数上同形，必须靠读码分开）。

主循环（mw/core.py:1170-1172）：
    while True:
        self.ledger.spend_step()
        it = self.ledger.steps_used
⇒ 第一轮 it=1 ⇒ 门 B 的条件 `it == 1` 指的是**第 1 轮**，不是第二轮。

⇒ **calls 的双峰（0 / 2）完全由门 A 解释**：planner 第 1 轮自由给候选，
   两题都提到 agent:code_agent 就是 2，都没想到就是 0。

对照：rounds=2 却有 31 次 calls=0 —— 与"门 B 在第 2 轮必然注入"的假设矛盾，
正是"门 B 默认关闭"的直接证据。

==========================================================================
C5  结论与 A 的落点
==========================================================================
1. calls 不是装置常量，是 planner 候选**顺序**的抽样（内核 enumerate 不重排）。
2. 它对分数的影响在 t04 上近乎确定性（calls=2 → 73/73 满分；calls=0 → 15/74）。
3. ⇒ V217 的 Δ=[0,+4,+4] 可由 calls 单独解释，无需"块内容"假设。
4. ⇒ **A 不需要写新代码**：`V1_EXTERNAL_ANSWER_TOOL=agent:code_agent` 打开门 B，
   第 1 轮即把外部插到候选第 0 位。该字段已在 `Limits.as_dict()`（口径签名）
   与 `ENV_KEYS`，契约 AE2 钉住 ⇒ 打开后口径签名会变，与旧读数**不可比**（这是对的）。

⚠️ 未证明：打开门 B 后 calls 是否真的恒为 2（可能有 `_closing_reserve_hit()` /
   `_dl is None` / 执行失败后不重试等分支）。这条要真跑才知道。
