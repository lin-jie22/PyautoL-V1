# 预注册 V214（§282）：累积学到的东西，到底有没有进到「真正解题的那次调用」里

**写于跑之前**（2026-11-20 19:0x，`bench_out/runs.jsonl` 基线 **274** 行）。

## 0. 为什么做这一轮

前十三轮（V209~V213）都在同一个位置反复量同一件事：投喂了评审之后分数动不动。
V213 把这个位置量到头了：**同一串 128 字节的 state 进 30 次，出 9 种答案**
⇒ 这套 2 题子集上任何 < 0.20 的效应都要 **18.3 机器小时**才测得出来。

但有一条**结构事实**从来没被当成读数，因为它太像一个配置细节：

> 默认配置下 `code_agent` 吃掉了 **65/77 = 84.4%** 的题次（§277 免费普查），
> 而 `mw/tools.py:341` 交给它的只是 `str(args.get("task", ""))` —— **planner 填的那一个参数**。
> 内核写进 state 的 `[外部评审]` / `[语义记忆]` 块，是不是也进了那次调用？

如果没进，那么「累积 → 求解」这条边在**部署默认配置**下从未接通过；
之前十三轮量的是 `--no-external`（内核自己解）这条**非默认**路径。
这两件事的后果完全不同，而我现在只有代码推断，没有读数。

⛔ 本轮**不测分数、不改产品行为**。只做一次**免费普查**：把内核交给外部能力的
stdin 原文存下来，看里面有没有评审块。

## 2. 判据（先写死，不许事后改）

| # | 命题 | 门槛 |
|---|---|---|
| **P1** | 装置：壳子真的被调用过 | `probe_stdin.jsonl` 行数 **≥ 2**，且 `runs.jsonl` 的 `kernel_external.calls` 与之**相等** |
| **P2** | 装置：state 里**确实有**评审块（正例对照） | `state_ext.jsonl` 里 `[外部评审]` 行 **≥ 2** |
| **P3** | ⭐ 外包 stdin 里**没有**评审块 | 全部调用 `has_review == False` **且** `has_mem == False` |
| **P4** | 口径：交出去的字数 ≈ 题面字数 | 全部调用 `task_chars - goal_chars ≤ 40`（题面长度见 §3） |

**判读规则**：
- P3 成立 ⇒ 结构性事实成立：**部署默认配置下，累积的知识没有进求解路径**。
  ⇒ 下一刀是「把块交给真正解题的那一端」，且它不再是猜测性的改动。
- P3 不成立（planner 自己抄了块）⇒ 这条担心从册子上划掉，主线回到「块进了、但没用」，
  与 `--no-external` 那条路径同形 ⇒ 那一支**不许**再拿「外包」当借口。

⛔ 本轮不押分数方向，也不看分数 —— 2 题 × 2 次没有任何判别力（V213：MDE 0.30+）。
⛔ 若 P1/P2 任一不成立 ⇒ 全轮 UNKNOWN，先修装置。

## 4. 自踩预案（这次先想好，别再事后补）

1. ⛔ **临时改 `agents.json` = 改提示词**：`catalog_sha` 会变。所以本轮**不跑契约**，
   只在恢复后跑；且 `input_sha.txt` 里两版 sha 都要在。
2. ⛔ **壳子必须对内核透明**：任何一处 stdout 变形（多一行日志）都会让内核读出
   `外部 agent 违约`，读数直接变成「调用全败」—— 那会被误读成「外包不可用」。
   自检：壳子对同一 stdin 的输出应与直接跑 `code_agent.py` **逐字节相同**（小样本，1 次）。
3. ⚠️ 2 次运行只有 4 次调用，样本极小 ⇒ 结论只关于**结构**（有没有），不关于**比例**。
