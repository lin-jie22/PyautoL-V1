# PREREG V223 —— 给定逐字节相同的输入，代码是不是逐字节相同？

写在**跑前**（2026-11-22 23:2x）。跑完只许补读数，⛔ 不许改判据。

## 0. 为什么这一轮值得花 5 分钟

V219~V222 五轮都拿「1 格」当效应，每臂只跑 1 次。整套归因压在一个从没被点名的
前提上：

> **同一个输入 ⇒ 同一个代码。**

这个前提在仓库里**有两份互斥的旁证**：

| 旁证 | 说法 | 出处 |
|---|---|---|
| 支持「确定」 | 同一评审块三遍，代码逐字节相同（sha `d4fc3372af`） | §292 V219d 七臂离线复跑 |
| 支持「确定」 | 同一代码变体在 211 次观测里重复出现 52 次 | V223 取证 Q2（本轮，离线） |
| 支持「抽样」 | 四个臂跑出四个不同代码，其中两个是**全历史首次** | §293 V220~222 |
| 支持「抽样」 | 同配置 `it=1` state 逐字节相同，但分数仍变 | §281 V213 |

⛔ 注意 V219d 是**离线复跑**（`exec` 已产出代码），不是实跑；拿它当「实跑确定」是越界。
本轮把它变成实跑可判。

⚠️ 为什么 3 次就够：判据是**全同 / 不全同**，不是「通过率」。3 次全同已经排除
「每次都重抽」；3 次全不同已经排除「确定」。2/3 同 = 部分确定，也是一个格子。

## 2. 判据（跑前写死）

**P0（前置，不成立则整轮 UNKNOWN）**
三次 probe 日志中 `t01_parse_duration` 那次调用的 `task` 全文 **sha256 相同**。
理由：纪律 111 —— 先查输入是不是同一个字符串。输入都不同，谈「同输入同输出」是假问题。

**P1（主判据）** 三次运行 `t01_parse_duration` 的答案 `sha256` **全同**（3/3）。
**P2（复核）** 三次运行 `t04_merge_ranges` 的答案 `sha256` **全同**（3/3）。
**P3（独立复核 Q1）** 三次 `t01` 的 `vec` 全同。

## 3. 判决（三值，跑前定死）

| 读数 | 判决 | 对前五轮的含义 |
|---|---|---|
| P0 ✅ 且 P1 3/3 且 P2 3/3 | **确定** | 1 格差异是**真效应**；L3 净 0 是真净 0 |
| P0 ✅ 且 P1 2/3 | **部分确定** | 1 格差异 = 效应 + 抽样混合，**不可分** |
