# PREREG V225 —— 写端「满分不覆盖」：修 §295 抓到的自毁，判据是**账本字节**

写于跑之前。跑完不改本文件；结论与偏差写进 `RESULTS_v225.md`。

## 1. 要修的缺陷（来自 §295 的现场证据）

`CritiqueLedger.add()` 的去重是**键覆盖**：`key = (scorer_sha, suite_sha, task_id)`，
同键再写就 `by_key[key] = 新条`。而 V224 现场看到：

```
TypeError 行 ──> 6/6 ──(写端按结果覆盖)──> "1.00 — 通过 6/6" ──> 2/6（4 次同码）
```

⇒ 满分那一轮跑完，账本把**产生满分的那条输入**换成了「通过 6/6」，
下一轮输入变了 ⇒ 分数按新输入重算 ⇒ 掉回 2/6。

**修法（默认 off）**：`add()` 遇到同键且**新分数 = 1.0** 时**不覆盖**，保留旧条，并计数 `frozen`。
非满分照旧覆盖（回归必须被记下 —— 那是真信息）。

## 4. 这个判据为什么不是同义反复

「账本不变」有两种来路：**冻结**（真修好）与**根本没写**（哑火）。
`W2`（`t01` 必须变）+ `W3`（`superseded ≥ 1`）就是为了把这两种分开 ——
否定断言必须带正例（纪律 5）。
