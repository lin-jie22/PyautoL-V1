# PREREG v230：喂「上一版**挖了一个洞**」的码 —— 抄洞 / 补洞 / 重写

**写于跑之前。不许事后补判据。**

## 1. 这一轮问的是哪一句话

V226b~V229 把这条通道的形态量清楚了：

| 轮 | 投喂 | 模型做了什么 | 净效果 |
|---|---|---|---|
| V226b | 本题上一版**正确**的码 | 逐字照抄 | 守住最优（恒等映射） |
| V227 | **别题**的码 | 不抄 | 两题都掉（噪声） |
| V229 | 名字对/错 × 体对/错 | **体是门**：体对就抄、把 `def` 改回；体不对就自己写 | 守住 |

⇒ 现形态的上限是「**守住最优**」。要问的是：**它能不能「提升」**——即把一份**有缺陷**的上一版
改成**更好**的一版。这是「累积」与「复读机」的分界，也是零代码改动能问的最后一个问题。

**做法**：把**本题自己的码**挖掉一处，投喂进去。

- 若**抄洞**（把缺陷一起照抄回来）⇒ 这条通道**结构上不可能提升**：它把输入原样搬运，连错也搬。
  那时「给产物」这条路在现形态下到头了，再往上**必须动提示形态**（只给失败片段 / 要求给 diff），
  那是改产品行为，须拍板。
- 若**补洞**（把那一处改回来）⇒ 第一次出现「上一版 → 更好的一版」的证据，累积**有牙**。

## 2. 洞（先用离线判分证明它是真洞）

判分用 `bench/probe_repair.py` 同款 `score_of`（每条测试在**全新命名空间**里跑），零模型、零网络：

| 题 | 洞（唯一一处改动） | 原码 | 挖洞后 | 打掉的格 |
|---|---|---|---|---|
| `t01` | 最后分支 `return hours * 3600` → `hours * 60` | 4/6 `011011` | **3/6** `010011` | `2h`（7200→120） |
| `t04` | 删掉一行 `pairs.sort(key=lambda x: x[0])` | 6/6 `111111` | **5/6** `111101` | `[(3,4),(1,2)]`（乱序不再排序） |

⚠️ 两处都**只打掉一格**，且离线复算的**原码**分数与运行账本逐格相同
（`t01` `011011`、`t04` `111111`）⇒ 判分器是同一个。

## 3. 关键对照：`why` 指的**不是**我挖的地方

账本行里 `why` 会跟着块一起进 prompt（`--critique-why raw`）。若不查这一条，补洞就没法归因。

| 题 | `why` 原文（进 prompt） | 我挖的洞 |
|---|---|---|
| `t01` | `通过 4/6；失败: parse_duration('1h30m') == 5400；parse_duration('10m') == 600` | **`2h`** ← 不在 why 里 |
| `t04` | `通过 4/6；失败: merge_ranges([(1,3),(2,6),(8,10)]) ⇒ TypeError: 'tuple' object does not support item assignment` | **`[(3,4),(1,2)]` 的顺序** ← 不在 why 里 |

⇒ 补**我挖的洞**只能来自**读体**；补 `why` 里点名的那两格只能来自**读 why**。
两件事在**同一次运行**里可以分开（下面判据分开报）。

## 4. 判据（逐题、字节级；分数只作旁证）

| 记号 | 定义 | 含义 |
|---|---|---|
| **抄洞 `COPY-HOLE`** | `sha(输出) == sha(投喂块)` | 缺陷被原样搬回 ⇒ 通道是搬运 |
| **补洞 `RESTORE`** | 输出 == **挖洞前**那份码（逐字节） | 那一处被精确改回、其余一字不动 |
| **局部补 `PARTIAL`** | 输出 ≠ 两者，但 diff 只落在洞附近（±2 行） | 改了那一处、写法不同 |
| **重写 `REWRITE`** | 输出与块的最长公共子串 ≤ 40 字节 | 又自己写了一遍 |
| **OTHER** | 以上都不满足 | 照实描述 diff |

分数作为**第二层**旁证（⛔ 先判字节、再判分数，纪律 146）：

- `t01`：`3/6` ⇒ 抄洞；`4/6` ⇒ 只补了我的洞；`5~6/6` ⇒ 还修了 `why` 点名的格子。
- `t04`：`5/6` ⇒ 抄洞；`6/6` ⇒ 补洞（或它自己重写到满分）。

## 5. 押（三值，逐题）

| 号 | 命题 | 押 |
|---|---|---|
| P1 | **前置**：两题入参 = V226b 同题前缀 + `"\n"` + `"[上版代码] "` + 挖洞后的码，前缀**逐字节相同** | 0.95 |
| P2 | `t01` 抄洞（EXACT） | **0.60** |
| P3 | `t04` 抄洞（EXACT） | **0.55** |
| P4 | 若 P2 ⇒ `t01` 分数 **= 3/6**（与离线复算的挖洞后分数同） | 0.90 |
| P5 | 若 P3 ⇒ `t04` 分数 **= 5/6** | 0.90 |
| P6 | `state` 未被裁（`< 1600` 且块完整） | 0.90 |

主押 **COPY-HOLE 两题**（0.50）；**RESTORE 至少一题** 0.30；**REWRITE 至少一题** 0.20（可重叠）。

⛔ P2/P3 分开押、分开判：一题抄一题补是**可能的结局**，合并会把两格平均掉（纪律 112）。

## 6. 判定规则（写死）

- **COPY-HOLE（两题）** ⇒ 通道**结构上不可能提升**：它搬运输入，连缺陷一起搬。
  ⇒ 「给产物」这条路在现形态**到头**，继续给它更多产物是**已知的零收益**。
  ⇒ ⛔ 不许写成「通道有害」（它仍守住最优，§299）；⚠️ 也不许写成「任何洞都会被抄」——
  本轮只测了**两个**洞（一个错常量、一个漏掉的排序）。
- **RESTORE（至少一题）** ⇒ 首次拿到「上一版 → 更好的一版」，**但**必须先扣掉 `why` 的解释
  （看它有没有同时修 `why` 点名的格子）。扣不掉就写 UNKNOWN。
- **一抄一补** ⇒ 两格都报，⛔ 不合并成「有时抄有时补」。
- **P1 不成立** ⇒ **UNKNOWN**，不许挑读数解释。

## 7. 装置前提

1. **确定性**：§294（同 stdin ⇒ 同代码，3/3）⇒ 只跑 1 次；跑完核对四格 `外部[agent] 调=1 成=1 采用=1`
   （纪律 147：若某格换成收尾交付，该格不判）。
2. **速度闸**：实测 **12.4 / 16.5 / 15.8 / 16.1 tok/s**（首样本含预热）⇒ 稳态 **16.0 ≥ 15**，放行（纪律 116）。
3. **预算**：`state_chars=1600`。预估 `t01` ≈ 276+1+682 = 959、`t04` ≈ 336+1+472 = 809，均在闸内。
4. **shim**：`SHIM_LOADED False`，否则不跑。
5. **agents 指纹**：跑前备份、跑后 `git checkout -- agents.json` 并核对 sha 还原（`674b8941…`）。
6. **零产品代码改动**：唯一变量是账本 `answer` 的字节（只挖一处）。`check_counts` 仍跑一次。

## 8. 限定（跑前先写下来）

- ⚠️ **只挖了两个洞**，且都是「一眼能看出」的类型（错常量 / 漏一行）。⇒ 结论只到
  「**这两类洞**会不会被补」，⛔ 不外推到「所有缺陷」。
- ⚠️ 账本 `score=0.6667` / `why` 与挖洞后的码**不一致**（`why` 说 4/6，实际 3/6 与 5/6）。
  这是前几轮就有的矛盾（§296 限制 2），本轮**故意不动**它：动了就多一个变量。
- ⚠️ `t01` 的洞让分数从 4/6 掉到 3/6，正好等于 V227 的 `t01` 读数 ⇒ **同一分数不同原因**，
  ⛔ 不许拿分数当唯一判据（纪律 146/149）。
- ⚠️ 两题 / 单臂 / 各 1 次，`n_eff=1`。
