## 1. 自踩一：V232 的判决**作废**（它测的是装置编的假诊断）

V233 的整个结论建立在「V232 补了实测值 ⇒ 诊断更错」之上。查原文：

```
lsn_v232.jsonl            …使用了不当的字符串操作，导致了 `SyntaxError`…
lsn_v232_after_r1.jsonl   …返回 None 而不是抛出 SyntaxError…
```

而 `failed_actuals` 当时对**账本里的原始输出**（带 ```python 围栏）直接 `exec`：
六条断言全是 `SyntaxError: invalid syntax (<answer>, line 1)`。

**那个 SyntaxError 是装置编的。** 代码里一次都没抛过。模型忠实地去修了一个
不存在的问题，而我们把这个读数记成了「补实测值让它更错」。

修法：`mw/reflect.py:as_code`（与打分器 `extract_code` 同源，由 T11 钉住）——
`failed_actuals` / `verify` / `trace_failure` 入口统一先剥围栏。

⛔ 因此：**A 臂不是 V232 的条件，而是它想测而没有测到的那个条件**。

## 2. 自踩二：预注册假设了「装置确定」，首跑就打了脸

P1 写的是「T 的候选 > A 的候选」，默认同 prompt ⇒ 同码（§294 / 纪律 133）。
V234a 首跑（A / T / A2）：

```
A  = 3/6   （改坏了：连 '2h' 都挂）
T  = 4/6
A2 = 5/6   ← 与 A 同一条 prompt，逐字节相同
```

⇒ 单点对照**不可解释**，P1 记 **UNKNOWN**。补测每臂 12 次（交错采样）之后才看清分层：

| 臂 | 3/6 | 4/6 | 5/6 | 6/6 | 均分 |
|---|---|---|---|---|---|
| A（why+实测值） | **9** | 1 | 2 | 0 | 3.42 |
| T（A + 执行轨迹） | **2** | 9 | 1 | 0 | 3.92 |

- **同批次连续重复是稳的**：A 的 12 次里有 9 次是同一份码（sha `ea010c75`，183 tok）。
- **跨批次不稳**：首跑那份 5/6（`93cfd57f`）在后来 12 次里一次没再出现。
⇒ 「确定性」不是装置的一个属性，是**分层**的（同一进程连续调用 / 跨批次）。纪律 158。

## 3. 轨迹（V234a 的正面与负面）

执行轨迹长这样（设备自动生成，零模型）：

```
【assert parse_duration('10m') == 600】
  第 16 行 | hours = int(parts[0])            [s='10m' parts=['10', '']]
  第 17 行 | minutes = int(parts[1].split('m')[0])   [s='10m' parts=['10', ''] hours=10]
  第 17 行 | minutes = int(parts[1].split('m')[0])   [⇒抛出=ValueError: invalid literal for int() with base 10: '']
  第 22 行 | except ValueError:               [s='10m' parts=['10', ''] hours=10]
  第 23 行 | return None                     [⇒返回=None]
```

- ✅ **它真的看得见根因**：`parts=['10','']`、哪一行抛、被 `except` 吞掉、最后交 None 全在。
  （T3/T3d/T4 三条自测钉住；T10 反证「旧装置确实会编 SyntaxError」，所以这不是自述。）
- ✅ **它降低「改坏」的概率**：3/6 从 9/12 降到 2/12。
- ❌ **它不提高「严格更好」的概率**：5/6 = 2/12（A）vs 1/12（T）。
  而 `promote` 只认「严格更好」⇒ **对闭环净贡献 0**（点估计反方向）。

⭐ 结论：**「信息给够」不是这条路的瓶颈。** 设备已经把调试器能说的都说了，
7b 仍然一次只修一处。

## 4. 闭环是怎么闭上的：候选是**采样**出来的，采纳由**尺子**说了算

四个 5/6 候选（各修一处，写法各不相同）：

| sha | 臂 | 修了哪处 | 残留 |
|---|---|---|---|
| `3b755be7` | A | h 分支补 `minutes` | `10m` |
| `7c08dbe3` | A | h 分支 `if 'm' in s` | `10m` |
| `d7bff8fe` | T | 在 `except` 里补 m 分支 | `1h30m` |
| `93cfd57f` | A2 | （首跑那次） | — |
| **`90579ece`** | **R1 采纳** | h 分支 `if len(parts[1])==0` | `10m` |

⇒ 单次提议命中「严格更好」的率 p̂ ≈ 3/25；`promote` 只认严格更好 ⇒ k=1 时基本不闭。
`--critique-propose-k 8`（默认 1 = V233 行为逐字节不变）让**同一把尺子**在 8 个候选里挑最优，
**仍然只有严格更好才写入**。R1 8 次里命中 1 次。

⛔ 这不是「调大参数」：判据一个字没动（相对起点严格更好），k 只决定采样几次。
⛔ 也不是「k 是剂量」那条已死的读法：本轮不报任何「k↑⇒分数↑」的斜率。

## 5. 闭环的证据链（三步，每步都能复核）

1. **采纳**：`crit_v234_r1_after.jsonl` 的 t01 行 = score 0.8333、sha `90579ece`、
   `why` 写明「8 次提议中同一判分器选出的最优，验证后采纳」。
2. **守住**：R2/R3 跑完，该行 sha **逐字节不变**（`freeze-best` 挡掉了降级写入，`保最优=1 次`）。
3. **用上**：R2 的产出 `bench_out/answers.jsonl` 里 t01 的 sha = **同一个** `90579ece`，
   分数 0.8333 ⇒ 下一轮**逐字节照抄**了被采纳的那一版（与 V226b 的通道一致）。

⚠️ 第 3 步同时说明：「**累积**」这一半成立了；「**自省**」这一半（自己写出更好的版本）
**没有**——本轮所有变好都来自「采样 + 判分器选择」，不是模型自己诊断出来的。

## 6. ⛔ 顺手抓到一个既存缺陷（不是本轮造成，但会喂假诊断）

`t04_merge_ranges` 那一行：

```
score = 0.6667   why = "… ⇒ TypeError: 'tuple' object does not support item assignment"
answer = a22691b5…   ← 用真打分器（子进程，6 条断言）复算 = 6/6
```

**score 与 answer 不同源**（纪律 152 的实形）：这个缺陷在 V231 的账本就带着，三轮没变。
后果：下一轮 `[上架代码] + [外部评审]` 会同时收到「满分代码」和「它有 TypeError」——
与 §1 那个假 SyntaxError 是同一类病灶（**给模型的判决与它手上的东西不是一回事**）。

本轮**没有**去改它（改它要动 `add()` 的写入语义，属于产品行为），只在这里立案。
⚠️ 附带后果：`--critique-promote` 用 `verify(_c.answer)` 而不是行内 score 当基线
—— 这一步**恰好**没被这个缺陷带偏（t04 的 base 被算成 6/6 ⇒ 直接跳过，没去打扰它）。

| 提议轮 | 提议次数 | 6/6 命中 |

| 离线 A/T（含首跑） | 25 | 0 |
| R1（起点 4/6） | 8 | 0（命中 5/6 ×1） |
| R2 | 1 | 0 |
| R3（起点 5/6） | 8 | **0** |

⇒ 42 次提议里 6/6 出现 **0** 次。缺口非常具体：**两处 bug 要同时改对**，
而模型每次都只改一处（`1h30m` 或 `10m` 二选一）。这与 V233 的结论相容，但更窄：
不是「提不出更好的」，是「提不出**同时**更好的」。

## 8. 新增纪律

- **157.** ⛔⛔ **诊断装置必须与打分器同源**：`failed_actuals` / `verify` 不剥围栏 ⇒
  喂出 `SyntaxError`，模型忠实地修了一个不存在的问题，而我们把读数记成「信息越多越糟」。
  V232 的判决整体作废。铁律：任何「给模型的诊断」在入口处剥壳，并用自测钉住同源（T11）。
- **158.** ⭐⭐ **「装置确定」要分层报**：同一条 prompt 首跑 3/6、再跑 5/6（P1 因此 UNKNOWN），
  但同批次连续 12 次里 9 次是同一份码。⛔ 不许用「同 prompt ⇒ 同码」跨批次推理。
- **159.** ⭐⭐⭐ **闭环的正解是「采样 + 判分器选择」**：单次命中 p̂≈3/25，
  k=8 就命中；同一条路上 V231~233 六次「换措辞 / 换信息」全是零。
  ⛔ 但要把「累积变好」与「自省变强」分开报——本轮只有前者。
- **160.** ⛔ **账本行的 score 与 answer 必须分别核查**：t04 行 score 0.6667 / answer 6/6。
  任何「累积有没有用」的判读，先 `verify(answer)` 重算一遍，别信行内 score。
- **161.** ⭐ **天花板要按「同一格被提议几次」报**：6/6 在 42 次里 0 次 ⇒ 是天花板；
  只报「没命中」而不报分母，会与「没试」同形。
