## §0 起点：一句会撒谎的话

V171 之后，部署形态长这样（§239.5 实测）：

```
  提议    0 条：COVER 0｜PROBE 0｜RAISE 0
（没有可提的目标：账本与套件都对不上，或该做的都做完了）
--- 已转运维 40 格（测量已用尽，不再重复提；⛔ 不是做到了）---
```

第二节「已转运维」是对的，第一节「（没有可提的目标…）」是**错的**：

| 提议 0 条的真实成因 | 旧文案怎么说 | 该怎么说 |
|---|---|---|
| 套件里根本没有题 | 「账本与套件都对不上，**或**该做的都做完了」 | `EMPTY` |
| 全部转运维（测量已用尽） | 同上 | `IDLE` |
| 每一格读数都达标 | 同上 | `DONE` |
| 目标被已 MET 的 gid 挡住 | 同上 | `STALE` |

四件事挤在一句**带「或」的句子**里 ⇒ 读者只能猜。而读这个输出的人
（包括下一轮的我）最可能的猜法是最后那个短句：**做完了**。
这正是「无事可做」与「做完了」被混成一个量的地方。

## §1 这一轮要回答的问题

> 系统停下来时，它能不能说清**是哪一种停**？

形式化：一个纯函数 `state(goals, esc, suite_ids, obs) -> (名字, 证据)`，
名字取自 5 个固定字符串，判定**只引用已有读数**（提议条数、转运维格数、每格的
`n_obs` 与 `mean_score`），⛔ 不引入任何新阈值、新目标类型、新分数。

⛔ **它不是新装置**：`state()` 不提议、不判定、不记账、不改任何一格读数。
它只做一件事：把已经算出来的三个量（`len(goals)`、`len(esc)`、逐格 `satisfied()`）
变成一句**不再带「或」**的话。轮次目标是「让『没有目标』这句话可分辨」，
不是「让系统更强」——按 §零 的提问，这轮让**累积离可测更近了吗**：
近了半步（账本上第一次能区分「做不动」与「做完」），但**没有**新增任何能力。

## §2 判据（8 条，全部结构命题）

分母一律写进字段名或括号里；⛔ 不许用「40 题」当 P1 的分母（纪律 46/67）。

| # | 命题 | 判 FAIL 的条件 |
|---|---|---|
| **P1** | **五态可达**：5 个构造输入 ⇒ 恰好 5 个**互不相同**的名字，且逐个与预期相等（分母 = 5 个构造输入） | 出现重复名字、出现 `UNKNOWN_STATE`、或某个预期名字没出现 |
| **P2** | **IDLE ≠ DONE（本轮主押）**：40 格全饱和 ⇒ `IDLE`；40 格全达标 ⇒ `DONE`（分母 = 2 个臂 × 40 格） | 两臂同名，或任一臂落到别的名字 |
| **P3** | **DONE 由读数算，不由「提议 0」算**：某格均分 0.5（3 次观测）且其 `RAISE` gid 已在 `done` 里 ⇒ `STALE`，且证据里**点名该格**、`blocked` 长度 = **1**（分母 = 1 个构造格） | 判成 `DONE`，或 `blocked` 为空、或长度 ≠ 1 |
| **P4** | **EMPTY 优先于 IDLE**：套件 0 题 + 历史账本里有转运维格 ⇒ `EMPTY`（分母 = 1 个构造） | 判成 `IDLE`/`DONE`（拿「测量已用尽」冒充「套件里没题」= 缺席冒充零，纪律 8） |
| **P5** | **可撤销（不是状态位）**：全饱和臂删掉**一行** `NOT_MET` ⇒ 该格不再转运维 ⇒ 提议 ≥1 ⇒ `WORK`；且除这一格外其余 39 格的转运维状态不变（分母 = 40 格） | 删行后仍是 `IDLE`；或转运维格数不是从 40 变 39 |
| **P6** | **CLI 表面换了话**：`--goals` 在 0 条时打印「状态    IDLE（…）」且**不再**打印旧文案「（没有可提的目标」；`DONE` 臂打印 `DONE` 且**不含** `IDLE`（分母 = 2 份输出） | 任一份输出里缺状态行、或旧文案仍在、或 DONE 臂出现 `IDLE` |
| **P7** | **不新增可调参数**：`mw/goals.py` 模块级常量仍为 `{KINDS, MIN_OBS, TARGET}`；`state()` 的默认值只引用这两个常量（无新数值字面量） | 出现新的模块级阈值常量，或默认参数里出现新的数字 |
| **P8** | **反例臂（判据有牙）**：把 `state()` 换成恒返回 `("WORK", {})` ⇒ P1/P2/P3/P4 **全 FAIL**（4/4，分母 = 这 4 条） | 任一条仍 PASS（⇒ 该条判的是常量，不是判别力） |

### ⚠️ 已知会被 P2 挤出真相的一点（先写，不事后解释）

`state()` 只能看**套件里的格**。若套件之外还有格被转运维，它们既不在 `IDLE` 的
计数里、也不会进 `DONE` 的判断 —— 那种情形下 `EMPTY`/`DONE` 说的是「**套件内**」。
本轮**不**扩展到「所有历史格」，理由：`suite_ids` 是环境边界，把它换成「账本里出现过的
全部 id」会让 `EMPTY` 永不出现（账本非空 ⇒ ids 非空），反而挡住 P4 那条判据。
⇒ 措辞里一律写「套件 N 格」，不写「全部」。

### ⛔ 不押的（避免先看后押）

- 不押任何**延迟/耗时**幅度（那是机器属性）。
- 不押真账本那一臂的具体提议条数（V171 已读到 40，再押就是自证）。
- 不押 `STALE` 在部署里**会不会**出现 —— 那是行为问题，本轮只造出来。
