## §0 起点：两次「先量」把题目换掉了

### 0.1 第一次量：§240.7 押的那条是空改动

`propose()` 末尾 `goals = [g for g in goals if g.gid not in done_set]`，`record()` 只记
`propose()` 的输出 ⇒ **进过 `done` 的 gid 不可能再出现 MET 之后的行** ⇒
「最后一次判定是 MET」≡「曾经 MET」。STAGE0 在真 API 造的 8 行 loop 账本上实测：
`MET 之后出现 NOT_MET 的行数 = 0`，`hist == naive == read`。

### 0.2 第二次量：真正的死结在 `RAISE` 的判据

`done` 只可能装 `COVER`/`PROBE` 的 gid，而这两类的判据是**出现次数**（只增不减）。
那 `RAISE` 为什么从没在 `done` 里出现过？STAGE0 穷举（`score ∈ {0,.5,1}`，`n ≤ 5`，364 组）：

| 读数 | 值 |
|---|---|
| 会提出 `RAISE` 的组合 | **348** |
| 当前读数已达标（`n≥3 且 mean≥1`）的组合 | **3** |
| 两者交集 | **0** |

解析理由（一句话）：`mean ≥ 1` ⟺ **每个**分数都 ≥ 1（分数上限就是 1.0）；
而 `RAISE` 只在 `mean < 1` 时提出。⇒ **一条 `RAISE` 目标被提出时，
它的判据已经不可能满足了**：观测只追加不替换，老的失败永远留在分母里 ——
再来多少次满分，均分只**趋近** 1，永不等于 1。

⇒ 本轮真正要做的不是「让 `done` 不单调」（那是空改动），而是：
**把「这一类目标按定义做不到」写成账本事实**，而不是等 V171 的
「连判 3 次且均分逐位相同」才认（那只抓到「模型确定性地重复」这一种情形）。

### 0.3 为什么这不叫「换尺子」

⛔ 本轮**不改** `TARGET`、`MIN_OBS`、`KINDS`、`criterion` 的任何一个字。
改的只是：**当判据可证不可满足时，把它从「待办」移进「已转运维」，并给出证明**。

### 0.4 与 V171 的关系

V171 的 `escalations()` 用**行为**判「测量没用」（3 次逐位相同）；
V173 加一条**结构**判据（一轮读数就够，且给出为什么）。
两者**共存**：行为那条留给「读数在动但没到 1.0」的格（例如 0.2→0.4→0.6，
AZ133a 钉着它不许乱转）；结构那条只在 `∃ score < TARGET 且 n ≥ MIN_OBS` 时触发。

## §1 改动（三处，都在 `mw/goals.py` + 一处 `run.py` 显示）

1. `unreachable(cell, obs, *, target, min_obs) -> dict | None`
   纯函数。返回证据或 `None`。**fail-open 两条**：
   - `n_obs < min_obs` ⇒ `None`（还没到提 `RAISE` 的门槛）
   - 发现任何 `score > target` ⇒ `None`（尺子坏了/口径混了，弃权，⛔ 不许拿坏读数断言做不到）
2. `escalations()` 增加第 4 个来源：结构不可达。证据里带 `reason` / `n_below` / `min` / `ceiling`。
   ⛔ 不动 V171 那三条触发条件（连判次数 / 逐位相同 / 达标即消失）。
3. `render_escalations()` 按 `reason` 分行渲染，**理由与读数都要印**（纪律 10）。
   `run.py` 的「已转运维」节保持**永远打印**（0 条也打）。

## §2 主实验判据（7 条，全部预注册）

装置 `v173.py`。

| # | 命题 | 它否掉什么 |
|---|---|---|
| **P1** | `RAISE` 不可达成：穷举 364 组，`提出 RAISE` ∩ `当前达标` = **0**；且「均分≥1」⟺「每个分数≥1」反例 **0** | 「提分目标做不完是模型不够强」 |
| **P2** | `unreachable()` 与解析式**逐组一致**：`n ∈ 3..6` × `score ∈ {0,.5,1}` 全枚举，判「不可达」⟺ `∃ score < 1`（且 `n ≥ MIN_OBS`）；追加 `k ≤ 8` 个满分后均分**严格 < 1** 且**单调上升** | 「装置把可达的也判成不可达」 |
| **P3** | 行为变化（同一台 loop 装置、`git stash` 真跑两臂）：`RAISE` 提议数 **5 → 0**、执行轮数 **8 → 3**、转运维时刻 **round 6 → round 4** | 「只多了一张报告」 |
| **P4** | 不误伤：全 1.0 且 `n≥3` ⇒ 不判（已达标）｜有 `<1.0` 但 `n<3` ⇒ 不判（仍提 `PROBE`）｜出现 `>1.0` 的分数 ⇒ **弃权**，`RAISE` 照常提 | 「为了报做不到，把能做的也说成做不到」 |
| **P5** | 留痕：转运维输出必须出现**理由**（结构 / 行为各一种）与读数（`n_below`、`min`、`mean`）；0 条时这一节仍然打印 | 「静默丢弃 = 做不成的被悄悄忘掉」 |
| **P6** | 部署态两个数：真账本 **40 条提议逐条相同（gid 集合相等）**、`escalations` **0 格**；并报「今天有几格在门槛外」（覆盖 6 格全 `n=1`） | 「改了就等于变好」 |
| **P7** | 变异体有牙：`unreachable` 恒 `None` ⇒ **P3/P5 FAIL**；恒非空 ⇒ **P4 FAIL**（两个都跑） | 「判据恒真/恒假」 |

**判据与押同向**（纪律 76）：本轮押「结构判据能提前认出不可达，且不误伤」。
P1 押的是一个**命题**（不是我的改动），它成立是本轮的前提，不成立则整轮作废。

## §3 边界（⛔ 不许放大）

1. **不提高任何分数**。产物是「知道哪条目标按定义做不完」，不是「做完了」。
2. ⛔ 不动 `TARGET`/`MIN_OBS`/`KINDS`；⛔ 不改 `RAISE` 的判据形式 ——
   「均分」要不要换成「最近 k 次」是**另一轮**的事，且必须先有这一轮的读数。
3. ⛔ 不说「L5 完成」。这一轮是**关掉一类永远闭不上的目标**，不是新增能力。
4. ⛔ 不碰 V79（自造判据 0/8）。
5. 必须报一个**负面读数**：`RAISE` 归零之后，系统能提的目标只剩 `COVER`/`PROBE`
   ⇒「自主目标」里的**改进**这一维在判据修好之前是空集。⛔ 不许把它写成进展。
