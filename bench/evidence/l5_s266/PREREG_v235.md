目录：`bench/evidence/l5_s266/`
接：§238~§245（L5 V170~V180）、§305（V234 累积第一次跨轮抬高）

## 0. 起点：两个断点，都在同一句代码里

L5 的现状是「能从账本提目标、能自判、能记账、换下一个」，但**「提分」这一类闭不上**。
两个断点有明确的行号，不是一个笼统的「不够强」。

### 断点 1（目标语言）—— `mw/goals.py:221-230`

```python
elif st["mean_score"] < target:          # 均分 < 1.0 ⇒ 提 RAISE
    ...
    statement=f"把 {c} 的均分从 {st['mean_score']:.4f} 提到 {target:g}",
    criterion=(("mean_score", ">=", float(target)),),
```

V173（§241）已证明：这个判据**在提出时就不可能满足**（`均分 >= 1 ⟺ 每个分都 = 1`，
观测只追加不替换 ⇒ 过去的失败永远留在分母里）。定理正确，**但它推出的动作是错的**。

推出来的动作是 `escalations()` 把这格转运维、`propose()` 用 `if c in esc_set: continue`
从此不再提（`mw/goals.py:221-224`）⇒ 系统对「提分」这件事永久停手。

### 断点 2（执行端）—— `run.py:3286-3295`

`--goals-act` 的执行是 `core.run(同一题面)` —— 确定性 solver 下**产出同一份代码**，
所以重测只会让均分更稳。V171 的活性对照（8 轮均分逐位相同 0.0）就是这个事实。

⇒ **判据说「去做一件不可能的事」，执行端「重复做同一件事」**，两者互相确认对方没用。

## 1. 本轮的外部依据（2026-11-23 检索）

| 来源 | 机制 | 与本轮的关系 |
|---|---|---|
| **Absolute Zero / AZR**（NeurIPS 2025 Spotlight） | Proposer/Solver 自博弈，**learnability reward**：太难（全失败）与太易（全成功）都得 0，只奖励「偶尔做对」的 Goldilocks 区间 | **判据不该是「满分」，是「有没有在变好」** |
| **Self-Challenging Language Model Agents**（Code-as-Task） | 自造任务 = 指令 + 验证函数 + **示例解（证明可解）** + **三个失败案例（证明验证器有牙）**，约 5% 存活 | 可满足性必须**被构造出来**，不是被假设 |
| **Explorer-Zero** | 子任务检查点把二值奖励拆成可分解奖励，避免「全 0 无梯度」塌缩 | 「全 0」与「部分成功」必须分开，不能同一个终点 |
| **DAEDALUS** | explorer 造题、solver 解，只有反复被验证有效的做法才沉淀成记忆 | 与 V234 的「采样 + 同一把尺子选择」同构 |

⛔ 只用它们的**判据思想**（learnability / 可满足性），不引入它们的训练环、不造新尺子。

## 2. 改动（最小集，全部可回退）

### 2.1 目标语言：`RAISE` 的判据换成「超过基线」

```python
base = st["best_score"]                      # 历史最好的一次单题得分
criterion = (("best_score", ">", base),)     # 可满足：只要出现更好的实现
```

- `stats()` 增 `best_score = max(scores)`（缺失时 0.0；**不读题面、不读 vec**）
- `evaluate()` 的算子值域加 `>`
- `base` 进 `criterion` ⇒ 进 `gid`（内容寻址，`AZ132c` 不变）⇒ 刷新一次就是**新一代目标**
- `best >= target` ⇒ **不提**（无可提升）

### 2.2 终止条件：新增 `STUCK_BEST`（与 `STUCK_MEANS` 并存）

同一 `gid` 连判 `MIN_OBS` 次 `NOT_MET` 且这几次 `reading.best_score` **逐位相同** ⇒ 转运维。
历史行没有 `best_score` ⇒ **不参与**（fail-open；V171 的 `STUCK_MEANS` 对它们照旧生效）。

⇒ 两条理由分工：
- `STUCK_MEANS`：读数（均值）没动 —— 抓「确定性重测」
- `STUCK_BEST`：最好成绩没动 —— 抓「换了路但都没超过基线」

### 2.3 执行端：`--goals-swap K`（默认 0 = 旧行为逐字节不变）

对目标格采样 `K` 个候选实现（复用 `mw/reflect.py` 的提议 + 每题自己声明的断言，
与 V234 的 `--critique-propose-k` 同一套零件），取最优写入账本；**只有严格更好才写**
（`promote` 语义，与 V228b/V234 同一条不变量）。

⛔ 不新增打分器：候选由**该题自己的断言**判分。
⛔ 不造题：只在现有套件上换实现。

## 3. 判据（预注册，跑之前写死；⛔ 事后不许改定义）

### P1 新判据在**真历史**上判出 MET
用 V234 的真实账本序列（`bench/evidence/l3_s302/crit_v234_r1_after.jsonl` 的 t01 行：
score 0.6667 → 0.8333）重建 obs，`propose()` 产出的 `RAISE` 必须是 `best > 0.6667` 形状，
且 `evaluate()` 在「5/6 那一版存在时」返回 **MET**。
**押**：MET，base=4/6，best=5/6。

### P2 旧判据在同一序列上恒 NOT_MET（两判据分道）
同一份 obs 上，`criterion=(("mean_score",">=",1.0))` 的判定必须是 **NOT_MET**。
**押**：NOT_MET。⇒ 「改的是判据本身，不是把数据换了」。

### P3 MET 之后**能再提一条**（链式，不是无限重复）
`done_gids()` 里那条 MET 被排除后，`propose()` 必须给出**新 gid** 且 base 更新到 5/6。
**押**：新 gid ≠ 旧 gid，`criterion` 的第二项 = 0.8333。

### P4 换路用尽 ⇒ esc(`STUCK_BEST`)，且修复轴 = MODEL
在候选池（V234 的 25 次采样，去重 6 个实现）上顺序喂：
第一次就出现 5/6 ⇒ best 刷新；之后 4 个候选（3/6、4/6 等）都不超过 5/6
⇒ 连判 3 次 `NOT_MET` 且 `best_score` 逐位相同 ⇒ 转 esc，`reason=STUCK_BEST`，
`repair_axes` 含 **MODEL**。
**押**：转运维，且 `n_swap` 被记账（不是静默跳过）。

### P5 天花板是**读数**，不是定理
候选池上 `max(best) = 5/6 < 6/6` ⇒ 6/6 在**这 25 次采样**里不可达。
必须报分母（25 次采样 / 6 个去重实现），⛔ 不许写成「6/6 不可能」。

### P6 不新增模块级常量、不改 `KINDS`
`AZ134f` 仍绿：`["KINDS","MIN_OBS","TARGET"]`；`KINDS` 仍是三元组（⛔ 不加第四类）。
`base` 是**目标内容**不是阈值常量。

### P7 变异体有牙
- 把 `best_score` 换成 `mean_score` ⇒ **P1 必须红**
- 把 `base` 固定成 0 ⇒ 首轮恒 MET ⇒ **P3/P4 必须红**
- 把 `STUCK_BEST` 的「逐位相同」删掉 ⇒ **P4 的误伤组必须红**（在收敛的序列上转）

### P8 历史重放不变
改的是「下一轮提什么」，不是「历史怎么判」：
`goal_obs` / `score_ledger` 的既有 66 行在 `stats()` 新字段下读数逐位不变
（`best_score` 只是新增字段，`mean_score`/`n_obs` 一字不改）。

## 5. 边界（⛔ 不许放大）

1. **V173 的定理没错**：`mean_score >= 1.0` 确实不可满足。本轮改的是**动作**（不再用它当目标判据），
   不是推翻证明。⛔ 不许写成「V173 错了」。
2. **不越过 V79 墙**：不要求系统自己写测试/自己造判据。判据仍是**题自带的断言**。
3. **类型表仍人写**：`KINDS` 仍是 `COVER/PROBE/RAISE` 三类。本轮修判据，不修类型表。
   ⛔ 不许写成「L5 完成」或「自己决定要变成什么」。
4. **离线重放 ≠ 新能力**：候选池是 V234 的真实采样产物，但**重放不产生新采样**。
   P1/P2 证明「判据改对了」；P4 证明「换路耗尽会被记账」。⛔ 不证明「模型变强了」。
5. **执行端换路是本轮才接的**：`--goals-swap` 默认 0，部署态行为不变；
   真跑它的读数在 `RESULTS_v235.md` 里单独报，与离线读数分开。
