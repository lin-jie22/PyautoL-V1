## 1. 命题

**H1（装置）**：换路行带 `vec` 之后，行为池的 `n_kept` 覆盖全部候选，
`n_behaviors` 可随新候选变化（旧装置在这条上**结构上不可能变**）。

**H2（机制）**：**换模型**能扩候选空间 —— 合并池（多模型）的行为类数
**严格大于**任一单模型池的行为类数。

**H3（收益）**：合并池的命中率（`score > 0.8333`，即 6/6）严格大于
单模型 7b 池的命中率。

**H4（反证）**：若三臂的行为类数完全相同且都为 2，则「候选空间窄」
**与模型无关** ⇒ MODEL 轴否证，下一步只能换任务形态（需拍板）。

## 2. 判据（三值；缺一条前提即 UNKNOWN）

| # | 谓词 | 通过条件 |
|---|---|---|
| P0 | 起点可复现 | 用真打分器（子进程）算 `start_answer.py` = 5/6，且 `vec` 非空 |
| P1 | 装置修好 | 换路产出的每一行都带 `vec`（`n_no_vec == 0`） |
| P2 | 换模型真的换了东西 | 至少一对 (模型A, 模型B) 的 `code_sha` 集合交集 < 各自大小（不是同一批输出） |
| P3 | 行为类数增加 | 合并池 `n_behaviors` **>** `max(单臂 n_behaviors)` |
| P4 | 命中率提高 | 合并池 `hit_over_n` **>** 7b 单臂 `hit_over_n`（两个分母都写进字段名） |
| P5 | 有牙（反证组） | 同一份 7b 候选重算两次，`n_behaviors` 与 `hit` 逐位相同（装置确定性） |
| P6 | 14b 小样单列 | 4 次的读数**单独报**，不并入合并池（破速度闸 ⇒ 不许当整轮证据） |

`P3`/`P4` 的分母口径：
- `n_behaviors` 的分母 = **去重后的行为向量数**（不是采样次数）
- `hit_over_n` 的 `n` = 该臂**实际拿到判分的候选数**（失败/空产出不计入分母，但单独计数）

## 8. 预注册**后**修订（pilot 1 次/臂之后；如实留痕）

⛔ 这三条都是**跑正式读数之前**发现并写下的，判据（P0~P6）**一个字没改**。

### 8.1 自检判据自己的量纲错了

P0 首版写 `abs(score - 5/6) < 1e-6`，而打分器给 `round(k/n, 4) = 0.8333`，
差 3.3e-5 ⇒ 自检当场 FAIL。**装置没坏，是判据的量纲错**（纪律 163 又一次）。
改为 `round(5/6, 4)`，同精度比。

### 8.2 `Qwen3.5-4B` 是 **thinking** 模型 —— 900 token 全被思考吃掉

`/api/show` 读数：`capabilities = [completion, tools, thinking]`，`family=qwen35`。
900 token 预算下实测：**thinking 3195 字符 / content 0 字符 / `done_reason=length`**。
`v1/chat/completions` 兼容层只回 `message.content` ⇒ 产出为空。

⇒ **同一 900 预算测 thinking 模型，测的是「截断」，不是「能力」**（纪律 77/96）。
若照此判「4B 不行」，那是判装置。

修订（两条，都单列）：
1. `B_4b` 按预注册 §5 的退出条件跑：**连续 2 次 `finish != stop` 就停该臂**，
   如实报「等预算下交不出代码」，⛔ 不补跑、不重试。
2. 追加 **`B_prime`**：同模型、`max_tokens=2400`（思考 + 代码）、4 次。
   ⛔ **不进合并池、不进 P3/P4 的分子分母**，只作方向指示。
