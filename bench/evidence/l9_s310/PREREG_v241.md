## 0. 为什么这轮非做不可

V239 记了一句「4B 能给 6/6，但 **3/6 截断**」。这句话现在**不可解释**：

1. 那个 `6` 的分母是**落分的候选数**，不是**调用次数** —— 被截断的调用抛
   `LLMError`，**不写 obs**（`run_v239b.log` 里两行「换路 #1/#3 失败：响应被截断」
   在 `obs_d2.jsonl` 里**没有任何对应行**）。分子分母不同源（纪律 4）。
2. 于是「4B 不行」与「4B 的答案比预算长」这两件事在读数上**同形**。
3. 而预算当时写死 ⇒ 「换个预算再看」结构上做不到。V240 把这扇门打开了。

**本轮问题**：把预算从 900 抬到 1600 / 2400，4B 的**截断率**与**落分率**怎么变？

## 1. 口径（写进字段名，不许事后再解释）

| 量 | 定义 | 取数处 |
|---|---|---|
| `n_att` | **调用次数**：动作 + 换路**实际发出**的 LLM 请求数 | 日志 `换路 #N` 行数 + `换路成功` 行数（见 §2） |
| `n_trunc` | 其中 `done_reason=length` 的次数 | 日志「响应被截断（done_reason=length）」行 |
| `rate_trunc` | `n_trunc / n_att`（**分母=调用次数**） | 上式 |
| `n_land` | 落分候选数（出现在 `obs` 里、有 `score`） | `obs_*.jsonl` |
| `rate_land` | `n_land / n_att` | 上式 |
| `vec` | 6 条断言的逐条通过位 | obs |
| `exact` | 产出与**起点**逐字节相同（`impl_sha == 90579ece`） | obs |

⚠️ `n_att` 必须**从日志行数数**，不能拿 `n_land` 反推 —— 那正是这轮要修的错。

| # | 命题 | 押 |
|---|---|---|
| **P1** | `rate_trunc` 随预算单调不增：`t900 >= t1600 >= t2400`，且至少一处**严格**下降 | PASS |
| **P2** | `rate_land`（4B）在 2400 下高于 900 | PASS |
| **P3** | 7b 的**每次**调用 `eval_count < 900` ⇒ 它在三臂里结构上都不可能被截断；其 `n_trunc` 恒 0 | PASS |

UNKNOWN 条件（任一）：① 服务在跑期间不可达；② 某臂 `n_att(4B) < 4`（早停）；
③ 日志缺 `eval_count` ⇒ 无法判 P3；④ 三臂不在同一时间窗（超过 60 min）。
许撤不许藏：任一条不成立 ⇒ 写 FAIL + 原文读数，⛔ 不许改写成「方向一致」。

**反证条件（这轮最要紧的）**：若 `t2400 >= t900`，则「4B 的失败主要是预算不够」
**当场死**，后续不许再拿预算当解释。同理若 `rate_land` 不涨，则「抬预算就能多拿分」
死，且**死因要单独写**（是「更长但更差」，还是「一样长」）。

## 4. 已知陷阱（跑之前写死，防事后找补）

1. **温度 1.0** ⇒ 同预算两次调用产出不同。所以「900 臂与 V239b 逐字节相同」**不是判据**，
   只有**聚合率**可比。
2. **早停**：R1 判 MET 就会缩短后续轮次 ⇒ `n_att` 天然不等到臂间相同。
   ⇒ 只能比**率**，不能比**次数**；且必须把 `n_att` 一起报。
3. **4B 的 6/6 是整段重写**（84 行），不是局部改（V239c）。抬预算可能只让重写更长。
   ⇒ 必须同时记 `exact`（照抄率）与产出行数，否则「变好」与「写更多」分不开。
4. **`--goals-swap-max-tokens` 只作用换路**，动作（`goals-act`）仍走它自己的 2048。
   ⇒ 动作行的截断**不计入**换路口径，单独记一行。
