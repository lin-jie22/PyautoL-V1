## 2. 口径（写死，防事后改）

| 量 | 定义 |
|---|---|
| `hit` | 把源码做**一次**编辑后能升到 6/6 的候选个数（单点可修性的存在性） |
| `nbr` | 该编辑空间的大小（可枚举，不是抽样） |
| `flat` | 与自身**同分**的邻居占比（越高 = 梯度越平；步长 7 采样，可复算） |
| `pos` | 洞命中的用例在**题面列举**里的序号（题面点 4 例：`1h30m`/`45s`/`2h`/`10m`） |
| `sim` | 与起点代码的 `difflib` 字符相似度（判「照抄 / 局部改 / 重写」，⛔ 不用行数差） |

单点编辑 = 以下四种之一：
1. 替换**一个** token（池 = 11 份实现 ∪ 2 份 6/6 实现里出现过的全部标识符/字面量，**不是我手写的修法清单**）
2. 删除**一行**
3. 插入**一行**（供体 = 两份 6/6 实现里的任意行）
4. （含在 1 里）改一个下标数字

**排除项（如实登记）**：`parse_duration`（替换成自身 ⇒ 无限递归）、
`input/print/open/exit/quit/eval/exec/compile`（替换成它们 = 引入外部 I/O 或反射，
与修补无关，且会让枚举**永久阻塞** —— 实测踩过，见 §6.1）。共剔除 2 个。

⚠️ `hit` 只回答「**单点**空间里有没有解」，不回答「全局修法是否唯一」——
重写是一条独立路径（§4.4）。

## 4. 四条结论

### 4.1 双向错配（本轮主结论）

| | `90579ece`（起点 B） | `09d0e23d`（起点 A） |
|---|---|---|
| 洞的形态 | 一行索引错（`parts[1]` 应为 `parts[0]`） | 只认单单位，复合格式整块缺失 |
| **单点修复存在？** | **是，1 个**（`1`→`0` @位置 432） | **否，0 个**（token/删行/插行全 0） |
| 模型实际动作 | 照抄 11/12 | 局部改 2/2（`sim` 0.639 / 0.814） |
| 结果 | 停在 0.8333 | 停在 0.8333（改不动） |
| **失败性质** | **意愿**：能改，不改 | **能力**：改了也没用 |
| 能被机制解开？ | **能**（只要指到那一个字符） | 不能（局部改空间里无解） |

**这是对 V239 §3.3 那句「洞越显眼越会改，洞越隐蔽越照抄」的精确化**：
显眼度决定的不是「改不改」，而是**「代码看起来是否完整」** ⇒
`90579ece` 有 h/m/s 三级分支 + try/except + 26 行，**外观完整** ⇒ 模型判定「无需动」；
`09d0e23d` 只有一层「按后缀取数」，**外观简陋** ⇒ 模型判定「必须改」。
两次改的产物都保留了起点的 `time_units` dict 与注释（`sim` 0.639/0.814），是**真局部改**。

### 4.2 分数不是单射的逆：同分 ≠ 同行为

把两处同形行一起改（`90579ece` 的 L16 与 L23 都是 `parts[1].split('m')[0]`）：

- 只改第 1 处 ⇒ `vec=111111`，**1.0**
- 两处都改 ⇒ `vec=011111`，**0.8333**（分数**完全不动**，只是洞从第 4 格挪到第 1 格）

⇒ 在 `90579ece` 上「改对」与「改坏」**在分数上不可区分**（都是 0.8333）。
`flat=0.152` 的 1480 个同分邻居里，至少这一类的 `vec` 是变的。
**推论**：任何只看分数的取舍（含 `auto` 的「严格更高才换」）在这份补丁上**都盲**。
这与 V239 §4 的 `auto` 失效是同一个病，只是这次发生在代码层。

### 4.3 洞的显眼度可操作化为两个数

| | `90579ece` | `09d0e23d` |
|---|---|---|
| 挂的格在题面列举的序号 | **4/4**（最后一例） | **1/4**（首例） |
| 题面里与洞**同构**的例子数（能被用来「验证模式」的） | **2**（`45s`、`2h` 都过 ⇒ 「单单位都行」已被证实） | **0**（`1h30m` 是唯一复合例） |

⇒ 「隐蔽」不是形容词：**同构且已通过的例子越多，洞越隐蔽**。
`90579ece` 有两个已通过的同构例在为它作证。

### 4.4 7b 与 4B 收敛到同一份代码，差一个 token

`6925d6b9`（7b，0.8333）与 `303b3bb6`（4B，1.0）**相似度 0.988**，同一轮独立生成，
差异只有：

```diff
-    parts_m = remaining_lower.split('m')     # 7b：'30m' -> ['30',''] ，len==2 -> 当有秒 -> 空 -> None
+    parts_m = remaining_lower.split('s')     # 4B：'30m' -> ['30m']  ，len==1 -> 当纯分钟 -> 5400
```

**一个字符（`m`→`s`）决定 0.8333 还是 1.0**，而两者的行数、结构、注释**几乎逐字相同**。
⇒ 这是「分数跟代码走、不跟说法走」最锐利的实例；也说明**洞不必隐蔽就能藏在两份近乎相同的代码里**。

⚠️ 7b 与 4B 之间**没有投喂**（并行候选），0.988 是**独立收敛**，不是复制。
两者的共同来源只能是同一条 prompt（含起点与题面），本条**不做**「谁抄谁」的推断。

## 6. 自踩（五条，两条会让读数反号）

1. ⛔ **枚举被 `len`→`input` 挂死整条**：替换目标池里含 `input`，
   候选变成 `if input(parts) == 1:` 去等 stdin ⇒ 进程被 SIGKILL（EXIT=137），
   输出全丢。**根因**：我把「池 = 语料里出现过的 token」当成了无副作用。
   **修**：排除 I/O/反射内建（2 个），stdin 钉到 `/dev/null`。
   **教训**：枚举里「语法合法」≠「可执行完毕」；**每个候选都要有墙钟上限**。
2. ⛔ **`ORIGIN` 首版把 act 行算成「从 seed 改」**：act 是**从题面独立生成**，
   没有起点代码。错归因会把 `1eb1b0ab`（独立写的 0.6667）算成「改了起点」。
   修后 `sim` 列只对 swap 行有值。
3. ⛔ **`limb` 首版用行数差判「局部 / 重写」**：`9454d0d2` 19 行 vs 起点 21 行（差 9.5%）
   ⇒ 误判「局部」，而它的内容差异其实很大。改 `difflib` 相似度后：`9454d0d2`=0.639、
   `5c07ad8e`=0.814（**都是真局部改**）、`6925d6b9`=0.329（重写）。
   **教训**：行数相同也能是重写；**分类必须先定数值口径**（纪律 89）。
4. ⚠️ **`flat` 是步长 7 的采样**，不是全枚举（全枚举要重跑 9 份 × 3000~30000 次）。
   报的是估计值，`table_v239c.json` 里有 `nbr` 可在需要时全算。
5. ⚠️ **`hit=1` 只在「单 token / 单行」空间里成立**。若允许「换掉整个函数体」，
   解有无数个。§5 的推荐依赖的是**局部**这条通路，不是「全局唯一」。
