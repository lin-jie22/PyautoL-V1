# mutate_s70 —— 「变异有界」的证据（第七十轮，2026-10-23）

## 这批文件是什么

| 文件 | 是什么 |
|---|---|
| `run_probe.log` | `bench/probe_mutate.py` 的完整输出（32 条检查全绿，含三臂生效读数） |
| `withdraw_AZ70_AZ72_AZ73.log` | 5 条新撤回态的逐条结果（各**单红**，R13 通过） |
| `mutate.py` / `mutation_check.py` / `probe_mutate.py` | 产生上面两个读数时的源码快照 |

`FILES.sha256` 是这批文件的指纹。核验：`shasum -a 256 -c FILES.sha256`。

## 三条**不能**读成的东西

1. **不是「内核能自己变强了」**。本轮建的是「界 + 拒绝 + 裁决前提 + 台账」，
   **没有**把自主变异接进 `Core.run`。为什么不做：现有 4 题集（天花板 0.70、
   连续四轮负结果）没有裁决能力，接上去只会得到一串 `UNKNOWN`。
2. **不是「变异有收益」**。`run_probe.log` 里三臂的分数都是 0（离线桩）；
   这个探针量的是**机械事实**：停滞轮数恰好等于 `max_stall`（1/2/3），
   说明旋钮真的被内核读了。把读数从 3 变成 1，和让答案变对，是两件事。
3. **不是「判定器能用真数据跑」**。`mutation_verdict` 只被形状化的数字喂过
   （0.60 → 0.85 之类），没有一次真实臂读数进过它。这条缺口登记在 DESIGN §33.8。

## 最硬的一格

`run_probe.log` 的「生效读数」段：

```
max_stall= 1  status=stalled  停滞=1 重复跳过=1 不同动作=1 交付= 19字  已变异
max_stall= 2  status=stalled  停滞=2 重复跳过=2 不同动作=1 交付= 19字  基线（未改）
max_stall= 3  status=stalled  停滞=3 重复跳过=3 不同动作=1 交付= 19字  已变异
```

`停滞` 列**恰好等于**阈值，而 `不同动作` 一直是 1、`交付` 一直是 19 字 ——
即：变的是"停得多晚"，不变的是"做过几件不同的事"与"最后交了多少"。
这说明旋钮走的是它该走的那条路，而没有顺手改动别的东西。

## 复现

```
python3 bench/probe_mutate.py          # ~2 秒，零模型、零网络
python3 bench/withdraw_check.py AZ70 AZ72 AZ73   # ~3.5 分钟（要跑 7 次完整契约）
```

⚠️ 撤回器**必须后台跑**：它每次都要跑一遍完整契约（约 30s），
前台会撞上执行上限并被 SIGTERM，而 python 重定向是块缓冲 ⇒ 日志 0 字节
**不代表**没在跑（本项目为此栽过一次，见 DESIGN §30.7 ②）。
