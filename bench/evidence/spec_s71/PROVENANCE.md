# spec_s71 —— 「题面与 oracle 同源」的证据（第七十一轮，2026-10-23）

## 这批文件是什么

| 文件 | 是什么 |
|---|---|
| `gen_spec_tasks.log` | `bench/gen_spec_tasks.py` 的完整输出：6 道题的逐题准入结果 + 8 道按种子铸的题全过 |
| `run_probe.log` | `bench/probe_taskspec.py` 的完整输出（10 项全绿，含四条反证与两条读数） |
| `withdraw_AZ75_AZ77.log` | 4 条新撤回态（㉖–㉙）逐条结果：各**单红**，基线 `565/0` 还原后仍是 `565/0`，R13 通过 |
| `taskspec.py` / `gen_spec_tasks.py` / `probe_taskspec.py` | 产生上面三个读数时的源码快照 |

`FILES.sha256` 是这批文件的指纹。核验：`shasum -a 256 -c FILES.sha256`。

## 三条**不能**读成的东西

1. **不是「这套题能分辨模型强弱」**。本轮**没有**任何真模型读数。
   这 6 道题的 headroom 是未知的。能说的只有三件：
   题面与 oracle 由同一份 spec 生成、四条证据各自被坏样本打红过、常识实现被扣到 2/7。
2. **不是「手写题也安全了」**。这套检查只覆盖**生成的**题：
   手写题没有 spec，后置条件无从推导 —— 7y 那个「题面写 n、oracle 交 n+1」
   在手写题上**依然只能靠人读**。覆盖面不许被读大。
3. **不是「内核变了」**。`harness_sha` **未变**（只动了 `bench/`）。
   旧曲线点没有因为本轮断段 —— 「加题」与「改内核」是两件事，本轮只做了前者。

## 最硬的一格

`run_probe.log` 里的两条读数：

```
常识分（严格居中即合格）：sg01=2/7 ｜ sg02=2/7 ｜ … ｜ sg06=2/7
长度合格却答错的题：['sg01', 'sg02', 'sg03']
```

第二条是本轮唯一称得上「新知识」的一格：截断的常识写法（留 n-1 个字符再补省略号）
长度**也 ≤ n** —— 后置条件（A3）全过，内容却是错的。
⇒ **题面承诺「能被检查」不等于承诺「能被满足」**；后者只能靠逐条比对（A4）。
谁把 A4 删掉，AZ77 就红。
