## 一、要回答的问题（只有这一个）

§72.5 与 §74.2 把载荷的价值形式化成一句话：

> 载荷的价值 = **题集里有多少失败能被一个名字说清**。

这句话到现在**只有方向性证据**（`tasks_v4` 上 `1` 比 `2` 高 10 格；`tasks_v1` 上 `1` 比 `2` 低 6 格），
**没有量过那个「多少」**。本轮把它量出来，并且按尺子分别量 —— 因为反号事实要求
「两把尺子的占比不同」这个中间量必须存在。

⛔ 本轮**不**回答：默认值该取几（那要 V4 的线性检验）。⛔ 也不回答「报名字是否总是更好」。

## 二、可操作定义（先写死，落盘后不许改）

### 2.1 单位与去重

- **单位** = 一份**唯一交付物** `(suite, task_id, sha256)`。
  同一份代码在多个臂/多轮出现 ⇒ 只算一次（分数与分类必然相同）。
- 只采 `answers.jsonl` 里 `kind == "answer"` 的行；`suite` 取自表头 `meta.suite`；
  无 `meta.suite` 的文件只许在 `PROVENANCE.md` 明确写出题集时才收录，并在输出里标注来源。
- 去重后的分母记为 **D1**（唯一失败交付物）。另报 **D2** = 不去重的失败行数（按文件逐行）。
  **两个分母都写出来**；主张挂在 D1 上，D2 只作稳健性。

### 2.2 「一个名字说清」的判据：**规范修复**

对每份交付物：

1. `code = code_exec.extract_code(answer)`
2. `base = code_exec.score(task, code)`（逐 test 独立子进程，与台账同一把尺子）
3. `names = mw.verify.undefined_names(code)`（**与内核载荷同源**，这是刻意的：
   要量的是「内核那个名字说不说得清」，不是别的东西说不说得清）
4. **规范修复**：对 `names` 里每一个 `(作用域, 名字)`，若该名字是**可 import 的模块**
   （`importlib.util.find_spec(name)` 成功），就在文件**顶部**按原顺序插入 `import <名字>`；
   `names` 为空、或是 `None`、或任一名字不可 import ⇒ 不做修复（并据此归族）。
5. `rep = code_exec.score(task, 修复后的代码)`

### 2.3 分族（互斥，按下列顺序判定）

| 族 | 条件 | 含义 |
|---|---|---|
| `NO_CODE` | 抽不出代码 | 空交付 |
| `PASS` | `base == 1.0` | 不进入失败分母 |
| `UNDECIDABLE` | `undefined_names` 返回 `None`（语法错 / 动态绑定） | 静态不可判 |
| `NO_NAME` | `names == ()` | 失败与「名字没绑」无关 |
| `NAME_OTHER` | 有名字，但至少一个**不可 import** | 名字不是模块，一行 import 补不出来 |
| `NAME_NULL` | 修复后 `rep <= base` | 名字在那里，但不是失败原因 |
| `NAME_PARTIAL` | `base < rep < 1.0` | 说出了**一部分** |
| `NAME_FIXED` | `rep == 1.0` | **一个名字就说清了**（这就是要量的面） |

- 主指标 `share = |NAME_FIXED| / |失败交付物|`，失败交付物 = 除 `PASS` 外的全部。
- 副指标 `share_any = (|NAME_FIXED| + |NAME_PARTIAL|) / |失败交付物|`。

⛔ 判据的已知偏向（写在这里，不留给事后）：这是**上界**。
它假设修复只会补绑定、不会改坏别处；真实重写会顺手改坏（§74.2 的 `4beacfc9`）。
所以 `share` 是「这个机会面**至多**有多大」，不是「报名字能拿到多少格」。
