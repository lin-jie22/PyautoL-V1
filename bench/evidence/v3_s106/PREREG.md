# 预注册 · 第 106 轮 · V4′：把「名字类机会占比」做成自变量

写定时间：**2026-10-28 21:30**（在**任何**模型调用之前；第一次跑批见 §6 时间戳）
上游欠账：§75（第一百零五轮）把「价值 = 题集里有多少失败能被一个名字说清」判成**欠定**，
因为同一个占比换分母（D1 交付物 / D2 行 / D3 格）就把四把尺子的排序翻过来。
§75.5 把出路改写成 **价值 = 机会 × 兑现**，并要求**两个因子分别控制**。

本轮只动第一个因子：**机会**。兑现那一半靠 §74 已有读数（`at04` 兑现 100% vs 0%、
`sg01` 兑现 38% vs 85%），本轮**不重测兑现**。

## 1. 一句话假设

> 若「报名字」的价值真的随**名字类失败占比**上升，那么在名字类占比 = 1 的题组上，
> `=1` 相对 `=2` 的格分差必须**大于**占比 = 0 的控制组。

## 2. 题集（构建物，已冻结）

- 文件：`bench/specgen/tasks_v5.jsonl`，**6 题 × 16 断言 = 96 格**
- 生成器：`bench/specgen/gen_v5.py`（`--emit` 才写盘；打分永远对着冻结的 jsonl）
- 文件 sha256 前 16 位：**`57e8d229dd1d25fa`**（30 929 字节）
- 结构（**这是本轮唯一的结构自变量**）：

| 组 | 题 | 交付时**必须**用到的外部模块 | 谁能被"名字没绑"绊住 |
|---|---|---|---|
| `nc` | nc01 / nc02 / nc03 | `re`+`os` / `json`+`os` / `datetime`+`os` | 是 |
| `ct` | ct01 / ct02 / ct03 | **无**（纯 `str`/`dict`/`int` + `open`） | **不能**（oracle 里零 `import`，S8 钉死） |

六题**交付形态相同**：都是「写一个文件，断言读它的字节」。三组对照差异写在第 5 节。

S8 的结构性反证（已跑，见 §4 N1）：把 `nc` 题 oracle 里提供某模块的那一行 import 删掉，
分数从 16/16 掉到 **0/16**，且 `mw.verify.undefined_names` **恰好**报出那个名字（6/6 全中）；
`ct` 题 oracle 里 `^\s*(import|from)\s` **一条都没有**。
S11 再反证一次检测器本身：往 `ct01` 里人为插一个没 import 的 `os.path.dirname`
⇒ 0/16 且报 `os`（说明「控制组零机会」是**题目的性质**，不是检测器睡着）。

## 3. 两个分母（§75.9 V5 的硬教训，先写死再跑）

| 记号 | 定义 | 本轮用途 |
|---|---|---|
| **D3′（主）** | **组内格分**：nc 组 3×16 = 48 格；ct 组 48 格；全体 96 格 | **判决只用它** |
| D1（辅） | 唯一失败交付物（按 `(题, sha256)` 去重）计数 | 只作描述，**不参与判决** |
| D2 | 全部失败行 | **本轮不用**（§75 已证明它只放大重复交付） |

**为什么主分母是 D3′**：本轮的自变量是**题组**，题组是按"格"定义的（每题 16 格、三题一组），
不是按"交付物"定义的。D1 会把「同一题答错三次」算成三个样本，而它们来自**同一份代码**——
那正是 §75.4 里 D1/D3 反号的原因。⛔ 所以本轮**不许**用 D1 的排序去支持或反驳任何结论。

## 4. 判据与判负（写死，事后不许改）

设 `score_A(t)` = 臂 A 在题 t 上的**平均格分**（3 次 rep 的 16 格平均，取值 0~1），
`Δ_t = score_A(t) − score_B(t)`，
`Δ_nc = (Σ_{nc} Δ_t) / 3`，`Δ_ct = (Σ_{ct} Δ_t) / 3`，`Δ_all = (Σ_all Δ_t) / 6`。

| # | 方向 | 条件 | 判定 |
|---|---|---|---|
| **P1** | need_diff | `Δ_nc − Δ_ct ≥ 4/48 = 0.0833` | 「Δ 随名字类占比**上升**」成立（与 §74 的 `at04` 方向一致） |
| **P2** | need_diff（反号侧） | `Δ_nc − Δ_ct ≤ −0.0833` | **反号** ⇒ 撤回「价值 = 机会 × 兑现」这个**乘法形式** |
| **P3** | 灰带 | `|Δ_nc − Δ_ct| < 0.0833` | **UNKNOWN**：这把尺子分辨不了，不许说"支持"也不许说"否证" |
| **P4** | 描述 | 两臂 `NAME_FIXED` 计数、每题的 sha 重复情况 | 只登记，不作判决 |

**门槛来源**：4/48 = 8.33% ≈ 每题 16 格里「差 4 格」。§74 实测 3 格是本尺子的分辨力下限
（`probe_at04.py --selftest` 的第 4 例），取 4 格以留 1 格余量。⚠️ 这是**门槛**，不是显著性检验：
48 格来自 3 道题，**有效样本 = 3**，本轮只能做**否证**（两族同向 ⇒ 打脸乘法形式），
不能做「证实」。⛔ 报告里不许出现 p 值，也不许写「显著」。

判负（装置层，任一红 ⇒ 本轮读数作废）：

| # | 条件 | 硬要求 |
|---|---|---|
| N1 | 尺子十一条自检 | `python3 bench/specgen/gen_v5.py` **EXIT=0**（S1~S11，含 S8/S11 两处反证） |
| N2 | oracle 上界 | `--solver oracle` 在 `tasks_v5.jsonl` 上必须 **96/96**（否则题目不可解） |
| N3 | 分类可复现 | 同一份台账跑两遍分类表，`sha256` 逐字相同 |
| N4 | 口径签名 | 两臂 `caliber_sig` 逐字段 flat 比对，**只许差 `limits.verify_static` 一项** |
| N5 | 同端口 | 两臂代理都监听 **8812**，`--upstream`/`--inject`/模型相同 |
| N6 | 尝试数 | 每臂 `▶ 任务开始` 计数 = **18**（6 题 × 3 rep）；代理台账行数 > 0 |
| N7 | 机会测量独立于臂 | 「首答是否有未定义名」用**反馈前**的第一份交付 + 纯静态 `undefined_names`，**零模型** |

## 5. 已知混杂（如实登记，不假装消除）

1. **`nc` 组多一条规则**：`nc` 要"父目录不存在时先创建"，`ct` 明说"父目录总是已存在"。
   这条规则**不能删** —— 它就是 `os` 这个名字的来源。⇒ 两组差异**不止一条**：
   除了名字机会，`nc` 还多一条 IO 规则（8/8/7 条规则 vs 7/7/7 条）。
   这条规则**不偏向任何一臂**（两臂都要满足它），但它会抬高 `nc` 组的整体失败面。
2. **难度没有被匹配**，也不声称匹配。`nc` 与 `ct` 只保证"`undefined_names` 在 `ct` 上无事可做"。
3. **顺序**：A（`=1`）→ B（`=2`）串行，不随机。§74 同夜三臂也是串行，登记为已知混杂。
4. **同夜**：两臂同一 session（§62：跨晚对照一律不算数）。
5. **一次跑批 18 次尝试/臂**，模型为 `qwen2.5:7b`，`temperature=0`，
   但 §63 已登记「`T=0` 不是逐字确定」⇒ 方差来自通道，不来自温度设置。

## 6. 决策规则（**先写死，避免事后挑臂**）

**D0**：`nc` 组首答（反馈前）里「含未定义名」的题 **< 2 道** ⇒ 判定**题面构造失败**（把占比抬不起来），
A 臂跑完即**不跑 B 臂**，登记「名字类机会不可由题面构造控制」+ 成因读数
（逐份首答：用了模块吗 / 写了 import 吗）。这条与 `Δ` 无关，**只看静态分类**，所以不受臂影响。

**D1**：D0 不触发 ⇒ 跑满两臂，按 §4 判读 P1/P2/P3。

**D2**：若 P1 成立，**也不改内核默认值**。改默认为 `1` 需要的是"哪把尺子说了算"的判据，
本轮只回答"Δ 是否随占比动"。⛔ 默认值仍为 `2`。

## 8. 预注册修正（**在 A 臂仍在跑、任何 Δ 都还没算出来的时候写下**）

### 8.1 ⛔ §6 的 D0 取证方式**不可行** —— 台账里没有"第一次交付"

开工后核对台账结构（`§74 a1_v4/answers.jsonl` = **24 行 = 24 次尝试**，8 题 × 3 rep）：

> 台账**只存每次尝试的最终交付**。一次尝试内部的多次模型调用
> （包括被自检打回后的重写）只留下**最后一份**。

⇒ 预注册写的「首答（**反馈前**）」在本装置里**不存在独立记录**。
若坚持拿"每次尝试的最终交付"当首答，`=1` 臂的首答已经吃过自己的打回
⇒ 机会被**系统性低估**，而低估的幅度恰好等于机制的效应 —— 正是本轮最该避免的污染。

### 8.2 替代取证：打回日志（`probe_gate_hits.py`）

`run.log` 在机制**触发的那一刻**独立记账，而被打回的就是那一次交付：

```
🧪 自检未过（第 1/2 次打回） ⇒ 退回重写：1/5 项未过：未定义的名字 'os'（在 … 内被引用，…）   ← =1 臂
🧪 自检未过（第 1/2 次打回） ⇒ 退回重写：1/5 项未过：自检未通过（不提供细节）              ← =2 臂
```

- **机会(题)** = 该题至少有一次交付被判「未定义名」
- **机会(尺)** = 机会为真的题数 / 3
- ⚠️ `=2` 臂**看不见名字**（盲报的载荷就是不给细节）⇒ 名字归因只来自 `=1` 臂；
  两臂的**触发题数**若相同，则触发集等价（§73 的等长安慰剂臂正是靠这一点成立）。

**§6 的 D0 阈值与判读不变**：`nc` 组触发过的题 **< 2** ⇒ 判题面构造失败、不跑 B 臂。
变的只是取证来源。
