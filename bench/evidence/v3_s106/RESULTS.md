## 76.0 一句话

造了一把 6 题 96 格的尺子，其中 3 题**强制**用 `re`/`json`/`datetime` 与 `os`；
模型 18 次交付**一次都没忘 import** ⇒ 名字类机会 **0/3 题** ⇒ 预注册 D0 触发，不跑第二臂。

⭐ 而零模型的成因分析给出了真结论：**「缺名字」只出现在「整份答案一行 import 都没有」的交付物里**
（7/7），而在有 import 行的 **49 份里 0 份**。⇒ 机会不是「题目需不需要模块」的函数，
是「这一份答案长什么样」的函数，而后者**不由题面决定**。

  这条规则**就是 `os` 的来源，删不得**；两臂都要满足它，所以它不偏向任一侧（PREREG §5.1）。

## 76.3 ⭐⭐ 为什么机会是 0：它只出现在"没有 import 行"的答案里

`probe_import_shape.py`（零模型，扫全部已冻结交付物，按 `(suite, task, sha)` 去重）：

| 尺子 | 交付 | 整份答案无 import 行 | 无 import 且缺名 | **有 import 且缺名** | 缺名合计 |
|---|---|---|---|---|---|
| `tasks_v1` | 14 | 7 | 1 | **0** | 1 |
| `tasks_v2` | 48 | 29 | 2 | **0** | 2 |
| `tasks_v3` | 10 | 7 | 0 | **0** | 0 |
| `tasks_v4` | 22 | 7 | 3 | **0** | 3 |
| `tasks_v5`（本轮） | 6 | 2 | 0 | **0** | 0 |
| `v1_s102_at04` | 2 | 1 | 1 | **0** | 1 |
| **合计** | **102** | **53** | **7** | **0** | **7** |

> **7 份缺名字的交付物，7 份整份答案里一行 import 都没有；有 import 行的 49 份里，0 份缺名字。**
> （102 − 53 = 49。这个减法必须写在旁边 —— 我第一次口述成 "95 份" 就是没做这道减法。）

`§75` 的 94 份冻结分类表按族交叉，同一结论：

| 族 | 有 import | 无 import |
|---|---|---|
| `NAME_FIXED`（一个名字就说清） | **0** | **6** |
| `PASS` | 16 | 19 |
| `NO_NAME`（失败但不是名字） | 28 | 18 |

本轮 6 份唯一交付的形态：`nc01`/`nc03` 顶层 import、`nc02` 在**函数体内** import、
`ct01`/`ct03` 无需 import、`ct02` **在不需要的时候 import 了 4 个模块**（见 76.4）。

⇒ 把三件事分开（这是本轮最有用的一句）：

1. **题面能决定的**：这一题**用不用**外部模块（本轮做到了：`nc` 组 3/3 用了）。
2. **题面决定不了的**：模型会不会写 `import` 行（本轮 3/3 都写了，`nc02` 写在函数体内）。
3. **缺名字只发生在 2 为"否"时**（7/7 vs 0/95）。

⇒ §75.5 的「价值 = 机会 × 兑现」里，**机会这一项不是题集的属性**。
上一轮把它当作"题集里有多少失败能被一个名字说清"，本轮证明连"造题集去把它抬高"这条路也堵了：
**抬高它的唯一办法是控制答案形态**，不是控制题目。

## 76.4 失分面 vs 可判据面：33.3% vs 0%

两处 0/16 都是**真失败**（我用 `bench/scorers/code_exec.py` 复算过，不是题面欠定）：

- **nc02**：把 `json.dumps(...)` 写成 `str(dict).replace(' ','')` ⇒ **单引号**、不是 JSON ⇒ 16/16 断言全红。
  它 import 了 `os` 与 `defaultdict`，**名字一个不缺**。
- **ct02**：规格明说"父目录总是已存在、不需要创建"，它自己加了
  `if not exists(dirname(path)): makedirs(dirname(path))` ⇒ `dirname('c.txt') == ''` ⇒
  **`FileNotFoundError: ''`** ⇒ 16/16 全红。它 import 了 4 个模块，**名字一个不缺**。

⇒ 这把尺子上：**失分 96/288 格（33.3%），其中"名字没绑"能说清的 = 0 格（0%）**。
闸 18 次尝试一次没触发，不是闸坏了（`判据=5项(…/未定义名)` 每次都跑了），
而是**它判的那一类错误这一次一个都没出现**。

这给 §73.3「判据的修复面 ≠ 尺子的失分面」添了一个更极端的形态：
**失分面很大（1/3 的格），可判据化的子集是空的。** 而且 `ct02` 那种失败形态
（多写一步、运行期炸）**按设计**不在静态判据的能力范围内 —— 要抓它必须执行，
而执行早在 §80 就被读数否掉了（沙箱代价、边际 +1 格）。

## 76.6 自踩（五处）

1. ⛔ **预注册 §6 的取证在装置里不存在**。原本写「`nc` 组**首答（反馈前）**含未定义名的题数」，
   开工后核对台账：`answers.jsonl` 24 行 = 24 次尝试（§74 可查）⇒ **只存每次尝试的最终交付**，
   一次尝试内部的多次调用只留最后一份 ⇒ "反馈前的第一次交付"没有独立记录。
   拿它当机会会**系统性低估**，而低估幅度恰好等于机制效应。
   修法：改用**打回日志**（机制触发那一刻的当场记账），并在 §74 旧日志上做跨方法核对
   （`a1_v4`：3 次打回全 `os`；`a2_v4`：6 次打回无名字）—— 与 §74 已登记事实一致。
   ⚠️ 这是"测量装置吃掉效应"的第 6 次同族（§70.4③ / §73.5.2 / §75.7.2）。
2. ⚠️ **`run_v5.sh` 里那道自动闸接在了一个我自己刚降级的探针上**：判决口径变了，脚本没跟着改。
   这次两个探针都给 0（凑巧一致），但那是**运气不是设计**。下一轮把闸接到 `probe_gate_hits.py`。
3. ⚠️ **"配平规则条数"没做到**：`nc` 8/8/7 vs `ct` 7/7/7。已在预注册 §5.1 登记；
   事后看它连混杂都算不上（它没能制造出任何机会），但登记本身不能省。
4. ⭐ **3 rep 逐字节相同**（6 个 sha 各出现 3 次）⇒ 本轮任何"格级"统计只有 **6 个独立样本**。
   若我拿 288 格去算置信区间，会把样本量虚报 48 倍 —— 这正是 §75.4 里 D1/D3 反号的同一种病。
5. ⛔ 尺子里的 `nc01` 有 16 条断言的期望值是 `re.sub` 语义，若模型的实现用 `str` 手工删标记
   也能过 —— 那是**允许的**（题面没说必须用 `re`）。这正是"题面决定不了答案形态"的另一面：
   题面可以说"你需要这个能力"，但不能说"你必须写这一行 import"。
