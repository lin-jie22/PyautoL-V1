## 4. 分母：三选一

| 分母 | 定义 | 本轮 |
|---|---|---|
| D1 | 按**题**（3 题/组） | 用于 **P1 / P3 的按题部分**、P4 |
| D2 | 按**题 × rep**（9 格/组） | ⛔ 不用 |
| D3 | 按**格**（48 格/组） | 用于 **P0 / G1 / P2 / P3 的按格部分** |

### 4.1 为什么**必须**两套分母并用

§78 的教训是硬的：`Δ_ni = +16/48` 看起来很大，但**全来自 1 题**（3 题 Δ_t = {0,+1,0}）。
⇒ 只报格数会**系统性高估**，把"1 题动了"读成"平均 +0.33"。

但只用题数又太粗：3 题只有 0/1/2/3 四档，`M_wi = 12/16` 这个精度表达不出来。

**分工写死**：

- **P0 / G1 / P2 / P3（格侧）用 D3** —— 它们是"幅度/贴壁"判断，需要分辨率。
- **P1 / P3（题侧）/ P4 用 D1** —— 它们是"是不是只有 1 题在动"的判断。
- **D2 一律不用**：3 rep 逐字节相同（§76/§77/§78 连续三把尺子都是）
  ⇒ 9 格 = 3 个独立样本，`rep` 不是独立维度。

⛔ 不许在报告里只报 D3 不报 D1；也不许拿 D3 的 `Δ` 去写"平均提升"。

### 5.3 ⭐ 为什么 P1 按题而 P2 按格

- **P1 问"有没有多数题在动"** ⇒ 必须按题，否则 1 题刷 6 格就能过。
- **P2 问"动了多少"** ⇒ 必须按格，否则"1 题满分"与"3 题各涨 5 格"分不开。
- **两条都过**才算 `Δ_ni` 成立；**任一条不过** ⇒ `Δ_ni` 记作"未成立"，理由是具体的（缺哪条）。

### 5.4 P4 为什么放在形态层

§78 的形态层读数是本轮**唯一不受 `P0` 影响**的东西（零模型，只读交付文本）。
`added = 交付 import 行数 − 骨架自带 import 行数`：
- `wi` 组自带 1 行 ⇒ 交付也是 1 行 ⇒ `+0`（没补、也不该补）
- `ni` 组自带 0 行 ⇒ 交付有 1 行 ⇒ `+1`（**自己补的**）

⛔ 不许用 `from re import sub` 冒充"补了 `re`"（绑成员 ≠ 绑模块名，`undefined_names` 仍报 `re`）。

## 12. ⚠️ 更正（2026-10-29 15:00 追加，起跑后 3 分钟发现，**未改任何门槛**）

§1.1 与 §10.1 登记的 `suite_sha = aece03f6dec738fc` **是错的**。
真口径（runner / `caliber.sig` 里那个）是：

```
Suite.sha() = 519dad774a3664612e6611b220b33f4a
```

**错因**（已实测复现，不是推测）：`aece03f6dec738fc` =
`sha256(json.dumps(rows, ensure_ascii=False, sort_keys=True))[:16]`，
即"把 JSONL 六行读成 list 再整体 dumps"的口径；而 `mw/bench.py:442` 的 `Suite.sha()`
是对 **task fingerprint** 做的 `_canon(...)` 哈希。**两个函数，同一份文件，两个数。**

| 公式 | 值 |
|---|---|
| `Suite.sha()`（真口径，进 `caliber.sig`） | **`519dad774a36…`** |
| `sha256(json.dumps(rows, sort_keys=True))[:16]`（我写进 PREREG 的） | `aece03f6dec738fc` |
| `sha256(json.dumps(rows))[:16]`（不排序） | `31d6d366135c2ebe` |
| 文件 sha256[:16] | `2f88c1702fa43e0a`（**与 §1.1 一致，文件没被动过**） |

### 12.1 影响评估（逐条核，不许一句"无影响"带过）

| 问 | 读数 |

| 两臂用同一份文件吗 | ✅ 是（同一个 `SUITE` 变量，同一副本 `/tmp/v1_s109_work`） |
