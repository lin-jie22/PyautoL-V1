### 3.1 那 4 轮**不是**模型交空，是客户端超时（逐条取证）

`s0_r1` 的 `e3wi` 段原文：

```
00:39:42 ▶ 任务开始: …把函数 `week_of` 补全
00:42:57   💥 内核异常 LLMError: 请求失败: TimeoutError: timed out
00:42:58 ■ error | steps=0 | … | 抖动重试=1 重试后仍失败=1
```

`195 秒` 从开始到放弃，而 `V1_LLM_TIMEOUT_S=120`、`V1_LLM_RETRIES=1`
⇒ 第一次 120 s 超时，重试再等 75 s 后被墙钟截断。

代理台账（`/tmp/v22/proxy.jsonl`，357 行）**全部 `status=200`、`error_code=None`**，
且 `00:42:58` 那一条是 `finish_reason=stop`、`completion_tokens=176`、`prompt_tokens=1948`
⇒ **服务端 1 秒后就把结果算完了，客户端早了一秒放弃**。

⇒ 这是纪律 8 的正例：「通道忙 ≠ 模型交空」。所以按 `P0-a` 的要求**补跑**，不记 0 分。

## 5 核心发现：`e1ni` 的交付件 diff

`S0`（无 reward 段，529 字）与 `S1`（有 reward 段，565 字）的 diff：

```diff
 ```python
-import re
-
-def _strip_tags(text):
-    return re.sub(r"@[A-Za-z0-9]+", "", text)
-
-
 def clean_lines(items, path):
     kept = []
     seen = set()
-    for item in items:
-        stripped = _strip_tags(item).strip(" \t")
+    for raw in items:
+        clean = _strip_tags(raw).strip(" \t")
+        ...
+    # 遍历 items，按规则 1~3 生成 kept（处理后的字符串列表）。
+    # _strip_tags(raw) 删标记；去首尾空白用 .strip(" \t")。
```

ⓘ **`S1` 把 `import re` 和 `_strip_tags` 的**整个定义**都删了，但代码里仍然调用 `_strip_tags(raw)`**
⇒ `NameError` ⇒ 0 分。而 `S0` 完整保留了这两段 ⇒ 16 分。

⇒ 这**不是**「模型没读懂检查项」那么简单：
`S1` 的版本多了注释、多了 `clean.strip("@")`、变量改名 `item`→`raw`
—— 它是**把整个文件重写了一遍**，重写时丢了前置骨架。
这与 §74「改动半径」、§79.6「`keep_ratio` 掉下来时丢的是骨架函数」是**同一形态**。

## 8 边界

⛔ 本轮**不能**得出：

- 「累积循环闭合了」—— 只有一次投喂、seed 固定，闭环没走两圈。
- 「系统自己学会了」—— 检查项→错误类别映射是人写的模板。
- 「检索有区分力」—— 6 题里 4 题恒定，能动的只有 `e1ni` 一道。
- 「提示内容有害」—— 本轮只测到「有这个块 vs 没这个块」，**没做等长安慰剂臂**
  （§85.9）。内容与扰动在 `T=0` 下结构性不可识别。
