# V26 判决书 —— V25 那 +16 的通路不是 `facts`，是**一个字符**

> 预注册：`PREREG.md`（冻结于任何 V26 读数之前）。装置：`run_v26.sh`。分析：`analyze_v26.py`。
> 内核**零 diff**。四轮，2026-10-31 12:04–12:31，同一时段连续跑完。

## 0 这一轮有没有让「累积循环」离可测更近一步？

**有，而且是往回退了一步才发现路在哪。** 上一轮我写的归因是错的；这一轮把它推翻了，
并给出**字符级**的通路：跨轮唯一改变 prompt 的东西，是工作记忆句柄编号 `b#1` → `b#12`。

---

## 1 先撤销上一轮的一句归因

V25 §89.4 写「通路由 `facts` 进 prompt」。三条独立读数把它否掉：

| # | 读数 | 命令/位置 |
|---|---|---|
| 1 | `recall(e1wi 题面)` 在真实库上返回 **0 条** | `MemoryStore.recall`（`memory.py:351`），FTS 24 个 token 对 2 行 facts |
| 2 | 用真实库复算 `_state(e1wi)` 只有 `['[目标]','[第']`，**无 `[语义记忆]`** | `Core._state`（`core.py:1377`） |
| 3 | 日志 `语义记忆=2` 是 `memory.stats()["facts"]` = **表行数**，不是送达条数 | `core.py:1964` → `memory.py:398` |

**第 3 条是我自己误读自己的台账**：把「库里有几条」当成了「送进去了几条」。
本轮的最强证据不是复算，而是**模型自己看到的那一行**：

```
[工作记忆] [b#1 23字 sha=34ea10ccd32e] recall ⇒ ✔ (语义记忆中无相关条目)
```

两轮**都**是「无相关条目」⇒ `facts` 在两轮里都没有进 prompt。**归因作废。**

## 2 装置与读数

| 臂 | 库 | echo | 轮 | e1wi | 其余五题 | Σ |
|---|---|---|---|---|---|---|
| `d2` | 累积 | 0 | r1 | 0（`4e9be367`） | 与 r2 同 | **48** |

- **正控 `f2`：两轮 17 个 `(task, it)` 的 state 逐字节相同（差异 0 个）。**
  ⇒ 「同起点 ⇒ 同 state ⇒ 同答案」在**这一晚**成立，`noise_floor = 0` 这次是 state 级的，不只是分数级的。
- `d2` 重复出了 V25 的 +16（`e1wi` 0→16，同一对交付件 sha `4e9be367` → `7fd287cd`）。

## 3 判决（按 PREREG §2）：**J1 定位成功**

`d2` 六个 `(task, it)` 的 state 不同，**首差异块全部是 `[工作记忆]`**：

| task | 步 | 差异行数 | 归一化后 | len |
|---|---|---|---|---|
| `e1wi` | 2 | 2 | **相同** | 1384 → 1385 |
| `e2wi` | 2 | 2 | **相同** | 1559 → 1560 |
| `e2ni` | 2/3/4/5 | 2 | **相同** | 1552/1585/1585/1585 → +1 |

**归一化 = 把 `b#\d+` 全换成 `b#N` 再比。六处全部相同。**
⇒ 跨轮 prompt 的**全部**差异就是句柄编号本身，**没有一个字的内容差异**。

`e1wi` 步 1 的 state **逐字节相同**（1198 = 1198，差异行 0），步 2 只差这一处：

```
-[工作记忆] [b#1  23字 sha=34ea10ccd32e] recall ⇒ ✔ (语义记忆中无相关条目)
+[工作记忆] [b#12 23字 sha=34ea10ccd32e] recall ⇒ ✔ (语义记忆中无相关条目)
```

`b#` 的来源：`memory.capture()` 用 `blobs` 表的 `lastrowid` 造句柄（`memory.py:228-233`）。
跨轮库不重置 ⇒ 行号接着涨 ⇒ 第 2 轮的第一次捕获从 `b#12` 起（第 1 轮写了 11 条）。

## 4 ⭐⭐⭐ 一句话结论

> **累积循环确实通电，但它送进 prompt 的不是知识，是一个自增行号。**
> 一个字符（`1` → `12`）就足以把 `e1wi` 从 0 分的那版（`set`+`append`，AttributeError）
> 翻到 16 分的那版（`list`+`seen`）。

⇒ 这才把 V23「内容值 0」、V24「投喂×盲报的交互」、V25「扰动不是知识」三句话**统一到同一个机制上**：
在这套装置里，**任何**对 prompt 的改动都会让 7B 模型换一个采样点；而跨轮累积**目前唯一**
能改动 prompt 的东西，是 `blobs` 的自增 id。

⚠️ 必须同时说清的一条：**这不等于「记忆通道永远只能是噪声」**。它说的是
「**在这套装置 + 这个模型 + 这个预算下**，跨轮真正进到 prompt 的信息量为 0，
能观察到的 Δ 全部由 token 级扰动产生」。若哪天有内容真的进了 prompt（`[语义记忆]` 非空、
`echo=1` 的 reward 段），那是另一个量级的事 —— 本轮没测到那种情形。

## 5 三条连带修正

1. **`facts` 通道在本装置上等于没接线**：`recall(题面)` 对 v8 六题全 0 命中
   （题面的 24 个 token 与 2 行 facts 无交集）。V22 §0.4 那句「断电在检索层」**至今仍成立**，
   V25 以为它通了的判断作废。
2. **`[工作记忆]` 的句柄 id 是一个把库的增长泄漏进 prompt 的通道**：内容零信息、形状是编号。
   它让「库变大」与「模型行为变化」之间出现了一条**与语义无关**的因果边。
3. **`f2` 正控第一次做到 state 级**：V25 只能用分数说 `noise_floor=0`，本轮能说
   「同起点的 17 个 state 快照逐字节相同」。

## 6 边界（⛔ 不许越过）

1. 只能说：`tasks_v8` / `qwen2.5:7b` / **2026-10-31 12:04–12:31 本时段** / 起点全空库。
2. ⛔ 不许说「内核学会了怎么写 `clean_lines`」：它连 `[语义记忆]` 都没看见。
3. ⛔ 不许说「累积无用」：累积确实改了答案，只是改的**途径**是行号不是知识。
4. ⛔ 不许与 V25 的轮次并列（不同时段，§87.6）。
5. ⚠️ 本轮 `d2` 只有 2 轮、`+16` 仍是 **1 次观测**（`f2` 只是同起点控制，不是同一变量的对照）。
   ⇒ 下一步必须做成**单变量对照**：冷启动 + 人为把 `blobs` 预置 11 行 ⇒ 句柄从 `b#12` 起，
   其余一切不变。若那样也能翻到 16，才是字符级因果（见 §7）。

# 附：V27 字符级因果 —— **一个自增行号足以把 `e1wi` 从 0 翻到 16**

> 预注册 `PREREG_V27.md`（12:5x 冻结，早于任何 V27 读数）。装置 `run_v27.sh` + `seed_blobs.py`。
> 两次独立冷启动，12:42–12:57，与 V26 同一时段。内核零 diff。

## 8.1 装置（唯一变量 = `blobs` 的自增行号）

`s12` 臂 = **空库 + 预置 11 条 dummy blob**。预置脚本只调 `MemoryStore.capture()` 11 次：
`blobs max_id=11 count=11 | facts=0 episodes=0`（⛔ 不写 facts / episodes / reward）。
⇒ 冷启动第一次捕获拿 `b#12`，其余一切与对照 `d2_r1`（冷启动、`b#1`）相同。

## 8.2 读数

| 臂 | 起跑库 | 首个句柄 | `e1wi` | `e1wi` 交付件 | Σ |
|---|---|---|---|---|---|
| `d2_r1`（对照） | 空 | `b#1` | **0** | `4e9be367`（463 字） | 48 |
| `f2_r1` / `f2_r2`（对照） | 空 | `b#1` | 0 / 0 | — | 48 / 48 |
| `s12_r1` | 空 + 11 dummy | **`b#12`** | **16** | `7fd287cd`（499 字） | **64** |
| `s12_r2` | 空 + 11 dummy | **`b#12`** | **16** | 同上 | **64** |

- 正控（PREREG §2 条件 0）：两次的 state 里真的出现 `b#12 b#15 b#17 b#18 b#19` ⇒ 预置生效。
- `s12` 两次独立冷启动的 17 个 `(task, it)` **state 逐字节相同** ⇒ 装置可重复。
- `s12_r1` 与对照 `d2_r1` 的逐字节差异：**6 个 `(task, it)`，全部归一化后相同**
  （把 `b#\d+` 换成 `b#N`）；`e1wi` 步 2 唯一的差异行：

```
s12 :  [工作记忆] [b#12 23字 sha=34ea10ccd32e] recall ⇒ ✔ (语义记忆中无相关条目)
对照:  [工作记忆] [b#1  23字 sha=34ea10ccd32e] recall ⇒ ✔ (语义记忆中无相关条目)
```

## 8.3 判决：**J1 字符级因果成立**（按 PREREG_V27 §2）

> 把一个 `1` 变成一个 `12`（+1 个字符，且它是一张表的自增行号），
> `e1wi` 就从 `set`+`append`（AttributeError，0 分）变成 `list`+`seen`（16 分）。

两次观测一致、两次对照（`d2_r1`、`f2_r1/r2`）一致、state 级逐字节把关。
⇒ V26 的 J1 不再是「1 次观测」：**操纵变量被单独拿出来了**。

## 8.4 这一条把 V25 的「相消」彻底拆开

V25 的核心谜团是「`c2` 48→48，两格反向各 16 抵消」。现在两格各有机制：

| 格 | 变化 | 机制 | 属于 |
|---|---|---|---|
| `e1wi` 0→16 | **+16** | `blobs` 自增行号 `b#1`→`b#12`（1 个字符） | **扰动**（零信息） |
| `e1ni` 16→0 | **−16** | `echo=1` 的 reward 段（`e1ni` 实测 159 字）进了 `propose` | **内容**（有信息，且有害） |

- `c2z`（`echo=0`）轮 2 = 64 ⇒ 只有扰动，没有内容 ⇒ 净 **+16**。
- `c2`（`echo=1`）轮 2 = 48 ⇒ 扰动 +16 与内容 −16 同时发生 ⇒ 净 **0**。
⇒ V25 的字面判决 J3「累积无效」现在有了完整的机制解释：**不是没有累积，是两种性质不同的效应精确抵消**，
其中正向那一半是**纯记账噪声**。

## 8.5 ⛔ 边界（不许越过）

1. 只能说：`tasks_v8` / `qwen2.5:7b` / 2026-10-31 12:04–12:57 本时段 / 冷启动。
2. ⛔ 不许说「记忆让系统变强了」：`s12` 的库里有**零条**知识（facts=0, episodes=0），
   唯一变化是行号。
3. ⛔ 不许由此推出「记忆通道永远无用」：本轮只测了 `echo=0`（reward 段被关掉）。
   `echo=1` 时有真文字进 prompt，实测对 `e1ni` 是 **−16**（有害，不是无害）。
4. ⚠️ 单题（`e1wi` 一格）+ 单一模型 + 单一预算 ⇒ 这是一条**装置属性**，不是模型能力结论。
