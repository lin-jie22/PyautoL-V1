## 5. 判决 `J3` 与逐格归因

### 5.1 那 +16 不是「用上了评审」

`e1wi` 在 `o4_r2`（无评审块）交付的是**有 bug 的版本**：

```python
kept = set()
for item in items:
    ...
    if stripped not in kept:
        kept.add(stripped)
        kept.append(stripped)     # ← set 没有 append ⇒ AttributeError，0 分
```

`p4_r2` 交付的是**修好的版本**：`kept = []` + `kept.append`，还多了四行注释。

**但它看到的三段评审里没有任何一段提到 `set` / `append`**（见 §5.2）。
⇒ 修复**不是**「照着评审改」，而是「prompt 多了 208 字 ⇒ 生成路径变了」。

### 5.2 送进去的到底是什么（`crit[-3:]` 的固定偏差）

`core.py:1443` 取 `crit[-3:]`、`critique.py:126` 按 `task_id` 字典序排
⇒ 恒取 `e2wi / e3ni / e3wi`。账本六条里这三条的内容：

| 来源 | score | `why` | 可行动 |
|---|---|---|---|
| `e2wi` | 1.00 | 「通过 16/16」 | ❌ |
| `e3wi` | 1.00 | 「通过 16/16」 | ❌ |
| `e3ni` | 0.00 | `NameError: name '_split' is not defined` | ✅ |

⇒ 208~317 字里**三分之二是「全过了」**；唯一可行动的那条对 `e2ni`（同为 `_split`）
才有直接意义，而 `e2ni` 三轮一格没动。
`e1wi` 自己的评审（`AttributeError: 'set'.append`）**永远送不出去**（被 `crit[-3:]` 排除）。

### 5.3 ⭐ 同样的两格互换，在「零信息占位」下也发生过

把 V29 与 V30 的五种条件并排（全部同题集、同判据）：

| 条件 | cap | 到达 | `e1wi` | `e1ni` | Σ |
|---|---|---|---|---|---|
| `off` | 1600 | 0/6 | 0 | 16 | 48 |
| `prev` 真实 `why`（V29 `p2` = V30 `p3`） | 1600 | 2/6 | 0 | 16 | 48 |
| `prev` **等长零信息占位**（V29 `q2`） | 1600 | 2/6 | **16** | **0** | 48 |
| `off` | 2400 | 0/6 | 0 | 16 | 48 |
| `prev` 真实 `why` | 2400 | **6/6** | **16** | **0** | 48 |

- 那两格是**双稳**的：同一对格子在不同条件下取两个值。
- 但**方向不能由内容预测**：零信息占位能翻、真实评审在 1600 下不翻、到 2400 才翻。
- Σ 在**全部五种条件下都是 48**。

⇒ **本轮不是「评审有用」也不是「评审有害」，而是「这 208~317 字是一支扰动的骰子，
掷出来的两格恰好相消」。** 这是「相消」的第三次出现（V25 §89.8-2、V29 §92.6、本轮），
且第一次拿到可复现读数。
