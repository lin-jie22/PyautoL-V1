## 4 ⭐ 本轮真正的产出：`s3 ≡ s4` 把「内容」与「长度」第一次拆开了

`s3`（74 字，说「上一轮交付的结构安排与本题面的约定之间并无实质差异…」，**不含任何动作**）
与 `s4`（74 字，说「骨架要整份原样输出…顶部补上本题用到的 import」）**等长、同位置、同送达对象**。

| | `e1wi` | `e1ni` | 交付件里 e1ni 有 `import re` 吗 |
|---|---|---|---|
| `s3`（零信息） | 0 | **16** | **有**（`1e97ad71`） |
| `s4`（可行动） | 0 | **16** | **有**（`7fd287cd`） |

⇒ **那 74 个字说了什么，对分数没有任何影响。** 我起跑前写的因果叙述
（「P 点名了 import，所以 `e1ni` 会补 import」）被自己的安慰剂臂直接否掉：
**零信息文本也让 `e1ni` 补上了 import。**

这是十三轮里第一次把「内容」与「长度」分开：以前所有对照（V23 `A1`/`A2`、V29 `q2`）
都只做到「两份载荷等长」，从来没有「载荷 vs 不含载荷的基线」这一段。
**结果是：内容项 = 0，长度项 ≠ 0。**

## 5 ⭐⭐ 尺子的可动面：6 格里只有 2 格会动，而那 2 格是守恒对

| 题 | 六臂下**不同答案**的个数 | 六臂的分数 |
|---|---|---|
| `e2ni` | **1**（`711ae11d`，六臂逐字节同一个答案） | 0 / 0 / 0 / 0 / 0 / 0 |
| `e3ni` | 2 | 0 / 0 / 0 / 0 / 0 / 0 |
| `e2wi` | 2 | 16 / 16 / 16 / 16 / 16 / 16 |
| `e3wi` | 2 | 16 / 16 / 16 / 16 / 16 / 16 |
| `e1wi` | 3 | 0 / 16 / 16 / 0 / 0 / 16 |
| `e1ni` | 4 | 16 / 0 / 0 / 16 / 16 / 0 |

三条硬结论：

1. **`e2ni` 在六种条件下给出逐字节相同的交付件**（无块 / 有块 / 有块+66 字可行动 / 零信息 / 零送达 / 复跑）。
   ⇒ 这一格**不是「材料没送到」，也不是「模型没照做」，而是模型对这道题的输出形状完全不随 prompt 变**：
   它永远只交 `def group_names` 那一段、永远不写 `import json`。
2. **`e3ni` 同理**（只有 `s3` 的答案变了几个字节，仍然 0、仍然只交 `week_of`）。
3. **`e1wi` 与 `e1ni` 是一个守恒对**：`e1wi` 过 ⟺ `e1ni` 不过，六臂里没有一次同时过或同时不过。
   而这一对的取值**既不是长度的单调函数，也不是内容的函数**：
   - 没有块（`s0`）→ `(0, 16)`
   - 有块（`s1`/`s2`/`s1b`）→ `(16, 0)`
   - 有块 + 66 字（`s3`/`s4`）→ `(0, 16)`

⇒ 装置的可动面 = **一对守恒格**（±16，恒有反向补偿）。Σ 因此在结构上就**只能恒等于 48**，
除非有某一格能突破「模型固定输出形状」这道墙 —— 而六种条件里没有一种能。

## 6 于是 V19~V30 的十二轮零读数，该怎么重新标注

预注册给 `J_NOROOM` 准备的措辞是「全部改标为未测到」。实际判的是 `J_DICE`，
但按 §5 的读数，正确的标注是**分两种**、不能一句话装完：

| 这批格子 | 正确标注 |
|---|---|
| `e1wi` / `e1ni` | **「与内容无关」已实测**（`s3 ≡ s4`）⇒ 以前那些 ±16 的逐格解释**全部作废**，包括 V25 的 `+16`、V30 §94.4 的「修复来自多了 208 字」——现在有了更硬的版本：**是长度，不是内容** |
| `e2ni` / `e3ni` | **「模型输出形状不动」**（`e2ni` 六臂 1 个答案）⇒ 这两格上的零读数**不是**「载荷没送到」，也不是「内容无用」，而是**这两格对任何 prompt 附加物都不响应** |
| 合计 Σ | **48 是这台装置的结构上限**，不是「系统学不会」的证据 |

⛔ 但仍不许说「记忆无用」：本轮的 `s3`/`s4` 只覆盖「加 66 字」这一种扰动，
没覆盖「换一套能动的格子」。**量不出来的东西不等于不存在。**

## 7 自踩两条

1. **探针把打分器写错**（`assertion.py` 而非 `code_exec.py`，`run.py:915-916` 的默认值）
   ⇒ 算出 `scorer_sha=254bef5b…` 与种子的 `d4b1cbbf…` 不符 ⇒ 探针判「种子不可用」。
   **那是探针的错，不是种子的错**。跳过这一步就会得到「载荷送不到」的假结论，
   然后拿它去改实验设计（§93.5 的同一种坑）。
2. **押注的推理是错的，不只是位置错**：我把「P 点名 import」当成因果，
   而安慰剂臂给出同样的分数与同样的 `import re`。⇒ 新纪律：**「我说了什么」和
   「模型改了什么」之间必须有一个等长的零信息臂挡着，否则不许写因果。**
