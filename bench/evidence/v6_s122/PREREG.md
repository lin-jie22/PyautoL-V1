## 1 这一轮要回答的问题

「累积 → 预测 → 自省」里，**自省**的实现是：跑完一轮 → 每条评审落盘 → 下一轮 prompt 里带
`[外部评审]` 块。V19~V31 十八轮都在改「往块里灌什么」，全都零净效应。

本轮换一个更靠前的问题：

> **块里最该出现的那一条 —— 「你上次这道题错在哪」—— 送得到吗？**

V32 探针（`p0_selfreach.txt`）给的答案是 **0/6**：

| 当前题 | `admissible` 拿到的 | `crit[-3:]` 之后真正进 prompt 的 |
|---|---|---|
| e1wi | e1ni e2ni e2wi e3ni e3wi | e2wi e3ni e3wi |
| e1ni | e1wi e2ni e2wi e3ni e3wi | e2wi e3ni e3wi |
| e2wi | e1ni e1wi e2ni e3ni e3wi | e2ni e3ni e3wi |
| e2ni | e1ni e1wi e2wi e3ni e3wi | e2wi e3ni e3wi |
| e3wi | e1ni e1wi e2ni e2wi e3ni | e2ni e2wi e3ni |
| e3ni | e1ni e1wi e2ni e2wi e3wi | e2ni e2wi e3wi |

两道独立闸把它挡死：

1. **`critique.py:107`** `if exclude_task_id and tid == exclude_task_id: rejected["self"] += 1; continue`
   —— 同题评审一律拒收。注释理由是「防自评」，那对**轮内**是对的；但它对**上一轮**同样生效。
2. **`core.py:1443`** `crit[-3:]` —— `crit` 按 `task_id` 字典序排（`critique.py:126`），
   末三恒为字典序尾部三条，与被评题**毫无关系**。

⇒ 即使拆掉第 1 道闸，第 2 道仍会把自评切掉。**两道都必须改，改一道等于没改。**

## 2 本轮装置改动（内核，`harness_sha` 因此断段）

| 文件 | 改动 | 为什么要改内核而不是在 `run.py` 绕 |
|---|---|---|
| `mw/critique.py` | `CritiqueLedger(path, *, allow_self: bool = False)`；`admissible` 的自评闸加 `and not self.allow_self`；`stats()` 增 `allow_self` | 绕法只能是给 `task_id` 加后缀，而 `as_line()` 会把后缀印给模型看 ⇒ **对模型撒谎** |

  逐字节比对**（P0-g）。这一条不过，整轮作废 —— 因为断段后唯一的可比基线就是它。

**新增能力的精确形状**（`e1wi` 视角，种子账本）：

| 档位 | 进 `[外部评审]` 的三条 |
|---|---|
| `prev` | `e2wi`（16/16 满分）· `e3ni` · `e3wi` |
| `prev-self` | **`e1wi`（本道题上次 0/16 的失败原因）** · `e3ni` · `e3wi` |

⇒ 两臂的差别**只换第一条**。⚠️ 代价：那一条更长（约 +100 字），长度项无法消掉 ——
V31 已测长度项不是主因（`s3`/`s4` 块长逐字节同 274，轨迹仍不同），但仍如实登记为混淆项。

## 3 押注前必须承认的一件事（V31 的教训）

V31 判 `J_DICE`，本轮把 `/tmp/v31` 的答案原文翻出来，机制是**两行代码**：

```
s4/e1wi（0 分）   kept = set()  …  kept.add(x); kept.append(x)        ⇒ AttributeError
s1/e1ni（0 分）   kept = set()  …  _strip_tags 用 re 但没 import re   ⇒ NameError
```

全量复核（`p0_dice.txt`，12 轮 100 个 run 的 9395 份答案原文）：

| 题 | `kept = set()` | 0 分 | 1 分 |
|---|---|---|---|
| `e1wi` | 是 | **65** | **0** |
| `e1wi` | 否 | 2 | 67 |
| `e1ni` | 是 | **5** | **0** |
| `e1ni` | 否 | 31 | 92 |

⇒ **`kept = set()` ⇒ 0 分，70/70 零例外。** 而 `kept = []` 时 `e1ni` 的 31 次失分是**第二个坑**
（`_strip_tags` 用 `re` 却没 `import re`，或干脆不用 `re` —— `e1ni` 是不给 import 行的变体）。

**这意味着**：本装置的可动面（`e1wi`/`e1ni` 那一对守恒格）不是能力，是**两个代码生成缺陷**。
Σ 之所以几乎恒为 48，是因为两题「恰好一题抽搐」。

⇒ 本轮的副判据 `T`（抽搐题数）不是新尺子，它是**已有答案的一个字符级特征**，
用途是把 Σ 的噪声源分层 —— 而它恰好是「自省」最该修好的东西（模型该学会「别用 set 装 append 列表」）。

## 4 装置

### 4.1 臂

每臂 **4 轮**，每轮 = **一个独立的 `run.py` 进程**（⚠️ 不能用 `--repeat`：`prev` 的快照在
run 开始时构造一次，`--repeat` 的第 2 轮看到的仍是同一份快照 ⇒ 根本不累积）。

| 臂 | r1 | r2 | r3 | r4 |
|---|---|---|---|---|
| `c0` | `prev` | `prev` | `prev` | `prev` |
| `c1` | `prev` | **`prev-self`** | **`prev-self`** | **`prev-self`** |

r1 两臂**同条件** ⇒ 必须逐字节相同（P0-e）。从 r2 起才分岔 ⇒ 这是前后对照，不是初始化差异。

共同条件：
- `V1_STATE_CHARS=2400`、`V1_REWARD_ECHO=0`、`V1_VERIFY_STATIC=2`、`temperature=0`、`--repeat 1`
- `--memory-dir` 每臂一个**累积**目录（记忆跨轮累积，这是主线的要求）
- `--critique-file` 每臂一个账本，r1 前从 `v6_s121/seed_base/critique.jsonl` 拷贝
- 6 题 / 96 格，`suite_sha=519dad774a3664612e6611b220b33f4a`

### 4.2 读数（只从落盘产物 / state dump 取，⛔ 不看日志标签）

1. 每轮 Σ（`bench_<arm>_r<k>/runs.jsonl` 的 `report.per_task`）
2. 每轮逐格（6 题）
3. 每轮 `e1wi`/`e1ni` 最终答案的 `kept` 容器（`answers.jsonl` 该 `(run_id, task_id)` 的最后一行）
4. 每个 state 里 `[外部评审]` 块是否含 `[tasks_v8/e1wi]`（自评送达）
5. 每轮逐题步数（state dump 行数）

⚠️ state dump 用 `(task, it, 同键第几行)` 三键 —— `--state-dump` 对同一 `(task, it)` 会写多行（纪律 35）。

### 4.3 分母

**分母 = 每臂 4 轮 × 6 题 = 24 个可判格**（Σ 与逐格都用它）。

- ⛔ 不用「只算作答成功的格」：那会把客户端超时从分母里剔除，系统性高估。
- ⛔ 不用「只算 r2..r4」：r1 两臂本应相同，若不同那是装置 bug，必须让它看得见。
- `skipped_no_answer` / `failed_scorer` 逐轮分开计数（纪律 24）；任何一轮非 0 ⇒ 该轮标注、不进主判据但**保留在分母里记 0**。

## 5 判据（按顺序执行，前面的不过就不许判后面的）

### P0 前提闸（任一不过 ⇒ 整轮 `J0`，不许往下判）

- **P0-a 通电闸**：`c1` 的 r2~r4 里，`e1wi` 的 state **必须**出现 `[tasks_v8/e1wi]`（自评送达）。
  同时 `c0` 的**全部** state 里 `e1wi` 视角**不得**出现 `[tasks_v8/e1wi]`（自评零泄漏）。
  ⛔ 若 `c1` 送达 0 ⇒ 载荷没到，读数是「未测到」不是「无效」。
- **P0-b 起点同闸**：`c0_r1` 与 `c1_r1` 的全部 state 逐字节相同、6 题分数逐格相同。
- **P0-c 覆盖闸**：r2 加载到的账本必须是 r1 写的那一份（`e1wi` 那条的 `why` 含 r1 自己的失败原因，
  不是种子里那条）—— 从 `state` 原文核，不看计数。
- **P0-d 落盘闸**：4 轮 × 2 臂都有 `runs.jsonl` 且 `attempted=6`、`recorded=6`。
- **P0-e 漂移闸**：r1 之后**再跑一次** `c0_r1`（`c0_r1b`），state 逐字节比对，量本时段漂移。
  漂移 ≠ 0 ⇒ 任何 |Δ| ≤ 漂移的判据一律记「不可判」。
- **P0-f 旧口径等价闸**：`c0_r1` 的 24 个 state 与 V31 `states_s1.jsonl` **逐字节比对**。
  （`c0` 与 V31 `s1` 同条件：`prev` + 同种子 + cap 2400。这一条同时验证 `core.py` 的
  `pick` 改动在无自评时**一字未变**。）
- **P0-g 门禁闸**：契约 / 锚层 / `check_counts` / `run_tests.sh` 七步全绿，且 `mw/` 在起跑前 `git status` 干净。
  **实测（起跑前）**：契约 **599/0**、锚层 **97/0**、撤回态 **185**、`check_counts` 22 处一致、
  `run_tests.sh` 七步 `EXIT=0`；`AZ98`/`AZ99` 撤回态**逐条单红**（`红=['AZ98']` / `红=['AZ99']`）。

### 主判据（并列，缺一不可 —— 纪律 32）

- **S（Σ）**：`Σ(c1, r_k) − Σ(c0, r_k)`，逐轮列出，并报 4 轮合计。
- **C（逐格）**：6 题 × 4 轮的逐格差，按 `{(题): (r1..r4) 的 c0→c1}` 列出；**必须打印上升格与下降格两张表**。

### 副判据（本轮的核心观测量）

- **T（抽搐题数）**：每轮 `e1wi`+`e1ni` 里 `kept = set()` 的题数 ∈ {0, 1, 2}。
  报 `c0` 与 `c1` 的 **r2~r4 序列**（r1 两臂相同，作为基线）。
- **R（自评送达率）**：`c1` 的 r2~r4 中含 `[tasks_v8/e1wi]` 的 state 数 / 总 state 数。

## 6 押注（写死，不许事后改）

**押 `J_SELF`**：`c1` 在 r2~r4 的抽搐合计应低于 `c0`。

理由（可被自己读数否证）：`e1wi` 上次的失败原因原文是
`通过 0/16；失败: … AttributeError: 'set' object has no attribute 'append'` ——
这句话直接点名了「set 不能 append」。只要它进了 prompt，模型下一轮就不该再写出
`kept = set()` 又 `append`。

**如果读数打脸**（`J_NULL` / `J_DICE` / `J_HARM`），必须如实登记成：
「把最该送达的一条送到了、模型看见了、仍然抽搐」 —— 并且**不许**把它写成
「记忆无用」或「内核不会变强」，只能写成「本装置 + 本模型下，跨轮自省未产生可测改善」。
