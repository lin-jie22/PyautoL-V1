# V34 判决 —— 一发是**重放**，不是抽样；而「Σ 上限 48」要撤

> 证据目录 `bench/evidence/v6_s124/`。预注册 `PREREG.md`（13:0x 落盘，早于本轮任何 LLM 调用）。
> 装置：`probe_v34_replay.py` / `run_v34.sh`；历史复核：`probe_v34_history.py`（6 个子命令，全部零 LLM）。

---

## 0 一句话

**同一个请求连发 16 次，答案逐字节相同**（两组都是 16/16，各组内只有 1 种答案）⇒
`T=0` 的「多发」是**重放**，不是抽样。押的是 `J_REPLAY_NOISE`，**押错**。

与此同时，本轮用零 LLM 的历史复核推翻了两个长期结论：
**`Σ` 上限不是 48**（同一把尺子上 `Σ=64` 出现过 **27** 次、`Σ=96` 一次）；
**`e1wi + e1ni ≡ 16` 不是结构律**（112 个 run 里 28 次两边都过）。

## 2 主读数

| 组 | `n`（要求几个候选） | messages sha | 16 次的答案 | `k` |
|---|---|---|---|---|
| A | 1 | `369151c6` | `60a74736` × 16 | **1** |
| B | 3 | `0904295c` | `3dede36f` × 16 | **1** |

重复发送的是 **`Planner.propose` 真拼出来的那份 messages**（`ToolRegistry` 取 `Core` 里同一份），
state 取 V33 `c0_r1` 的 `e1wi` it=1 原文。⇒ **`J_REPLAY_FIXED`**。

两次重放给出的答案都是同一类写法：

```python
kept = set()
...
if stripped not in kept:
    kept.add(stripped)
    kept.append(stripped)      # ⇒ AttributeError: 'set' object has no attribute 'append'
```

即 §96.2 里 `4e9be367` 那个坑。**模型不是"有时抽到 bug"，是稳定地写出这个 bug。**

## 3 这一条对旧结论的影响

- **纪律 41 不被否证**：「`T=0` 的轮数是 1 次观察」这个口径，在本轮的分辨率上**仍然成立**。
  但只能写到「**在本探针的 16 次分辨率上没看到噪声**」——
  若真实 `p(主答案)=0.85`，16 次全同的概率是 `0.85^16 = 0.074`，
  **「16 次全同」不能证明 `p = 1`**。
- ⛔ **不能**因此说「确定性已证明」。本轮证的是「这两个 prompt 上、16 次内没有噪声」。

---

## 4 但「同 state 不同答案」并没有消失 —— 它反而更尖锐了

`p0_samestate.txt` 记着三组 state 逐字节相同、答案却不同。既然模型在同请求上是确定性的，
那么这三组的 **prompt 必然不同**，差别只能落在 `--state-dump` 没落的输入上。

最硬的一对（**同一轮、同一内核、同一 state**）：

| run | `e1wi` it=1 state | 答案 |
|---|---|---|
| `v26/d2_r1` | sha `debe3b9cd0`，1198 字 | `4e9be367`（`set()`，0 分） |
| `v26/d2_r2` | **同一 sha，1198 字** | `7fd287cd`（`list`，**16 分**） |

`d2_r2` 与 `d2_r1` 的差别只有一个：**r2 看到了 r1 累积下来的记忆**。
而 `e1wi` 是 suite 第一题，`[工作记忆]` 在 it=1 还是空的（state 已核）。
⇒ 差别只能来自**两个没进 dump 的输入**：

1. **`wm.guidance()`（第③条通道）** —— 从世界模型/语义记忆取「易错点」，直接进 planner 的提示词，
   `core.py:851`，**不进 `state`**；
2. **`n`** —— `selfmodel.advise()` 可能把候选数从 1 改成 3，提示词里那句
   「请给出 N 个」就变了，而 `n` 也不进 dump。

⭐ **这就是下一轮该补的洞**：`--state-dump` 的 `state` **不是 prompt 的身份**。
本轮之前所有「state 逐字节相同 ⇒ 同条件」的论证（V32 的 P0-b、P0-f）都只证明了
「state 相同」，没证明「prompt 相同」。它们当年的答案也相同，所以结论没被推翻 ——
但**论证的强度要降级**。

## 5 ⭐ 更大的修正：`Σ ≤ 48` 是错的

同一 `suite_sha`（`519dad774a3664612e6611b220b33f4a`）**且**同一 `scorer_sha`
（`d4b1cbbfd7f1ef50…`，112/112 全同 —— 不是两把尺子）的 run：

| Σ | 32 | 48 | **64** | **96** |
|---|---|---|---|---|
| run 数 | 8 | 83 | **27** | **1** |

逐轮（`p0_round.txt`）：

```
v19 {48:4, 64:2}   v21 {48:4, 64:2}   v22 {32:3, 48:3, 64:4}  v23 {32:3, 48:3, 64:3}
v24 {48:3, 64:9}   v25 {32:2, 48:7, 64:3}  v26 {48:3, 64:1}  v27 {64:2}
v28 {48:6}  v29 {48:6}  v30 {48:12}  v31 {48:6}  v32 {48:9}  v33 {48:12}
```

⇒ **48 的"平台期"是 `v28` 之后才出现的（45 个 run 零例外），不是装置的结构上限。**
MEMORY 里「本装置不可判 / 可动面只有一对守恒格」这条结论**必须撤销或降级**。

## 6 同一批数据给出的机制：分数由**容器**决定

| 题 | 答案形态 | 过 | 不过 |
|---|---|---|---|
| `e1wi` | `kept = []` | **48** | 2 |
| `e1wi` | `kept = set()` | **0** | **81** |
| `e1ni` | 写了 `import re` | 90 | 0 |
| `e1ni` | 没写 `import re` | 0 | 40 |

零例外。而唯一能过的 `list` 写法（`7fd287cd`）**最后一次出现在 `v27`（10-31 12:50）**；
`v28` 起 `e1wi` 再没写过 `list`。⇒ Σ 从 64 掉到 48，不是"能力退化"，是**这个写法不再被生成**。

⭐ 而 §4 的那个洞正好是它的入口：`v26/d2_r1` → `set()`、`d2_r2` → `list`，
**差别只在一次记忆累积**。也就是说，**累积循环曾经能改变这个写法，`v28` 之后就再没改变过**。
这是下一轮真正该查的东西。

## 7 ⛔ 不许说的三句

1. 「模型有噪声 / 温度不为 0」—— 32 次同一请求，两组各 16/16 全同。
2. 「确定性已证明」—— 分辨率是 16；`p=0.85` 时全同概率 0.074。
3. 「Σ 就是 48」—— 同一把尺子上 64 出现过 27 次。

## 8 自踩（三条）

1. **押错，而且错在把 dump 当 prompt**：我据 `p0_samestate` 的「同 state 不同答案」
   押 `J_REPLAY_NOISE`。那条证据从一开始就**不闭合**（`state ≠ prompt`），
   预注册 §6 里我自己写了这一点，却还是按它押了注。⇒ 通则：
   **预注册里写了「这条证据不闭合」，就不许再拿它当押注理由。**
2. **`resp_bytes` 当内容指纹是假的**：本探针 16 次同一请求、答案逐字节相同，
   `resp_bytes` 却有 3 个取值（1049 / 1051 / 1052），`completion_tokens` 恒 **178**。
   我一度据此写出「78 次同请求不同响应」的假结论（`proxy_same_req.txt` 保留为反例）。
   ⇒ 通则：**代理台账里没有响应哈希，`resp_bytes` 不是内容指纹**。
3. **D2 的 `import_re` 列失真**：代码被 JSON 包着，开头是 `"""import re`，
   `^\s*import\s+re`（`re.M`）匹配不到 ⇒ 16 次全报「无」。容器列不受影响（`kept = set()` 在行首）。
   D1 用的是整段 sha，不受影响。
