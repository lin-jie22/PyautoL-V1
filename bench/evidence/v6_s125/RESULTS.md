### 1.1 `[语义记忆]`：626 次比较，**零差异、零出现**

这是本轮最硬的读数。`recall()` 这条通路在**十五轮、32 个比较对、626 次块级比较**里
**从来没有向 state 贡献过一个字的跨轮知识**。

⚠️ 这不是新发现，而是**把旧结论从离线搬到在线**：
V31 的「六题 0 命中」是离线复算（拿当时的库重建 `recall`），本轮是在**真实跑出来的 state**
上全量验证 —— 626 次，零例外。

⇒ 任何「靠 `[语义记忆]` 起效」的假设，**在本装置里是结构性空的**，不需要再测。

### 1.2 `[外部评审]`：唯一通电的知识通路

- **42 次「从无到有」**：第 1 轮该块为空、第 k 轮出现。
- **214 次 content 变化**，其中 172 次是**长度相同、内容不同**。
  样例（`v33/c1`，`e1wi` 的 it=1，两轮都是 215 字）：
  ```
  r1: [外部评审] [tasks_v8/e2wi] 1.00 — 通过 16/16 ｜ [tasks_v8/e3ni] 0.00 — … ｜ [tasks_v8/e3wi] 1.00 …
  r2: [外部评审] [tasks_v8/e1wi] 1.00 — 通过 16/16 ｜ [tasks_v8/e3ni] 0.00 — … ｜ [tasks_v8/e3wi] 1.00 …
  ```
  ⚠️ **条数都是 3，只有第一条的 task id 换了**。这是 V32 那两道闸（`exclude_task_id` + `crit[-3:]`）
  换了选择结果，不是"多了一条经验"。

⇒ **单看 content=214 会说"载荷很活跃"；看条数就知道：信息量没变，换的是被选中的那几条。**

### 1.3 `[工作记忆]`：handle-only 占 73/100

⚠️ 注意这些不是 V25~V28 说的 lastrowid 大跳（那是 `b#1`→`b#12`），而是 v28 改成

## 二、可比性：`same_as()` 会判死整个累积实验

`p2_caliber.txt`，70 个「同臂 r1 → rk」比较对：

| 读数 | 值 |
|---|---|
| 全字段 `diff()` | **70/70 都非空**（`memory_seed` 必然变） |
| 豁免 `memory_seed` 后的意外差异 | **66/70 为空** |
| 存在意外差异 | **4/70**：`v30/{o3,o4,p3,p4}` 的 r1→r3，差 `llm_cond.endpoint`（`8821` → `8823`，代理重启） |

⭐⭐ **这是一条方法论修正，而且是十五轮的公共问题**：

`Caliber.same_as()` = `not diff()`，`diff()` 按 `CALIBER_KEYS` 全字段比，而 `memory_seed` 在
`CALIBER_KEYS` 里（`mw/bench.py:132`），还有契约钉着「只有记忆基线不同 ⇒ 口径不同」
（`tests/bench_test.py:130` A8）。

**而累积实验的设计本身就是让记忆基线增长** ⇒ 同一臂的 r1 与 r2 **按定义**就不是 `same_as`。

⇒ 若拿 `same_as()` 当可比性判据，**累积实验在制度上永远不可比**。
同一个文件里给了第三条路：`Caliber.diff_except(other, declared)` ——
「声明哪些字段允许不同，剩下的任何一个不同都算失败」。
用它，66/70 通过。

⛔ 但这**不等于**"十五轮的跨轮比较一直非法"。多数轮次报告的是**同轮内不同臂**的比较
（`o3` vs `p3`），那些是 `same_as` 合法的。这条修正只针对**"同一臂的 r1 vs rk"**这类累积读数。

## 三、一个字符 vs 四百八十八个字节（`p3_char.txt`）

`/tmp/v26` 的 `d2` 臂，`Σ` **48 → 64**，全部差额来自 `e1wi` 的 **0 → 16**。

### 3.1 那 16 分的载体是**一个字符**

| 步 | r1 | r2 | 判定 |
|---|---|---|---|
| `e1wi` it=1 | 1198 字 `debe3b9cd0` | 1198 字 `debe3b9cd0` | **逐字节相同** |
| `e1wi` it=2 | 1384 字 `a28ae7099c` | 1385 字 `d4eabe45e5` | **差 1 字符** |

字符级 diff：
```
insert: a[1199:1199]=''  b[1199:1200]='2'
上下文: ... [工作记忆] [b#1 23字 sha=34ea10ccd32e] recall ⇒ ✔ (语义记忆中无相关条目)\n[轨迹] [step 1] ...
```
⇒ `[b#1 …]` → `[b#12 …]`。**插了一个 `2`。**

### 3.2 socket 层确认：请求真的不同

proxy 台账里 `e1wi` 的 3 次请求，r1 / r2 逐条对照：

| # | r1 `req_sha` | r2 `req_sha` | `req_bytes` | `resp_bytes` | `completion` |
|---|---|---|---|---|---|
| 0 | `56dcd4ac…` | `56dcd4ac…` **同** | 10950 / 10950 | 2329 / 2329 | 493 / 493 |
| 1 | `17198ede…` | `17198ede…` **同** | 2831 / 2831 | 454 / 454 | 34 / 34 |
| 2 | `ba957838…` | `8635c8f7…` **异** | 12382 / **12383** | **1036 / 1075** | **171 / 181** |

⇒ 1 个字符的输入差 ⇒ 39 字节 / 10 token 的输出差 ⇒ `kept = set()` 变 `kept = []`。

⚠️ **这条把「+16 与语义无关」钉死到字符级**：同一次实验里，r2 比 r1 多的那"一份记忆"
内容上逐字节相同（都是 `recall ⇒ ✔ (语义记忆中无相关条目)`），只有句柄数字变了。

### 3.3 但同一批数据里还有 **488 字节**找不到主人 ⛔

33 对请求逐条对照：**17 同 / 16 异**。异的那 16 对里，除了 #2 差 1 字节，还有 6 对差
**488 / 489 / 220 字节**（#3、#6、#10、#14 差 488~489；#17、#26 差 220）。

而块级归因说：v26/d2 的 `[目标]` `[语义记忆]` `[外部评审]` `[轨迹]` `[步号]` **全部 same**，
`[工作记忆]` 只有 6 处 handle-only。

⇒ **state 只差几个字符，请求却差 488 字节**。差额必然来自 state 之外
（`Planner.propose` 的 `guidance` / `blocked` / `rejected` / `history`）。

⛔ **本轮不解释它。** 登记为「已量到、未定位」，理由写在 §七 的自踩 3。
已知并排除的两个假解释：
- `proxy.jsonl` 的 `n` 字段是 5,6,7…37 连续递增 —— 它是**行计数器**，不是模型参数 `n`（纪律 29 再现）；
- `history` 在 `core.py:759` 每题清空，不是跨题累积。

## 四、主问题的答案：`v28` 之后还能不能把 `e1wi` 从 `set` 推到 `list`？

| 臂 | `[工作记忆]` same/handle/content | 结论 |
|---|---|---|
| `v26/d2`（v28 之前） | 12 / **6** / 0 | 6 处句柄漂移 ⇒ 有一格翻了 16 分 |
| `v28/d2`（v28 之后） | **18 / 0 / 0** | 逐字节全同 ⇒ 答案必不变（V34 确定性） |
| `v29/p2` | 13 / **5** / 0 | 漂移**又回来了** |
| `v32/c0` | 17 / **5** / 2 | 同上 |
| `v33/P` | 17 / 0 / 3 | 这次没漂 |

**答案**：
1. 在 `v28/d2` **这条臂上不能** —— state 18/18 逐字节相同。
2. 但**原因不是"句柄被固定了"**。`memory.py:248` 的是
   `seq = int(cur.lastrowid) - self._blobs_base` —— **本会话内序**，不是常量。
   只要 r2 在到达同一段内容之前**多捕获了 k 条**，序号就整体后移 k。
   `v29/p2`、`v32/c0` 各 5 处 handle-only 就是它在别处照常发生。
3. ⇒ **`v28` 只把漂移幅度从"库增长量"（1→12）压到"会话内增量"（8→9），
   没有把 `b#N` 从 prompt 里去掉。那条"一个字符翻转 16 分"的因果边**仍然活着**。**

⚠️ 所以「48 平台期」不能被归因成"v28 修好了扰动"，只能说"v28 让扰动变小了，
小到在 `d2` 这条臂上恰好没触发"。

## 七、自踩登记

1. **押注押错（`J_EMPTY` → `J_CONTENT`）**。押注依据是 V31/V33 的五条独立读数，
   但漏了一点：那五条测的是「**内容可分辨性**」，不是「**块是否出现**」。
   `[外部评审]` 的 42 次 born 从来不是"内容变好了"，而是"这个槽位从空变成了有"——
   两件事被我当成了同一件。

2. **`content` 这个分类太粗**。它把"条数从 3 变 5"和"条数 3，只换了一个 id"
   算成同一个读数（214）。看到样例才知道后者是多数。
   ⇒ 下次分类至少要加一维：**条数是否变化**。

3. **488 字节找不到主人就停手**。我可以继续查（用 `probe_v34_replay.py` 重建 messages、
   逐项开关 `guidance`/`blocked`/`rejected`），但那会变成"为了解释一个新现象再造一个探针"，
   违反 §零 第②条。**登记为未定位，留给 V36**。

4. **`proxy.jsonl` 的 `n` 字段是行计数器**，不是模型参数。我在逐条对照时先入为主地
   按"候选数"读了一轮，才发现是 5..136 连续递增。纪律 29（「读数标签不是读数」）
   又一次应验，而且这次是在**我自己刚写的分析里**。
