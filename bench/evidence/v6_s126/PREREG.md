## 3. 为什么 M1/M2 是安全的（改动**前**就查清的事实）

1. 模型**没有任何**按 `ref` 取回原文的工具。`mw/tools.py` 里 `recall` 是语义检索（facts 表），不是 expand。
   `expand` 只由内核 `_recall_for`（`core.py:1356`）用**进程内**的 `handle.ref` 调用。
2. 索引行三个字段里，`chars` 与 `sha` 都是**内容的函数**（`sha = sha256(body)[:12]`），
   只有 `ref` 是**捕获次序**的函数（`seq = lastrowid - _blobs_base`）。
3. ⇒ 去掉 `ref` 后，同一段观测在**任何轮次、任何库状态下**渲染逐字节相同；
   保留 `ref` 则只要本轮比上轮多捕获 k 条，同一段内容的句柄就整体后移 k。

**这就是 V25~V35 那 +16 的全部来源按 V35 的归因。本轮是去验证它，不是去相信它。**

**`J_NULL`**：去掉 `b#N` 后，累积臂与重置臂的 Σ **相同**，`e1wi` 两臂**同格同分**。

依据两条旧结论，都已有读数钉着：

⚠️ **若 D4 成立**（guidance 跨轮确实不同），则即使 `J_NULL` 成立，也必须写清
「零差异是**两股力相消**，还是**两股力都没力**」——
V30（`e1wi`+16 / `e1ni`−16）与 V33（c1 0 / P 16）已经**两次**栽在相消上，本轮不许第三次。

## 6. 有效样本口径

每臂每轮是**独立进程**，但同一 `(suite_sha, scorer_sha, 参数)` 下 `T=0` 是**确定性重放**——
V34 已直测：同一 messages 连发 16 次 ×2 组，**各 16/16 全同（k=1）**。

⇒ **有效样本 = 每臂的独立 prompt 数，不是轮数**（纪律 41；V34 已验证其前提成立）。

本轮两臂的差别**只有** `--memory-dir` vs `--fresh`：
- 若 state 逐字节相同 ⇒ **有效样本 = 1**，⛔ 不许把「两臂各跑 k 轮」写成「n=k」；
- 若 state 不同 ⇒ 有效样本 = 2（两个 prompt），仍不是 k。
