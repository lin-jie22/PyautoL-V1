## 三、三个新事实

### 1. 记忆库真的长了，而 prompt 一个字节没变

| 轮 | 起跑时的记忆基线 `memory_seed` | Σ |
|---|---|---|
| `cum_r1` | `[0, 0]` | 48 |
| **`cum_r2`** | **`[1, 27]`**（1 条 fact、27 条 episode） | **48** |
| `rst_r1` | `[0, 0]` | 48 |
| `rst_r2` | `[0, 0]` | 48 |

`cum_r2` 起跑时库里有 27 条 episode（`cum_r1` 写的），**而它的 21 条 state 与 `cum_r1` 逐字节相同。**

### 2. 同起点的正控是干净的

`cum_r1` vs `rst_r1`：`req_sha` **34/34 全同**、`diff_except` 无差异、Σ 都是 48。
⇒ 两臂起点确实是同一个装置、同一个 prompt。

### 3. 累积确实改了 prompt —— 但只改了 5 条，且没改任何答案

`cum_r2` vs `rst_r2`（同一轮、只差"是不是累积"）：

| | 值 |
|---|---|
| 请求条数 | 34 : 34 |
| `req_sha` 相同 | **29 / 34** |
| 不同 | **5 条，Δ = −2220 字节**（−268, −488, −488, −488, −488） |

`cum_r1` vs `cum_r2` 是它的**精确镜像**（同位置 #3/#6/#11/#24/#30，Δ=**+2220**）。

⇒ 这条把 V35 的悬案收窄了一个量级：
**那 488 字节确实在 state 之外，而且它确实只出现在"有记忆的那一轮"。**

⛔ 但**字段级仍未定位**：`guidance` 测了（全空）、`n` 测了（两轮同为 `[1,2,3]`）、
`state` 测了（逐字节同）、`history` 的可见部分（`[轨迹]`，12 个非空块）也相同。
剩下没进 dump 的只有 `blocked`（已尝试动作签名）与 `rejected`（reseek 提示）。
**本轮不猜，登记为未定位**，V37 用 `state_meta` 把这两样落盘再判。

⚠️ 更要紧的是最后半句：**这 2220 字节没有改变任何一格分数**。
这是 V33「载荷内容不可分辨」在字节层面的又一次印证 —— 连 prompt 都不一样了，答案还一样。

## 四、押注结果

预注册押 **`J_NULL`**（去掉句柄后两臂 Σ 相同、`e1wi` 同格同分）—— **押对**。

它的推翻条件（「两臂 Σ 差 ≥16」或「`e1wi` 任一格翻转」）一条都没出现。

⚠️ 但押对不等于结论强：`J_NULL` 只要求"没有差异"，而**没有差异可以有三种来源**
（V30/V33 已经两次栽在相消上）。本轮排除掉两种：
- **不是"两股力相消"**：`diff_except` 无意外差异、`req_sha` 29/34 全同、块级 45 个非空块逐字节同
  ⇒ 两臂在绝大多数位置上**真的是同一个输入**；
- **不是"装置没跑"**：`[工作记忆]` 15 个非空块、`[轨迹]` 12 个非空块、84 条 dump 行、140 条代理记录。

剩下那一种（"两股力都很弱"）本轮**不能排除** —— 见下面的范围限制。

## 五、范围限制（⛔ 读结论前必须先读这一节）

1. **只有 6 道题，其中 4 道是常数。** 本轮 Σ 的每一分都来自 `e1ni`/`e2wi`/`e3wi` 三道，
   而它们四轮全过；`e1wi` 四轮全 0。**真正会动的格子在本轮一次都没动过。**
2. **能带记忆的两条通路本轮都是空的**：`[语义记忆]` 0 条、`[外部评审]` 0 条。
   本轮**只测了**「记忆有没有从 `[工作记忆]`/`[轨迹]` 这两条路漏进 prompt」。
   ⛔ 不许把结论写成「记忆没用」—— 那两条通路本轮**根本不在射程内**。
3. **`Caliber` 不含内核哈希**（`CALIBER_KEYS` 里只有 `tool_catalog_sha`）。
   ⇒ 本轮改的是 `mw/core.py` + `mw/memory.py`，但 `caliber_sig` **对这件事无感**。
   「断段」在本装置里是**人工声明**的，不是签名自动捕获的。
   ⭐ 这是一条新的装置缺口，已登记进 MEMORY。
4. 有效样本：每臂 2 轮，但 `rst_r1` vs `rst_r2` 的 `req_sha` **34/34 全同**
   ⇒ 按纪律 41，**有效样本 = 每臂的独立 prompt 数（2 臂 × 1 个），不是 4 轮**。

## 六、自踩四条

1. **首跑漏了 `V1_LLM_TEMPERATURE`**，被 H0-c 当场拦下（`temperature=0.2`）。
   命令行 `--temperature 0` 不够 —— H0-c 读的是 `cfg.settings()`（环境层），
   两者不一致时「我传了 0」只是意图，不是读数。
2. **污染了生产记忆库。** 13:41:58 我跑 `run.py --selftest` 时**没设 `V1_STATE_DIR`**，
   `state/memory.db` 被打上时间戳 `Nov 1 13:41:58`，多了 2 条 episode（`selftest` / `worldmodel`）。
   这与门禁步骤 0 专门治的那次事故（36 条污染）是同一个形状。
   ⛔ 本轮**不删**它（那是累积循环的唯一载体，删比留更危险），只登记。
   ⚠️ 之后任何用生产库的累积实验，必须把这 2 条记进基线。
3. **差点把「6 个块 100% same」读成「装置极度稳定」。**
   直到加了「非空块数」一列才发现 `[语义记忆]`/`[外部评审]` **全程 0 条**——
   它们的 100% 是「空 == 空」。这正是纪律 19（聚合方式会骗人）的现场版。
4. **改渲染打断了 `bench/probe_recall.py` 的 P8。** 它从回看块标题里取「第一个词」当句柄，
   而那部分已经变成 `sha=`。已改成「抓 sha → 反查库行 → 换算内序句柄」，
   仍然从产物取（不是手写 `b#1`），P1~P10 全过。
   ⚠️ 这处改动**不在预注册的 M1~M6 里**，如实登记为连带修复，它不改任何判据。
