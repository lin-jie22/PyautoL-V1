### 2.1 ⛔ 第一版设计已作废（自踩 #1，登记在此）

第一版写的是「否决 ⇒ **让位给下一个候选**」，条件 `ci < len(cands)-1`。
**没量就写。** 开工后零成本量 V36 四轮日志：

```
run_cum_r1.log  19× 通道=深 候选=1
run_cum_r2.log  19× 通道=深 候选=1
run_rst_r1.log  19× 通道=深 候选=1
run_rst_r2.log  19× 通道=深 候选=1
────────────────────────────────
候选 ≥ 2 ：0 次（76/76 全是 1）
```

即：`plan.steps` 恒为 **1 条**；`n`（3/2/1，见 `states_*.jsonl`）只是**上限**，
**从来没有被填满过**。⇒ `ci < len(cands)-1` **永远为假** ⇒ 第一版是**结构性零次机制**。

这正是纪律 29 的字面意思：**押注前先量载荷能不能到达押注的格子。**
本轮把它记成 V37 的第一条硬读数，并据此改成 M2/M3（`Continue` 的出口问题，
而不是"换哪个候选"的问题）。

### 2.2 为什么 M3 是**必须**的（不是保险）

`continue` 之后 `executed` 保持 False ⇒ 会落到 `if not executed:` 的
`consecutive_failures += 1`（"全部候选被拦"）。那是**把"我们决定不做"记成"做错了"** ——
三轮就熔断 ⇒ 交付变空 ⇒ 那一格会被读成"接上预演有害"，而事实是记账记错了。
同构先例：`skipped_now`（第六十八轮，"没额度 ≠ 失败"）。

### 2.3 为什么交付动作豁免（M2 里的 `not _produces_early`）

`finish` / 外部能力是**唯一出口**。否决它 = 手段停了把目的也停掉（§31.7 / §63）。
被豁免的次数记在 `veto_refused_answer`，**必须与 `vetoed` 并列** —— 否则
`vetoed=0` 会被读成"模型从没预测过失败"。

### 2.4 离线自检已经跑出来的一条真实路径（登记，不用于判决）

`run.py --selftest`（`DemoLLM`，零网络）两档逐行 diff，`V1_FORESIGHT_VETO=1` 那档：

```
🔮 预演否决（expect_ok=False）⇒ 不做：把本轮发现写回语义记忆
🔮 本轮 1 个候选被预演否决（不是失败，是决定不做）
⚠️ 合法 JSON 但没有可用候选（⇒ 改提示词）
✅ 收尾: （规划降级：模型输出不可解析，未能形成有效计划）
worldmodel: vetoed=1   planner: degraded=1 empty_plan=1 reseek=1
```

对照档（`=0`）同一步是：`↳ note ok=True` ⇒ `🔁 失配[outcome] 预演=失败 实际=成功`
⇒ `📎 回看` ⇒ `✅ 收尾: 根因是未指定 encoding…`（**正确答案**）。

⇒ **veto 掉唯一候选 = 把一条能成功的路砍掉，然后规划器给不出替代品 ⇒ 降级交付。**
这条路径离线可复现，是押注 `J_VETO_COSTLY` 的**唯一**依据，但它
⛔ **不是本轮读数**（`DemoLLM` ≠ 真模型，且 1 题 1 步）。

## 二·五、追加的前置量（写于开跑后、读数落地前，⛔ 不改任何判据与押注）

**来源**：V36 的冻结产物 `/tmp/v36/bench_cum_r2/runs.jsonl` 的
`kernel_worldmodel.confusion`。这不是本轮读数，是**上一轮已经落盘的事实**。

```
cum_r2: confusion = {"ok_ok": 22, "ok_fail": 1, "fail_ok": 11, "fail_fail": 0}
```

读法（`_observe_outcome` 的键是 `预测_实际`）：

| 格 | 次数 | 含义 |
|---|---:|---|
| `ok_ok` | 22 | 预演说会成功、实际成功 |
| `ok_fail` | 1 | 预演说会成功、实际失败 |
| `fail_ok` | **11** | **预演说会失败、实际成功** |
| `fail_fail` | **0** | 预演说会失败、**实际也失败** —— 一次都没有 |

⇒ **`expect_ok=False` 在 V36 一轮里出现了 11 次，且 11 次全是误报（11/11）。**

这一条同时回答了两件事：

1. **载荷能到达押注的格子**（纪律 29 检查通过）：`vetoed` 不会是结构性的 0。
2. **押注 `J_VETO_COSTLY` 的先验极强**：如果 A1 的否决真的生效，它砍掉的
   候选里按 V36 的分布**全都会成功** ⇒ 分数下降几乎是必然而非偶然。

⛔ 但它**不能替代本轮读数**，理由两条：
- 这 11 次是 **V36 的内核 + 无 veto** 下统计的；A1 一改执行路径，
  累积的内容与后续预演的输入都会变（§102 已证预演的 `known` 来自累积）；
- 它是**混淆矩阵的合计**，不含"这 11 次分别落在哪道题的哪一步"，
  而那些位置里有多少是**唯一候选**、有多少是**交付动作**（会被豁免），本轮才知道。



## 二·六、⭐ 对 §二·五 的**勘误**（写于跑批进行中、判决之前）

§二·五 引用的 `kernel_worldmodel.confusion` **是重复计数的产物，不可用**。

### 怎么发现的

`a0_r1` 跑完后对账，三处数字对不上：

| 来源 | 读数 | 说明 |
|---|---|---|
| `proxy.jsonl`（时间窗切 a0_r1） | **10** 条 `max_tokens=200` | 真实发出的预演请求 |
| `states_a0_r1.jsonl` 的 `preds` | **10** 条（逐条记录） | 与上一条**完全一致** |
| `runs.jsonl` 的 `kernel_worldmodel.predictions` | **34** | ⛔ 与上面两处矛盾 |

再看日志里 6 题逐题的 `预演=N`：**2, 3, 5, 6, 8, 10** —— **单调递增**。
差分 = `2, 1, 2, 1, 2, 2` = **10**，与 proxy 逐条对上。

⇒ `WorldModel` 实例**跨题共享**，`stats()` 返回的是**累计值**；
而 `run.py:_kwm_absorb` 把每次的**累计值**当增量相加 ⇒
`acc = 2+3+5+6+8+10 = 34`。

### 影响面（必须逐条说）

| 字段 | 是否被污染 | 说明 |
|---|---|---|
| `predictions` / `scored` / `hits` / `mismatches` | **是** | `Σ(累计值)` ≠ 真实总数 |
| `confusion` 的四格 | **是** | 同上 |
| `hit_rate` | 否（比值） | 但它的分子分母各被污染一次，**恰好约掉** |
| 本轮的 `preds`（`--state-dump`） | **否** | 逐条 append，不经 `_kwm` |
| 本轮的 `vetoed` / `veto_refused_answer` | **是** | 同源 |

⇒ §二·五 里那句「`expect_ok=False` 出现 11 次、11/11 全误报」**撤回**：
真实检验只有 10 次，`fail_*` 的 11 是累计相加造出来的数。

### 但 §二·五 的**结论方向**没变，理由换了

| 原依据 | 现在还能用吗 |
|---|---|
| `confusion.fail_ok=11` | ⛔ **不能**（重复计数） |
| 真实 `检验=10、命中=7、失配=3`（差分算出来的） | ✅ 能：**10 次里 3 次预测错** |
| 候选恒为 1（76/76，直接数日志） | ✅ 能（与 `_kwm` 无关） |
| 离线自检跑出「否决⇒降级交付」的完整路径 | ✅ 能（逐行 diff，与 `_kwm` 无关） |

⇒ `J_VETO_COSTLY` **不撤销**，但它的第一条依据作废，剩下两条独立成立。
⛔ 不许事后把押注改成"因为勘误所以弱化" —— 押注是押注，勘误是勘误。

### 这个缺陷本身

它**比本轮的主变量更重要**：所有历史读数里"预演了多少次、命中几次"
**全部是重复计数**。修法（`_kwm_absorb` 加差分，或 WorldModel 每题重置）
会改变**全部历史读数**的含义 ⇒ ⛔ 本轮不动，单开一轮（记进 V38）。

### D1 机制可达性（Q1）
对 **A0 臂**（veto 关，纯观测）统计 `preds`：
- `K = #{ ok is False 且 trust is True }`
- `J_NO_INPUT`：`K == 0` 且 `predictions > 0` ⇒ **机制没有输入**，D2/D3 不判定。
  ⛔ 这不等于"机制无效"，也不等于"预演没用" —— 它是"这套 6 题下模型从不说会失败"。
- `K > 0` ⇒ 继续。

### D2 通电（Q1 的后半）
对 **A1 臂**：
- `vetoed > 0` ⇒ 通电。
- `vetoed == 0` 且 `K > 0` ⇒ 必须给出原因，且原因只能是二者之一：
  ① `veto_refused_answer == K`（全被交付路径豁免）；
  ② 预演结论在 A0/A1 之间不同（须逐条附 `preds` 对照）。
  ⛔ 不许用"大概"解释。

### D3 净效应（Q2）—— **必须并列，只报 Σ 不合格**
- 逐格置换表：6 题 × 16 格，A0 vs A1，**逐格列出变了的那些**。
- Σ（满分 96）。
- ⛔ 纪律 30：只报 Σ 会让"两格反向相消"不可见。

### D4 代价（Q3）
- `planner.degraded` / `empty_plan` 的次数：**A1 不许高于 A0**（高了 = 拿降级换否决）。

- `mismatches_outcome`：veto 掉的预演**永远拿不到 ground truth** ⇒
  `scored` 会少 `vetoed` 那么多。这是已知缺口，读数里必须显形。

### D5 口径
- `Caliber.diff_except(other, {"memory_seed", "limits"})` 必须**空**。
- 且 `limits` 两个字典的**逐键 diff 必须恰好是 `{"foresight_veto"}` 一项**

## 五、押注（用 V36 的装置赌 V37 的结果）

### `J_VETO_COSTLY`：A1 的 Σ **低于** A0，且 `degraded` 上升。

**理由（三条，都可复核）**：
1. `候选=1` 是 **76/76** 的常态 ⇒ 否决几乎总是"否决唯一出路"。
2. 离线自检已经跑出完整路径：否决 ⇒ 重规划 ⇒ `no usable candidate` ⇒ 降级交付。
3. 预演的 `known` 只有 1~2 条泛化事实（§102.2 逐字节算过），
   分辨率不足以区分"这一步真的会失败"与"这一步只是没被记录过"。

**推翻条件（写死）**：
- A1 的 Σ ≥ A0 的 Σ ⇒ **押错**；
- 或 `vetoed > 0` 且 A1 的 `degraded` 不高于 A0 ⇒ 说明降级路径可被绕开 ⇒ **押错**。

**押错的后果**：说明"接上预演"在单候选下也能不亏 ⇒ V37 的方向是错的，
真正该推的是「候选数为什么恒为 1」，而不是"预演接不接"。

## 六、有效样本口径（纪律 39）

- `T=0` ⇒ **一发是重放，不是抽样**。有效样本 = 每臂的**独立 prompt 数**，不是轮数。
- 两轮交叉的作用是**对冲时段漂移**，不是把 n 从 1 变 2。
- 同一个 `(task, it)` 在两轮里若 `req_sha` 相同，它**只有 1 个有效样本**。

## 七、三类禁止解释（写死）

1. ⛔ **"预演没用"** —— 本轮只测了"否决"这一种接法。
2. ⛔ **"累积没用/有用"** —— 两臂都是累积臂，本轮**不比较累积**（那是 V25~V36 的事）。
3. ⛔ **"分数降了所以机制有害"** —— 必须先看 D4：降的那几格是不是"降级交付"造成的
   （即"否决之后没有替代品"），那是**接线位置的缺陷**，不是预演内容的缺陷。

## 九、自评（写在这里，等读数来判）

本轮最大的风险是 **M2 把"不做"变成"降级"**。
若 `J_VETO_COSTLY` 押对，那么本轮**不是**"预演接线失败"，
而是**"在 `候选=1` 的前提下，任何否决型机制都会退化成降级"** ——
这个结论比"接线失败"有用得多，因为它把下一步指向**探索宽度的兑现**，
而不是继续在预演上打磨。
