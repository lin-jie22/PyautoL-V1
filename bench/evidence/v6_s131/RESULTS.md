## 一、判决

> **三候选进 `core` 之后，第 1 轮只有 1 个候选被 `dispatch`。**
> **而"让位"通路是通的 —— 差别只有一个：被*跳过*会让位，被*执行*（无论成败）都不让位。**

| 场景 | 候选序列 | 第 1 轮 `dispatch` | 交付 |
|---|---|---|---|
| **S1** 三 `finish`，首候选过闸 | A / B / C | `['finish(A)']` | **A** |
| **S2** 首候选被 guard 拦 | `run_shell` / A / B | `['finish(A)']`（`run_shell` 0 次） | **A（第 2 候选）** ✅ 让位 |
| **S3** 首候选被自检打回 | BAD / A / B | `['finish(BAD)']` | 无（随后降级） |
| **S4** ⭐ 真实形态 | V39 原文的 3 个候选（449/443/411） | `['finish(449)']` | **449 字符** |

S4 是本轮最硬的一条：**不是编的候选**，是 V39 当时模型真的给出的三段实现，
走的是**真题面**（`tasks_v8` 的 `e1wi`，自检判据 `函数名 clean_lines` 等 5 条）。
结果：交付长度 **449** = 第 1 个候选的长度，后两个候选**一次都没被碰过**。

## 二、为什么（`core.py` 的三个分支）

```
949   for cand in cands:                       ← 顺序遍历，不是比较
 985     if sig in attempted_sigs:  continue   ← ① 重复 ⇒ 跳过 ⇒ 会到下一个
1000     if not gv.allow:           continue   ← ② guard 拦 ⇒ 跳过 ⇒ 会到下一个
1032     if not vj.allow:           continue   ← ③ 价值层拦 ⇒ 跳过 ⇒ 会到下一个
1110     if _vetoed:                continue   ← ④ 预演否 ⇒ 跳过 ⇒ 会到下一个
1231     if not result.ok:                      ← ⑤ 执行失败
1243         executed = True; break             ←    ⇒ **break**（不让位）
1248     if _produces:                           ← ⑥ 执行成功且是交付动作
1261         return _done("done", answer, "")    ←    ⇒ **return**（不让位）
```

`for cand in cands` 是**短路求值**：第一个"能执行"的候选决定结局，
其余候选只在前面全部被 `continue` 掉时才被看见。

⇒ 而 V39/V40 冻结原文里的真实形态是 **3×`finish`**（两份能给 3 个候选的样本，
`tools` 都是 `['finish','finish','finish']`）⇒ 首候选要么成功（⑥`return`）、
要么被自检打回（⑤`break`），**两种都不让位** ⇒ 第 2/3 个候选**结构性不可达**。

L1 静态印证：`core.py` 里 `cands` 共 **12 处**读取点，
**比较/选择 0 处**（其余是赋值、`len()`、`for` 遍历、`[c.as_line() for c in cands]`）。
这个文件里没有任何一处问过"这三个候选哪个更好"。

## 六、对主线的意义（必答三句）

1. **第 2/3 个候选能不能被读到？** 只有在前面全部**被跳过**时。`finish` 形态下
   （= 全部真实样本）**不能**。
2. **为什么？** `core.py:1231/1248` 的两个分支 —— 失败 `break`、交付 `return`，
   都跳过 `for` 循环的剩余部分。`cands` 的 12 处读取点里没有一处做比较。
3. **对"累积→预测→自省"意味着什么？** 探索宽度是**预测的前置**：没有 3 个候选，
   `foresight_veto` 的"否决后换一个"就永远是零次机制（§103 当初就是因为这个
   把"让位"设计作废的）。V40 修好了供给，本轮量出需求侧是断的
   ⇒ **下一件事不是再修供给，是给"打回后换候选"接一条线**。

   ⛔ 但这仍然是"人能踢的那一脚"。它不会让系统自己变强 ——
   它只是让"系统自己产生的第二、第三个想法"**有资格被看见**。
   看不见的想法不是想法。

## 七、自踩（四条）

1. ⭐⭐⭐ **布景失效但读数一度"很好看"**：第一版 S3 用纯文字题面 + `finish("")`，
   结果**空答案在规划阶段就被 `propose()` 的 `blank` 过滤掉**，根本到不了执行器。
   第一版读数显示 S3 交付 = 第 2 候选 —— 差点被读成"失败也让位"，
   而真相是"首候选压根不存在"。⇒ **判据的窗口必须落在宣称的机制上**（纪律 25 同源）。
2. ⭐⭐ **PREREG 与实现漂移**：PREREG §三 写的是"空答案被打回"，实现改成了
   "代码题 + 错函数名"。这是**布景失效后的改写**，已在 §七.1 说明；
   ⛔ 不能让读者以为判据是事后改的。
3. ⭐⭐ **写了一个死函数**（`_planned()` 恒返回 0）并在同一次编辑里删掉 ——
   登记它是因为它暴露了一个冲动：又想拿"候选数"当读数。而"候选数"正是 V39 栽的那个坑。
4. ⭐ **`p2` 的日志措辞依赖**：`候选=N` / `自检未过` 是**机制打印的**名字，
   不是"读数标签"（V39 栽的是把 JSON 数组长度当模型输出）。这条边界写进了脚本 docstring
   —— 否则下一个人会以为可以随便 grep 日志。

## 八、下一轮（V42）的唯一题目

> **首候选被自检打回时，把剩下的候选交出去 —— 且必须先证明它不是"更差的答案"。**

设计边界（预注册要写进去，本轮**不实现**）：

1. **只动一条边**：`if not result.ok:` 分支里，若 `cands` 还有未试的候选，
   `continue` 而不是 `break`。开关进 `Limits`（`V1_CAND_FAILOVER`），默认 0。
   ⛔ 不是"换成最好的候选"，是"换成下一个"—— 后者不需要任何判断，前者需要。
2. **必须量代价**：换候选会让"失败"变成"又一次尝试"，直接影响
   `consecutive_failures` / 级联熔断 / 预算。这些读数必须与"救回来的次数"并列。
3. **必须先有窗口读数**：V41 已给 8/64。V42 要报的是"这 8 次里救回几次"，
   而不是"分数涨了几格"。
