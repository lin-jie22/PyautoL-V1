## 2. 要加的读数（只进 `stats`，不进 prompt、不进打分器）

### 2.1 `planner.stats()["width"]`（模型**给了**多少 vs **可用**多少）

| 键 | 含义 | 为什么必须分列 |
|---|---|---|
| `offered` | 模型原始给了几条（含非 dict） | V40 的老病：**「候选数 3」≠「互不相同的候选 3」** |
| `dropped_dup` | 因 `tool\|sorted(args)` 重复被丢 | 与下一项修法不同：这个是"模型重复"，那个是"模型想了不存在的工具" |
| `dropped_unknown` | 因工具未注册被丢 | 修法是加工具/改描述 |

### 2.2 `core.stats()["plan"]`（**能进执行器**的候选长什么样）

| 键 | 含义 |
|---|---|
| `rounds` | 真正拿到 `cands` 的规划轮数 |
| `cands_total` | 各轮候选数之和 |
| `by_tool` | `{tool: 次数}`，跨轮汇总 |
| `by_tool_max_round` | **同一轮里同一个 tool 出现的最大次数** ← 本轮的核心量 |
| `produces_by_round` | 每轮有几个是**交付动作**（`finish` 或 `produces_answer`） |
| `per_round` | `[{"n":N,"tools":{...}}]`，按轮序 |

⭐ `by_tool_max_round` 是这个读数的**唯一理由**：`by_tool` 只能说明"这个工具总共被提了几次"，
说明不了"它在一轮里占了多少宽度"。V43 现场的病是后者。

## 3. 判据（预注册，⛔ 读到之后不许改）

### J1 恒存在 —— 分母 = 本轮两次**真实运行**（A 臂无 shell / B 臂有 shell）

任何一次真实运行都必须同时满足：
1. `stats["plan"]` 存在；
2. `rounds >= 1`；
3. `len(per_round) == rounds`；
4. `sum(by_tool.values()) == cands_total`；
5. `cands_total == sum(r["n"] for r in per_round)`。

> 为什么分母是真实运行而不是离线探针：**离线探针的 plan 是我自己造的**，
> 它能证明"形状对"，证明不了"每次都接得上"。§15「缺席冒充零」的同一条：
> 计数必须来自**恒存在**的产物。

**押注**：五条全成立。（若不成立 ⇒ 读数没接上，本轮判负。）

### J2 能非零 —— 分母 = A 臂（无 shell）的 `per_round`

`by_tool_max_round >= 2`（即**某一轮里同一个 tool 被提了 ≥2 次**）。

**押注：成立**（依据 V43 现场 5 个候选里 3 个 `code_agent`）。
⛔ 若实测 < 2，如实登记为**押错**，并说明"V43 那个人工读数可能是跨轮的、或被去重掉了"，
不许把 `by_tool_max_round` 改成跨轮口径来凑。

### J3 离线可复算 —— 分母 = 一个手造的 3 候选 plan

假 plan = `[finish, agent:code_agent, run_shell]`（各 1 个）⇒
`per_round[0]["tools"]` 必须逐字等于 `{"finish": 1, "agent:code_agent": 1, "run_shell": 1}`，
且 `by_tool_max_round == 1`、`produces_by_round[0] == 1`。

### J4 不改行为 —— 分母 = V44 的八个离线场景

同一份探针（`v6_s134/probe_v44_delivery.py`）改动前后输出**逐字节相同**
（`p1_probe.txt` 的 sha 不变）。

> 这是"读数改动"的**唯一**自证方式。⛔ 不许用"我只加了 print"当理由。

### J5 签名不变 —— 间接证据，明写是间接的

`git diff --stat` 不含 `mw/config.py`（没加 `Limits` 字段），
门禁 P5 打印 `limits 字段 25 个`。
⭐ 真读数只能是下一次跑批对 `Caliber.signature()`；本轮**不跑 96 格**，
所以这一条**只给间接证据**，不许写成"签名未变已验证"。

### J6 撤回态精确红

AZ108 撤回后：**只有** `plan` 块缺失那一格红，其余格（`width` 三键、`produces_by_round`）保持绿。
多处红 = 无（纪律 4）。

## 5. 预期会被打脸的地方（先写下来）

1. **`offered` 可能等于 `cands_total`** —— 因为 `plan.steps[:n]` 会截断，
   而 `_extract` 已经丢过重复。若两者恒等，说明"截断"从没生效过，那本身是读数。
2. **`by_tool_max_round` 可能只有 1** —— 若如此，则 V43 那句"3 个 code_agent"
   是**跨轮累计**（同一工具在 3 轮里各出现 1 次），而不是同一轮占宽度。
   这两种情况的修法完全不同（去重 vs 换提示词），所以必须量出来。
3. `produces_by_round` 在真实任务上可能**恒为 0**（模型一次 `finish` 都没给，
   全是 `run_shell` / `code_agent`）—— 那 V42 的"让位无弹药"就有了真实解释。
