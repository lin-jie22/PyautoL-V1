# V53 预注册 —— 收尾出口的闸只问了**文本**，没问**产物**

冻结时刻：本轮任何读数产生**之前**。⛔ 本轮不改交付物、不改分数、不新增尺子，
只把一句已经在撒谎的日志改成实话 + 给它一个**可累加的计数**。

## 0 缺陷已经落盘（不是我推测的）

V52 两臂（`bench/evidence/v6_s142/logs_a.txt` / `logs_b.txt`）同一时刻写了三行：

```
🧪 收尾交付过闸
📦 收尾交付 77 字符（来源=收尾调用）
■ not_applicable 验收=FAIL(0/1，缺 report.md) | ... 收尾闸=1跑/1过/0未过
```

⇒ **`收尾闸=1跑/1过`** 与 **`验收=FAIL(0/1，缺 report.md)`** 说的是同一份交付物，
两句话互相矛盾。原因在装置里：

- `_close_out` 的闸是 `vfy.run(best, self._checks)` —— 判据由**题面的静态形态**派生
  （`derive(goal)`），它只问"这段文本像不像能跑的代码/是不是空的"；
- 产物问（`vfy.check_delivery`）**只在 `_finish` 里算**，而 `_finish` 在 `_close_out`
  **返回之后**才跑 ⇒ 「过闸」这句话是在产物还没被问过的时候说出来的。
- 分母：V52 两臂 **2/2** 次收尾交付都落在「日志说过闸、验收 FAIL」这一格里。

## 1 假设

> 「收尾交付过闸」这句话的真实内容是「**文本**判据过了」；
> 它被读成「**交付**过了闸」，是因为产物问在**时间上**排在它后面。
> ⇒ 把产物问**提到这句话之前**，让这句话只在产物也在时才说，缺陷即消失。

可证伪形态：若把产物问挪到闸之前、并且只在 `verdict ∈ {PASS, ANSWER, EMPTY}` 时才允许
打印「收尾交付过闸」，那么：
① 产物缺失（`FAIL`/`PARTIAL`）时该子串**不再出现**；
② 产物在（`PASS`）时该子串**仍出现**（否则我只是把闸改成了恒不打印）；
③ `best` 逐字不变（与 A 臂基线比较）。

## 2 装置

| 项 | 值 |
|---|---|
| 类型 | **零模型**（装置级断言）。被测物是代码路径属性，不是模型行为 |
| 载体 | 契约测试新增 `AZ116`（三形态各一个 fixture）+ 撤回态一条 |
| 工作目录 | 每个 fixture 一个**新建空目录**（`V1_WORKSPACE` 构造前设，⛔ 不改 frozen dataclass） |
| 题面 | `把结果写入工作目录下的 report.md`（带写动作 ⇒ `expected_artifacts` 判为**产物**） |
| 交付物 | 固定字符串（不走模型）⇒ 可逐字比对 |
| 判据来源 | `c._checks` **显式给**（AZ92 的老坑：不显式给就会被前序断言改过的 `os.environ` 影响） |

⛔ 不动 `mw/verify.py`：`check_delivery` 已经是唯一判据来源（§110），本轮只改**调用时机**。

## 3 押注（形态一并写死）

| 编号 | 判据 | 形态 |
|---|---|---|
| **J1**（主押） | 产物缺失 ⇒ 日志**不含**「收尾交付过闸」 | `verdict=FAIL`（零产物，`report.md` 不存在） |
| **J2**（反向闸） | 产物存在 ⇒ 日志**含**「收尾交付过闸」 | `verdict=PASS`（`report.md` 真建出来） |
| **J3**（分列） | `FAIL` 与 `PARTIAL` 计数**分开** | `artifact_fail=1` / `artifact_partial=1` 各一格，不是一个 `artifact_missing=2` |
| **J4**（不依赖开关） | `verify_retries=0`（`_checks` 空）⇒ 文本闸零跑，但产物问**仍然发生**且可计数 | `verify_stats["closeout_runs"]==0` ∧ `artifact_fail==1` ∧ 无「过闸」子串 |

**分母三选一 + 理由**：本轮计数分母取 `closeout_stats["triggered"]`（收尾**真的交付了**几次）。
- ⛔ 不用 `verify_stats["runs"]`：那把主循环的闸也算进分母，而主循环根本没走到收尾；
- ⛔ 不用题数：一题可触发多次收尾（重试链），题数会低于触发数 ⇒ 分母被低估；
- ✔ `triggered` 是唯一"这份交付物真的被交出去过"的计数，与 `artifact_fail/partial` 同一层级。

## 4 不改什么（混口径防护）

- **不改 `best`**：本轮的预测是"交付物逐字不变"。改了就是"记账"与"改分"混在一起（§45.9）。
- **不改 `status`**：仍是 `closed`/`stalled`/`not_applicable`（过程量），"产物在不在"是结果量（§110 已分列）。
- **不改 `verdict`**：`_finish` 里那次 `check_delivery` 不动 —— 它已经是实话，本轮只是让出口**早一步**说实话。
- **不做交付闸**：不在收尾处拦截、不重试、不重新要答案（V51 的负结果不因本轮改写）。

## 5 撤回语义（每条都要能单独打红）

1. 把 `if _co_art_bad:` 分支删掉（恢复无条件打「收尾交付过闸」）⇒ **AZ116 J1 必红**；

4. 把产物问挪回 `if self._checks:` 里面 ⇒ **J4 必红**（关掉判据时产物问消失）。
