## 0 一句话

而 `_finish` 在它返回之后才跑）。本轮把产物问**提到这句话之前**，并给它三个可累加的计数。

## 5 自踩四条

1. **BSD grep 不认 `\|`**（第一次 grep 返回空、`EXIT=0`，看起来像"文件里没有这个词"）。
   ⇒ 判"存在性"只用 Grep 工具或 Python，这条纪律 MEMORY 里已有，本轮又踩了一次。
2. **改契约文件尾部时把汇总行删了**：`old_string` 是三行（`print()` + 汇总 + `print()`），
   `new_string` 末尾只还了一个 `print()` ⇒ 汇总行消失。`tail` 一眼看出来并补回。
   与 V52「old_string 带收尾括号把 AZ112 整条删了」是**同型第二次**。
   ⇒ 纪律：覆写性 `old_string` 必须在 `new_string` 里**逐行包含**，不许"省略中间几行"。
3. **加完撤回态立刻跑基线 ⇒ 基线红（AZ44）**，我第一反应去查"为什么红"，
   而真相是**量具在正常工作**：`AZ44` 拿 `len(withdraw_check.CASES)` 对 README 顶部的声明，
   201 ≠ 200 ⇒ 必须先把 15 处文档数字同步好。
   ⇒ 纪律：**加撤回态的顺序是「加 CASES → 同步文档 → 跑基线」**，反了就会把"该做的事"读成"故障"。
4. **`check_counts` 的输出被 `head` 截断后误读**：`:1134`/`:1450` 那些行是 **README** 的行号
   （那一节标题就是 `── README.md ──`），我却当成 DESIGN 的台账，差点去改历史 DESIGN 记录。
   ⇒ 与 V52 第 18 条同源：**读量具输出先确认它扫的是哪个文件。**
