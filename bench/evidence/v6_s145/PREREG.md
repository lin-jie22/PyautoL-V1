**③ 的口径（写死，防事后放宽）**：
- 只认行内含 `验收=` 的 `■` 行；
- 排除 `bench/evidence/v6_s144/{p0_before,p1_after}.txt`（合成探针格，不是真实任务）；
- 排除 `bench/evidence/v6_s144/arms_summary.txt`（**派生文件**，只摘了 `■` 行，回溯计数必然为 0）。

⇒ 32 − 4（探针格）− 2（派生文件）= **26 行**。

## 4. 判据（改后必须全绿；一条不成立即回滚）

本轮**唯一**落地：把「**按题的下发次数 × 验收结论**」写进 `runs.jsonl` 的 `kernel_exec`。

| # | 判据（连形态） | 判据用的字段在产物里存在吗 |
|---|---|---|
| **C1** | `runs.jsonl` 行里有 `kernel_exec`，且 `tasks` = 本轮题数 | 键由本轮的 `_kexec_zero()` 造 |
| **C2** | `kernel_exec.dispatched == sum(每题 stats["exec"]["dispatched"])`；`ok`/`fail` 同理 | `stats["exec"]`（V54 造，`core.py:2531`） |
| **C3** | **反向闸**：探针 S1（一道 0 下发的题）⇒ `zero_dispatch_tasks=1` 且 `zero_dispatch_by_verdict["ANSWER"]=1` | 同上；S1 的 `verdict` 已实测 = `ANSWER`（V54 S1） |
| **C4** | S2（3 次下发的题）⇒ `zero_dispatch_tasks=0`，且 `by_verdict` 仍为它记账（**两个字典不许混成一个**） | 同上 |
| **C5** | 交付物 sha 两态相同（改前文件 vs 改后文件） | `out.answer` |
| **C6** | `catalog_sha` 两口径不变 | `mw.tools.catalog_sha()` |

**C3 为什么是反向闸**：只测"有下发的题不记零"或只测"零下发的题记零"，都能被一个**恒 0** 或
**恒 +1** 的计数器满足。两个方向各一格，才排除"写成常量"。

## 7. 已知会咬人的地方（写在前头）

1. **`Core.log` 默认写文件**，不是 stdout；探针必须传 `log=收集器`。
2. **一轮塞三个候选只执行一个**（成功后即停）⇒ 要三次下发就给三轮。
3. **`↳` 行行首带时间戳**（`HH:MM:SS  ↳ …`）⇒ `startswith("↳ ")` 恒 False。今天已栽一次。
4. **`Paths` 是 frozen dataclass** ⇒ 构造时给全，不许事后赋值。
5. 契约 fixture **不许裸调 `cfg.settings()`**（前序断言会改 `os.environ`）。
