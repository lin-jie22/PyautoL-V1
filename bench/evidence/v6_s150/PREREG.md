## 1. 要回答的问题

V59 把「8/8 未轮到」劈成两半之后，留下一句**没被检验**的话：

> 4 个 `pos=1` 轮的首位候选是 `run_shell`，被 `--allow-shell` 拦掉

这句话里有两个可测的成分，本轮分开量：

| 记号 | 问题 | 需要什么 |
|---|---|---|
| **Q1 采用率** | 打开 shell 之后，模型**会不会真的跑**？ | 两臂对比 `dispatched` |

「`run_shell` 执行了没有 / 返回码是多少 / 失败之后又发生了什么」。

（工具调用成功、命令自己失败）⇒ **"跑过但结果说代码错了"在现有读数里不可见**。

## 4. 新读数出口：`kernel_shell`（本轮唯一的内核改动）

动笔前先确认**要记的字段在这一层拿得到**：

| 字段 | 来源 | 拿得到吗 |
|---|---|---|
| 候选里有没有 `run_shell`、排第几 | `plan_stats.by_tool` / `delivery_pos_by_round` | ✅ 已有 |
| 真的执行了几次 | `core.py:1449` 的唯一 `dispatch` 点（V54 起就是唯一） | ✅ 已有 |
| **返回码** | `run_shell` 的返回值首行恒为 `rc=<int>`（`mw/tools.py:236`） | ✅ 可解析，**但解析不到必须记 `rc_unknown`，⛔ 不许当 0** |
| 失败之后又跑了/又交了 | 需在同一个循环内按 `cand.tool` 记序 | ⛔ 现有账本没有 ⇒ 本轮新增 |

`kernel_shell` 的键（**先写死，跑完不许加减**）：

```
tasks / tasks_with_shell / offered / dispatched / rc_zero / rc_nonzero / rc_unknown
err / blocked / blocked_by_checkpoint{} / rounds_with_shell / shell_first_rounds
after_fail_retry / after_fail_answer / trace[]
```

- `after_fail_retry` = 上一次 shell 返回非 0 之后**又执行了一次** shell 的次数；
- `after_fail_answer` = 上一次 shell 返回非 0 之后**交付了答案**（且这次之前没再跑 shell）的次数；
- ⛔ 两个名字都只描述**事件**，不描述意图（"改代码"是推断，不是读数）；
- `trace` 每题一条，形如 `"r1:1"` / `"r2:0"`（轮号:返回码），`rc_unknown` 记 `"r1:?"`。

## 5. 分母三选一 + 理由

| 分母 | 数 | 回答什么 | 本轮用途 |
|---|---|---|---|
| **题**（task-run） | **12** | 采用率：**几题**真的跑了 | **Q1 主分母** |
| **轮** | 18（A）/ 待测（B） | 顺序与"失败后下一步" | Q3 用**事件** |
| **次**（shell 执行） | 待测 | 验证动作本身的成败 | Q2 归因用 |

**选择题作 Q1 主分母的理由**：采用率问的是"这道题会不会去验证"，
一旦上轮它跑过、下轮它没跑，也是同一题上的事件；用轮做分母，同一题跑两轮会被读成两次采用。

## 7. 判决口径（先写死）

1. **P1 或 P2 落空** ⇒ 本轮判 **UNKNOWN**：两臂不同源，比较作废。⛔ 不许"接近"。
2. **P1/P2/P3 中 且 P5 落空** ⇒ 结论是 **「装置说可以，模型不跑」**：
   V59 那句「拦掉的正是唯一的验证动作」要撤回一半 —— 拦是真的，但放开后它不跑。
3. **P5 中 且 P9 落空** ⇒ 结论是 **「跑了，但没变好」**：这是负结果，
   与"没跑"的修法**相反**（前者换验证方式，后者修闸）。
4. **P4 落空** ⇒ 结论是 **「开了一层还有一层」**：下一轮的唯一动作是查第二层的名字，
   ⛔ 不许同轮再动第二个变量。
5. ⛔ 本轮**不**判「内核会自己变强」：模型跑一次验证再改一次代码，只是**一次**纠错，
   不是三循环闭合（MEMORY §零）。
6. ⛔ 本轮**不**改提示词、不改交付时机、不改 `Guard` 的语义。

## 8. 可能的自踩（先登记）

1. **`rc` 解析**：`run_shell` 成功时输出形如 `rc=0\n<stdout>`；但 `dispatch` 的失败路径
   （缺参 / 异常 / 未知工具）**没有** `rc=` 行 ⇒ 必须落进 `err`，⛔ 不许当成 `rc=0`。
2. **`dispatch` 眼里的 `ok` 与命令的成败不是一回事**：`rc=1` 仍是 `result.ok=True`。
   ⇒ `kernel_shell.rc_nonzero > 0` 而 `exec_stats.fail == 0` 是**正常**的，不是装置坏了。
3. **两臂的 workspace 必须同一个路径**（见 §3），否则路径不同 ⇒ 提示词不同 ⇒ 两变量。
4. **B 臂可能超时/变慢**：`V1_MAX_WALL_S=300`、`max_steps=12` 都是硬闸；
   若出现 `budget_exhausted`，那是读数的一部分，⛔ 不许重跑直到"好看"。
5. **`logs/core.log` 是追加日志**：本轮两臂都设 `V1_LOG_DIR` ⇒ 各自独立，parse 时按目录分，
   ⛔ 不许按时间戳猜（V59 已经用过一次时间边界，那是没得选的退路）。
6. **新账本键会被 `check_counts` 的 22 处文档声明扫到吗**：若文档里写了键名，
   必须同步；跑门禁前先看。
