# V62 判决 —— 「打回 → 重写」这条边：**位置不是病，模型不看反例才是**

> 两臂真跑批（12 格 × `repeat=2`），只差 `V1_REJECT_CARRY`；`V1_VERIFY_EXEC=1` 是两臂常量。
> 读数原文：`readings.txt`｜两臂 CLI：`arm_a_cli.txt` / `arm_b_cli.txt`｜预注册：`PREREG.md`。

## 1. 一句话

**机制通了（`carried=2`），分数一格没动（`0.8611 → 0.8611`），而且「模型改没改」的答案是"没改"——
4 次打回、4 次逐字重提、0 次改写。**

⇒ 「打回 → 重写」这条边**不是**载荷问题、**不是**位置问题、**不是**显著性不够。
把报错原文放进 `replan` 的 `failed` 行、让它在让位成功之后**也活下来**、多给它一遍，
模型仍然提交**逐字节相同**的答案。

## 3. 三条判决

### 3.1 V61 的 `unaccounted=4` 找到正身了（本轮唯一"新事实"）

V61 的漏斗残差 `38 − 24 − 0 − 10 = 4` 一直是"少一类出口"。本轮在**重复闸**里补了那一格，
两臂读到的都是：

```
rework.same = 4   rework.dup_skipped = 4   rework.redelivered = 4
```

那 4 个就是被重复闸吃掉的 `finish` —— 也就是"模型把同一份答案又交了一遍"。
**这不是算术错，是漏斗缺格**（V61 §127.9 第 2 项，本轮顺手做掉了）。

### 3.2 载荷/位置/显著性**全部排除**

PREREG §0.2 的单题探针（真实模型 + `--state-dump`）已经证明 `it=3/4` 的 state 里含：

```
[工作记忆] finish ⇒ ✘ [工具失败] 自检未通过：1/6 项未过：题面示例未通过：
           TypeError: 'tuple' object does not support item assignment
```

本轮 B 臂又在**重规划位置**多加了一遍（`↻ 打回报文进下一轮提问（让位成功也没把它冲掉）`，
`carried=2`，恰好在 t04 的两 rep 各一次）。**结果：`same=4 → same=4`、`diff=0 → diff=0`。**

⇒ 三种解释被同一条读数打死：不是"没送到"、不是"位置不对"、不是"只说了一遍不够"。

### 3.3 分数 Δ=0，轮数也不变 —— 因为**行为没变**

两臂 26 轮、`dispatched=24`、`unreached_by_tool` 逐项相同。
`carry` 只替换了**那一次**提问的形态（`propose` → `replan`），没有改变模型给的东西
⇒ 后续轨迹逐字同构（V36 那条老结论的又一次现身：**输入差得不够，输出就不变**）。

## 5. 自踩（本轮五条，全部当场抓到）

1. **`redelivered` 记错了地方**：第一版记在"又被打回"分支 ⇒ 一份**改对了**的重写会让它少 1，
   而 `passed_after` 多 1 ⇒ 恒等式不成立、`rework_gap` 把"改对了"报成"漏计"。
   冒烟（stub）当场抓到 ⇒ 改成在**闸的入口**记。**"检测器自己失效"的第三形态。**
2. **`same` 在闸里永远到不了**：逐字相同的交付**签名也相同** ⇒ 在重复闸就被丢，
   `_gate_finish` 根本不执行。第一版把 `same` 记在闸里 ⇒ 照抄那一跑读到 `same=0`。
   修法不是改断言，是**把计数记在真正发生它的地方**（重复闸）。
   ⇒ 这条同时把 V61 的漏斗第四格补齐了。
3. **AZ124 第一版把 `Outcome` 当 dict 用**（`(v or {}).get(...)`）⇒ `AttributeError`
   让整个契约从 627 掉到 **PASS=7 / FAIL=0**：**崩溃被读成"跑完了、只跑了 7 条"**。
   "缺席冒充零"的变体，只不过冒充的是"通过"。
4. **AZ63 抓到我新增了第三处 `replan` 调用点**（喂入点 2→3）。改法不是 `>=2` 放宽，
   而是精确改成 3 并在注释里写明"第三处是哪一处"。
5. **`--state-dump` 传目录** ⇒ `IsADirectoryError` 让整轮跑批作废（第一版探针）。
   重定向到**文件路径**才对；而且第一次跑批的 `EXIT=1` 是"早退"，⛔ 不能当读数用。

## 6. 这条负结果值多少

它不是"又白跑一轮"，它**关掉了一整类解释**：

| 假设 | 状态 |
|---|---|
| 报错没送到 prompt | ⛔ 否证（state 原文含 `自检未通过`+`TypeError`） |
| 送到了但位置不对（不在 `failed` 行） | ⛔ 否定（B 臂多了那一行，行为不变） |
| 只说一遍不够 | ⛔ 否定（`carried=2`，`same` 不变） |
| **模型对具体反例不敏感（7b / T=0）** | ✅ 唯一未被排除的解释 |

⇒ 下一步**不许**再在"提示词 / 载荷 / 位置 / 强调"这一层加料。要继续走，只有三条路，
而且**都要换装置或换口径段**，属于要用户拍板的事：

| 方案 | 代价 | 能回答什么 |
|---|---|---|
| **A** 换采样（`T>0` 或 k 采样选优） | 断口径段（`temperature` 在 `Limits` 里）、T=0 的可复现性消失 | "是不是采样把它钉死了" |
| **B** 换模型（更大的一个） | 换装置、与全部历史读数不可比 | "是不是 7b 的能力上限" |
| **C** 换题（错误类型不同的题） | 换尺子（`suite_sha` 变）⇒ 要重做基线 | "是不是 `TypeError` 这类错误对模型无信息" |

⛔ 我**不建议**在没有用户同意的情况下动 A/B/C 中任何一个：三条都会让"0.8611"这个基线作废。
