# V65 前置探针 —— 用户选了 B（换模型），但**前提被 10 秒的探针否证了**

> ⛔ 本目录是**定位探针**，不是尺子：判据用的是 `bench/tasks/coding_small.jsonl`
> 每题自带的 `tests`（与 bench scorer 同源），不另造题、不另造 oracle。
> ⛔ 不入判决：本节只回答"要不要换模型"，不押分数。

## 0 起因：本机只有更小的模型

用户拍板走 **B（换模型）**。先取证本机有什么：

```
nomic-embed-text:latest   0.27 GB   137M   （嵌入模型，不能用）
Qwen3.5-4B:latest         2.74 GB   4.2B   （**更小**，且换代际 ⇒ 双变量）
qwen2.5:7b                4.68 GB   7.6B   （当前）
```

⇒ 没有更大的。于是开始 `ollama pull qwen2.5:14b`（同家族同代、只变规模 ⇒ 唯一干净的单变量）。

**等待期间做了一次零成本探针**，结果把 B 路的前提推翻了。

## 1 第一刀：单题、单轮，7b 自己会不会做 `merge_ranges`？

`v65_probe_model.py`（system = "你是程序助手。只输出代码，不要解释。"，`max_tokens=2048`，T=0）：

```
qwen2.5:7b   10.3s   通过 6/6
```

⚠️ 但整跑批里 t04 是 **0.3333（2/6）**。
⇒ 7b **会做**这道题；在内核路径下却做错了。**"是不是 7b 的能力上限"这个问题，到这里已经半否。**

## 2 第二刀：直连（`--solver llm-direct`，走 `DIRECT_SYSTEM`）

```
python3 run.py --bench --solver llm-direct --suite <t04 单题> --temperature 0 --repeat 1
⇒ 0.6667（4/6）
```

三层递降 ⇒ 病不在模型：

| 路径 | system | t04 |
|---|---|---|
| 内核（整跑批） | `_SYS`（planner.py:95）+ 交付句（:159） | **2/6** |
| 直连 `llm-direct` | `DIRECT_SYSTEM`（run.py:146） | **4/6** |
| 单轮探针 | "你是程序助手。只输出代码，不要解释。" | **6/6** |

## 3 第三刀：受控消融（同模型 / 同题面 / 同 `max_tokens=2048` / T=0，**只差 system**）

| 变体 | system | 通过 |
|---|---|---|
| `direct` | 你是代码助手。只输出一个 python 代码块，**不要任何解释**、不要示例调用。函数名与签名必须与题目要求完全一致。 | **4/6** |
| `no_noex` | 删掉「不要示例调用」 | **4/6** ← 仍差 |
| **`no_noexp`** | **删掉「不要任何解释」** | **6/6** |
| `shape_only` | 你是代码助手。只输出一个 python 代码块。 | **6/6** |
| `no_sig` | 删掉「函数名与签名必须完全一致」 | **4/6** ← 仍差 |

⇒ **有害的是「不要任何解释」这五个字。** 其余三句删了都不变。

`direct` 与 `no_noexp` 的失败原文**逐字相同**：
`TypeError: 'tuple' object does not support item assignment`
—— 与整跑批里 t04 的失败原文**一字不差**。

## 4 整题集（`v65_probe_suite.py`，6 题 × 2 变体）

| 变体 | 断言级 | 题级 mean | 墙钟 |
|---|---|---|---|
| `direct`（现状） | 29/31 = **0.9355** | (5 + 4/6)/6 = **0.9444** | 28s |
| `no_noexp`（删一句） | 31/31 = **1.0000** | **1.0000** | 40s |

逐题差：**只有 t04 变了**（4/6 → 6/6），其余五题一格没动。

⚠️ 与整跑批对照（题级）：内核 **0.8611** < 直连 **0.9444** < 直连删句 **1.0000**。
⇒ 有两层损耗，第一层已经定性（这一句），第二层（内核上下文：`_SYS` + 状态 + 工具 + 多轮）
还没定位。

## 5 结论

1. ⛔ **B 路的前提不成立**：`0.8611` 不是「7b 的能力上限」——
   同一个模型、同一个题集、单轮就能 **1.0000**（删一句 system）。
   ⇒ **不需要更大的模型。**
2. ⭐ **新的病位**：`mw/planner.py:159`
   `"只输出最终答案本身：不要 JSON、不要解释、不要道歉、不要代码块围栏。"`
   —— 交付答案走的就是这句，而被评分的就是交付的答案。
   内核侧还有 `planner.py:95`（规划器："只输出 JSON，不要解释"）。
3. ⚠️ 但**改它有两处风险**，必须先量：
   - 交付解析：模型若开始写解释，`finish` 的答案提取会不会把解释也带进去（影响评分）；
   - 规划器那句（:95）是 JSON 解析，若放开"不要解释"，`parse_json` 的命中率可能下降。

## 6 边界（⛔ 不许把本节读大）

- n=1（T=0 确定性 + 同 prompt ⇒ 可重复，本轮关键档各跑过 2 次，读数相同）。
- 只 6 题 / 31 条断言 ⇒ 分辨率 = 1/31。
- 直连 ≠ 内核：本节证明的是**输入构造**的问题，**不是**"内核没用"。
- 未做：`no_noexp` 全跑批（那才是对 `0.8611` 的正式检验）—— 需要用户拍板动内核提示词。

## 7 复现

```bash
# 单题（可换 PROBE_SYS=direct|no_noexp|shape_only|no_sig）
PROBE_SYS=no_noexp PROBE_MAXTOK=2048 python3 v65_probe_model.py qwen2.5:7b

# 整题集两档
PROBE_MODEL=qwen2.5:7b PROBE_MAXTOK=2048 python3 v65_probe_suite.py
```
