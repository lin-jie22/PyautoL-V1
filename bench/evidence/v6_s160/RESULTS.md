# V71 取证结果：全仓「打回 → 重写」兑现率 = 1/19，而那 1 次不是被检查输出改的

> 本轮 **不调模型、不改内核、不押方向、不新增尺子**。
> 只从**已冻结**的 93 个 `runs*.jsonl`（312 行）与同期日志里搬数，全部可复算：
> `python3 bench/evidence/v6_s160/analyze_v71.py detail`

---

## 1. 这一轮问的是什么

§138.6 留了一个**前置问题**，答不出来就不许押「让检查执行 ⇒ 分数升」：

> **`run_shell` / 自检的输出，能不能改变下一版代码？**

§138 只量到「载荷指向的检查在六跑里执行 0 次」，所以那条路上的分母是 0。
本轮换问法：**不去造检查，去历史上找「检查执行过、失败了、并且之后真的又交了一版」的格子，数清楚它兑现了几次。**

三个计数器本来就是为这个问题建的（`run.py:1161-1188` 定义、`mw/core.py:2005/2012/2022` 落点）：

| 字段 | 定义（回读源码行，不靠记忆） |
|---|---|
| `task_runs_rejected` | 被打回过至少一次的**题-run** 数 ⇒ 下面四项的分母 |
| `redelivered` | 打回之后**又交了一次**（这条边存不存在） |
| `same` | 重交的那版与被打回那版**逐字相同**（在重复闸被丢，`core.py:1407`） |
| `diff` | 重交的那版**不同**（`core.py:2012`） |
| `passed_after` | 重交那一版**过闸**（`diff` 的子集，`core.py:2022`） |
| `rework_gap` | `redelivered − (same + diff)`，恒等式，必须为 0 |

## 2. 读数一：全仓兑现率

| 量 | 值 |
|---|---|
| `task_runs_rejected` | **10** |
| `redelivered` | **19** |
| ├ `same`（逐字相同） | **18** |
| └ `diff`（真的不同） | **1** |
| `passed_after` | **1** |
| `rework_gap` | **0**（恒等式成立，无漏计） |
| `verify.exhausted`（重写配额用满） | **0** |
| `verify.failed` / `verify.runs` | 19 / 150 |
| `verify.example_failed` / `example_runs` | 16 / 40 |
| `kernel_shell.dispatched` / `rc_nonzero` | 10 / 3 |

⇒ **改版率 = 1/19 = 5.3%**；**改版后过闸率 = 1/1**。

⚠️ 口径提醒（第 4 次栽在这条上）：`task_runs_rejected=10` 是**题-run**，`redelivered=19` 是**次**。
一道题被打回两次（主循环闸 + 收尾闸）就会贡献 2 次重交 ⇒ 19 不是 10 的倍数，也不是漏计。

### ⛔⛔ 必须先说的一条限定：19 是**次数**，不是 **19 个独立样本**

那 8 跑（V66 ×1 + V67 ×7）打回的是**同一道题**（`merge_ranges`）、**同一个模型**（`qwen2.5:7b`）、
**同一句报错**（`TypeError: 'tuple' object does not support item assignment`），
而 `T=0` ⇒ 同提示词必然同输出（V36/V59/V66 反复确认）。

⇒ **等效独立样本最多是 1**（题 × 检查 × 模型这一格）。
把这个表读成「18 次实验都证明模型不改」是**分母造假**；正确说法是
**「这一格上，反例在场 18 次，一次都没改变输出」**。
本轮真正的样本量是 **2 格**：`merge_ranges`（带细节，2 次重交）+ `k02_encode_cookie`（盲报 + guard 拦截，1 次重交，改了）。

## 5. 读数四：唯一一次改版，是被**拦截**改的，不是被**判错**改的

`bench/evidence/v6_s159/core_A3.log`（V70 的 A3 臂：32 条记忆、`struct_convert_heldout`、`k02_encode_cookie`）：

```
:20  🧪 自检未过（第 1/2 次打回）⇒ 退回重写：1/5 项未过：自检未通过（不提供细节）
:23  ↪ 交付被打回 ⇒ 让位给候选 2/2（不重规划，直接用已有的）
:24  ✋ [guard:goal_hijack] 拦截 —— 动作与目标无公共词：['10','cmd','import','parse']
:25  ⛔ 全部候选被拦 (2 次连续失败)
:26  ↻ 带错误原文重规划（连续失败 2 次）：**全部候选均被 guard 拦截**
:29  ✎ 重写的答案与被打回那版**不同**（模型改了）
:30  ✅ 打回之后的重写**过了闸**
```

三个细节值得记：

1. 这次打回是**盲报**（`1/5 项未过：自检未通过（不提供细节）`，`mw/verify.py:510`，第八十轮 `KEEP` 的默认档），
   **没有**任何错误细节。
2. 真正改写提示词的是 **guard 的拦截原文**（「动作与目标无公共词」+「全部候选均被拦截」），
   而**不是**自检结论。
3. 同一跑次里，模型最早那一版其实还想做检查 ——
   `core_A3.log:15` 的「模型输出不是合法 JSON」片段里有 `{"intent": "检查示例输入", "tool": "run_shell"}`，
   被**解析器**吃掉（与 §138.4 同一出口、不同跑次再次复现）。

⚠️ 而这次「改对了」**没有加分**：`k02` 仍是 0.8，A3 的 `mean` 仍是 0.7500，与空记忆基线逐格相同。

## 6. 判决

### 6.1 §138.6 的前置问题**有答案了**

> **能。1/19 次（次数口径；等效独立样本 2 格）。而且那唯一 1 次的触发不是检查输出，是 guard 的拦截原文。**

这与「输出没用」是两句话：输出**确实**进过 19 次上下文，其中 18 次模型给出了逐字相同的答案。

### 6.2 修正 V61 的一句话（收紧，非重开）

V61 §127.5② 写「**重写一次都没发生**」，那是**那一轮**的读数（`exhausted=0`、4 次打回全在 t04），成立。
但全仓不成立：**`diff=1`、`passed_after=1`** ⇒ 这条边**存在，只是极稀（5.3%）**。
⇒ 正确表述：**「打回 → 改版」这条边不是没装，是 19 次里只兑现 1 次。**

### 6.3 断点位置再挪一层（这是本轮唯一的新结论）

V57~V70 一路把断点从「漏斗」挪到「顺序」到「验证」到「执行器」。本轮再挪一格：

> **检查跑了、报错具体、原文进了提示词 —— 模型仍然交出逐字相同的答案。**
> 断点不在「有没有反例」，也不在「反例到不到得了」，在**「到了之后模型要不要动」**。

而唯一动的那一次，上下文里多出来的是**「你的候选全部被拦住了」**（一个「上一版不可再用」的事实），
而不是**「你的上一版是错的」**（一个判断）。

⭐ 由此得到一条**未验证**的假设（⛔ 不当结论，下一轮才能测）：

> **能改变下一版的是「上一版被判为不可再用」，不是「上一版被判为错」。**

## 7. 本轮不能说的话

- ⛔ 不能说「模型改不动」——它改过一次（A3），且改完过闸；
- ⛔ 不能说「给了细节就会改」——给了 `TypeError` 的 9 跑，18/18 没改；
- ⛔ 不能说「盲报更好」——第八十轮的三臂（base 0.5574 / 报名字 0.6190 / 盲报 0.6905）
  是在**另一套 6 题尺子**上量的，⛔ 不相减，本轮也没有重测；
- ⛔ 不能说「A3 那次改版让系统变强」——`k02` 0.8 不变、`mean` 0.75 不变；
- ⛔ 不能把 `redelivered=19` 与 `verify.runs=150` 混用（前者分母是「被打回之后」，后者含第一次交付）。

## 8. 下一刀（本轮未做，需单独立轮）

假设只有一个可测形式：**把「打回」的呈现从「判决」换成「封锁」** ——
即打回时不给「你未过闸」这种判断，而给「这一版已不可再用」+ 强制重规划（而不是让位给一个步骤动作）。

- 装置现成：`cand_failover`（让位）、`verify_retries`（打回上限）、`verify_exec`（题面示例）都在 `Limits`/`Guard` 上；
  A3 那次「全部候选被拦 ⇒ 带错误原文重规划」的路径**已经存在**，只是要靠 guard 偶然触发。
- 判据只用**计数**，⛔ 不用分数（形状噪声 0.1290 远大于可能的 Δ）：
  押 **`diff/redelivered` 从 1/19 升到 ≥ 1/4**（三值：升/平/降）。
- ⚠️ 分母只有 10 题-run，先把「打回」的发生率（10/140 = 7.1%）算进去：
  一轮 6 题 × `--repeat 1` 期望打回 ≈ 0.4 次 ⇒ **必须靠 `--repeat` 或扩大题数把分母做出来**，
  否则又会掉进「判据分辨率高于装置」。
