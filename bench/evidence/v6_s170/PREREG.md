## 1. 要回答的问题

V79 判死「模型自写断言」（判别力 0/8）：断言与实现**共用同一个误解**。

剩下唯一没被否掉的变体：**约束由规则从题面文本抽出**，因此它与模型的读法

## 3. 规则表（开跑前固定，⛔ 跑完不许加）

| # | 题面模式（正则） | 派生约束 | 探针输入怎么来 |
|---|---|---|---|
| R1a | `用 ['"]([^'"]{1,8})['"] 连接`（子句无「路径/键」） | 多元素分隔符**必须**是该字面量 | `tests` 里实参含 ≥2 项的那条 |
| R1b | 同上但子句含「路径」或「键」 | 嵌套路径用该字面量连接 | **规则自造**：`{'a': {'b': 1}}` vs `{'a': {'b': 2}}` |
| R2a | `末尾也要有换行符` | 非空输出以 `\n` 结尾 | `tests` 全部 |
| R2b | 同上（**解释性加严**：一行一个换行 ⇒ 不许有空白尾行） | 非空输出**恰**以一个 `\n` 结尾 | `tests` 全部 |
| R3 | `最大下标 \+1` 且 `未填的位置写 None` | `{'a[2]': 0}` ⇒ `{'a': [None, None, 0]}` | **规则自造**（`base='a'`, `i=2`） |
| R4 | `([^\s，,；;]+)→(%[0-9A-Fa-f]{2})` | 值里的该字符必须转义成该 `%NN`，且原文不许残留 | `tests` 里实参字符串含该字符的那条 |
| R5 | `大小写不敏感` / `首尾空白忽略` | `f(x) == f(x.upper())` / `f(' '+x+' ') == f(x)` | `tests` 里字符串实参 |
| R6 | `不超长时原样返回` | `f(s, n) == s`（当 `len(s) <= n`） | `tests` 里满足条件的调用 |
| R7 | `保持原顺序` | 返回值必须是入参的**原序子序列** | `tests` 里 list 实参 |
| R8 | `输入可能是 int 或 float` | 无（记 0 条） | — |

⛔ 规则只看 `prompt` 文本。⛔ 不许读 `tests` 的期望值。⛔ 跑完看到结果再改规则 = 作废。

## 4. 三条前置 + 一条部署性

| 指标 | 定义（分母写进名字） | 开闸线 |
|---|---|---|
| **S1 可抽约束条数** | 8 题里被规则表派出的 spec 条数 | `> 0` 且 ≥ 6 题有 spec |
| **S2 咬住** | 31 份**已知错**实现里被判 `FAIL` 的份数 | `≥ 8 / 31`（≈26%） |
| **S3 误伤** | 9 份**已知对**实现（8 个 oracle + 1 份 stored pass）里被判 `FAIL` 的份数 | **必须 = 0** |
| **S4 部署性** | 「真正咬住过至少一份错实现」的 spec 里，**探针不依赖 `tests` 实参**的条数 | `≥ 1` |

S3 是硬闸：任何一条误伤 ⇒ F 不开（否则它会把对的答案打回，重试边反而变差）。
S2 是软闸：咬不住就说明「规则抽得出的约束」不是这批错的原因。

## 6. 已知的量具风险（先写下来）

1. **R3 的常量是我选的**（`base='a'`, `i=2`）。换 `i` 结果可能不同 ⇒ 结果里必须报
   「逐条 spec 的咬住数」，不许只报总数。
2. **R1b/R3 探针是自造输入**，模型可能对这类输入另有 bug ⇒ 咬住**不等于**错因正确。
   必须同时报出「判 FAIL 的原因原文」，人工核是不是题面写的那件事。
3. **子进程超时**：答案里有死循环 ⇒ 记 `TIMEOUT`，**不算咬住也不算通过**（单列）。
4. ⛔ 不许把「咬住」写成「系统学会了自检」——这一步的判定规则仍是**人写的**。
