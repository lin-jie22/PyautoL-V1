## 0. 一句话

**累积循环的写端一直在写，读端一直在读另一张表，而把两张表连起来的那唯一一个函数
（`mw/abstractor.distill`）在 `run.py` 里有 0 个调用点。**

真实模型跑批臂（struct_convert A5）里有 **10 条满分交付**躺在 `episodes(kind='finish')` 里；
`recall()` 唯一会读的 `facts` 表里 **3 条**，全是「动作预演偏差」，**没有一条来自这些交付**。

## 1. 为什么这轮不是"再量一次累积"

§138.2 那张表把「累积 0→62 条」写成了 `memory_seed` 的第二分量。
`run.py:191` 的定义是 `(facts, episodes)`：

```
[0,0] → [0,13] → [3,32] → [3,49] → [3,62]
 ↑facts ↑eps     ↑facts ↑eps
```

⇒ A1→A5 五臂里，**可读层（facts）只从 0 走到 3**，那 3 条是 worldmodel 的
「动作预演偏差」，与题无关；真正长的是 episodes（0→62）。

`recall()` 的 SQL 只查 `facts`（`mw/memory.py:410-425`）；`episodes` 的读点只有三处
（见 §3）。⇒ **五轮「累积 Δ=0」测的是"读了 2~3 条无关事实"，不是"累积无效"。**
按纪律 8（读数标签不是读数），这个标签要改。

## 3. 读端实况（静态，`mw/*.py`）

| 表 | 读点 | 在生产路径上？ |

```
把 episodes 变成 facts 的函数 distill() 在 run.py 的调用点 = 0
```

⇒ 结构：**写端 `episodes.finish` → 可读层 `facts` 的桥没有接在跑批上**，

## 4. 判决

| 判据（开跑前就成立，探针只是量化） | 读数 | 判 |
|---|---|---|
| E：`g7j_n4` 的库里有 ZK 惯例？ | `LIKE '%ZK%'` = **0**；g7 臂 24 条交付满分 **0** | ❌ **E 前置不成立** |
| E：struct_convert 的「累积」动过可读层？ | facts **0→3**（3 条与题无关），episodes 0→62 | ❌ **不成立** |
| 累积库里有"对的"可复用？ | A5 臂 **10 条满分**（工作库另有 9 条真跑） | ✅ **有，但读不到** |
| 「把成功交付记住」能救失败题？ | 失败题在库里 `encode_cookie 0/5`、`unflatten 0/5` ⇒ **0 条满分** | ❌ **上限 = 0** |
| 蒸馏器能产出"成功经验"？ | `_DISTILL_SYSTEM` 第 3 条只要「下次怎么避免同一个坑」；`abstractor.py:208` 注释亲口写「成功记录本来就没什么可提的」 | ❌ **输出空间里没有成功语义** |

**三条连起来的结论**：

1. **E 不开。** g7j 上零记忆 vs 累积记忆是恒等式（库里没有惯例）；struct_convert 上
   §138.2 已经量过平 —— 而且现在知道"累积"动的是 episodes，不是 facts。
2. **"两张表"的准确说法不是"两套 API 各自能跑通"，而是"桥在生产路径上不存在"。**
   比 §136.5 更硬：不是"库里没有对的"，是**库里有一批对的，却没有路通向读端**。
3. ⛔ **不许把结论 2 读成"接上桥就会变强"**：失败题在库里 0 条满分（案例记忆救不了它），
   而唯一能把"做对过"变成"下次做对"的是**可迁移规则**，蒸馏器的输出空间恰恰不含它。
   ⇒ 接桥是**必要**条件，不是充分条件。

## 6. 自踩（三处，全是探针自己失效）

① **抽取器只认 ``` 围栏**：第一版把 **277 条裸代码**（`done: def flatten(...)`）判成
「无代码块」⇒ 差点写成"库里大半交付不是代码"。库里主力形态是**不带围栏**的。
修法：去前缀后含 `def ` 即整段当代码，让打分器自己判。
② **题集挂少了**：先只挂 5 个 heldout ⇒ `flatten` 358 条全部"可判=0"。扩到 `bench/tasks/*`
后才判得出。⚠️ "可判=0"一律记 `unscored_no_task`，**不记 0 分**（缺席冒充零，纪律 8）。
③ **桩跑当成了真跑**：第一版把工作库的 **139 条满分**算成"系统自己攒的对答案"，
实际那些交付 `wall_s = 0.00`、415 条只有 **4 份互异原文** ⇒ 是 `oracle/partial` 桩的产物。
真跑满分只有 **9 条**（工作库）+ **10 条**（A5 臂）。⛔ 以后凡是"库里有多少对的"，
**先按 `wall_s` 劈桩/真**，再看数。（这是"缺席冒充零"的镜像：**桩跑冒充真跑**。）
