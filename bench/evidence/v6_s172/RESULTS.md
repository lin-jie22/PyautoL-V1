## 3. 判决

1. **V82 之后要修的第一块不是蒸馏器，是读端入口。**
   蒸馏器再准，产出也进不了 `[语义记忆]` 块 —— 现状下 `hit4 = 0/4`。
2. **「累积 Δ=0」的归因要改写**（第二次改写，第一次是 V82 的"累积其实只长 episodes"）：
   - V82：写端有对的，桥不在生产路径上；
   - V83：**桥就算在，读端也用不上** —— 题面的中文 run 与经验的中文 run 不可能**逐字相等**。
3. **不许读成"记忆无用"**：`g7e` 2/4、`g7j` 4/4 证明通道**能**送，
   而 §7e/§7f 已证"送到 ⇒ 行为会变"（`g7e2` 0.2→1.0），只是那一轮被**邻域效应**
   （同一 state 里另三条惯例从 182 字变 291 字 ⇒ 单题极差 0.80）吃掉了归因。
4. **两个候选读法都够用**（`hit4` 4/4、rank@1 4/4），精度指标本轮选错，不是方案不行；
   部署要在**真 `recall` 路径**上重测 `hit4`，⛔ 不许用本探针的旁路实现当部署证据。

## 4. 自踩 / 风险（都写出来，不许只留好读数）

1. **预注册里 47 行是我数错**，实际 51 行。已在校正后保留两个数（`PREREG.md` 表内注明）。
2. **`distract_top6_s2 ≤ 1` 押错**（实测 12），且这个指标本身就选错 —— 见 §1。
3. **S1/S2 是旁路实现**（我在探针里自己写的 SQL/索引），**不等于** `mw/memory.py` 里改完的行为。
   ⛔ 部署前必须在真 `recall` 上复测；本轮不认领"改了就 4/4"。
4. **`layer_recalled` 是假零**：它只在 `memory_mode == ABSTRACT_MODE` 时累加
   （`core.py:2242`），非 abstract 臂恒 0 ⇒ 不能拿它当"没送达"的证据（本轮改用 state 原文）。
5. **两字链会大幅提高召回，也必然提高误招**：S1 前 6 名 14 条无关、S2 12 条。
   部署时是否要收紧（阈值/取 top-2）是下一轮的变量，不是本轮结论。
6. ⛔⛔ **我把归档证据库改坏了（最重的一条）**：第一版为了量噪音，直接用
   `MemoryStore(bench/evidence/v6_s159/final_memory.db)` 打开归档库并 `build_char_fts`

   顺手造了个 **0 字节的 `seed_memory.db`**（`connect` 会建文件）。
   已 `git checkout --` 复原 + 删空文件，并用 `repro_readings.py`（**先 `shutil.copy` 再开**）
   复算 —— **逐题读数与第一版完全一致**（送达 0/4、S1/S2 噪音 0/0/0/2）。
