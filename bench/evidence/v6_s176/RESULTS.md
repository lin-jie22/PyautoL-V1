## 3 旁落的机制：不是噪声，是**记忆串味**

`crosscontam.py` 量化（标志取自每条 ZK 的字面物；**白名单**排除题面已写的要求，
因为 `strip().lower()` 同时属于 ZK1 与 g7e1 的题面）：

| 库 | 条数 | 串味总数 | g7e2 的实现 |
|---|---|---|---|
| V85-A（空库） | 0 | **0** | `s[:n] + '…'`（老实，无串味） |
| M0（全给） | 4 | **0** | `'…' + s[-n:]`（干净） |
| M1（删 ZK1） | 3 | 0 | 干净 |
| M2（删 ZK2） | 3 | 1（串入 ZK1） | 混了 `.strip().lower()` |
| M3（删 ZK3） | 3 | 1（串入 ZK1） | 混了 `.strip().lower()` |
| M4（删 ZK4） | 3 | **2（串入 ZK1 + ZK3）** | ↓ |

M4 的 `truncate_tail` 全文：

```python
def truncate_tail(s, n):
    if len(s) <= n:
        return s
    trimmed = s.strip().lower()                 # ZK1 的去重归一化
    if trimmed.startswith(('y', 'yes', '1')):   # ZK3 的开关真值表
        return s[:n] + '...'
    return s[-n:] + '...'
```

⛔ **截断题里混进了开关题的真值表。** 这不是上下文长度噪声，是内容串味。

⚠️ 样本每臂 n=1，且 M1 是 0 ⇒ 「缺一条」**不是充分条件**。
能说的只有：**0 条与 4 条时串味 0（0/9 格），缺一条时 4/12 格出现串味，且缺的正是它自己那条时最脏**。

## 5 判词

> **记忆 → 行为 的因果链是通的，而且是逐字节的；但它的强度取决于「排第几」和「齐不齐」。**

三条支撑：

1. **通**：删哪条，哪条对应的代码就变，分数就掉（4/4，Δ = −0.2~−0.8）。
   对比 V86：奖励提示 747 字送进 prompt，`why` 逐字节不变 ⇒
   **带具体字面量的记忆改得动代码，类别级建议改不动**。
2. **位置决定完整度**：ZK2 排第 2 只执行一半（逗号），排第 1 才全执行（空格）。
   ⇒ V85 的「知道≠照做」应改写为 **「排在第二就只做一半」**。
3. **缺一条会串味**：3 条的库里，模型把别题的惯例搬进本题（M4 最脏）。
   ⇒ **记忆库「缺一条」比「空库」更危险**：空库时它老实按题面做（0.2，代码干净）；
   缺一条时同样 0.2，但代码是**照着错的依据**写的。

   ⇒ **「三臂都没写过某个 token」不等于「这条记忆对这题没用」**，它可能只影响别处。

## 7 边界（⛔ 不许越界读）

1. ⛔ 不许说「记忆有用/无用」：本轮量的是**单条删除的代价**，不是总量收益。
2. ⛔ 不许说「系统会自己变强」：五臂的起跑库全是**人写的**，系统只是被审计。
3. ⛔ 不许把串味读成「模型笨」：它是**结构性**的 —— 题面挂了 4 个标号，库里只有 3 条，
   模型就失去「哪条对应本题」的锚。真正的修法是**让题面指针与库一致**，不是骂模型。
4. ⛔ 不许说「P3 证明排序比内容重要」：P3 是 n=1 的一格，且顺序与「删 ZK1」共变（混杂）。
