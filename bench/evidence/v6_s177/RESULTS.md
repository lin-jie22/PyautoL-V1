## §3 P3 判负：k=2 的 g7d3 = 0，是一个**非单调低谷**

| k | 块里有什么（位序，§7 实读） | g7d3 实现 | 分 |

| 1 | ZK1 | `return '{:,.2f}'.format(x)` | 0.2 |

## §4 逐题机制（全部从 `episodes.kind='finish'` 的实现逐字节读出）

### g7d2（去重）：**一条就够**
k=1 起就是 `norm_x = x.strip().lower()`，六个 k 全 1.0。⇒ ZK1 是该题的唯一必需项。

### g7e2（截断）：串味**先发生、后显形**
| k | 实现 | 分 | 读法 |
|---|---|---|---|
| 1 | `if len(s) <= n: return s` / `return '…' + s[-n:]` | 1.0 | 完美 |
| 2 | `s = s.strip().lower()` / `if len(s) > n: return '…' + s[-n:]` | **1.0** | **串味已发生**（ZK1 的归一化被抄进来了），但测试串全小写 ⇒ 没暴露 |
| 3 | `s = s.strip().lower()` / `return '…' + s[-(n-3):]` | **0.2** | 串味升级成**数值错误**（`n-3` 无来历） |

⭐ 这条是本轮唯一能**分开**「内容污染」与「分数」的格：**污染在 0 分损失时就已经存在**。
⇒ 「实现逐字节没变 ⇒ 知识没起作用」这个判据**不成立**（V87 §156 用过它）；
反过来「实现变了 ⇒ 知识起作用」也不成立。

### g7e1（开关）：**救它的是无关条目**
| k | 实现关键行 | 分 |
|---|---|---|
| 1（ZK3） | `if s in ('', 'false', 'off', 'no', '0', 'none'): return False` | 0.4 —— `'true'` 掉进 `return None` |
| 2（ZK3→ZK1） | `elif s in ('true', 'on'): return False` | 1.0 |
| 3/4/6 | 同 1.0 | 1.0 |

⚠️ 唯一变量是**多了一条 ZK1（去重惯例，与开关判定无关）**。
k=1 时 ZK3 已经把「'true' 算假」写在块里了，模型没照做；多一条无关的 ZK1 反而照做了。

⇒ **这一格不能用「知识」解释。** 只能是 prompt 字节串变了 ⇒ T=0 下走了另一条分支。

## §5 「无关条目」的三次翻转（本轮最强的负面证据）

| 变化 | 与题目有关吗 | 分数 | 方向 |
|---|---|---|---|
| g7e1：加 ZK1 | ❌ 去重惯例 ≠ 开关判定 | 0.4 → 1.0 | **升 0.6** |
| g7e2：加 ZK2 | ❌ 金额惯例 ≠ 截断 | 1.0 → 0.2 | **降 0.8** |
| g7e2：再加 ZK3 | ❌ 开关惯例 ≠ 截断 | 0.2 → 1.0 | **升 0.8** |

三条**全部**是与被评题无关的条目，且两条的幅度（0.8）**大于任何一条相关条目的边际贡献**。

⛔ 不能把它们读成「无关条目有害」或「有害后被后一条治好」——
方向不一致（一次升、一次降、一次升），**没有稳定符号**。
⭐ 能读的只有：**分数是「注入块的具体字节串」的函数，不是「注入了哪几条知识」的函数。**

## §7 判词

1. ⭐⭐⭐ **k 不是剂量。** 0.65 → 0.75 → 0.65 → 0.85 → 0.85 是**非单调**的；k=2→3 是负收益。
2. ⭐⭐⭐⭐ **边际曲线（借 V85 A 臂空库 0.20 作 0 点）**：`0.20 →(k=1) 0.65 → 0.75 → 0.65 → 0.85 → 0.85`。
   ⇒ **第一条值 +0.45，后面三条一共值 +0.20，中间还要掉一次。**
   这是「累积」目前能给的最诚实的账：**知识整体有用，但从第 1 条往后，边际收益落到噪声量级。**
3. ⭐⭐⭐⭐⭐ **P1 判负的根因是我预注册写漏了**：只量了「收到哪条」，没量「这题需要几条」。
   g7e1 需要 ZK3 **加** ZK1 的归一化，V87 的 M1 已经预告过（删 ZK1 ⇒ 0.4），我没读到。
   ⇒ 新纪律：**押「只留第 1 条就够」之前，先逐题查「历史臂里删掉别的条目时这题掉不掉」。**
4. ⭐⭐ **g7e2 的串味在 K2 就已发生但没掉分** ⇒ 「实现变了」不等于「知识起作用」，
   「实现没变」也不等于「知识没起作用」。V87 §156 用逐字节相同当「没通电」的判据，**需要收窄**。
5. ⛔ **不许说「k=1 更省 token 且效果相当」**：0.65 vs 0.85 差 0.20，等于噪声上限（0.1290）的 1.5 倍。
6. ⛔ 不许说「检索器能按题目排序」：`probe_order.txt` 与 `bm25` 分数显示，
   中文内容**零贡献**（`_TOKEN` 把连续中文当一个 token ⇒ 题面的「用什么符号」与 ZK2 的「用空格分隔」不相等），
   真正命中的只有 `ZK1..ZK4` 标号与 `True/False/None/y/1/n` 这类 ASCII 词。

## §8 局限（必须跟着结论走）

- 本套件四题的**题面里明写了 `（ZK1）（ZK2）（ZK3）（ZK4）`**（V83 的构造）。
  ⇒ 「k=1 时 3/4 题收到自己那条」是**标号 token 的产物**，不是语义检索的产物。
  **不能推广到题面不写标号的场景**。
- 每臂 n=1（K1/K6 各 2 跑）。P5 全同 ⇒ 地板为 0，但只覆盖了 2 个 k 值。
- E 结论边界：`V1_RECALL_K` 只截断 `core.py:2238` 的注入；模型自调 `recall`（`tools.py:203`）默认 k=6 不受影响。
  ⇒ 本轮测的是「**自动注入**够不够」，不是「检索能力够不够」。
