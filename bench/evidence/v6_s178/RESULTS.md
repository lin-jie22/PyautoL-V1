## §2 A 段：召回窗口只有题面前 **24 个 token**（本轮的核心）

`fts_query()`（`mw/memory.py:103`）：`" OR ".join(f'"{t}"' for t in toks[:24])`。
**第 25 个 token 起不进查询。** `LIKE` 回退另有一条，只看 `normalize(query)[:64]`。

| 题 | token 总数 | 钥匙 token 及位置 | 窗口内 | 实际召回 |
|---|---|---|---|---|
| g7d2 / g7d3 / g7e1 / g7e2 | 17 / 21 / 23 / 20 | `ZK?`@9~16 | 4/4 | 四条全到 |
| k01_diff_tree | 25 | `None`@**20** | 1/1 | ZK3 |
| k02_encode_cookie | 34 | `None`@**12** | 1/1 | ZK3 |
| k03_unflatten | 27 | `1`@20 `None`@**22** | 2/2 | ZK3 |
| k04_to_ini | **40** | `None`@**26** `true`@**30** `false`@**31** | **0/3** | **（空）** |

**边界验证（纯函数级，不动题面）**：`zz1..zz23 + None` = 24 token ⇒ 命中 ZK3；
`zz1..zz24 + None` = 25 token ⇒ **零召回**。两发都 ✓，边界就是 24。

⭐ 这解释了此前 12 轮都没问过的一层：**不是「送达 = token 相等」，是「先有资格进查询」**。
`g7j` 整套能送达，是因为标号落在第 9~16 位 —— **题面构造的产物，不是检索能力的产物**。
`k04` 一条都召不回，是因为 `None` 落在第 26 位 —— **主题面 40 个 token，后 16 个对检索不存在**。

## §3 B 段：k01 塌掉，机制逐字节

| 臂 | `k01_diff_tree` 实现（def 之后前 5 行） | 分 |
|---|---|---|
| E1/E2 | `result = {}` / `for key in set(a.keys()).union(b.keys()):` / `if key not in a:` / `result[f"{path}{key if path else key}"] = [None, b[key]]` | **1.0**（5/5） |
| Z1/Z2 | `if isinstance(node_a, dict) and isinstance(node_b, dict):` / `return {k: compare_nodes(path + '.' + k, node_a[k], node_b[k]) for k in set(node_a) \| set(node_b)}` / `elif node_a == node_b: return {}` | **0.0**（0/5） |

失败原文：`diff_tree({'a': 1}, {'a': 1}) == {}` ⇒ 递归版在叶子层返回 `{}`，被上层收进 `{'a': {}}` ⇒ **漏了「空子树就丢弃」的剪枝**。

⇒ 注入的那条 ZK3 是「开关惯例：y/yes/1 算真，'true' 算假，其余返回 None」。
**与 `diff_tree` 毫无关系，也不含「递归」二字。** 模型却把迭代写法换成了递归写法，并写漏一步。
⛔ 不能归因于「ZK3 的内容」。能说的只有：**这 63 个字节把这个题的分支推到了另一条路上**。

## §4 我必须自评的一条：P3 几乎没有判别力

P3 押「掉分只发生在 k01/k02/k03」，实测只有 k01 掉 ⇒ 形式上命中。
