# V93 预注册：知识的**表示形式** —— 规则 vs 示例

> 写于开跑前。跑后不改，除非按纪律登记「预注册错了」并说明错在哪。

## 0. 这一轮要回答什么

L4 的定义是「系统自己写出有用的知识」。它卡住是因为 **V87 探针 4/4 全 `NONE`**：
给模型一份满分实现，问它体现了什么惯例，它回答「题目已经明确了」。

但 V87 的输入是**成功**，「成功」与题面高度重合，没有参照系。
**失败不一样**：`assert fmt_amount(1234.5) == '1 234.50'` 里同时有输入、期望输出、
和「这条我错了」这个事实。期望输出来自测试用例 —— **异源**，不是模型自省的产物。

`probe_pairs.py` 已离线验证：从 `per_task.why` 里能**机械**抽出
`fmt_amount(1234.5) -> '1 234.50'` 这样的对，g7d3 抽出 **3/3**。

⇒ 本轮要测的是：**同一条知识，写成「规则」和写成「示例」，哪一种能被正确执行？**
若示例有效，L4 的写端就可以完全绕开模型的判断力 —— 直接从失败反馈里机械取。

## 1. 装置

套件 `bench/heldout/g7j_n4_heldout.jsonl`（`suite_sha=ade419351103`，4 题，每题 5 条断言）。
四臂 × 2 跑 × 4 题 = **32 格**。`V1_RECALL_K` 走默认 6，**`mw/` 零改动**。
唯一变量 = **起跑库的四条事实怎么写**。

### R0 空库（基线）

无事实。已知历史值 `mean=0.20`（V85 A 臂 ×3、V88 K1 臂）。

### R1 规则（= V85 B 臂，逐字相同）

```
（ZK1）去重惯例：比较前先去掉首尾空白并转小写，遇到重复时保留第一次出现的那条原文。
（ZK2）金额惯例：千分位用空格分隔，保留两位小数，负数用圆括号包裹、不写负号。
（ZK3）开关惯例：只把 y/yes/1 当成真，'true'、'on' 这类历史脏值一律算假，其余无法识别的返回 None。
（ZK4）截断惯例：超长时保留最后 n 个字符，前面加一个省略号字符 '…'（U+2026），不超长时原样返回。
```

已知历史值 `mean=0.85`（`1.0 / 0.4 / 1.0 / 1.0`，V85 B ×3、V88 K6 ×2 逐格相同）。

### R2 示例（每题取该题**前 3 条断言的期望值**）

```
（ZK1）去重惯例：['A','a'] 得 ['A']；['b',' a ','A'] 得 ['b',' a ']；['x','y','X','y '] 得 ['x','y']。
（ZK2）金额惯例：1234.5 得 '1 234.50'；-1234.5 得 '(1 234.50)'；0 得 '0.00'。
（ZK3）开关惯例：'y' 得 True；'true' 得 False；'TRUE' 得 False。
（ZK4）截断惯例：('abc',5) 得 'abc'；('abcdef',3) 得 '…def'；('0123456789',4) 得 '…6789'。
```

⚠️ **只给前 3 条**（每题 5 条里的 3 条）。硬编码上限 = 3/5 = **0.6**；写对完整规则才 5/5。
⚠️ 示例由 `mk_seed_examples.py` 从题面的 `tests` 字段**机械取**，不经人手写、不经模型。

### R3 示例·安慰剂（同形式、同标号、**内容取模型的自然默认**）

```
（ZK1）去重惯例：['A','a'] 得 ['A','a']；['b',' a ','A'] 得 ['b',' a ','A']；['x','y','X','y '] 得 ['x','y','X','y']。
（ZK2）金额惯例：1234.5 得 '1,234.50'；-1234.5 得 '-1,234.50'；0 得 '0.00'。
（ZK3）开关惯例：'y' 得 True；'true' 得 True；'TRUE' 得 True。
（ZK4）截断惯例：('abc',5) 得 'abc'；('abcdef',3) 得 'abc...'；('0123456789',4) 得 '0123...'。
```

⇒ 白送同样多的注意力（同形式、同数字密度、同标号），但**不含**本题需要的暗规则。

## 2. 判据

分母口径一律写进字段名。

| # | 押 | 形式 | 理由 |
|---|---|---|---|
| **Q1** | `R2` 的 `mean_4task` **≥ 0.85** | 三值：高/等/低 | 示例不差于完整规则 ⇒ L4 写端可以走机械提取 |
| **Q2** | `R2.g7d3` **≥ 0.8** | 数值 | R1 在同一题只有 **0.4**（V85/V88 五次一致）；若示例能到 0.8，说明**示例比规则好执行** |
| **Q3** | `R2` 两跑**逐格相同** | 全同/有翻动 | 与 R1/R0 同口径的确定性检查 |
| **Q4** | `R2.mean_4task > R3.mean_4task` 且 `R2.g7d3 > R3.g7d3` | 严格大于 | 是**内容**在起作用，不是「多了几个数字」 |
| **Q5** | `R0` 与历史 `0.20` 逐格一致 | 全同 | 装置跨轮同口径（不合格则本轮全部作废） |

**判负预案**：若 `R2 ≤ R0 + 0.1290`（形状噪声），判「示例无效」，
⇒ L4 的机械提取路线死，改走「换模型」或「承认 L4 在此架构不可达」。
**不做**：不因此去调 `k`、不改 `recall` 排序、不加新开关。

## 3. 已登记的混淆因素

1. **位序实测（`probe_block.txt`，跑前已量）**：

| 臂 | g7d2 | g7d3 | g7e1 | g7e2 | 块字数 |
|---|---|---|---|---|---|
| R1 | ZK1→ZK2→ZK4→ZK3 | ZK1→**ZK2**→ZK4→ZK3 | ZK3→… | ZK4→… | 211 |
| R2 | ZK3→ZK4→ZK2→ZK1 | ZK1→ZK3→ZK4→**ZK2** | ZK3→… | ZK3→… | 290 |
| R3 | ZK3→ZK4→ZK2→ZK1 | ZK1→ZK3→ZK4→**ZK2** | ZK3→… | ZK3→… | 307 |

⚠️⚠️ **R2/R3 的 g7d3 里，正确知识 ZK2 排第 4（最后）**，而 R1 是第 2。
V91 已证 g7d3 对 **ZK2 的位序**敏感（+0.2），所以 **Q2 若判负，不能直接归因于「示例不好」**。

处理方式（不新增臂，用判据拆开）：
- **Q2 拆成两个方向**：R2.g7d3 **≥0.8** ⇒ 判「示例好，且位序劣势被克服」，强结论；
  R2.g7d3 在 **0.4~0.6** ⇒ 判 **UNKNOWN**（示例与位序分不开），不支持任何方向的结论；
  R2.g7d3 **≤0.2** ⇒ 判「示例不但没帮忙，还在最差位序下更差」。
- 其余三题 R2 的 ZK 也在第 4 位（最差），若仍拿 1.0，那是**位序劣势下仍有效**，结论更强。

2. **块字数不同**：R1 211 / R2 290 / R3 307 字。
   R2 vs R3 只差 17 字（290 vs 307）且位序**完全一致** ⇒ Q4（R2 > R3）是干净的**内容对照**。

3. **前 3 条示例 = 部分规格** ⇒ 剩余 2 条是隐藏的，硬编码上限 0.6。
   ⭐ 有意为之：测的是「从部分示例能不能推出完整规则」。

4. **R2/R3 的文本由脚本从题面 `tests` 取** ⇒ 同一把尺子的用例既当示例又当考试。
   ⚠️ 这是 test-leakage 的合法形态（真实系统就是拿失败反馈学），但**必须在结论里写明**：
   本轮证明的是「从反馈学得会」，不是「无反馈也能学」。
