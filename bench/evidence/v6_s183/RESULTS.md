## 3. 三件事被分开

### 3.1 长度有害：C3 的 g7d3 = **0.0**（纯规则 0.4）

只把每条事实从 43/40/63/56 字拉到 93/85/91/98 字（块 211 → 376），
g7d3 就从 0.4 **掉到 0**。⇒ V91 §160.3 的「L2 让 g7e1 掉 0.6」不是偶然，
**加字本身在压低执行质量**，而且能压到 0。

### 3.2 示例逐题**符号相反**

以 C3（同长度、无示例）为基线：

| 题 | C3 | C1（+对示例） | Δ |
|---|---|---|---|
| g7d3 | 0.0 | **1.0** | **+1.0** |
| g7e2 | 1.0 | **0.2** | **−0.8** |
| g7d2 | 1.0 | 1.0 | 0 |
| g7e1 | 1.0 | 1.0 | 0 |

⇒ 「示例有用 / 有害」都不能说。**它是逐题定符号的。**

### 3.3 g7e2 的机制：示例把「保留 n 个」读成「总长度 n」

逐字节（`probe_impl.txt`）：

| 臂 | `truncate_tail` 实现 | 分 |
|---|---|---|
| C3（规则+填充） | `return '…' + s[-n:]` | **1.0** |
| C1（规则+**对**示例） | `return '…' + s[-(n-3):]` | 0.2 |
| C2（规则+**错**示例） | `return '…' + s[-(n-3):]` | 0.2 |

⚠️⚠️ **正确示例和错误示例得到了同一个错误实现。**

示例是 `('abcdef', 3) 得 '…def'`。输出看起来 4 个字符，而 n=3 ⇒
模型去凑「总长度应该等于 n」⇒ 保留 `n-3` 个。规则那句「保留最后 n 个字符，前面加省略号」
反而被覆盖了。

⇒ **示例不是「更多的信息」，是「另一种信息」，而且可以覆盖规则的精确性。**

## 4. 对 L4 的意义（本线第一次拿到可执行的写端规则）

不存在「一种万能表示」。但**该用哪种是代码可判的**：

| 判据（机械） | 表示 |
|---|---|
| 函数体只吃一个参数、且期望输出里**没有**与输入数值有算术关系的长度 | 规则 + **示例** |
| 存在整数参数、且 `len(期望输出)` 与该参数接近 | **只写规则**（示例会引入歧义） |

理由：`fmt_amount(x)` 的示例 `'1 234.50'` 里每一个字符都是规格本身；
`truncate_tail(s, n)` 的示例 `'…def'` 里「n 到底指什么」反而被示例搅浑了。

⭐ 这条规则**不需要模型判断**，也不需要"什么值得写"的主观判断 ——
它是从 `tests` 的语法结构上算出来的。⇒ 这是绕开 §4.4「同源自评」墙的第一条具体路径。
