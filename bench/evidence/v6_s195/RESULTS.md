# V106 结果：适应度地形是**单向棘轮** —— 字符级只能往下，语句块级才能往上

**一句话**：从 0.4 的 `075b4099` 出发，**596 个 1-字符-编辑邻居里 0 个比它高**（538 个更低、57 个持平）；
而把**最后一行整行**换成满分实现的那一行，**一步就到 1.0**（2/76 组合）。
⇒ **梯度只存在于语句块粒度，不存在于字符粒度。**

- 轮次：V106（`bench/evidence/v6_s195`）
- 模型调用 **0 次**，网络 **0 次**；判据 = `bench/scorers/code_exec.py`（每候选一次子进程，**不复刻判据**）
- 耗时 5 分 55 秒，3 并发，**1694 次判分**
- 读数：`python3 bench/evidence/v6_s195/landscape.py`（全文 `READINGS.txt`、原始 `landscape.json`）

## 二、字面读数（§2/§3 完整分布）

### 2.1 从 0.4 出发：**没有一条上坡路**

```
075b4099（起点 0.4）：合法邻居 596 个　分布 0.4×57  0.2×204  0×335
  ⇒ 邻域最高分 = 0.4　比起点高的邻居：0 个
```

⭐ 596 个里 **538 个更低（90.3%）**、57 个持平（9.6%）、**0 个更高**。
⇒ 在字符粒度上，这个点是一个**纯下坡点**：任何单字符改动要么打坏它，要么什么都不改。

### 2.2 从 1.0 出发：**台地很宽，边缘很陡**

```
8089eee6（起点 1.0）：合法邻居 722 个　分布 1×62  0.6×199  0.4×46  0.2×7  0×408
  仍 1.0：62（8.6%）　掉到 ≤0.6：660（91.4%）　掉到 0.0：408（56.5%）
```

⭐ **两个方向都值得记**：
- **台地宽**：62 个互异的 1-编辑邻居**仍然是 1.0** ⇒ 满分盆里至少有 **63 个**互异实现，
  而档案里 42 格只出现过 **2 个**（V105）。⇒ **满分实现极度欠采样。**
- **边缘陡**：91.4% 的扰动直接掉到 ≤0.6，56.5% 掉到 0.0。

## 三、块级：唯一存在上坡路的地方

```
075b4099（0.4）76 组合 ⇒ 到 1.0 的 2 个：
   ✅ 075b4099:L4 <- 8089eee6:L4  ⇒ 1.0
   ✅ 075b4099:L4 <- 309f1027:L4  ⇒ 1.0
419ec792（0.4）76 组合 ⇒ 到 1.0 的 2 个：同上（L4 <- 两个满分实现的 L4）
5755e033（0.6）46 组合 ⇒ 到 1.0 的 0 个，最高 0.2
```

- `L4` 就是 `return fmt_str` 那一行。两个 1.0 实现的 `L4` 是 `return fmt_str.replace(',', ' ')`。
  ⇒ **一步**、**2/76 = 2.6%** 的组合命中。
- ⛔ 但 `5755e033`（0.6）**一步都上不去，反而最高只剩 0.2** ⇒ 它不是「差一行」，
  是**结构不同的另一个盆**（用 f-string 与 `.replace('-', '( ')` 的写法），搬行只破坏它。

⇒ 地形不是单一梯度，是**分块**的：有的盆「差一行」，有的盆「差一个写法」。

## 四、这一轮立住的结构性结论

> **在代码空间里，字符级扰动是单向棘轮（只降不升），上坡只发生在语句块粒度；
> 1.0 是一片很宽但边缘很陡的台地，而 0.4 的点在台地之外、无上坡可走。**

三条推论，每条都有直接读数：
1. **「自己变强」不可能靠微调字符实现** —— 596 个邻居 0 个上升（P1）。
2. **必须靠「搬运语句」** —— 唯一的上升路径是整行替换（P3），且来源是**别的实现**。
3. **搬运的来源只能是实现库** ⇒ 这正是「累积」该起作用的地方：
   库里有 1.0 的实现，0.4 的实现才有一行可搬；库里没有，就永远上不去。
   ⭐ 这与 V105 的「42 格只 9 个实现」接上了：**库的覆盖度直接决定可修复性。**

## 五、自踩与限制

1. ⛔ **`diff_at_1` 这个字段是恒真的**：我算的是「mutant 代码 != 原代码」，而按定义所有 mutant 都不同。
   写在 `READINGS.txt` 里像一条读数，实际上是**恒真**（纪律 6 的老毛病，第 N 次）。
   ⇒ 真正有意义的写法是「62 个互异实现仍是 1.0」，这一条成立且不恒真。
2. ⚠️ **缩减了测点**（`PREREG.md` §7）：字符级只跑了 `075b4099` 与 `8089eee6`；
   原计划的 `419ec792`/`5755e033`/`309f1027` 没跑。⇒ P1/P2 只在这两个点上成立，**不许推广**。
3. ⚠️ **`compile()` 过滤丢掉了 73.7% 的变异体**（2260 → 596）。
   抽 20 个验证 code_exec 确实给 0.0（20/20），但这是**抽样**，不是全部。
4. ⚠️ **P3 的两条中奖路径都是「搬 return 行」**，它接近「抄一份更好的实现」。
   ⛔ 不许把它说成「系统学会了修复」——它做的是**跨实现搬运**，而供体是同一道题、同一个人的库。
   真检验应是「能不能从**别的题**的实现里搬一行过来」（V107）。
5. ⚠️ 只做了 **1-编辑** 邻域。2-编辑邻域里可能存在上升路径（比如 `",".replace` 需要两次编辑）。
   ⛔ 不许把「1-邻域无上坡」读成「永远上不去」。
