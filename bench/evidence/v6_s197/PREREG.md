# V108 预注册：结构能否迁移 —— 把私有名字去掉再搬

> 目录 `bench/evidence/v6_s197/`。零模型、零网络。
> 判据 = `bench/scorers/code_exec.py`（每候选一次子进程）。

## §0 承 V107

V107 判死了一件事：**整行作为迁移单位，必然带着题目私有的名字**
（`fmt_str` / `seen` / `flag` / `s` 各不相同）⇒ 跨题 56 个能编译的候选**全部低于起点**，命中 0。

但那一轮**只否掉了「整行原样搬」**。剩下没试、也是唯一有意义的问法：
**把私有名字去掉之后，剩下的「结构」能不能迁移？**

## §1 装置

- **目标**：`075b4099`（0.4），5 行。
- **捐赠池**：别的 3 道题（`g7d2_dedupe_keep` / `g7e1_parse_flag` / `g7e2_truncate_tail`）的 17 个实现。
- **改名（alpha-renaming）**：对每个捐赠实现
  1. `ast` 解析出它的 `FunctionDef`，取**形参名**与**函数体内被赋值的局部名**；
  2. 形参 → `x`；**若局部名恰好 1 个** → `fmt_str`；**若 ≥2 个** ⇒ **跳过该捐赠者**（映射不唯一，不许硬凑）；
  3. 用 `tokenize` 只替换 `NAME` token（不碰字符串里的字面量）。
- **算子**：与 V106/V107 相同的**盲整行替换**（目标第 `j` 行 ← 改名后的捐赠第 `k` 行）。
- **过滤**：`compile()` 不过的丢弃。

## §2 判据（跑之前写死）

### R1｜改名后跨题能否到 1.0（核心）

- 押：**能，命中 > 0**。
- 理由（跑前给出）：V107 的 0 命中里，最主要的一类是 `NameError`（名字不存在）。
  改名把这个主因**直接消掉**，所以至少应该出现「编译通过且不崩」的候选；
  是否到 1.0 取决于别的题里有没有 `X.replace(A, B)` 这种结构。
- 若命中 = 0 ⇒ **结构也不可迁移**，L4 的搬运路线到此为止，必须改成「重新发明」。

### R2｜编译通过率

- 押：从 V107 的 **56/225 = 24.9%** 上升到 **> 50%**。
- 理由：名字错是 `SyntaxError` 与 `NameError` 之外的最大一类失败源；改名后应显著改善。
- ⚠️ 若没上升 ⇒ 说明「名字」不是主要失败源，V107 的机制解释要重写。

### R3｜命中要分「结构」还是「常量巧合」

对每一条命中，把它与两个满分实现的 `L4` 对比：
- **除变量名外常量也一致**（即改名后与满分 `L4` 逐字相同）⇒ 记为 **常量巧合**（搬过来的其实是题目惯例）；
- **常量不一致却仍 1.0** ⇒ 记为 **结构迁移**（这才是真正的「学会」）。
- 押：**两类都会出现**，且「常量巧合」不会超过 2 条（因为 `,`→`' '` 这个组合很特定）。

### R4｜不要只看命中

- 必须报**全部**候选的分数分布（含 0.0 与 0.2 的条数），不许只报命中数。

## §3 判负预案

| 读数 | 该怎么写 |
|---|---|
| R1 = 0 | ⛔ **结构也不可迁移** ⇒ 「搬运」这条路整体作废，L4 只能靠「重新发明」。这是本轮最重的负结果，要写清楚 |
| R2 未上升 | 「名字」不是主要失败源 ⇒ V107 §175.4 的机制段要重写 |
| R3 全是常量巧合 | ⭐ 可迁移的不是「结构」而是**题目惯例的常量**（`","` / `" "`）⇒ 那「累积」该攒的是**惯例表**，不是实现库 |
| R3 出现结构迁移 | ⭐ 第一次出现「跨题搬结构能修好新题」的读数，逐条列原文 |

## §4 不许做的事

- ⛔ 不许把「改名」做成「按目标变量名硬套」——只能按捐赠自己的形参/局部名做**自洽映射**。
- ⛔ 局部名 ≥2 的捐赠者不许硬凑（跳过并报数）。
- ⛔ 不许只报命中数，必须报全分布（R4）。
- ⛔ 不许把「改名后仍 0 命中」说成「V107 白做」—— V107 判的是整行，本轮判的是结构，两件事。
