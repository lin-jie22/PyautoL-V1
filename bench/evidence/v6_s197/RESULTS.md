# V108 结果：把名字消掉之后，横在中间的是**语义** —— 结构也不可迁移

**一句话**：V107 的跨题候选里 **61% 死于 `NameError`（名字不存在）**；
把名字统一改掉之后，**命中仍然是 0**，最高分仍只有 **0.2**。
⇒ 名字可以消掉，但**「这行算的东西对不对」消不掉**。
⇒ 「搬运」路线到此为止：能跨题的不是结构，是**题目惯例的常量**。

- 轮次：V108（`bench/evidence/v6_s197`）
- 模型调用 **0 次**，网络 **0 次**
- 读数：`rename_transfer.py`（结构迁移穷举）+ `why_v107.py`（失败原因分解），全文 `READINGS.txt`

## 二、⛔ 我把 R2 的判据形态写错了（升纪律 47）

PREREG 的 R2 写的是「改名后编译通过率应从 24.9% 升到 >50%」。

**这条判据在原理上就测不到东西**：改名改的是**运行时绑定**，而
「未定义的名字」在 Python 里**语法完全合法** ⇒ `compile()` 根本不看它。
⇒ 改名**不可能**提高编译通过率，R2 从一开始就是个空判据。

✅ 正确的测法（事后补的 R5）：看 `code_exec` 返回的 `why` 里是哪种异常。
读数：**`NameError` 占 34/56 = 61%** ⇒ V107 那句「名字要么不存在」是**对的**。

→ **纪律 47：判据必须能「变」**。——写一条判据前先问：**我改的那个变量，会不会影响这个观测量？**
不影响就别写。（这与纪律 36「与零假设同值的格不是证据」是一对：36 管「读数不动」，47 管「读数动不了」。）

改名后的捐赠行是些什么（前几条）：

```
'def parse_flag(fmt_str):'
'    fmt_str = fmt_str.strip().lower()'
"    if fmt_str in ['y', 'yes', '1']:"
'        return True'
```

⇒ 一眼能看出问题：**这些行在 `fmt_amount` 的上下文里没有意义**。
`return True` 不是金额，`if fmt_str in [...]` 判的是 flag 不是数字。
**名字改对了，语义完全不对。**

## 四、机制：跨题搬运的失败是**两层**的

| 层 | 证据 | 能不能消掉 |
|---|---|---|
| **名字**（`NameError`） | V107 的 56 个候选里 **34 个（61%）** 死在这 | ✅ 能（本轮做了，仍 0 命中） |
| **语义**（`AssertionError` 算错） | **17 个（30%）** | ⛔ **不能**：搬过来的语句算的不是这件事 |

⭐ 关键：**把 61% 的名字问题消掉之后，剩下的 39% 是「算错了」，而它一格都没改善**（最高仍 0.2）。
⇒ 跨题可迁移的**不是「结构」**，而是**「惯用法 + 这道题的常量」**（`, → ' '`）。
而常量恰恰是**题目私有的知识** —— 一换题就失效。

⇒ 这就回到了 V107 的结论，但这次是**机制级的**，不是统计级的：

> **能跨题搬运的东西，只剩「题目惯例的常量」；而常量正是换题后无效的那部分。**
> ⇒ **实现库里攒的东西，天然只对自己那道题有效。**

## 五、对主线的意义

V105 → V106 → V107 → V108 四轮连起来是一条清晰的因果链：

| 轮 | 读数 | 定理化的说法 |
|---|---|---|
| V105 | 42 格只 9 个实现；满分实现在 4 组里 0 次 | 候选空间太小 |
| V106 | 字符级 596 邻居 0 上升；块级 1 个修补点 | 上坡只有一个动作 |
| V107 | 跨题整行 56/56 全坏 | 那个动作**只对本题目录**有效 |
| **V108** | 名字占 61%，消掉后仍 0 命中 | 剩下的 39% 是**语义**，不可搬 |

⇒ **「累积实现库 → 迁移到新题」这条 L4 路径，在这套装置上是堵死的。**
⛔ 但这不是「L4 不可能」，而是：**可迁移的单位是「惯例 + 常量」，而现在的管线里没有任何一步
把「惯例」从实现里抽出来、也没有任何一步检查它换题后是否仍然成立。**

⭐ 这条恰好解释了 V82~V87 那一整片负结果：那些轮次试图把惯例写成自然语言再读回来，
**方向是对的，但缺的那一步是「验算惯例在新题上还成立吗」** —— 而 V104 的**留一性质法**
正是这一步的可执行形式（给定判据集 + 实现集，剔掉一条看判别是否崩）。

## 六、自踩与限制

1. ⛔ **R2 判据写坏了**（见 §二），升纪律 47。这是本轮最大的错，比 0 命中还重要。
2. ⚠️ **改名是退化的**：8 个改名成功的实现里，多数「唯一局部名」**就是形参本身**
   （如 `flag = flag.strip()`），于是映射 `{flag: 'x', flag: 'fmt_str'}` 塌成 `{flag: 'fmt_str'}`，
   `def parse_flag(flag)` 变成 `def parse_flag(fmt_str)` 而不是 `def parse_flag(x)`。
   ⇒ 这不是干净的 alpha-renaming，如实登记。它不影响结论（那 19 个候选仍然 0 命中），但要说清楚。
3. ⚠️ **捐赠池很薄**：17 个实现里只有 8 个能唯一映射，改名后只剩 **17 条互异行**。
   ⇒ 「结构不可迁移」只在这 8 个实现上成立，**不许推广成「跨题永远不行」**。
4. ⚠️ 只做了**整行**替换。表达式级/片段级迁移（如 `.replace(A, B)` 这种调用）**没做** ——
   而按 §四 的机制，那才是唯一可能有用的单位。这是 V109 的方向，不是本轮的结论。

## 七、下一轮（V109）方向：迁「惯用法」，不迁「语句」

按 §四 的机制，下一个该测的不是更大的单位，而是**更小的、带常量的单位**：

- **单位**：把捐赠代码里的**方法调用链**（如 `X.replace(a, b)`、`X.strip().lower()`）抽出来，
  连同它的**字面常量**一起，作为「惯用法」入库；
- **问法**：同一条惯用法在**几道题**上成立？（这道题 `, → ' '`，那道题是不是也 `, → ' '`？）
- **判据**：一条惯用法如果在 ≥2 道题上都让分数上升 ⇒ **它是真的可迁移的**（这才是「累积」的实证）。
  若每条惯用法只在 1 道题上有效 ⇒ **「累积」只能加速同一道题，不能帮新题**，L4 到此为止。

⛔ 预告陷阱：不同题的「正确常量」大多不同，命中 ≥2 题的概率很低。
⇒ 这条判据**大概率判负**，但它是决定性的：判负就等于把「累积→迁移」这条路正式关掉，
而不是像现在这样一直悬着。
