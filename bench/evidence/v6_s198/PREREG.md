# V109 预注册：惯用法能不能跨题 —— 「累积」到底攒的是什么

> 目录 `bench/evidence/v6_s198/`。零模型、零网络（只需重算 26 个实现的分，约 12 秒）。

## §0 承 V108 的机制

V108 的结论：跨题失败是两层的 —— **名字 61%（可消）、语义 30%（不可消）**。
改名之后仍 0 命中 ⇒ 可迁移的**不是语句、也不是结构**，而是
「**惯用法 + 这道题的常量**」（`, → ' '`）。

那么下一个问题就是决定性的：
> **一条惯用法，能不能在两道以上的题上都抬分？**

- 能 ⇒ 「累积惯用法」是真路径，L4 有实证落点；
- 不能（每条只对自己那道题有效）⇒ **累积只能加速同一道题**，L4 的「迁移」正式关闭。

## §1 装置

- **语料**：档案里全部 4 道题、26 个互异实现（`g7d2_dedupe_keep` / `g7d3_fmt_amount` /
  `g7e1_parse_flag` / `g7e2_truncate_tail`），各自用**本题的 tests** 重算分数。
- **惯用法抽取**（规则，非人工）：
  - 方法调用链：正则 `\.(\w+)\(([^()]*)\)` ⇒ 惯用法 = `.(方法名)(参数原文)`，
    参数会被**保留**（`replace(',', ' ')` 与 `replace('-', ' ')` 是两条不同的惯用法）；
  - 格式说明符：正则 `\{:[^}]*\}` ⇒ 惯用法 = 该格式串本身（`{:,.2f}` / `{: .2f}` …）。
- **抬分的定义**（对某题 `T` 与惯用法 `I`）：
  - `T` 的实现里，**含 `I`** 的组均值 > **不含 `I`** 的组均值，且两组都非空 ⇒ 记为「`I` 在 `T` 上抬分」。
- ⛔ **这是相关，不是因果。** 本轮只做筛选，因果留到干预实验（V110）。

## §2 判据（跑之前写死）

### S1｜有没有惯用法能跨 ≥2 道题抬分（核心）

- 押：**没有，命中 0 条**。
- 理由：4 道题做的事不同 —— `dedupe_keep` 去重保序、`fmt_amount` 金额千分位（含 `, → ' '`）、
  `parse_flag` 真假值解析（`.strip().lower()` + 成员表）、`truncate_tail` 截尾。
  惯用法要么带题目私有常量（`','` / `' '`），要么是通用到不区分好坏的（`.lower()`）。
- 若命中 ≥1 ⇒ 必须把**那条惯用法、它抬分的那几道题、各自的均值**逐条列出。

### S2｜至少有一条在单题上抬分

- 押：**是**（否则「惯用法」这个单位本身没有信息量，方法失败）。

### S3｜有没有**负迁移**（一题抬、另一题掉）

- 押：**有**。
- 理由：`replace(',', ' ')` 在 `fmt_amount` 是正解；搬到 `parse_flag` 会把逗号变空格而破坏输入。
- 若成立 ⇒ 「累积」不只是没用，还可能**有害** —— 这决定 V110 的干预实验必须带「否决机制」。

## §3 判负预案

| 读数 | 该怎么写 |
|---|---|
| S1 命中 0 | ⛔ **「累积惯用法 → 迁移新题」正式关闭**。写明：累积只能加速同一道题，L4 的迁移路线到此为止；⛔ 不许说「L4 不可能」，只说「以惯用法为单位的迁移不可能」 |
| S1 命中 ≥1 | ⭐ 逐条列出；并立刻检查**是不是同一份实现共享多条惯用法**造成的伪相关（混杂） |
| S2 = 否 | 方法失败：惯用法粒度太细或抽取规则不对，本轮结论作废 |
| S3 = 无 | 「负迁移」不存在 ⇒ 搬运是单调安全的，V110 可以不设否决机制 |
