# V114 预注册（**跑之前落盘**，第 192 轮）

> 目录：`bench/evidence/v6_s203/`
> 零模型、零网络。16 个非满分实现 × 1 次判分 ≈ 8 秒。

## 0. 承 V113

V113 量到：55 个失败格里只有 **8 格是 A_sub**（去重后只有一个单字符替换），且全在 g7d3。
本轮问：**把这 8 格里读出的动作自动合成成代码，能不能真的修好？**

这是「诊断 → 治疗」的转化率，也是 V113 唯一能接上「自改」的地方。

## 1. 装置（全自动，无人工挑选）

1. 从 V113 的 `failures.json` 取每个实现全部 **A_sub** 格的 `(a, b)`。
2. 去重后，把每个 `(a, b)` 依次套成 `(EXPR).replace(a, b)`（EXPR = 每条 `return` 的表达式，
   复用 V110 的 `inject_returns`）。
3. 重算分。
4. ⛔ **不手工挑动作、不手工改代码**：动作全部来自 diff，位置全部来自「套在 return 上」。

## 2. 判据

| 编号 | 命题 | 押 | 判负后果 |
|---|---|---|---|
| **W1** | 至少有一个非满分实现被**自动合成**修到 1.0 | **有** | 若 0 个 ⇒ 「从 diff 反推」只停在诊断，这条通道彻底关闭 |
| **W2** | 转化率（被修好的 / 全部非满分实现）**≤ 20%** | **是** | 若 >20% ⇒ 诊断到治疗的转化比预期高，V113 的「形状」结论要放宽 |

## 3. 分母

- W1 分母 = **非满分实现数**（16）。
- W2 分母 = **16**。
- ⛔ 逐个实现报分数，不许只报总数。

## 4. 已知陷阱

1. `(EXPR).replace(a, b)` 会**改所有** return 的返回值；多 return 的实现可能被连锁改坏。
2. 对返回非字符串的实现（g7d2/g7e1），本来就没有 A_sub 动作 ⇒ 它们**必然不动**，
   这会稀释转化率。⇒ 必须**分题报**，不许合并成一个数就说「转化率低」。
3. `075b4099` / `419ec792` 修到 1.0 是**已知答案**（V100 就搜到过）⇒ 它只证明「通道通」，
   不证明「搜索能力」。⛔ 不许读成「系统会修 bug」。
