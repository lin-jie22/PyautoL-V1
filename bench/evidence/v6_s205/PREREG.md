# V116 预注册：把「输入级」做成唯一变量

> 落盘时间：跑前（脚本未写）。⛔ 跑后任何改动单列「事后更正」，不许覆盖本节。

## 0. 接的是哪条线

V115 量出：**L1 输出级动作 5/5 停 0.8，L3 输入级动作 5/5 到 1.0**。
但那两臂是**我手工施加的两组动作**。⇒ 这只能证明「两组动作效果不同」，**不能证明差异来自「看不看得到 test 实参」**。

V116 要把它变成**同一搜索器、同一动作模板集、同一预算**，唯一变量 = **候选词的原料里有没有 test 源码**。

## 1. 装置

零模型、零网络。判分 = 现有 `bench/scorers/code_exec.py`（⛔ 不造新尺子、不造新题集）。
语料 = V111 语料里 `g7e1_parse_flag`（5 实现）+ `g7d2_dedupe_keep`（2 实现），与 V115 同一批，可比。

### 1.1 搜索器（两臂完全相同）

爬山：从失败实现的基线分出发，每轮生成**全部 1-编辑候选**，判分，**只接受严格上升**，无上升即停并报 `EXHAUSTED`。

### 1.2 动作模板集（由 AST 决定位置，与题无关；两臂完全相同）

| 模板 | 位置 | 候选 |
|---|---|---|
| **T1 常量替换** | 每个 `return <Constant>` | 换成 `S ∪ {None, True, False}` 里的任一个 |
| **T2 容器插入** | 每个 `Compare.in` 的 `[...]` / `(...)` 容器 | 追加 `S` 里的任一个 |
| **T3 返回值包装** | 每条 `return EXPR` | `(EXPR).lower()` / `.strip()` / `.strip().lower()` |
| **T4 比较主语包装** ⭐跑前补 | 每个 `Compare` 的 `left` 是 `Name` | `left.lower()` / `.strip()` / `.strip().lower()` |

### 1.2.1 ⚠️ 跑前更正（脚本未写、未跑，此处如实登记）

写 PREREG 时只列了 T1~T3。落脚本前对着源码核了一遍，发现 **T1~T3 覆盖不到 `g7d2` 需要的「key 归一化」**：
`74aa48d8` 的 `normalized_x = x.lower()` 既不是常量替换、也不是容器插入、也不是 `return` 包装。
⇒ 补 **T4 比较主语包装**（对 `Compare.left` 做包装）。T4 两臂完全一致，不引入偏置。

同时更正 **W4 的措辞**（原写「都到 1.0」，预设了模板集的能力上限，不是判据该管的事）。
W4 改成：**两臂在 `g7d2` 上逐候选、逐分数完全一致**；**不预设是否到 1.0**。
理由：W4 要验的是「开关有没有副作用」，不是「模板集够不够强」。

### 1.3 唯一变量：`S`（候选词表）

| 臂 | `S` 的构成 |
|---|---|
| **OFF** | 实现代码里的**字符串字面量** ∪ **题面**的 ASCII token |
| **ON** | OFF 的全部 ∪ **test 源码**的 ASCII token |

⛔ `S` 里只收「ASCII 标识符样式、长度 ≤ 6」的 token，**不收中文**（中文当数据项插入容器是无意义的，会白烧判分）。这条限制两臂一致。

## 2. 跑前已查证的原料事实（不是猜测）

`g7e1_parse_flag` 的 ASCII 词表：

```
题面     : {false, none, parse_flag, s, true}
test     : {assert, false, is, maybe, none, on, parse_flag, true, y}
差集     : {assert, is, maybe, on, y}
```

⛔ **关键**：`true` **题面里就有**（「转成 True / False / None」）⇒ OFF 臂拿得到。
⛔ **`on` 只在 test 源码里** ⇒ OFF 臂拿不到。

⇒ 预计 `|S_off| ≈ 11`、`|S_on| ≈ 15`，**ON 相对 OFF 的必要新增词只有 1 个：`'on'`**（其余 4 个是噪声）。

## 3. 押注（三值：成立 / 不成立 / UNKNOWN）

- **W1（结构）**：OFF 臂在 `g7e1` 的 **5 个实现上全部 `< 1.0`**，且最优分 = **0.8**。押**成立**。
- **W2（结构）**：ON 臂在 `g7e1` 的 **5 个实现上全部到 1.0**。押**成立**。
- **W3（信息论）**：**`'on'` ∈ `S_on \ S_off`**，且它是 `g7e1` 到 1.0 的**必要新增词**（在模板集内）。押**成立**。
- **W4（对照，本轮最要紧）**：在 `g7d2` 上**两臂逐候选、逐分数完全一致**（`g7d2` 需要的动作**不消耗任何词**）。⇒ **开关的效应只出现在「原料不在输出/题面里」的题上**。押**成立**（⚠️ 不预设是否到 1.0，见 §1.2.1）。
- **W5（元认知）**：搜索器在候选耗尽时**能报 `EXHAUSTED`**，且 OFF 臂报的时刻**恰好在到达 0.8 之后**（不是提前放弃）。押**成立**。
- **W6（⭐ 可能修正 V111）**：**0.8 档至少有 2 个不同的行为盆** —— `[T,T,T,T,F]`（掉 t4）与 `[T,T,T,F,T]`（掉 t3），**分数相同、行为不同**。
  ⇒ 若成立，则 **V111「非零档全单射」的作用域必须收窄到「那 26 个实现的语料内」，不能外推到搜索空间**。押**成立**。

## 5. 判据能不能「变」（纪律 47 预检）

- W1 能变：OFF 臂若到 1.0，则「原料不在输入里」为假；若停在 <0.8，则 T3 也有贡献。
- W4 能变：g7d2 若两臂不同，则变量不唯一（可能 `S` 大小本身有影响）。

## 6. 已知风险与自我限制

1. ⛔ **模板集 T1/T2/T3 是我写的**。两臂相同 ⇒ 对**比较**无偏，但**不能**据此说「搜索器能自己想到动作」。诚实口径：**模板 3 条，人写的**。
2. ⛔ **W3 的「必要」只在模板集内成立**。模板集外（如 `s.startswith('o')`）可能有别的路，本轮不覆盖。
3. ⚠️ **`S` 的构造规则（ASCII、长度 ≤ 6、不收中文）两臂一致，但它本身是我定的** —— 若这条规则改变，`|S_off|` 会变，W1 的「停在 0.8」可能变。已登记。
4. ⚠️ **判分次数可能上千**，须缓存；若超时或中断，**以已判分的部分为准并如实报分母**，不许补。
5. ⛔ **不许把「OFF 臂拿不到 'on'」说成「系统有自知之明」** —— 它只是拿不到。
