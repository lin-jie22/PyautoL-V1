# V122 预注册：加一道硬预算闸 —— 把「省次数」变成「做得成」

**日期**：2026-11-15（跑前落盘）
**装置**：`bench/evidence/v6_s211/`。零模型、零网络、零子进程。
判据 = 现有 test 同一批。语料 = 现有 26 实现 / 4 题（`n_impl_parseable = 25`）。

## §0 为什么要加预算

V121 证明「写记忆 → 读回 → 用上」能把总判分次数从 **1381 降到 588（−57.4%）**，
但**三臂都 21/25 到 1.0** ⇒ 收益只是**效率**，不是**能力**。
⇒ 只有加一道**硬预算闸**，才能回答「累积有没有让它做成以前做不到的事」。

## §1 装置

- 同一搜索器、同一动作空间（V120 的 C1）、同一 `k=2`、同一早停规则（一到 1.0 就停）。
- **新增唯一变量：硬预算 `B`**。`n_eval` 达到 `B` 立即停，返回「到目前为止见过的最高分」。
- 两臂 = V121 的 COLD 与 WARM（记忆从 `v6_s210/memory.json` 读，**留一法**）。
- 记 `s1_at_budget` 与 `reached_1`。

## §2 押注（全部结构性，含精确数字）

依据 V121 `§3` 的 `n_eval`（到 1.0 所需次数）：

| 实现 | COLD | WARM |
|---|---|---|
| `g7e1` `1aa5099d` | 313 | **119** |
| `g7e1` `37a4f17f` | 298 | **114** |
| `g7e1` `f2d1efa6` | 268 | **104** |
| `g7e1` `a579b07a` | 342 | **129** |
| 其余 21 个 | ≤ 59 | ≤ 59 |

⇒ 取 **`B = 120`**：

- **W1**：COLD 在 `B=120` 下到 1.0 的实现数 = **17/25**
  （21 − 4 个 `g7e1` 卡点，它们分别需要 313/298/342/268 次）。押**精确等于 17**。
- **W2**：WARM 在 `B=120` 下 = **20/25**（21 − `a579b07a`，它需要 129 > 120）。押**精确等于 20**。
- **W3**：翻盘的实现**恰好**是 `{1aa5099d, 37a4f17f, f2d1efa6}`，
  且 `a579b07a` **不翻盘**（129 > 120）。押**集合精确相等**。
- **W4**：WARM 的「到 1.0」集合 ⊇ COLD 的（不许有任何实现因记忆而掉出预算）。押**成立**。
- **W5（剂量）**：`B` 从 60 加到 400，WARM 与 COLD 的差值不是单调增 —— 差值在某个区间达到峰值后
  **收敛到 0**（因为预算够大时两边都能做完）。押**差值在 B≥400 时 = 0**。

## §3 判决口径

- 「到 1.0」= `s1_at_budget = 1.0`（严格等于）。
- 分母：`n_impl_parseable = 25`。⛔ 不许把基线已 1.0 的算成「被预算救的」——
  **W1/W2 报的是「到 1.0 的总数」，同时另报「其中被预算卡住又救回来的」**。
- ⛔ 不许把 W1/W2 的差读成「记忆让它变强了」而不看 W3 的集合是否精确。

## §4 不能读成什么（跑前写死）

1. ⛔ **不是「系统有了新能力」**：翻盘的 3 个实现，**冷启动在无限预算下也能做到**（V120 已证 21/25）。
   预算闸测的是「**在资源约束下能否做成**」，不是「原理上能否」。
2. ⛔ **不是「记忆是通用的」**：记忆只覆盖「兄弟用过同一动作」的情形（V121 §4）。
3. ⛔ **V79 那堵墙依然不碰。**
