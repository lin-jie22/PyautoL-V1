# V135 预注册（跑前落盘，2026-11-15 16:40）

## §0 V134 把问题定死了

```
自省能便宜地做「必要条件检查」：不可匹配 ⇒ 一定没用    ✅ V131
自省不能便宜地做「充分性检查」：没赢过 ⇒ 没用          ⛔ V134，砍掉 56%
```

原因是**反事实不在一次运行的痕迹里**。V128 能算出 `'true'` 值 +446，是因为它**真的跑了 21 次留一法**。

⇒ 本轮的问题：**能不能用比 O(n) 更少的反事实实验，把「哪些键有贡献」识别出来？**

## §1 装置

21 条记忆记录，穷举基线 = **逐条删 21 次**（每次一次全库 sweep，`saved` 与 793 比）。

**二分（分组测试）**：对一组记录 `S`，删掉 `S` 后重跑。
- `saved == 793` ⇒ **`S` 全废**，整组一次干掉。
- 否则若 `|S| > 1` ⇒ 对半分，递归。
- 否则 `S` 是单条且 `saved < 793` ⇒ 它有贡献。

⭐ 二分成立的前提是**边际可加**（删 A+B 的损失 = 删 A 的损失 + 删 B 的损失）。
V128 实测 4 条 `('T2',"'on'")` 单独删都掉 0 ⇒ 加性在这个语料上是可疑的但可能成立。**本轮直接量它。**

## §2 押注（三值，全部结构性）

**W1（二分 == 穷举）**：二分法输出的「有贡献记录集合」与穷举逐条删得到的集合**完全相等**（集合相等）。
> 这不是数量相等 —— 必须逐条对上。

**W2（省了实验）**：二分的实验次数 **< 21**（`n_eval`-free，只数 sweep 次）。

**W3（加性成立，这是 W1 的机制）**：删除全部 21 条造成的损失，与各条单独删除的损失之和，
**相对误差 < 10%**。
> ⛔ 若加性不成立而 W1 偶然成立，那是巧合，不是机制。这一条与 W1 分开押。

**W4（顺序无关，防「恰好有利」）**：把 21 条**随机打乱 5 次**后再二分，
5 次的「有贡献集合」必须**都与穷举相同**，且实验次数都 < 21。
> 记录是按 tid 聚在一起的（同题的记录相邻），天然分组可能特别有利。必须排除这一点。

## §3 失败模式（⛔ 不许事后改）

1. 若 W3 ⛔（加性不成立）⇒ **分组测试的前提没了** ⇒ 即使 W1 成立也必须写成
   「在这个语料上偶然成立」，⛔ 不许当作通用方法。
2. 若 W1 ⛔ ⇒ 加性在关键处破了 ⇒ 必须打印「二分说废但穷举说有用」的具体键，定位互补/遮蔽。
3. 若 W2 ⛔（二分不比穷举少）⇒ 说明废组太小，分组测试没有意义。

## §4 边界（⛔ 提前写死）

1. **a次 sweep 仍是「真的重跑」**：本轮省的是**次数**，不是「不需要反事实」。⛔ 不许读成「自省变便宜了」。
2. **只有 21 条**：二分对 21 条的收益是 O(log n) 级别的常数，不代表大库上的比例。
3. **不碰 V79**；判据仍是现有 test 的分数。
4. **二分可能「过度合并」**：若两条键互补（单独删都掉 0、一起删掉很多），二分会把整组判活再细分，
   但细分后两条都「单独删掉 0」⇒ 会判废。这正是 W1 要抓的情形。

## §5 口径

- `saved` 基数 = 同轮冷启动重算（预期 1381，节省 793）。
- 「有贡献」定义 = 删掉该条后 `saved < 该轮基线`。
- 实验次数按**真实 sweep 次数**报，不按「理论上界」报。
