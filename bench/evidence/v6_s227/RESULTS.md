# V138 结果：生效性 —— 判据盲 19%，但「盲」有三种，只有一种是真的

跑批时间 2026-11-15 19:30~21:0x；预注册见 `PREREG.md`。零模型、零网络。

## 0. 一句话

**V137 说「80.9% 的位置没有信号」，这个说法被本轮拆成三份：**
54 个位置代码根本没跑到（NOOP）、3 个位置只有自己的返回值变了（SELF_ONLY）、
**15 个位置真的改了下游行为而 631 条断言一格没管（SPILL）**。
真的盲区是 **15/89 = 16.9%**，不是 72/89 = 80.9%。

## 2. ⛔ 本轮最大的自踩：装置第一版是错的，读数作废

第一遍 89 站跑完，结果是 **89/89 全部 EFFECT，零 NOOP**。这个「一律」不合常理，于是查了调用数：
**81 次突变的调用数与基线完全相同（1,517,002），可 325 个函数被判「变了」**。计数相同而值全变 ⇒ 差异不在执行路径上。

根因：负载里有一个函数专门哈希 `mw/*.py` 源码——

```
mw/loop.py:52  def harness_sha(root=None) -> str:
    """被测对象（内核源码 mw/*.py）的指纹。唯一实现。"""
```

**任何编辑（哪怕只是一个注释）都会改它。** 我的轨迹把它算进去，于是「生效性」判据退化成了
「文件变了没有」检测器——而文件当然每次都变。

### 证明（控制变异，`control.py`）

往 `mw/llm.py` 末尾追加一行**永不执行**的注释：

- 判据 **631/0**（那一行确实不执行）
- 轨迹里变了的函数恰好 **3 个**：`loop.harness_sha`、`loop.CurvePoint.as_line`、`loop.CurvePoint.as_dict`

⇒ 这 3 个是**纯源码派生**，它们的变化不携带任何「代码跑没跑到」的信息，必须从判据里剔除。

### 第二处自踩：`diff_fns` 传参层级错

`diff_fns(rec, bl["base_per_fn"], noise)` 里 `bl["base_per_fn"]` 已经是 per_fn 本身，
函数内部又 `.get("per_fn")` ⇒ 拿到 `None` ⇒ **每个函数都被算成变了**（所以日志里 `diff=325`）。
修正后真实差异是 1~207 个函数不等。这两处都记在 `SELF_TRAP` 里（见 §7）。

**处理**：不重跑，对**同一批已落盘轨迹**剔除那 3 个函数后重算（`reanalyze.py`）。
轨迹是读数，重算是过滤——但必须写明这是**事后修正**，见 §6 的登记。

### 第三处自踩：时间量（第一次抽查抓到的）

剔除那 3 个之后做复现抽查（1/9 = 10 站），结果 **3/5 一致、2/5 翻转**，且两站都是 **NOOP→EFFECT**。
查差异函数：两次只差一个 —— **`mw.mutate.record`**，`n` 相同（2 次调用）但值不同。
它的返回值里带 `{"ts": round(time.time(), 3)}` ⇒ **墙钟落进不同取整桶，全场同步偏一格**。

⛔ 我没有「看到哪站翻转就把哪个函数拉黑」——那是拿结果定装置。改成**静态规则**（`timescan.py`）：
凡源码里引用时间源（`time/monotonic/perf_counter/process_time/now/utcnow`）的函数，一律出局。
扫出 **8 个**：`bench.run_suite`、`budget.Ledger.elapsed`、`loop.run_loop`、
`memory.MemoryStore.{capture,commit_fact,record,think}`、`mutate.record`。

**剔除集合 9 → 16，结论一字不变（SPILL 32 / SELF_ONLY 3 / NOOP 54；BLIND 18/54）**。
⇒ 结论不是靠挑函数凑出来的。

**带 16 个剔除重跑同一批抽查：5/5 一致**（两站翻回 NOOP 并稳定）。

⇒ 「修好」仍然不是「修对」，但归因要改：不是「判据瞎」，是「**这个界在绿区里是死的**」。
⇒ 对退化修复：把界拧大代价为零、收益也为零（不产生可测后果），**所以它不是靠改坏系统来骗分，它什么也没改**。

## 7. 自踩登记（SELF_TRAP）

1. **装置第一版把源码指纹算进「行为」**。后果：89/89 假 EFFECT，第一遍读数全部作废。
   发现方式：调用数相同（81/89 与基线逐值相同）却有 325 个函数「变了」。
   ⭐ 教训：**「一律」本身就是告警**。判据若把一个必然变化的东西算进去，它就不再是判据。
2. **`diff_fns` 传参层级错**（`base_per_fn` 又被 `.get("per_fn")` 一次 ⇒ `None`）⇒ 日志里 `diff=325` 全是假的。
   教训：**派生量自己也要对账**（纪律 12）。
3. **第一遍是 6 路并行的，基线是串行的**。虽然最终确认噪声不来自负载（调用数相同），
   但这仍违反纪律 46 的口径一致：**基线与突变必须在同一条件下量**。已改为同一装置同一环境。
4. **装置第三版才复现**：源码派生 3 个 + 时间量 8 个，剔除集合 9 → 16。
   1/9 抽查首轮 **2/5 翻转**，修正后 **5/5 一致**。
   ⭐ 教训：**「两次空转相同」只能证明分钟级内稳定**，证不出跨时间桶稳定。
   剔噪名单必须由**静态规则**（谁引用了时间源）而不仅是**经验差分**（哪两次不同）来定。

## 8. 这一轮到底改变了什么

不是「判据更好了」，是**判据盲区的形状变了**：

| 原以为 | 实际 |
|---|---|
| 72/89 位置没有信号 | 54/89 根本没跑到（不是盲，是死） |
| 判据偏松，接受了真实改变 | 绿区里那个界是**死的**（下游无后果） |
| 只剩一个真问题 | **15 个真盲区**：改了有下游后果，631 条断言一格没管 |

真盲区的例子最扎眼的是 `memory.py:321/367 → abstractor.distill`：**207 个函数跟着变，判据 631/0**。
蒸馏链路整条都能被改而无人知晓。

⛔ 但这一轮**没有让系统多做对一道题**，也没有打开那三个「外面」。它只是让「改完之后我能知道什么」这件事变清楚了。
