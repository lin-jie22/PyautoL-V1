## 0. 这一轮为什么改 `mw/`

V136~V139 四轮**全部在 `bench/evidence/` 里**，`mw/` 一行没改。
那四轮买到的都是**我的**读数，不是**系统的**能力。
本轮的靶子是：把 V139 量到的那件事变成内核代码。

**V139 量到的是什么**（`v6_s228/RESULTS.md`）：

> 判据态是三值：绿 / 红 / **崩**。崩是最响的信号，却是唯一被解析器吞掉的一档。

**为什么它会被吞掉** —— 现场就在 `v6_s228/READINGS_crash_repro.txt:112`：

```
  ✅ H8 汇总行可被外部 runner 正则解析（§134/§135 的坑）  (PASS=7  FAIL=0)
```

这条断言的**名字**是「汇总行可被外部 runner 正则解析」，
而它的 **detail 文本**恰好就是让那个正则解析出错的字符串。
自指陷阱：用来证明「能被解析」的那句话，本身就是不可解析的污染的来源。

根因不在 grep，在 `mw/measure.py`：

```python
def summary_line(self) -> str:
    return f"PASS={self.pass_n}  FAIL={self.fail_n}"
```

`PASS=n  FAIL=n` 这个格式**与普通文本无法区分**。
任何事后读这份日志的人（包括系统自己读自己的 `run.py` 输出）都无法判断
「这一行是判据，还是某条断言在复述判据」。

⇒ 这是**内核缺陷**：内核产生的读数不自描述。

## 1. 改什么

### 1.1 `mw/measure.py`

1. 新增 `SENTINEL = "::VERDICT::"` —— 汇总行前缀，**只由 `verdict_line()` 产生**。
2. `Report` 新增 `finished: bool = False` + `finish()`。
   理由：现在「跑完了」是**默认状态**（不声明=没崩）。把它翻过来：
   **不声明 = 没跑完 = 崩**。
3. `Report.verdict() -> str` → `GREEN / RED / CRASH`。
4. `Report.verdict_line() -> str` → 唯一可解析行，含三值。
5. `Report.summary_line()` **保持原格式不变**（人读用，不作判据）。
   ⛔ 不改它：契约 H8 与 README 都引用了它，改动面与收益不成比例。
6. 新增模块级 `verdict_from(text, exit_code) -> tuple[str, str]`
   —— 从**一段日志 + 退出码**判读判据态。这是内核的「自省原语」。

`verdict_from` 的规则（⛔ 顺序即语义，不许重排）：

| # | 条件 | 判 | 理由 |
|---|---|---|---|
| 1 | 无 `SENTINEL` 行 | **CRASH** | 汇总行缺席 ⇒ 跑没跑完不知道。⛔ 不管文本里有多少个 `PASS=xxx` |
| 2 | 有多于 1 行 `SENTINEL` | **CRASH** | 不知道哪一行是真的 |
| 3 | 有 1 行但解析不出 PASS/FAIL | **CRASH** | 格式退化 |
| 4 | FAIL > 0 | **RED** | |
| 5 | FAIL == 0 但 `exit_code != 0` | **CRASH** | 打印汇总之后进程仍崩了 |
| 6 | 其余 | **GREEN** | |

规则 1 是纪律 8「崩溃冒充跑完」的**可执行版本**；
规则 5 是纪律 55「`EXIT≠0` 而 `FAIL==0` ⇒ 判据失效」的落地。

## 3. 判据（先写后跑）

### 3.1 装置自校验（must-pass，不构成「命中」）

**W1**：`verdict_from(READINGS_crash_repro.txt 的全文, exit_code=1)` 必须返回 `CRASH`；
同一段文本用**旧口径**（`grep -oE 'PASS=[0-9]+  FAIL=[0-9]+' | tail -1`）
必须得到 `PASS=7  FAIL=0`（即「绿」）。
**两者必须分叉** —— 不分叉说明装置没装对。

⛔ W1 是**机制上必然**的（规则 1 直接排除了无 SENTINEL 的情形），
所以它只证明「装对了」，**不算发现**。

### 3.2 复算一致性（must-equal，不构成「命中」）

**W2**：把 V139 的 89 站读数（`v6_s227/analysis.json` 的 `verdict` + `calls`）
重新用三值口径判读，结果必须与 V139 已登记的 `SPILL_CRASH = 2` 一致。

⛔ 这是**复算**，不是新信息。押「=2」就是押幅度（纪律 40），
所以不记命中，只登记「一致 / 不一致」。

### 3.3 真押注（可证伪）

**W3（结构性，双向）**：门禁 `run_tests.sh` 增加「必须存在 `::VERDICT::` 行」的检查。

- **W3a**：在**改动之前**，把 `contract_test.py` 末尾的汇总打印整段删掉，
  门禁**仍会通过**（因为退出码不变）。
- **W3b**：在**改动之后**，同样的删除注入，门禁**必须失败**。

⇒ 两个方向都押。若 W3a 已经失败（改之前就能抓），说明我的归因错了；
若 W3b 仍通过，说明改动没有通电。

**W4（无副作用）**：在 V139 的 89 站读数上，把「旧口径判决」换成「三值口径判决」，
**只有崩的站点改变判决**，原本判绿的站点一个都不许变红。

⛔ 这条防的是「新判据顺手把别的东西判死」——那是尺子被改动，不是能力提升。

### 3.4 边界（预注册时就写明，不许事后加）

   一律判 CRASH —— 这是**故意的** fail-closed，不是缺陷。
