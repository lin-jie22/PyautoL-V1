## 1. 缺陷的准确形态

`run_tests.sh:106`（改动前）用这个读判据：

```bash
grep -oE 'PASS=[0-9]+  FAIL=[0-9]+' /tmp/v1_contract.out | tail -1
```

而 `mw/measure.py` 的 `summary_line()` 产出的就是这个格式，**没有任何标记**。
于是断言 detail 里复述一遍判据，就与判据本身同形。
真实发生过（`v6_s228/READINGS_crash_repro.txt:112`）：

```
  ✅ H8 汇总行可被外部 runner 正则解析（§134/§135 的坑）  (PASS=7  FAIL=0)
```

这条断言的**名字**是「汇总行能被正则解析」，它的 **detail** 就是让那个正则解析出错的字符串。
自指陷阱 —— 用来证明「可解析」的那句话本身不可解析。

⇒ 根因不在 grep，在**内核产出的读数与普通文本同形**。

## 2. 改了什么（全部在 `mw/measure.py`）

| 新增 | 作用 |
|---|---|
| `SENTINEL = "::VERDICT::"` | 判据行的唯一前缀，只由 `verdict_line()` 产生 |
| `Report.finished`（默认 `False`） | **「跑完」从默认值变成需要声明的断言** |
| `Report.finish()` | 显式声明跑完；不调 ⇒ `verdict()` 永远 CRASH |
| `Report.verdict()` | `GREEN / RED / CRASH`，**崩优先于红** |
| `Report.verdict_line()` | 唯一可解析行：`::VERDICT:: GREEN  PASS=637  FAIL=0` |
| `verdict_from(text, exit_code)` | 从**一段日志 + 退出码**判读，返回 `(状态, 理由)` |

`summary_line()` **一个字没改**（契约 H8 与多处文档互锁，改动面与收益不成比例）。
正确做法是**另给一行**，不是改那一行。

### `verdict_from` 的六条规则（顺序即语义）

| # | 条件 | 判 |
|---|---|---|
| 1 | 无 `SENTINEL` 行 | CRASH（判据缺席） |
| 2 | 多于 1 行 | CRASH（有东西在冒充） |
| 3 | 有 1 行但解析不出计数 | CRASH（格式退化） |
| 4 | FAIL > 0 | RED |
| 5 | FAIL == 0 而 `exit_code != 0` | CRASH（打印后仍崩了） |
| 6 | 其余 | GREEN |

规则 1 = 纪律 8「崩溃冒充跑完」的可执行版：**缺席不许冒充零。**
规则 5 = 纪律 55 的落地。

## 3. 判决

### W1 装置自校验（不构成「命中」）

真实崩溃日志（`READINGS_crash_repro.txt` 那三行）上：

```
旧口径 re.findall(r'PASS=(\d+)\s+FAIL=(\d+)')  →  [('7', '0')]        = 绿
新口径 verdict_from(该文本, exit_code=1)      →  ('CRASH', '日志里没有汇总行…')
```

**两者分叉** ✅。机制上必然（规则 1 直接排除无 sentinel 的情形），
所以它只证明「装对了」，**不算发现**。

### W2 复算一致性（不构成「命中」）

`v2_relabel.py`，输入是 V139 已落盘的 `readings.jsonl`（89 站）：

```
站点数        : 89
旧口径分布    : GREEN 72 │ RED 17
exit 分布     : 0 → 70 ｜ 1 → 19
判决改变      : 2 站
  memory.py:321    GREEN(7/0)  exit=1 → CRASH
  memory.py:367    GREEN(7/0)  exit=1 → CRASH
```

与 V139 登记的 `SPILL_CRASH = 2` **完全一致** ✅。
⛔ 这是**复算**，不是新信息。押「=2」就是押幅度（纪律 40），不记命中。

⚠️ 第一次复算写错了分母：把它算成 99 站，因为我用 `":" in tag` 过滤，
把 Part B 的 `模块:行@值` 记录也收了进来（10 条）。修正后 89 站。
**分母口径必须写进字段名**（纪律 46）—— 这次的字段名是 `sites()` 的 docstring。

### W3 门禁的读法（真押注，双向）

**W3a（改动前）**：把 `contract_test.py` 末尾汇总打印整段删掉，跑契约：

```
EXIT = 0
grep -c 'PASS=631' = 0        ← 连汇总行都没有了
```

**门禁照样通过。** ⇒ 退出码对，但**日志作为证据是残缺的**：
「跑完了全绿」与「跑完了但判据没打出来」在日志上不可区分。✅ 押中。

**W3b（改动后）**：同样的注入，跑完整 `run_tests.sh`：

```
步骤 2/7  契约测试
  ❌ 契约测试退出码 0，但日志里**没有**判据行（::VERDICT::）
     ⇒ 判据缺席不许冒充通过（纪律 8 的可执行版）
...
EXIT = 1
```

**双向都成立** ✅

| | 注入「删掉汇总行」后 |
|---|---|
| 改动前（W3a） | `EXIT=0`，门禁**通过** |
| 改动后（W3b） | `EXIT=1`，门禁**失败**，且指名「没有判据行」 |

⛔ **第一次 W3b 的读数作废**（登记）：我在拷贝副本时排除了 `bench/evidence`，
导致 `AJ3` 等断言在副本里天然失败（主仓库同一断言是 ✅），
契约退出码本来就非 0，于是走的是 `else` 分支，
**我新加的检查根本没执行到**。日志里 `grep -n "判据行"` 为空 —— 这就是抓法。

重做时用**完整**副本（84MB，含 `bench/evidence`），注入后才得到上面的读数。
⇒ 教训：**注入实验的前提是「未注入时基线必须全绿」**，否则你量的是副本的残缺。
这一条与纪律 50「记录版装置必须自校验」同族。

## 5. ⛔ 自踩登记：断言自己成了污染源

AZ126f 第一版的 detail 写的是 `verdict={_mz_r.verdict_line()!r}` ——
那是**为了证明「summary_line 不含 sentinel」**，但它把 `verdict_line()`
原样打印了出来。于是整份契约日志里出现 **2 行** `::VERDICT::`：

```
              否则 AZ126b 的隔离立刻失效 —— 它读的就是「带前缀的那一行」
              (summary='PASS=7  FAIL=0' verdict='::VERDICT:: CRASH  PASS=631  FAIL=0')
::VERDICT:: GREEN  PASS=637  FAIL=0
```

`verdict_from(全文)` 当场判 **CRASH**（规则 2）。

这是**同一个位置的第二次自指陷阱** —— 第一次是 H8（用它自己的 detail 证明可解析），
第二次是我写的「不许 detail 污染」那条断言本身污染了 detail。

修法两条：
1. AZ126f 的 detail 不再打印 `verdict_line()` 原文，只打布尔结论。
2. `run_tests.sh` 增加硬检查：**判据行必须恰好 1 行**，否则 `FAIL=1`。

修完后实测：`grep -c '::VERDICT::' = 1` ✅。
