## 0. 一句话

V140 造了三值判据，但**只有测试在读**。这一轮把它接进 `run.py` 的 bench 路径：
一次真实运行**留下**日志，然后**从磁盘读回**它判读，读不回来就报 CRASH
并把退出码抬起来。**判据缺席不再冒充通过，也不再沿用上一次的结论。**

⚠️ 这仍然**没有让系统多做对一道题**。三个「外面」一个没打开。
它买的是：**系统平时会读自己的日志了** —— 这是「自省」这条循环的入口，不是它的成果。

## 1. 改了什么（`run.py` +178 行，`mw/` 一行没改）

| 位置 | 内容 |
|---|---|
| `cmd_bench` → `_bench_main` | 原名让给外壳；**函数体语义一字不动**，只在末尾多打一行判据 |
| `cmd_bench`（新壳） | `open("w")` 开日志 → tee stdout → 跑 → 关文件 → **`Path.read_text()` 读回** → 判读 |
| `judge_run_log(path, rc)` | **生产读取点**，唯一调用 `verdict_from` 的地方 |
| `_rc_after_readback(rc, state)` | 读回非 GREEN 而 `rc==0` ⇒ 抬到 1 |
| `_Tee` | stdout 双写；**每条 write 后 flush**（日志必须是活的） |
| `_bench_main` 末尾 | `Report()` + `finish()` + `print(verdict_line())` —— **恰好一行** |

三处刻意的选择：

1. **`open(..., "w")` 不是 `"a"`**：上一次运行的判据行必须物理上消失。
   追加写 + `tail -1` 就是 V140 那个病的复发形态（上一轮的绿冒充这一轮的绿）。
2. **读回读文件，不读内存里的字符串**。「这次到底有没有量到东西」必须由
   **落盘的证据**回答 —— 内存里那句 `Report` 说的话，正是要被校验的对象。
3. **`rc==2` 不判读**：用法/数据错误根本没进入测量。把「没跑」念成「崩了」
   会让真正的崩失去分辨力。这一条写在壳里，不是逃逸口。

分母口径（纪律 4/46）：bench 判据**分母 = 1 道闸**（「这次运行的读数可否用于判定」）。
⛔ 不是断言数，**不许与契约的 642 比大小**。只有一道闸是因为其它失败形态全都
提前 `return 2`（血缘闸 / 数据缺失 / 选项冲突）⇒ 走不到这里，把它们算进 PASS
就是恒真断言（纪律 5）。

## 4. ⛔ 自踩登记（两处，都是「检测器」不是「被测物」）

**(1) 加了 5 条撤回态却没同步文档 ⇒ 基线被自己的计数器判红。**
第一次跑 `withdraw_check.py` 直接拒绝开工：`基线 ('641','1') 红=['AZ44']`。
原因：`AZ44` 用 `len(withdraw_check.CASES)` **现算**撤回态条数，
而我让 README/site 停在 212。⇒ 这不是装置故障，是**装置按设计抓住了我**。
修法：README×3 + site×2 声明 `212 → 217`（⛔ 只改「撤回态」那几处，
README:946 那个「长度 212」是别的东西，全局替换会改错）。

**(2) 撤回驱动器不认自己的标签。**
修完文档后 5 条全报 `红=无 目标=✘`，第一反应是「断言恒真」。
真因是 `_run_suite()` 的红集正则 `[A-Z]{1,2}\d+\b` 在 `AZ127a` 上**匹配失败**
（`\b` 卡在 `7` 与 `a` 之间）⇒ 红集恒为空。
⇒ 这是纪律 5 的**第三形态**（检测器失效）在一次新装置上的重演：
「撤回后没转红」有两种可能，**先证明检测器能看见目标**，再怀疑断言。
修法：正则加可选小写后缀 `[a-z]?`（旧标签行为不变），并把理由写进注释。
⚠️ 顺带查出一件事：V140 的 `AZ126a…f` **从来没有撤回态记录** ——
它们一直是「红集看不见」的形态。本轮不补（不在预注册里），登记为欠账。
