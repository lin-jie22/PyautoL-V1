# V142 预注册（先写后做）—— 让上一次运行的状态约束这一次的判定

日期 2026-11-15｜上轮 §208（V141）｜纪律 1：本文件写完才动代码。

## 0. 靶子（V141 留下的三处空转）

V141 让系统**读**了自己的日志，但读到的状态**没有去处**：

| 出口 | 现状 | 后果 |
|---|---|---|
| `--save-baseline` | 不看这次运行的判据 | 一次崩掉的运行可以成为下一轮的标准 |
| `--compare` | 不看基线**是怎么来的** | 拿一次 CRASH 的读数当参照，算出「改进成立」 |
| `runs.jsonl` | 145 条历史记录里 `verdict` 这个键**根本不存在** | 任何读者要么不知道要读，要么 `.get("verdict", "GREEN")` 默认成绿 |

第三行是**真实的**历史数据，不是构造的：`bench_out/runs.jsonl` 现有 145 行，
逐行 `json.loads` 后 `"verdict" in rec` 全为 False。

## 1. 改动（形状先钉死，再动手）

1. `mw/bench.py`：在 `append_jsonl` 旁加两个出口
   - `stamp_verdict(path, run_id, verdict)`：把结论钉进**它自己那一行**。
     ⛔ 只钉 `run_id` 匹配的那条；最后一条不是它 ⇒ **拒绝**（不许「钉最后一行」）。
   - `ledger_verdict(path, run_id) -> (状态, 理由)`：键缺席 / `PENDING` / 无此
     `run_id` ⇒ **`UNKNOWN`**；`UNKNOWN ≠ GREEN`。
2. `BaselineStore.save(..., verdict=)`：**只有 `verdict == "GREEN"` 才写盘**，
   否则文件一个字节都不变；写盘时把 `verdict` 落进文件。
3. `BaselineStore.load_verdict()`：无键 ⇒ `None`（不是 `"GREEN"`）。
4. `--compare`：基线 verdict 缺席或 ≠ GREEN ⇒ **拒绝比较**，不打印「判定」行。
5. `run.py`：`store.save` 的调用点从 `_bench_main` **移到外壳**（读回之后）。
   `_bench_main` 只登记待办（一个 `_BenchGate`），不写盘。
6. 外壳末尾顺序固定：读回 → 与账本对齐（stamp → 回读）→ 两者不一致判 `CRASH`
   → 只有 `GREEN` 才执行 save。

## 2. 押注（可证伪；⛔ 押结构性命题，不押幅度）

| # | 押什么 | 怎么算红 | 分母 |
|---|---|---|---|
| W0 | 补 **AZ126a…f** 的撤回态（V141 登记的欠账），六条各自只让自己转红 | 任一 `目标=✘` 或基线不绿 | 6 条 |
| W1 | 旧记录**不许**被默认成绿 | 对真实 145 条逐条 `ledger_verdict` ≠ 145/145 `UNKNOWN` | 145 条 |
| W2 | 新记录带自己的 verdict | 新跑一条 `runs.jsonl`：`verdict != "GREEN"` 或 `ledger_verdict` 回读 ≠ GREEN | 1 条 |
| W3 | 崩掉的运行写不进基线 | 坏 JSONL 跑 `--save-baseline` 后基线文件 sha **变了**（或该不存在的文件存在了） | 1 次 |
| W4 | CRASH 基线不许比较 | 手造 `verdict=CRASH` 的基线 ⇒ 输出里出现「判定」行 | 1 次 |
| W5 | 旧基线（无 verdict 键）不许比较 | 删掉 `verdict` 键 ⇒ 输出里出现「判定」行 | 1 次 |
| W6 | 绿基线仍可比（无回归） | 真 GREEN 基线 ⇒ 输出里**没有**「判定」行 | 1 次 |
| W7 | 账本与日志打架 ⇒ CRASH（装置自检） | 把 `stamp_verdict` 换成空实现后 `rc` 仍为 0，或状态仍为 GREEN | 1 对（空实现 / 原样） |
| W8 | 无回归 | 门禁 `EXIT != 0` 或契约/锚层/撤回态/漂移任一不符 | 1 次 |

**W1 的对照组必须一起打**：同一批 145 条，按 `.get("verdict", "GREEN")` 读
⇒ 145/145 `GREEN`。两个数并排才说明「默认成绿」不是假想的风险。

**W7 是唯一需要注入的**：patch 掉 `stamp_verdict`（不写盘）后账本停在 `PENDING`
⇒ 外壳必须判 `CRASH` 且 `rc→1`；原样跑必须 `GREEN`。两边都成立才算数
（纪律 50：记录版装置必须自校验）。

**W3 的判据是 sha 逐字节相同**，不是「打印了拒绝」—— 一句 `print` 不构成证据。

## 3. 判据口径（纪律 4/46）

- bench 侧分母 = **1 道闸**（「这次运行的读数可否用于判定」）。⛔ 与 642 比大小。
- 契约侧分母 = 断言数（642 → 642 + 6 = **648**）。
- 「拒绝比较」不算新的一格状态：它只有一个含义 —— **不判定**。⛔ 不新造量表。

## 4. 明令禁止

⛔ 不许给旧记录**补** `verdict`（那等于伪造历史；旧记录只能被读成 UNKNOWN）。
⛔ 不许改 V140 那三个值（`GREEN/RED/CRASH`）。
⛔ 不许新造「运行健康度」分数。
⛔ 不碰 V79（自造判据判别力 0/8）。
⛔ 不许说「系统能自己判断改动对不对」—— 本轮只让它**不拿没量到的东西当标准**。

## 5. 已知会留下的缺口（先声明，免得事后当发现）

1. `--suite-dir`（跨领域）仍不产生判据行（V141 边界 4），因此也不写账本结论。
2. 账本结论是**最后一条**被钉的；一轮里多次 append（当前没有）会只约束最后一条。
3. `stamp_verdict` 会重写整个 `runs.jsonl`（145 行 482KB，可接受）；
   并发两个进程同时跑 bench 会互相覆盖 —— 当前无并发入口，登记为缺口。
