## 1. 这一轮改的是什么

V142 让基线带上 `verdict`，但那是**自述** —— 写在同一份文件里，谁都能改，
改了没人知道。这一轮加一格**身份证**（`run_id`），并要求**账本**复核：
同一次运行在 `runs.jsonl` 里有自己的一行，两处必须说同一句话；不成立时
**保守的那个赢**。

| 改动 | 位置 |
|---|---|
| `record_verdict(rec)` —— 「这一行的结论是什么」的**唯一**定义 | `mw/bench.py` |
| `ledger_strata(path)` —— 账本分层普查（无身份证 + 三值 + UNKNOWN） | `mw/bench.py` |
| `baseline_provenance_gate(...)` —— 五条规则（自述 → 身份证 → 查账 → 对齐） | `mw/bench.py` |
| `save(..., run_id=)` / `load_run_id()` | `mw/bench.py` |
| `--compare` 先复核账本，并把账本怎么说的念出来 | `run.py` |

## 4. ⛔ 自踩（两处，都在检测器上）

**(1) 判据行检测器把「判定」这两个字认成判定行。**
第一条读数里 W2/W3/W5 三格全报 `出判定=True`，而它们明明被拒了。
真因：`has_verdict_line()` 写的是 `"判定" in txt`，而**另一行**打印的是
`判据 分母=1 道闸（读数可否用于判定）` —— 检测器被它要读的输出里的一句话命中。
改成按形状认：`^\s*判定 (改进成立|不成立) —`。⇒ 纪律 5 第三形态（检测器失效）
在同一轮里第二次出现，且**同一个词**（V140 是 sentinel 被 detail 命中）。

**(2) 撤回态加了 7 条，文档没同步 ⇒ 基线被自己的计数器判红。**
`withdraw_check.py` 当场拒绝开工：`基线 ('656','1') 红=['AZ44']`（AZ44 用
`len(CASES)` 现算，我让它读到 231 vs 238）。⇒ 与 V141 完全同型。
修法：README×3 + site×2 `231→238`、`191→198`。⚠️ 另有一处
`657 契约 + 97 锚层 + 231 条撤回态` 藏在长表格里，第一遍漏了，
`check_counts.py` 逐个位置点名（`:1138`）才抓到 —— 这是单源核对器该有的样子。

## 6. 下一刀

账本现在能复核**基线**（一次运行的标准），但复核不了**结论链**：`--compare` 只说
「这次比上次好」，说不出「这条结论是在哪些读数上成立的」。而账本里已经有一批
带 `verdict` 的新记录 —— 没人回头问「哪些结论能被**跨会话**复算」。

下一刀：**让结论可以被第三方从账本重算** —— 给定一个 `run_id`，从账本里重算出
与当初写下的 `mean`/逐题分**逐格相同**的数字；重算不出来（账本被截断、`per_task`
缺行、`repeat` 对不上）⇒ 这条结论**不许**被引用。

可证伪：对至少一条真实记录，重算结果必须与账本逐格相同；随后把账本里那一行的
一行 `per_task` 删掉，重算必须**拒绝**（而不是补 0 或跳过）。
