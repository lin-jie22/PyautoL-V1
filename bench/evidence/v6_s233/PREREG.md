```
scores = [1.0, 0.4, 0.2, 0.2]
朴素 total += : 1.4000000000000001 → 1.6000000000000001 → 1.8000000000000002 → /4 = 0.44999999999999996  ← 记录值
```

⭐ 这条是 V144 的**第一等发现**，不是实现细节：判「逐格相同」必须把**求和算法**写进判据
（纪律 48 的形态），否则会把 28.7% 的正确记录判成假红 —— 而假红会让人去「修数据」。

## §3 判据（跑前写死）

重算公式（**必须逐字实现**）：

```
n_tasks = attempted // repeat            要求 repeat > 0 且 attempted % repeat == 0
round_r = fold(per_task 中 rep == r 的 score) / n_tasks      fold = 朴素左折叠，起点 0.0
mean'   = fold(round_r 按 r 升序) / len(rounds)
```

判「逐格相同」= `mean' == mean`，**IEEE-754 double 逐位相等**，⛔ 不用容差。
（容差会让「改掉一个分数使均值动 1e-9」蒙混过关；逐位相等要求重算与原算**同路径**。）

规则顺序即语义（先对账，再算账）：

| 规则 | 条件 | 判定 |
|---|---|---|
| R1 | 缺 `report.per_task` 或 缺 `measurement.mean` | `UNVERIFIABLE` |
| R2 | `per_task` 为空 | `UNVERIFIABLE` |
| R3 | `attempted != recorded + skipped_no_answer + failed_scorer` | `UNVERIFIABLE`（输入自相矛盾） |
| **R4** | `len(per_task) != recorded` | **`MISMATCH`**（删行/截断 —— 不许补 0、不许跳过） |
| R5 | 分母不可导（`repeat ≤ 0` 或 `attempted % repeat != 0`）或轮数 ≠ `repeat` | `MISMATCH` |
| R6 | `mean' != mean` | `MISMATCH` |
| — | 以上都不触发 | `VERIFIED` |

**J1 正例**：真实账本 136 行有明细 ⇒ 全部 `VERIFIED`，不符数 **= 0**。
**J2 负例**：从任一行删掉一条 `per_task` ⇒ `MISMATCH`，**理由必须是 R4（条数）**。
**J3 负例（关键）**：改掉一个 `score`（+0.01）⇒ `MISMATCH`，且重算值随改动**变化**。
   —— 若不变，说明重算值是装饰品（检测器失效，纪律 5）。
**J4 负例**：删掉 `measurement.mean` ⇒ `UNVERIFIABLE`。
**J5 缺席**：9 行无明细 ⇒ `UNVERIFIABLE`（⛔ 不是 `VERIFIED`）。
**J6 算法**：把 `_fold_sum` 换成 `sum()` ⇒ 不符数 **> 0**（钉住 §0 的发现）。

## §4 押注（三值，跑前）

- **W1**：J2 的拒绝理由落在 **R4（条数）**，不是 R6（数值）。
  理由：删一行后 `n_tasks` 仍从 `attempted` 推得，所以**算得出一个数**；只有先对账才能
  区分「这条记录被改过」与「这次运行确实有题没做」。
- **W2**：J6 用 `sum()` 时不符数 **> 0**（⛔ 不押具体个数 —— 押幅度违纪律 40）。
- **W3**：`audit_measurement` / `ledger_audit` 在**非测试代码**里被调用 **≥1 次**（通电，不是死代码）。
- **W4**：真实账本 145 行的审计分层里，`VERIFIED` 的条数 **> 0 且 < 145**（即：能复核的是多数，但不是全部）。

## §7 每轮必答

**这轮让「累积」离可测更近了吗？**
是，但只近一格：过去「同预算 17→20」这类累积结论，第三方无法验证那个 20 是从哪来的。
本轮之后，任何一条读数的 `mean` 都能被**独立重算**，不可重算的会被点名。
⚠️ 它不回答「这个读数有没有意义」，只回答「这个数有没有出处」。
