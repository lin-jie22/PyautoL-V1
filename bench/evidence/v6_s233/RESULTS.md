## 一、问题

V143 让**基线的可信度**必须由账本复核。但账本里的 `measurement.mean` 本身仍是**自述**：
它与 `per_task` 写在同一行里，却从来没有任何代码从明细把它算回来一次。
第三方拿到 `run_id` 只能**读**到一个数，不能**验**这个数。

## 二、做法

| 新增（`mw/bench.py`） | 作用 |
|---|---|
| `AUDITS = ("VERIFIED","MISMATCH","UNVERIFIABLE")` | 三值，**不参与任何加权** |
| `_fold_sum(xs)` | 朴素左折叠 —— 与 `run_suite` 的 `total += score` 逐位对齐 |
| `recompute_mean(rec)` | 从 `per_task` 把 `mean` 算回来；算不出 ⇒ `None` |
| `audit_measurement(rec)` | R1~R6 六条规则（顺序即语义） |
| `ledger_audit(path, run_id)` | 按 `run_id` 定位那一行再审计（⛔ 不按「最后一行」） |
| `ledger_audit_strata(path)` | 按可重算性分层 + 守恒式 |
| `baseline_recompute_gate(...)` | 基线闸第六格（第五格之后） |

`run.py`：外壳在账本钉完 verdict 后现算一次并打印 `读数复核`；`--compare` 在第五格之后接第六格。
**审计结果不落盘** —— 账本里只放事实，复核结论永远现算（写进账本就是第二个自述）。

## 三、读数

### 3.1 跑前（`READINGS_probe.txt`）

| 读数 | 值 |
|---|---|
| 账本行数 | **145** |
| 有 `per_task` | **136** |
| 明细为空 | **9** |
| 朴素左折叠重算，与写下的 `mean` 逐位相同 | **136 / 136** |
| 内置 `sum()` 重算，逐位相同 | **97 / 136**（39 行不符，最大差 1.11e-16） |

39 行不符的根因（`L16` 手算复核）：

```
scores = [1.0, 0.4, 0.2, 0.2]
total += :  1.4000000000000001 → 1.6000000000000001 → 1.8000000000000002 → /4 = 0.44999999999999996  ← 记录值
sum()    :                                                              1.8        → /4 = 0.45
```

⇒ CPython 3.13 的 `sum()` 对 float 走**补偿求和**。这是本轮第一等发现：
**判「逐格相同」必须把求和算法写进判据**，否则 28.7% 的正确记录会被判假红。

**反证组**（`PREREG §5`）：
- 把 `recompute_mean` 改成直接返回写下的 `mean` ⇒ 删一条**仍** MISMATCH（R4 不依赖重算）、
  改分数**变 VERIFIED**（重算被蒙混）⇒ **一 changed 一 unchanged**，证明两条规则各自独立工作。
- 删掉 R4 后，删一条落到 R6（`Δ=7.140e-03`）⇒ 证明 R4 是**先**抓的，理由确实不同。

### 3.3 边界（J7，⛔ 不是判据）

改一条明细**同时**把 `mean` 改成重算值 ⇒ **VERIFIED**。

⇒ 审计保证的是**内部一致**，不是**真实性**：
抓得到「改了明细没改结论」与「改了结论没改明细」，**抓不到「两者一起改」**。
⛔ 因此不许说「账本不可篡改」——只能说「单边篡改会留下不一致」。

### 3.4 真跑（正例路径，纪律 62）

离线 bench（`coding_small`，oracle，6 题，2.8s）：

```
判据      分母=1 道闸（读数可否用于判定）  可信=True
::VERDICT:: GREEN  PASS=1  FAIL=0
读数复核  VERIFIED  — 重算 1.0 == 写下的值（6 条明细 / 1 轮 / 分母 6）
判据读回  GREEN  — 全部 1 条断言通过，退出码 0；账本已钉 GREEN
```

`--compare` **正例**（基线可重算）：
```
账本复核  GREEN  — verdict=GREEN（run_id=41509@1794809015）
读数复核  VERIFIED  — 重算 1.0 == 写下的值（6 条明细 / 1 轮 / 分母 6）
基线 oracle（上界参照）@1x … ⇒ 进入比较，出判定行
```

`--compare` **负例**（复制副本后，把基线那一行的 `per_task` 删掉一条）：
```
账本复核  GREEN  — verdict=GREEN（run_id=41509@1794809015）      ← 第五格原封不动
读数复核  MISMATCH  — 明细条数 5 ≠ recorded=6 ⇒ 明细被删或被截断
⛔ 结论与明细打架，拒绝比较 ⇒ **拒绝比较**（不出一句「改进成立」）。
```

⭐ 这一格是本轮最值钱的读数：**`verdict` 一格没改，只是明细少了一条，比较就被拒**。
⇒ 第六格是**独立的第二道闸**，不是第五格的重复。

## 七、每轮必答

**这轮让「累积」离可测更近了吗？**
近一格，且只近一格：过去「同预算 17→20」「判分 −57.4%」这类累积结论，
第三方无法验证那个数是从哪来的；现在任何一条读数都能被**独立重算**，
不可重算的会被点名（`UNVERIFIABLE`）而不是被当成 0 或跳过。
⚠️ 它不回答「这个读数有没有意义」，只回答「这个数有没有出处」。
