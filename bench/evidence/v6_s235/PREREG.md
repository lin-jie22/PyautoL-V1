## 1. 已知事实（跑前量测，非判据）

`probe_inject.py`（零判分）：

```
别题键在本题能被匹配的实现：0/5、0/8、0/8、0/4  ⇒ 合计 0/25
```

⇒ V121 的「扰动太弱」准确说是 **扰动为零**：错知识从未进入任何一次排序，
所以根本不存在「用错了」这回事。**旧的错记忆臂测不到自省，是装置缺陷，不是能力墙。**

`probe_key.py`（有判分，只为挑注入点）：覆盖全部实现的非答案键里，
只有 `g7d3_fmt_amount::('T3','strip().lower')` 是**真无效**（8/8 实现最高分 **0.0**）。
其余键都只在部分实现上无效。

## 2. 本轮的假设

> **抽象键只保证「可匹配」，不保证「可用」。**
> `abstract()` 抹掉了「在哪个节点上改」（V131 的 W4 押破），所以同一个键在不同实现上
> 命中的是不同节点，其中有些节点改完是对的、有些不是。
> ⇒ 一条知识「在源实现上到 1.0」不蕴含「在其他实现上也到 1.0」。
> ⇒ 系统如果只看「源实现上有效」就把它当通用知识，就会在无效的实现上**先试错**。

## 4. 在线机制（唯一定义）

```
fails[k]  = 键 k 的候选被判分后「没有超过当前节点分数」的次数
order_key = (0 if fails[k] < 2 else 1, 0 if k in mem else 1)
```

- `fails[k] < 2` 的记忆键才享受「优先」（第一维 0）；
- 失败满 2 次的键退回普通候选（第一维 1），不再抢位置；
- ⛔ 不删除条目、不读 test、不用人写规则 —— **只用系统自己判过的分**。

阈值 2 是**人定的**（跑前写死，跑后不改）。边界里登记。

## 7. 边界（⛔ 现在就写死，防止事后吹）

1. **不判断知识的真伪**：只判断「在这个实现上，这条知识指向的候选有没有到 1.0」。
2. ⛔ **不是「系统自己发明知识」**：键仍来自人给的动作空间（V79 那堵墙一字未碰）。
3. **阈值 2 是人定的**，跑后不许因为读数不好看改成 1 或 3。
4. 语料仍是 25 实现 / 4 题；换库未知（V136~V138 已证真实库上不可用）。
5. **不是「在线学习」**：`fails` 不落盘、不跨实现共享，每次搜索从零开始。
6. `trace.json` 是**记录版装置** ⇒ 必须自校验（已做：1381/21），否则纪律 50 违规。
