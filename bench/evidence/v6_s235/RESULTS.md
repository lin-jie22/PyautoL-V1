## 1. 跑前量测：V121 的错记忆臂「扰动为零」，不是「太弱」

`probe_inject.py`（零判分）—— 别题的键在本题能被匹配到的实现数：

```
g7d2 0/5｜g7d3 0/8｜g7e1 0/8｜g7e2 0/4   ⇒  合计 0/25
```

⇒ 错知识**从未进入任何一次排序**，所以不存在「用错了」这回事。
**旧的错记忆臂测不到自省，是装置缺陷，不是能力墙。**

`probe_key.py` —— 覆盖全部实现的非答案键里，只有
`g7d3_fmt_amount::('T3','strip().lower')` 是**真无效**（8/8 实现最高分 **0.0**）。

## 2. 现象：可匹配面 ≫ 可用面

`probe_trace.py` 跑一次带轨迹的冷启动（自校验：`n_eval=1381` / `到1.0=21`，与 V121 逐字一致），
然后离线算每条记忆条目的两个面：

```
spread(k) = 轨迹里出现过键 k 的实现数   （可匹配面）
useful(k) = 其中至少一个候选拿到 1.0 的实现数（有效面）
```

| 条目 | spread | useful | ratio |
|---|---|---|---|
| `g7e1 ('T2',"'true'")` | 5 | **1** | **0.20** |
| `g7d3 ('ret',".replace(',',' ')")` | 6 | **2** | **0.33** |
| `g7d2 ('key','.strip()')` | 2 | 1 | 0.50 |
| `g7e1 ('T2',"'on'")` ×4 | 5 | 4 | 0.80 |
| `g7e2 ('C1',"'…' + s[-n:]")` ×2 | 2 | 2 | 1.00 |
| `g7d2 ('key','.strip().lower()')` | 1 | 1 | 1.00 |

**11 条可匹配条目里 8 条 `spread > useful`**（W1 线 ≥6 ⇒ ✅）。
最极端的一条知识，在 5 个实现里只有 1 个成立。

机制与 V131 的 W4 押破同源：`abstract()` 抹掉了「在哪个节点改」，所以同一个键在不同实现上
命中的是不同节点，改完有的对、有的不对。

## 3. 主判据：在线降权在这个语料上没有可测收益（W2/W4b 押破）

| 臂 | n_eval | 命中记忆的判分 | 到 1.0 |
|---|---|---|---|
| `WARM_ALL` | **588** | 43 | 21/25 |
| `ONLINE`（失败≥2 次降权） | **588** | 43 | 21/25 |
| `REV`（反证：失败越多越优先） | **588** | 43 | 21/25 |
| `WARM_BAD`（注入完全无效的键） | **590** | 51 | 21/25 |
| `ONLINE_BAD` | **590** | 51 | 21/25 |

| # | 判决 |
|---|---|
| W1 | ✅ 8/11 ≥ 6 |
| W2（`ONLINE ≤ 588×0.98`） | ⛔ **押破**，省 0 |
| W3（不伤正确性） | ✅ 21/25，逐实现 s1 无下降 |
| W4a（扰动可见） | ✅ 590 > 588（**+2**） |
| W4b（在线吸收 ≤ 589） | ⛔ **押破**，省 0 |
| W5（REV 必须上升） | ⛔ **押破**，588 == 588 |

**为什么降权无收益**（诊断，非判据）：`fails` 只积累在**本来就不优先**的键上；
记忆里的键失败次数只有 **0~2** 次，任何基于它的排序都改变不了多少。
注入那条「完全无效」的键也只造成 **+2** 次判分（不是 8 次）——因为「一到 1.0 就停」，
多数实现根本没走到它的候选。

⇒ **这个语料上「用错知识」的代价上限 < 1% 的判分量**，与噪声不可分。

## 4. 跑后诊断（⛔ 未预注册，不算押中）：判据能判对，但只能判 30%

把「这条知识在这个实现上有没有用」做成三值，只用系统自己判过的分
（`tries` / `bscore`）：

```
OK        VALID= 8   INVALID= 0   UNKNOWN= 1
FAILED    VALID= 0   INVALID=10   UNKNOWN= 0
UNTRIED   VALID= 0   INVALID= 0   UNKNOWN=41
                                        ↑ 41/60 = 68%
```

在**作出判断的 18 格**上 18/18，误报 0。

⚠️ **但这 100% 是同义反复**：系统判断与「真值」都来自同一个 `ev` 判分器
（`bscore < 1.0` ⇔ 轨迹里最高分 < 1.0），必然一致。⛔ 不许说「系统学会了判断知识对错」。

**真正的读数是第三行**：

> **60 格里 41 格（68%）是 UNTRIED —— 没试过就不知道。**
> 「不知道」不许算成「有效」（V145 纪律 64 的又一形态）。

## 5. ⭐ 本轮唯一站得住的结论：两种判据的信息成本差了一个数量级

| 判据 | 问的问题 | 信息成本 | 覆盖 | 出处 |
|---|---|---|---|---|
| **可达性** | 这个键能不能被匹配到 | **0 次判分** | **21/21 条** | V131（差集 0） |
| **有效性** | 这个键在这里有没有用 | **必须判分** | **18/60 格 = 30%** | 本轮 |

⇒ **「可匹配」免费，「可用」收费，而且收费也只买到试过的那部分。**

⭐⭐ **由此得到一条跨循环的约束**：
累积省下的正是判分次数（−57.4%），而自省要花的也正是判分次数。
**两者共享同一个预算** ⇒ 三循环不是可以各自最优的独立环节，
「让系统更会自省」在资源约束下等价于「让它少省一点算力」。

这不是新机制，是本轮读数直接给出的一个**冲突**。

## 6. 自踩三处

1. **`REV` 反证臂设计错误**：`fails` 全 0 时 `-0 == 0`，REV 与原臂**逐位相同**
   ⇒ 「判据没有能变」（纪律 47）。W5 押破的**一半**是装置问题，
   另一半是真实的（记忆键的 fails 分布只有 0~2，反转也改不动排序）。
2. **真值粒度写错**：第一版按 `tid` 聚合最高分 ⇒ 一个键在某一个实现上到过 1.0，
   被记成「对所有实现都有效」⇒ `INVALID` 全 0，矩阵退化成 18/0。
   第一次读数原样留在 `READINGS_diag_v1_badtruth.txt`。修成 `(tid,h,key)` 后才是 8/10/41。
3. **W2 的判据线可能定得不对**（跑前写死，如实登记）：`≤98%` 对应「省 ≥12 次判分」，
   而这个语料上「用错知识」的理论上限只有 +2 次 ⇒ **判据从一开始就不可能成立**。
   ⛔ 不改成「省 ≥1 次」来回收 —— 押破就是押破；但下一轮的线要按实测上限重定。
