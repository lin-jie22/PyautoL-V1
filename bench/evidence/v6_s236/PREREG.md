## 0. 为什么是这一刀

§213.9 登记的就是这一刀，理由不变：V146 给了两个端点 ——

| 判据 | 花的判分 | 覆盖 |
|---|---|---|
| 可达性（能不能匹配到） | **0** | 21/21 条 |
| 有效性（在这里有没有用） | **588** | 18/60 格 |

中间是空的。要问的是：**多花的判分买到的是新的「知道」，还是重复确认已经知道的？**
曲线是什么形状、有没有拐点、上界在哪。

## 1. 已知事实（**跑前量测，非判据**，如实披露）

### 1.1 记忆条目在装置里**没有应用通道**（零判分，代码取证）

搜索器用记忆的方式只有一处：

```
bench/evidence/v6_s210/v121.py:144
    mine = {(a, b) for k in mem[tid] if k["h"] != h for a, b in [tuple(k["act"])]}
```

`mine` 之后只出现在 `sorted(cands, key=lambda x: (0 if x[0] in mine else 1,))` 里
（`v121.py:150` 一带）。⇒ **记忆条目只当排序键用，从不被用来"施加"一次编辑**。
候选只能由 `X.gen(tid, node["code"], Sx, chains, exprs)` 产生，
`X.abstract(lab)` 只是事后**读**出来的标签。

⇒ **一个格 `(tid, h, key)` 能不能被试到，取决于 `gen` 在那条 frontier 路径上
有没有恰好产生这个键。** 这是本轮的机制前提，不是结论。

### 1.2 装置可行性（已跑 `--feas`，只报 n_eval，未看覆盖读数）

```
STOP   n_eval = 588   到 1.0 = 21/25   ← 与 V146 逐字一致
NOSTOP n_eval = 2301  到 1.0 = 21/25
前缀性（逐实现）✅ 25/25
逐实现 s1 有差异的实现数 = 0
墙钟 ≈ 4.5s
```

首读踩坑（如实登记）：第一版把前缀性写成**全局**事件序列比较，@14 报不同。
根因：两条臂都是"一个实现接一个实现"串行，某实现早停会让全局位置整体错位。
修法：前缀性**逐实现**断言。

## 2. 本轮的假设

> **自省覆盖不是预算的函数，是「可寻址性」的函数。**
> 记忆条目只作为排序键存在（§1.1），所以验证只能**顺带**发生在搜索经过的路径上；
> 一条知识「能不能被验证」取决于 `gen` 是否在该实现的 frontier 上恰好产出这个键。
> ⇒ 加预算只能买到最后一条路径上的格；不在任何被走到路径上的格，**任何预算都买不到**。
> ⇒ §213.6 那个"累积省判分 / 自省花判分"的冲突，代价不是线性的，有**结构性上界**。

## 3. 装置（两臂，同一搜索器）

| 臂 | 定义 | 与 V146 的关系 |
|---|---|---|
| `STOP` | `v121.search` 逐行同构，**一到 1.0 就 return** | == `WARM_ALL`，必须复现 588/21 |
| `NOSTOP` | 同一函数，**唯一差别是 `s>=1.0` 时不 return**，把 6 轮跑完 | 新增；是 `STOP` 的**行为延伸** |

`NOSTOP` 不是另一个装置：逐实现断言「`NOSTOP` 的前 `n_eval(STOP)` 个事件
与 `STOP` 的全部事件逐事件相同」（纪律 50）。已通过（§1.2）。

**事件三分类**（每次判分归一类，互斥，跑前写死）：

| 类 | 定义 |
|---|---|
| `NEW` | 该 `(tid,h,key)` 格在**本臂里第一次**被判分 |
| `RESOLVE` | 这次判分把该格的累计最高分从 `<1.0` 抬到 `≥1.0` |
| `REFINE` | 其余（已知格的再判分，只提高"不成立"的置信度） |

**格的分母**（纪律 46，写进字段名）：`universe` = 本 tid 的、来自**别的实现**的记忆条目
× 该 tid 的可解析实现。与 V146 的 60 格同一口径，脚本现算现打印。

## 3.1 跑后修订（预注册外，**如实登记**，附原样读数）

第一遍 `v147.py` 在 §4 崩溃（`checkpoint = 0` 的游标 bug），崩前已打印 §0~§3，
原样留在 `READINGS_v1_wrongdenom.txt`。从那份读数里发现装置**两处缺陷**，
方向、阈值、判据措辞**一字未动**，改的只是分母与分类：

1. **分母被哨兵格污染**：按 §3 口径算出 `universe = 60`，其中 **25 格**的键是记忆文件里的
   哨兵 `('?','<baseline>')`。`v121.abstract()` 的六条正则**都不产出这个形状**
   ⇒ 没有任何候选能命中它 ⇒ 这 25 格**结构上不可达**，混在「没试到」里会虚增 UNTRIED。
   ⇒ 修：两个分母都报 —— `universe_all = 60`（V146 口径）、`universe_real = 35`；
   **判据用 `universe_real`**。
   ⇒ **连带修正 V146**：§213.5 的「41/60 = 68% UNTRIED」按新口径应为「16/35 = 46%」。
   ⛔ 这不是"改判据回收押破"：W1~W5 的**方向与阈值逐字未动**；改的是纪律 46 要求写清的分母。
2. **四分类原本只有三类**：原分类把「候选的键不在记忆格里」的判分硬塞进 `REFINE`，
   等于把大量**与知识无关**的判分记成"重复确认已知"。
   ⇒ 修：加第四类 `NONMEM`（这次判分不验证任何知识）。原三类的定义逐字不变。
3. `curve()` 的 `checkpoint = 0` 永远不触发（`i` 从 1 起）⇒ 曲线表空。修：显式先发 `n = 0` 行。

| # | 命题 | 判定 | 若破 |

**W5 的零假设由重排造**（纪律 49）：只反转顺序，事件集合逐字不变。

**W4 为什么有牙**（不是自明）：不早停时，命中 1.0 的候选会照常进 `pool`
⇒ 可能挤掉原本的第二名 frontier 节点 ⇒ 后续路径改变 ⇒ 某个实现的 s1 **可能下降**。
"不降"是结构命题，不是定义。
