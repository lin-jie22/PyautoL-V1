## 3. 四分类：92.7% 的部署预算与记忆无关

## 4. 上界从哪来：16 格，两条路径都没生成过（跑后诊断，⛔ 未预注册）

```
NEW 的轮次分布：STOP {1: 19}｜NOSTOP {1: 19}   ⇒ 第 1 轮占比 100.0%
```

**覆盖在第 1 轮就被定死了**：记忆键在第一轮被排到最前，能生成出来的格全在那一轮被触；
之后的轮次只产 `NONMEM` 与 `REFINE`。

没试到的 16 格，逐格查冷启动轨迹（1381 次判分）：

```
两条路径（冷启动 1381 + 本轮 NOSTOP 2301 = 3682 次判分）都没生成过该键 = 16
冷启动生成过、本臂没排到                                          = 0
```

例：`g7e1_parse_flag::644f0618 ('T2',"'on'")`、`g7d2_dedupe_keep::6c9204fe ('key','.strip()')`、
`g7e2_truncate_tail::c21ee3b8 ('C1',"'…' + s[-n:]")`……

机制（代码取证，零判分）：记忆条目在装置里**没有应用通道**，只当排序键用 ——

```
v121.py:144  mine = {(a, b) for k in mem[tid] if k["h"] != h for a, b in [tuple(k["act"])]}
             ⇒ 之后只出现在 sorted(cands, key=... (0 if x[0] in mine else 1))
```

候选的唯一来源是 `X.gen(...)`，`X.abstract(lab)` 只是事后读出来的标签。
⇒ **一个格能不能被验证，取决于 `gen` 在该实现的 frontier 上有没有恰好产出那个键**。
这不由预算决定，由生成器与代码结构决定。

## 5. 押破与自踩

| # | 事项 | 判定 |
|---|---|---|
| **W2** | 「追加预算买到新格」 | ⛔ **押破**：+0。结论比预注册更强 —— 不是"买到一点"，是"一点都买不到" |
| **W5 / R3** | 「反转事件序列 ⇒ 覆盖改变」 | ⛔ **押破，且是装置自证不可能**：反转一个排列不改变它在全长上的集合。这是纪律 47，不是对世界的读数。⛔ 不许拿它当反证 |

修正后的灵敏度对照（跑后补，`§4b`）：

```
C1 计数器随预算动：coverage 0 → 4@25 → 8@50 → 10@100 → … → 19@588   （不是恒 19）
C2 匹配器两侧都非空：认出 19 格｜判「从未出现」16 格                  （不是恒真/恒假）
C3 换分母只改分母：19/35 = 54.3%｜19/60 = 31.7%（V146 口径）          （读数跟着分母走）
```

自踩三处：

1. **分母被哨兵格污染**：第一遍按 V146 口径算出 `universe = 60`，其中 **25 格**的键是
   记忆文件里的哨兵 `('?','<baseline>')`。`abstract()` 的六条正则**都不产出这个形状**
   ⇒ 这 25 格没有任何候选能命中，**结构上不可达**，混在「没试到」里虚增 UNTRIED。
   第一遍读数（含曲线表为空的 `checkpoint=0` bug）原样留 `READINGS_v1_wrongdenom.txt`。
2. **四分类原本只有三类**：把「候选键不在记忆格里」的判分硬塞进 `REFINE`
   ⇒ 555 次与知识无关的判分被记成「重复确认已知」。加 `NONMEM` 后才看清 92.7%。
3. **W5 押注写成了恒等式**（见上）。

## 6. 连带修正 V146：「68% 没试过」应为「46%」

V146 §213.5 的矩阵行 `UNTRIED ... 41`、以及 §213.6 的「18/60 格 = 30%」，分母含 25 个哨兵格。

| 口径 | 覆盖 | 成立 | UNTRIED |
|---|---|---|---|
| V146 原样（60 格） | 19/60 = 31.7% | 9/60 | **41/60 = 68%** |
| 修正（35 个真实格） | 19/35 = 54.3% | 9/35 | **16/35 = 45.7%** |

⇒ V146 的**方向不变**（多数格仍是"没试过就不知道"），但**幅度要撤**：
「68%」是 46%。「18/18 同义反复」一句不受影响（那 18 格全是真实格）。
⛔ 这条修正不动 V146 的任何判据结论（W1~W5 都不依赖这个分母）。

## 7. 结论

⭐ **覆盖不是预算的函数。** 曲线在第 1 轮定形、在 500 次判分左右到顶（19/35），
再多的判分一个新格都买不到 —— 因为记忆条目**只能被 `gen` 顺带验证**，没有应用通道。

| 问 | 答 | 证据 |
|---|---|---|
| 多花判分买到新知道吗 | **588 之前买到；588 之后 0** | NEW 100% 发生在第 1 轮 |
| 那 1713 次追加判分买到了什么 | +5 格「成立」，0 个新格，0 个答案 | RESOLVE 5→10，`s1` 全同 |
| 上界由什么定 | 可寻址性（`gen` 能不能产出那个键），不是预算 | 16 格 / 3682 次判分都没出现 |
| §213.6 那个冲突的代价 | 放弃早停：588 → 2301（×3.91，比无记忆的 1381 还多 67%），换来 0 答案 | 同表 |

⛔ **这不是「系统学会了自省」**：它只是**看见了分数**，覆盖是搜索路径的副产品，
且 92.7% 的判分与知识无关。

## 8. 边界

1. ⛔ 不是「系统学会了判断知识对错」：判分来自 `v119.ev`，判断与真值同源（V146 §213.5）。
2. ⛔ 不是「加预算没用」：**588 之前**它确实线性买到新格（0→19）；本轮量的是**在哪停、为什么停**。
3. `NOSTOP` 是反事实，**不是部署建议**：2301 次判分产出 0 个新答案。
4. 两条臂**在同预算点不可比**：`NOSTOP` 不早停 ⇒ 预算前置，`N=588` 时只覆盖 10 格。
   故 W2 比的是**各自终值**（588 处 vs 2301 处），不是同 N。
5. 语料仍 **25 实现 / 4 题**；`MAX_ROUNDS=6`、`k=2`、`order_key`、`abstract()` 的键形状全是人定的；
   V79 那堵墙（自造判据 0/8）一字未碰。
6. 哨兵格的识别是**结构性**的（`abstract()` 的正则不产出 `('?', '<baseline>')`），不是按读数筛的。
