# V148 预注册：可寻址性有多硬 —— 16 格是「没走到」还是「产不出」

**落盘时间**：2026-11-16 19:03（**判据读数之前**；跑前量测已在 §1 披露）

## 0. 这一刀问什么

V147 把自省的上界钉在一句话上：**一个格能不能被验证，取决于 `gen` 在该实现的 frontier 上
有没有恰好产出那个键**。但**没量过这个上界有多硬**：16 个没试到的格，是
「两条路径（冷启动 1381 + NOSTOP 2301 = 3682 次判分）恰好没走到」，还是
「该实现的 `gen` **根本产不出**那个键」？

两者含义完全不同：

| 若上界是「没走到」 | 若上界是「产不出」 |
|---|---|
| 换条路径/加预算就有救 | 换多少预算都没救，得改生成器或语料 |
| 自省的天花板是搜索策略 | 自省的天花板是**语法** |

## 1. 已知事实（**跑前量测，非判据**，如实披露）

### 1.1 候选的全部来源（代码取证，零判分）

`X.gen = S.candidates + V.candidates_B + W.candidates_C1`，三者的**站点**全部来自 AST：

| 模板 | 需要的站点 | 站点怎么来的 |
|---|---|---|
| `T1:ret{i}:={v!r}` | `Return` 且值是 `Constant` | 原代码 |
| `T2:cont{i}.{j}:+{w!r}` | `Compare` 的比较子里有 `List/Tuple` | 原代码 |
| `T3:ret{i}:{wrap}` | 任一 `Return` | 原代码 |
| `T4:cmp{i}:{wrap}` | `Compare.left` 是 `Name` | 原代码 |
| `B:ret/cmp{i}:{chain}` | `Return` / `Compare.left is Name` + 链 | 站点原代码，链从**同题兄弟**抽 |
| `B:key({var},{cont})` | 同一变量的 `In` 比较 **且** 同容器 `.add(var)` | 原代码（**两个都要有**） |
| `C1:ret{i}:={expr}` | 任一 `Return` + 表达式 | 站点原代码，表达式从**满分兄弟**抽 |

`v119.harvest_chains(corpus, tid, exclude=h)`、`v120.harvest_exprs(...)` 都**排除自己**
⇒ 链/表达式集合与当前代码无关，只与语料有关。

### 1.2 试跑（4 个实现，零判分）

```
g7d2 1ac9e8da: d1 keys=15 nodes=12  ｜d2 keys=15 nodes=55   ｜k2⊆k1 ✅
g7e1 644f0618: d1 keys=46 nodes=102 ｜d2 keys=46 nodes=4999 ｜k2⊆k1 ✅
g7d3 309f1027: d1 keys=11 nodes=12  ｜d2 keys=11 nodes=89   ｜k2⊆k1 ✅
g7e2 c21ee3b8: d1 keys= 7 nodes=11  ｜d2 keys= 7 nodes=74   ｜k2⊆k1 ✅
```

⇒ 4/4 上「深度 2 的键集 == 深度 1 的键集」。**但这不必然是定理**：
`C1` 会用满分兄弟的 return 表达式**替换**返回值，若那个表达式里含 `in ("a","b")`，
就会**新造出一个 `T2` 站点** ⇒ 深度 2 可能出现深度 1 没有的键。
这正是本轮要押的地方（W2）。

## 2. 本轮的假设

> **可寻址性由原代码的语法站点决定，不由搜索路径决定。**
> 每个模板的站点都只能被「包装/替换」，没有一条模板会**新增**站点
> （`T3/T4/B:cmp/B:key` 反而会让自己的站点消失）。
> ⇒ 「键宇宙」在深度 1 就定形；16 个格若不是「站点缺失/链不在兄弟集里」，就是硬墙。
> ⚠️ 唯一的例外通道是 `C1` 的表达式替换（见 §1.2），所以 W2 有牙。

| # | 命题 | 判定 | 若破 |

| **W5** | 反证组三条**全绿**：①伪键 `('Z9','nonsense')` 必须判「产不出」；②已覆盖 19 格必须判「可产出」；③**站点单调性**：深度 2 的站点集 ⊆ 深度 1 的站点集 | 押 ✅ | 任一条不过 ⇒ 装置不能分辨"产得出/产不出"，W3/W4 作废 |

**W5-③ 为什么不是恒等式**：它是**关于模板行为的断言**，不是关于排列的断言 ——
`C1` 替换返回值可以**新增** `in` 容器站点，所以站点集**可以**变大。⛔ 不拿"反转顺序"这类
置换不变量当反证（V147 的教训，纪律 68）。

## 5. 反证组与边界（⛔ 现在就写死）

1. **不是「系统学会了什么」**：全程零判分结论，纯静态可达性；它只回答"生成器能不能产出"，
   不回答"产出的东西对不对"。
2. **不是「改生成器就能变强」**：本轮的"硬墙"只说明**这个语料 + 这套模板**的组合产不出，
   不说明"加模板能提升 L 格"。
3. `MAX_ROUNDS=6`、`k=2`、`WRAPS`、`BAN`、链长 ≤3 全是人定的；V79 那堵墙一字未碰。
4. 语料仍 25 实现 / 4 题；**深度 2 的节点数可能爆炸**（已见 4999），逐实现设上限并打印
   「被截断的实现」，⛔ 不许把"没算完"写成"产不出"（纪律 64）。
5. ⛔ 不动 `mw/`、`run.py`、`tests/`；结论在证据脚本里。
