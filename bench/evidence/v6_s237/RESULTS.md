## 0. 这一刀问什么

## 1. 键宇宙在深度 1 就定形（W2 ✅）

对 25 个实现，各从**原始代码**出发做 d=1 / d=2 的 BFS（每个新代码再跑一次 `X.gen`）：

```
d2 ⊆ d1：25/25 ✅｜d2 比 d1 多出的键 = 0｜「新造站点」计数 = 0｜被截断 = 0
```

机制（代码取证）：每个模板的站点都只能被**包装/替换**，没有一条模板**新增**站点 ——
`T3/T4/B:cmp/B:key` 反而会把自己的站点弄没（把 `Name` 包成 `Call`）。
唯一可能新增站点的通道是 `C1`（用满分兄弟的 return 表达式替换），本轮**一次都没发生**。

⇒ **键宇宙 = 原代码的语法站点的函数**，与搜索走多深无关。这解释了 V147 的
「NEW 100% 发生在第 1 轮」：不是"第 1 轮运气好"，是**后面不会再有新键**。

## 7. ⭐ 新登记的缺口：自省的样本只来自失败的实现

`s0 >= 1.0` 就返回 ⇒ **10/25 的实现从不进入自省**。这意味着记忆库永远收不到
「在已经正确的实现上这条知识也成立/不成立」的证据 —— 知识库的验证样本有**选择偏差**，
只覆盖"需要修的"那一半。这不是 bug（不修就别动），但是一个**没有被量过的边界**。

## 8. 边界

1. ⛔ 不是「系统学会了自省」：全程零判分，只回答"生成器能不能产出这个键"。
2. ⛔ 不是「改生成器就能变强」：硬墙只说明**这个语料 + 这套模板**产不出。
3. `MAX_ROUNDS=6`、`k=2`、`WRAPS`、`BAN`、链长 ≤3 全是人定的；V79 那堵墙一字未碰。
4. 深度 2 的节点数最大 6573（`a579b07a`），未触顶；**没有被截断的实现**，所以
   "产不出"不是"没算完"（纪律 64）。

6. 三层分母是**逐层剔除并逐层打印**的，不是一次性挑到好看的数；每一层的剔除理由都是
   **结构性**的（正则形状 / 短路条件），不是按读数筛的。
