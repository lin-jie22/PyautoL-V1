# PREREG — V150「一条知识的单位是键，还是具体编辑」

**落盘时间**：2026-11-16 19:38（**判据读数之前**；跑前量测已在 §1 披露）

## 0. 这一刀问什么

V149 §216.3 撞到一件没法再往下推的事：同一个抽象键 `('C1', "'…' + s[-n:]")`
在两个 `s0=0.20` 的坏实现上有 `1.00` 的实例，在两个 `s0=1.00` 的好实现上只有 `0.80`。
⇒ **「这条知识对不对」在键的粒度上没有唯一答案。**

本轮不问「哪条知识对」，只问一个**表示层**的问题：

> 记忆里存的是 `(落点类, 链)` 这样的**抽象键**；验证时判的是**具体源码**。
> 一个键在同一个实现上对应几个具体源码？这些实例的分数跨度多大？
> 若跨度普遍 > 0，则「按键记三值」**必然**依赖「取 max / 取 first / 取 min」——
> 这不是实现缺陷，是**表示缺陷**。

## 1. 跑前量测（零判分，本轮披露，⛔ 不作判据）

`probe_mult.py`：只跑 `X.gen` 的 d=1/d=2 闭包并按 `X.abstract(lab)` 分组，**一次 `V.ev` 都不调**。

| 量 | 值 |

⇒ 抽象是**多对一**的：2.07 个具体编辑压成 1 个键，最深 3 个。
**这已经说明「一条知识」在表示层不是一条。** 但上面的 528/386 是**生成闭包**口径，
不是**判分**口径 —— 搜索有 `visited`/`seen_src` 去重与 6 轮上限，判到的实例一定是子集。
两个分母本轮都要报（纪律 64）。

## 2. 装置（两个臂，同一搜索器 / 记忆 / 25 实现）

| 臂 | `s0>=1.0` 短路 | 一到 1.0 就 return | 角色 |
|---|---|---|---|
| `ASK` | **关** | 关 | 主臂（= V149，2710 次判分），实例覆盖最全 |
| `ASK_EARLY` | 关 | **开** | 早停，用来量「预算能截断几个实例」（= V149，609） |

`search_trace` 相对 V149 **只加一处**：事件里记下 `src`（被判的具体源码），
其余逐行不动（`n_eval`/`n_dup`/`hit_at` 定义不变）。

## 3. 三个聚合（唯一的因变量是聚合方式，分数仍是 `v119.ev`）

对每个格 `(实现, 键)`，取该键在臂里的**全部判分** `S`：

| 聚合 | 三值 |
|---|---|
| `MAX` | `max(S) >= 1.0` ⇒ VALID |
| `FIRST` | `S[0] >= 1.0` ⇒ VALID（`S[0]` = 搜索顺序上第一个被判的实例） |
| `MIN` | `min(S) >= 1.0` ⇒ VALID |
| `MEAN` | ⛔ 不单列：阈值 1.0 时 `mean >= 1.0 ⟺ min >= 1.0`（分数 ∈ [0,1]），**它不是第三个独立读数** |

⛔ 不新造分数、不改阈值、不改 `gen`/`abstract`/记忆；⛔ 不碰 V79。

## 4. 判据（W1~W6，跑前写死）
