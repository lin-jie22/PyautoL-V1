# V151 预注册：`MAX` 能不能被证伪 —— 登记的那把刀砍空了，改问「满覆盖下极值还动不动」

**落盘时间**：2026-11-16 19:45（**主判据读数之前**）。跑前量测在 §1 全部披露，**只量了结构与成本，没算过任何一格的分数**。

## 0. 这一刀原本要做什么，为什么改

§217.8 登记：「把 `MAX_ROUNDS` 6 → 更大，量 `MAX=VALID` 的格数还涨不涨」。
跑前量测发现 **这个旋钮从来没被用到**：25/25 实现在 `round <= 2` 就因为 `if not pool: break` 退出
⇒ `MAX_ROUNDS=6` 是**死旋钮**。照原计划做只会读到「6 与 40 逐字相同」，读不出任何关于 MAX 的信息。

⇒ 改问同一个问题的真形态：**把覆盖推到这一类搜索的上界（满 d=2 闭包），`MAX` 还动不动？**
如果连上界都不动，那 MAX 是结构量；如果上界把它推到「凡有实例皆 VALID」，那 MAX 是**可达性判据**，
不是知识判据 —— 两种都是对本轮问题的回答。

## 3. 读数（每格 = `(实现, 键)`，共 35 个真实格）

- `n_inst(A)`、`n_inst(C)`：该键被判过的**不同源码**数（分母）。
- `MAX`、`MIN`：该键实例上的最高 / 最低分（1.0 为阈值）。
- 三值：`VALID`（max=1.0）/ `INVALID`（有实例但 max<1.0）/ `UNTRIED`（0 实例）。
- 翻转表：A 与 C 三值不同的格。
- 对 C 上仍非 `VALID` 的格，做**有界 d=3 探针**：取其 C 实例源码（按字典序）前 **40** 个，各再跑一轮
  `gen` 并判分子代码，看有没有 1.0。**已看/未看两个分母都要报**（纪律 64）。
