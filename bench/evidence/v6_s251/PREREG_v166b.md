# PREREG — V166b：把「语料已有惯例」从**子串匹配**改成**字面量相等**

## §0 为什么另立一轮（V166 的 F2 已经破了，不许重跑改判）

V166（`PREREG_v166.md`）预注册的 `P1` 定义是：

> 若 `s` 是 `sib_src` 的**子串** ⇒ 视为「语料已有惯例」⇒ 不生成该字面量的 del 候选。

读数：`P1` 命中 **24/25**、判分 366（−25.2%），**丢了 `5755e033`**。原因已定位（`probe` 级别，非猜测）：

```
兄弟 36317a87：  f"( {(abs(x):.2f):,}"   ← 这里的 "( " 是 f-string 里 `( {` 的**跨字符子串**
5755e033 需要的： '( '                     ← 真正要删的是这个 2 字符字面量里的空格
```

⇒ **子串匹配会跨字面量边界命中**，把「不同字面量里的巧合片段」当成「同一条惯例」。
这是**谓词粒度的缺陷**，不是「结构化触发没用」。V166 的 F2=FAIL **保留，不改判**。

本轮只换粒度：**字面量值相等**（不是子串），其余口径与 V166 逐项相同。

## §1 谓词 `P2`（跑前写死）

```
P2（T5 触发闸，逐字面量判定）
  sib_consts = 同题**其他所有实现**出现过的字符串常量值集合
               · 可解析的实现：ast.walk 的 Constant(str)（含 f-string 内部的格式说明符常量）
               · 不可解析的实现（36317a87）：tokenize 取非 f-string 的 STRING token，
                 ast.literal_eval 求值；求值失败的跳过（计进 sib_consts_skipped）
  若 字面量值 s ∈ sib_consts ⇒ 不生成该常量的任何 del 候选
```

- 与 `P1` 的**唯一差别**：子串 → 集合成员。
- 仍在付费点之前过滤（纪律 85）。
- 仍不读判分、不读测试（F/R 免费性判据核 `V.CACHE` 增量 == 0）。
